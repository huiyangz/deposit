# 单元测试用例生成 — 规则类型

## 概述

> 根据规则业务SPEC中的业务逻辑描述，解析枚举取值信息，按规则类型提取测试场景，为每个场景构造具体输入值和预期结果，产出结构化的单元测试用例文档。

## 数据源边界

> 不得探索项目目录结构。枚举源码按以下规则读取：

| 操作 | 说明 |
|------|------|
| 读取依赖分析产物 | 优先读取，获取已确认的枚举类路径 |
| 读取枚举类的源码内容 | **仅当构造测试用例需要该枚举的常量名时**，允许按照依赖分析产物中的枚举类路径读取对应源码。**禁止**读取依赖分析产物中未列出的枚举类。|
| 搜索/列出目录结构 | 禁止——所有需要的目录已在输入中提供，不得 `find`、`ls`、`Glob` 等任何方式探索其他目录 |
| 读取无关的源码文件 | 禁止——不得读取除当前规则涉及的枚举类外的其他类的源码文件 |

## 工作流

### 1. 解析枚举取值

从依赖分析产物中获取已绑定枚举的类路径，**仅当构造测试用例确需该枚举的常量值时**，才读取对应枚举源码提取可用常量名列表。**禁止**读取依赖分析产物中未列出的枚举类。

### 2. 提取测试场景

根据规则类型采用不同的提取方式，**目标是规则类行覆盖率 ≥80%**：

| 规则类型 | 提取方式 |
|----------|----------|
| 断言类 | 提取所有触发条件分支，覆盖**通过和未通过**两种结果的每个分支路径。不只看结果，要穷举每种输入组合对应的分支 |
| 计算类 | 提取正常路径；补充**输入为空/null/零**的边界路径；补充**输入超出合理范围**的异常路径 |
| 决策类 | 按决策表**每行至少一个测试用例**；标记为"/"或"不关心"的值取其默认值或枚举的第一个值参与构造，不参与断言；覆盖所有输入值组合，包括无默认行时补充兜底场景 |

### 3. 构造用例

为每个场景构造具体输入值（枚举参数使用步骤1获取的取值集合）和预期结果，确定断言方式。若输入中提供了「人工补充的单元测试用例列表」，须将其作为参考基线，确保生成的用例覆盖人工补充的场景与断言要求，不得与人工补充用例冲突或遗漏其覆盖的场景。要求生成的测试用例覆盖所有分支。

用例设计要求：
- 尽可能覆盖全部正常路径、边界路径、否定/异常路径；
- 断言类规则覆盖**所有条件分支**的通过/不通过结果；
- 每个用例需明确：输入参数赋值、预期返回值、断言方式（assertTrue/assertEquals 等）；
- 测试方法命名采用 `test{规则ID}T{两位序号}` 格式（如 `testBR001T01`）
- 输入值赋值时，对于枚举类型字段，**仅在需要时**从依赖分析产物中获取对应类路径并读取该枚举源码，提取可用常量名，在输入构造中以 `枚举常量名 // 中文含义` 格式输出，如 `ResOperateFlag.E // "E-检查类"；非枚举字段用合理占位值。**禁止**读取依赖分析产物中未列出的枚举类。

### 4. 输出产物

输出到 Agent 指定的路径。

产物采用 Markdown 格式，文档结构如下：

```markdown
# {规则ID} 单元测试用例

## 规则概述
- 规则ID：{规则ID}
- 规则名称：{规则名称}
- 测试类名：{规则ID}Test

## 测试用例表

| 用例编号 | 测试方法名 | 场景描述 | 输入构造 | 预期结果 | 断言要点 |
|---|---|---|---|---|---|
| ... | ... | ... | ... | ... | ... |

## 覆盖分析

| 覆盖维度 | 覆盖情况 |
|---|---|
| ... | ... |
```
