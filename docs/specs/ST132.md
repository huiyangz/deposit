# ST132 计算账户解限可用余额

## 目标与范围

本任务定义存款业务组件中「计算账户解限可用余额」步骤（步骤类型：计算/取数类）的行为契约：以调用方上送的账号为起点，先取账户内部键值，再取该账户的汇总金额与透支金额，按二者之和得出账户可用余额并作为本步骤输出返回；取数失败时以业务错误码结束本步骤。

范围内：

- 两段取数路径及其先后依赖：按 `{账号}`（`baseAcctNo`）查询【账户信息】（对公存款账户主表 `RB_BUS_ACCT`）取得账户内部键值（`internalKey`）；再以该账户内部键值查询【账户余额信息】（对公存款账户余额表 `RB_BUS_ACCT_BALANCE`）取得汇总金额（`totalAmount`）与透支金额（`odAmount`）。
- 计算公式：`acctAvailBal` = `totalAmount` + `odAmount`（需求原文为「{汇总金额}加{透支金额}」）。
- 两类业务失败的触发条件、错误码与结束语义：查不到账户、该账户没有余额记录，均返回错误码 ER0048「账户不存在」并结束本步骤。
- 结果以本步骤输出 `acctAvailBal`（`java.math.BigDecimal`）返回。
- 其余失败仅由技术异常传播表达，不映射为业务结果。

不在范围内：

- 不定义 `{账号}` 的合法取值域、校验规则与来源渠道（需求未规定，由调用方上送）。
- 不定义【账户信息】【账户余额信息】的数据源绑定方式（需求「来源实体」列只给出实体表名，未声明组件/接口绑定）。
- 不定义余额记录的更新与写回：需求只声明输出 `acctAvailBal`，未声明对 `RB_BUS_ACCT_BALANCE` 的写入。
- 不定义精度与舍入方式（需求未规定，见「验收范围与明确不覆盖的事项」）。
- 不定义按 `{账号}` 查询【账户信息】命中多条记录时的处理（需求未定义）。
- 不定义本步骤结果在业务流程中的保存、持久化与下游取用（需求未定义）。
- 不定义并发、幂等、性能与日志要求（需求未涉及）。

| `acctAvailBal` | java.math.BigDecimal | 非必填 | 对公存款账户余额表（RB_BUS_ACCT_BALANCE） | 账户可用余额，值为 `totalAmount` + `odAmount`。「非必填」标记反映实体字段本身可空，不代表本步骤可能不产出结果；取数成功的路径恒产出该输出，取数失败的路径不产出 |

依赖契约：

- 组件内步骤调用：不适用。需求「步骤描述」「失败处理」均无调用其他组件步骤的描述，本步骤无调用位置、参数来源与调用结果用途的绑定要求。
- 跨步骤数据传递：本步骤内部两段之间传递账户内部键值（第一步取得 → 第二步作为查询条件）；汇总金额与透支金额从第二步传递到计算与输出环节。本步骤不向其他步骤传递数据。
- 外部依赖：
  - 【账户信息】= 对公存款账户主表 `RB_BUS_ACCT`，以 `baseAcctNo` 为查询条件取数；
  - 【账户余额信息】= 对公存款账户余额表 `RB_BUS_ACCT_BALANCE`，以账户内部键值（主键 `INTERNAL_KEY`）为查询条件取数；
  - 业务错误码 `ER0048`「账户不存在」。
- 计算口径：加法，无优先级、无分支互斥；两个加数均取自同一条余额记录。
- 幂等与副作用：本步骤不产生写操作（需求未声明对任何表的更新），重复执行同一输入得到同一结果。

## Requirements

### Requirement: REQ-001 按账号查询【账户信息】取得账户内部键值
来源：`docs/requirements/ST132.md`「步骤描述」子步骤 1（「先按{账号}查询【账户信息】取得账户内部键值」）、「输入」表（`baseAcctNo`、`internalKey` 均来源 RB_BUS_ACCT）。

系统 SHALL 以调用方上送的 `{账号}`（`baseAcctNo`）为查询条件查询【账户信息】（`RB_BUS_ACCT`）；查询命中时，SHALL 取得该账户记录的账户内部键值（`internalKey`）并用于后续余额查询；查询未命中（查不到账户）时，SHALL 返回错误码 ER0048「账户不存在」并结束本步骤。

#### Scenario: REQ-001-S01 按账号命中唯一账户记录并取得账户内部键值
- **GIVEN** `{账号}` = `"6217000000000001"`，【账户信息】中存在 `baseAcctNo` = `"6217000000000001"`、`internalKey` = `1001` 的账户记录
- **WHEN** 执行本步骤的获取账户余额信息环节
- **THEN** 使用 `baseAcctNo` = `"6217000000000001"` 查询【账户信息】并命中该记录，取得账户内部键值 `1001`，且以 `1001` 作为后续【账户余额信息】的查询条件（不得以 `{账号}` 直接查询余额表）

#### Scenario: REQ-001-S02 查不到账户时返回 ER0048 并结束本步骤
- **GIVEN** `{账号}` = `"6217000000000009"`，【账户信息】中不存在 `baseAcctNo` = `"6217000000000009"` 的记录
- **WHEN** 执行本步骤的获取账户余额信息环节
- **THEN** 返回错误码 ER0048「账户不存在」，结束本步骤；不执行余额查询，不执行可用余额计算，不产出输出 `acctAvailBal`

### Requirement: REQ-002 按账户内部键值查询【账户余额信息】取得汇总金额与透支金额
来源：`docs/requirements/ST132.md`「步骤描述」子步骤 1（「再按账户内部键值查询【账户余额信息】获取$汇总金额$、$透支金额$」）、「输入」表（`totalAmount`、`odAmount` 来源 RB_BUS_ACCT_BALANCE）。

系统 SHALL 以 REQ-001 取得的账户内部键值（`internalKey`）为查询条件查询【账户余额信息】（`RB_BUS_ACCT_BALANCE`）；查询命中时，SHALL 取得该余额记录的汇总金额（`totalAmount`）与透支金额（`odAmount`）；该账户没有余额记录时，SHALL 返回错误码 ER0048「账户不存在」并结束本步骤。

#### Scenario: REQ-002-S01 按账户内部键值命中余额记录并取得汇总金额与透支金额
- **GIVEN** REQ-001 取得的账户内部键值为 `1001`，【账户余额信息】中存在 `internalKey` = `1001`、`totalAmount` = `1000.00`、`odAmount` = `200.00` 的余额记录
- **WHEN** 执行本步骤的获取账户余额信息环节
- **THEN** 查询【账户余额信息】命中该记录，取得汇总金额 `1000.00` 与透支金额 `200.00`，两者进入计算环节

#### Scenario: REQ-002-S02 该账户没有余额记录时返回 ER0048 并结束本步骤
- **GIVEN** REQ-001 取得的账户内部键值为 `1001`，【账户余额信息】中不存在 `internalKey` = `1001` 的余额记录
- **WHEN** 执行本步骤的获取账户余额信息环节
- **THEN** 返回错误码 ER0048「账户不存在」，结束本步骤；不执行可用余额计算，不产出输出 `acctAvailBal`

### Requirement: REQ-003 计算账户可用余额为汇总金额加透支金额
来源：`docs/requirements/ST132.md`「步骤描述」子步骤 2（「赋值[账户可用余额]={汇总金额}加{透支金额}」）。

系统 SHALL 按 `acctAvailBal` = `totalAmount` + `odAmount` 计算账户可用余额；结果为两个加数的和，不依赖余额记录中原有的 `acctAvailBal` 取值，也不引入除这两个加数之外的其他数据项。

#### Scenario: REQ-003-S01 汇总金额与透支金额相加得到账户可用余额
- **GIVEN** 取得的汇总金额 `totalAmount` = `1000.00`，透支金额 `odAmount` = `200.00`
- **WHEN** 执行计算账户可用余额环节
- **THEN** 得到账户可用余额 `1200.00`（= `1000.00` + `200.00`）

#### Scenario: REQ-003-S02 计算结果以两个加数为准，不取用余额记录原有可用余额
- **GIVEN** 取得的汇总金额 `totalAmount` = `1000.00`，透支金额 `odAmount` = `200.00`，同一条余额记录中原有 `acctAvailBal` = `0.00`
- **WHEN** 执行计算账户可用余额环节
- **THEN** 得到账户可用余额 `1200.00`；结果不等于原有 `acctAvailBal` 的取值 `0.00`，也不为 `1000.00`（即不得只取汇总金额或只取原有可用余额）

### Requirement: REQ-004 以输出 acctAvailBal 返回账户可用余额
来源：`docs/requirements/ST132.md`「输出」表（`acctAvailBal`，`java.math.BigDecimal`，非必填，来源对公存款账户余额表）。

系统 SHALL 将计算结果作为本步骤的输出 `acctAvailBal`（`java.math.BigDecimal`）返回；取数成功的路径 SHALL 恒产出该输出，其取值等于 REQ-003 的计算结果。输出表中该字段标记为「非必填」，仅表示实体字段本身可空，不表示本步骤可以缺少该输出。

#### Scenario: REQ-004-S01 成功路径返回可用余额作为步骤输出
- **GIVEN** REQ-001 与 REQ-002 均取数成功，计算得到账户可用余额 `1200.00`
- **WHEN** 本步骤执行完成
- **THEN** 本步骤输出 `acctAvailBal` = `1200.00`，类型为 `java.math.BigDecimal`；本步骤不对【账户余额信息】做任何更新写入

### Requirement: REQ-005 业务失败以 ER0048 结束，其余失败由技术异常传播
来源：`docs/requirements/ST132.md`「失败处理」节。

系统 SHALL 仅将「按 `{账号}` 查不到账户」与「该账户没有余额记录」两种情形作为本步骤的业务失败场景，返回错误码 ER0048「账户不存在」并结束本步骤；除该两种情形外的其他失败，SHALL 仅由技术异常传播表达，不映射为业务错误码、不产出输出。

#### Scenario: REQ-005-S01 除两类业务失败外的失败以技术异常传播
- **GIVEN** `{账号}` 对应的账户与余额记录均存在，取数环节发生技术性故障（如数据访问异常）
- **WHEN** 执行本步骤
- **THEN** 该故障以技术异常向上传播，不被转换为业务结果；不返回 ER0048，不产出输出 `acctAvailBal`

## 验收范围与明确不覆盖的事项

覆盖：

- 两段取数路径的顺序依赖：先按键值取数、再以键值查余额，且余额查询条件是账户内部键值而非账号。
- 两类业务失败的触发条件、错误码 ER0048 与「结束本步骤、不产出输出、不继续计算」的短路语义。
- 计算公式 `acctAvailBal` = `totalAmount` + `odAmount`，以及结果不受余额记录原有 `acctAvailBal` 影响的断言。
- 输出 `acctAvailBal` 的类型与取值来源。
- 其他失败以技术异常传播、不映射业务错误的契约。

明确不覆盖（需求无依据，验收不得据此断言）：

- 精度与舍入方式：需求未规定小数位、精度或舍入规则；测试按两个加数的精确和断言（如 `1000.00` + `200.00` = `1200.00`），不得断言任何舍入或截断行为。
- `{账号}` 为空、为 `null`、格式非法或不存在于任何账户时的差异化行为：需求只定义「查不到账户」一种结果，测试不得断言另外的校验或提示。
- 按 `{账号}` 查询【账户信息】命中多条记录时的处理（返回哪一条、是否报错）：需求未定义。
- 【账户信息】【账户余额信息】的数据源绑定（具体 BCC/接口）与账户内部键值的传递载体：属实现选择，不是业务契约。
- 对 `RB_BUS_ACCT_BALANCE` 的更新或写回、对账户其他字段的变更：需求只声明输出，未声明任何写操作，测试不得断言副作用发生。
- 输出的保存位置、持久化与在本流程中的下游消费步骤：需求未定义。
- 输入表中 `acctAvailBal`、`internalKey` 等字段是否作为外部入参上送：输入表为「步骤引用的实体字段」列示口径，本 Spec 不据此约束调用方入参集合。
- 并发、幂等（同一输入重复执行的去重或次数限制）、性能与日志要求：需求未涉及。
