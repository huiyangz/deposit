# ST032 检查交易金额

## 目标与范围

本 Spec 定义交易执行步骤「检查交易金额」（ST032）的输入输出契约与行为。步骤以必填输入 交易金额（tranAmt，java.math.BigDecimal）执行金额检查：当交易金额小于等于 0 时返回业务失败（错误码 ER0050），否则返回检查结果为"通过"。

范围仅覆盖需求「步骤描述」条目 1 与「输入」表已确认的内容。必填输入缺失时的行为、检查结果"通过"的业务输出承载方式等需求未定义情形见「待确认事项」，不作为已确认条款写入验收预期。

- 步骤结果契约：`com.dcits.common.step.StepResult` 含 succeed、errorCode、errorMessage，成功时 errorCode 与 errorMessage 为 null；交易级响应头 `com.dcits.common.task.RespHeader` 同构。本步骤仅以公共步骤结果表达成功与业务失败，需求未声明跳转目标（未声明 `GotoStepCondition`），不新增流转断言。
- 名称映射核对：`requirement-name-mapping` 资产未收录「交易金额」的实体或属性域映射，按技能要求保留原业务称谓，未收录不影响已确认内容。
- 本步骤仅对输入交易金额做数值比较，不查询数据库、不调用规则或其他组件接口；对应步骤实现尚未生成，不构成依赖缺失。
- 比较口径：`java.math.BigDecimal` 的"小于等于0"按数值比较（`compareTo(BigDecimal.ZERO) <= 0`）执行，忽略小数位表示差异（0 与 0.00 数值相等，均满足"小于等于0"）。

## Requirements

### Requirement: REQ-001 步骤输入契约
来源：需求「输入」表（tranAmt、java.math.BigDecimal、必填、交易金额）。

本步骤 SHALL 接收必填输入 tranAmt（`java.math.BigDecimal`，交易金额）作为金额检查依据，并据其执行本步骤的判定。

#### Scenario: REQ-001-S01 接收交易金额输入
- **GIVEN** 本步骤作为交易执行步骤被调用，调用方提供必填输入 tranAmt（`java.math.BigDecimal`，交易金额）
- **WHEN** 本步骤执行金额检查
- **THEN** 本步骤以该交易金额数值执行"小于等于0"判定，按判定结果返回成功或业务失败

### Requirement: REQ-002 交易金额小于等于0时返回业务失败
来源：需求「步骤描述」条目 1（原文：若{交易金额}小于等于0，则返回[错误码]"ER0050"）；工程错误码资料 `errorcodes.properties`（ER0050=交易金额不能小于等于0）。

当交易金额（tranAmt）数值小于等于 0 时，系统 SHALL 返回业务失败：`errorCode="ER0050"`、`errorMessage="ER0050::交易金额不能小于等于0"`、`succeed=false`。比较按数值口径执行，数值上等于 0 的任意小数位表示（如 0、0.00）均满足"小于等于0"。

#### Scenario: REQ-002-S01 交易金额等于0（边界）
- **GIVEN** tranAmt 数值为 0（如 `new BigDecimal("0")` 或 `new BigDecimal("0.00")`，示例值）
- **WHEN** 本步骤执行金额检查
- **THEN** 因交易金额小于等于 0，本步骤返回业务失败：`succeed=false`、`errorCode="ER0050"`、`errorMessage="ER0050::交易金额不能小于等于0"`

#### Scenario: REQ-002-S02 交易金额为负数
- **GIVEN** tranAmt 数值为负数（如 `new BigDecimal("-100.00")`，示例值）
- **WHEN** 本步骤执行金额检查
- **THEN** 因交易金额小于等于 0，本步骤返回业务失败：`succeed=false`、`errorCode="ER0050"`、`errorMessage="ER0050::交易金额不能小于等于0"`

### Requirement: REQ-003 交易金额大于0时返回检查结果为"通过"
来源：需求「步骤描述」条目 1（原文：否则返回检查结果为"通过"）。

当交易金额（tranAmt）数值大于 0 时，系统 SHALL 返回检查结果为"通过"，步骤正常完成：`succeed=true`、`errorCode=null`、`errorMessage=null`。检查结果"通过"的业务输出承载方式见待确认事项 TBD-2。

#### Scenario: REQ-003-S01 交易金额为正数
- **GIVEN** tranAmt 数值为正数（如 `new BigDecimal("100.00")`，示例值）
- **WHEN** 本步骤执行金额检查
- **THEN** 因交易金额大于 0，本步骤返回检查结果为"通过"，步骤正常完成：`succeed=true`、`errorCode=null`、`errorMessage=null`

## 待确认事项

- **TBD-1（关联 REQ-001、REQ-002、REQ-003）**：tranAmt 标记"必填"，但需求未定义其为空（null）或未提供时的行为（是否由本步骤自行校验并失败、对应错误码与错误信息）；需求仅声明"交易金额小于等于0"返回 ER0050，未覆盖金额为空的情形。按步骤错误结果约定，需求未声明该失败条件，本 Spec 不新增失败场景，需确认调用方保证提供或步骤需校验。
- **TBD-2（关联 REQ-003）**：需求无「输出」表，未声明承载"检查结果为'通过'"的业务输出字段；"通过"是仅以公共成功状态（succeed=true）表达，还是另有业务输出字段承载，未在需求中确认，需确认。
- **TBD-3（关联 REQ-001）**：tranAmt 的来源实体需求输入表未指定（来源实体列为空），其在实际交易流程中的取值路径未在需求中确认，需确认。
