# ST032 检查交易金额

## 目标与范围

本任务为交易执行步骤类（源需求以「步骤描述」给出单条检查动作）：检查交易金额。步骤在交易执行过程中，依据入参交易金额（tranAmt）的数值大小判定该金额是否为合法交易金额，并据此给出检查结果或错误码。

本次 Spec 覆盖：

- 判定入参：tranAmt（交易金额，必填，类型 `java.math.BigDecimal`）。
- 判定逻辑：将 tranAmt 的数值与 `0` 作大小比较，共两种结果——**小于等于 0** 时返回错误码 `ER0050`；**大于 0** 时返回检查结果为「通过」。
- 比较口径：以 `BigDecimal` 的数值大小进行比较，「小于等于 0」的分界点为 `0`，`0` 本身归入小于等于分支。
- 产出：错误码 `ER0050` 或检查结果「通过」，二者互斥，由同一分支判定产出。

不在本次范围（源需求未涉及，本 Spec 不作要求）：

- 入参 tranAmt 为空值（未提供）时的步骤行为（源需求仅将该入参标记为必填，未定义空值分支）。
- 交易金额的精度、标度与舍入规则；本步骤不做任何算术运算，判定直接取入参数值。
- 交易金额以外的其它交易要素（交易类型、币种、账户、凭证等）的检查。
- 组件内步骤调用、规则调用、外部服务/领域服务调用、数据查询、超时与重试（源需求未描述任何依赖调用）。
- 检查结果与错误码的落库位置、报文承载字段及对外展示形式（源需求未给出输出表与来源实体）。
- 返回错误码 `ER0050` 之后交易的终止、回滚与向上传播方式。

## Requirements

### Requirement: REQ-001 交易金额小于等于 0 时返回错误码 ER0050

来源：`docs/requirements/ST032.md` 步骤描述第 1 条（原文：「检查交易金额：若{交易金额}小于等于0，则返回[错误码]“ER0050”」的「若」分支）、输入表 tranAmt 行。

系统 SHALL 在执行本步骤时，当入参 tranAmt 的数值小于等于 `0` 时，返回错误码 `ER0050`，且不返回检查结果「通过」。

#### Scenario: REQ-001-S01 交易金额为 0 时返回 ER0050

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `0`
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 步骤产出错误码 `ER0050`
- **THEN** 不产出检查结果「通过」
- **THEN** 判定体现「小于等于」中的「等于」边界：取值恰为 `0` 时进入本分支

#### Scenario: REQ-001-S02 交易金额为负值（小于 0）时返回 ER0050

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `-0.01`
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 步骤产出错误码 `ER0050`
- **THEN** 不产出检查结果「通过」

#### Scenario: REQ-001-S03 交易金额为较大负值时返回 ER0050

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `-1000000.00`
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 步骤产出错误码 `ER0050`
- **THEN** 不产出检查结果「通过」
- **THEN** 判定不因负值绝对金额的大小而改变

### Requirement: REQ-002 交易金额大于 0 时返回检查结果为「通过」

来源：`docs/requirements/ST032.md` 步骤描述第 1 条（原文：「否则返回检查结果为“通过”」的「否则」分支）、输入表 tranAmt 行。

系统 SHALL 在执行本步骤时，当入参 tranAmt 的数值大于 `0` 时，返回检查结果为「通过」，且不返回错误码 `ER0050`。

#### Scenario: REQ-002-S01 交易金额为最小正边界值时检查通过

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `0.01`
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 步骤产出的检查结果为「通过」
- **THEN** 不产出错误码 `ER0050`
- **THEN** 判定体现大于 `0` 的下边界：任何大于 `0` 的数值均进入本分支

#### Scenario: REQ-002-S02 交易金额为典型正值时检查通过

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `100.00`
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 步骤产出的检查结果为「通过」
- **THEN** 不产出错误码 `ER0050`
- **THEN** 判定不因金额大小而改变（仅以是否大于 `0` 为准）

### Requirement: REQ-003 交易金额判定按数值大小比较，与表示形式无关

来源：`docs/requirements/ST032.md` 步骤描述第 1 条（「小于等于0」的比较表述）、输入表 tranAmt 行（类型 `java.math.BigDecimal`）。

系统 SHALL 以入参 tranAmt 的**数值大小**与 `0` 比较来判定「小于等于 0」与「大于 0」：`BigDecimal` 的标度（scale）、尾随零等书写形式不改变判定结果；数值相等的两个取值（例如 `0` 与 `0.00`、`1` 与 `1.0`）SHALL 得到相同的判定分支。判定不得采用依赖表示形式的等值比较（即不得以 `BigDecimal.equals` 语义替代数值比较）。

#### Scenario: REQ-003-S01 标度为 2 的零与整数零判定一致

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `0.00`（数值等于 `0`，标度为 2）
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 判定结果为「小于等于 0」，按 REQ-001 产出错误码 `ER0050`
- **THEN** 判定结果与取值为 `0` 时一致（见 REQ-001-S01），不因存在小数位而被判为大于 `0`

#### Scenario: REQ-003-S02 带尾随零的正值与等值整数判定一致

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `1.0`（数值等于 `1`，标度为 1）
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 判定结果为「大于 0」，按 REQ-002 产出检查结果「通过」
- **THEN** 判定结果与取值为 `1` 时一致，不因标度不同而改变

#### Scenario: REQ-003-S03 判定不使用舍入或精度规整

- **GIVEN** 本步骤在交易执行过程中被调用，tranAmt 取值为 `0.0001`（数值大于 `0`）
- **WHEN** 执行本步骤的交易金额检查
- **THEN** 判定结果为「大于 0」，按 REQ-002 产出检查结果「通过」
- **THEN** 判定直接取入参数值进行数值比较，不对入参做四舍五入或按任何标度规整
- **THEN** 步骤执行前后 tranAmt 的取值与标度保持不变
