# ST007 检查对手账户是否存在

## 目标与范围

本 Spec 定义交易执行步骤「检查对手账户是否存在」（ST007）的输入输出契约与对手账户信息存在性检查行为。步骤接收必填输入对手账号（`othBaseAcctNo`），根据对手账号查询账户信息（对公存款账户主表 RB_BUS_ACCT）获取对手账户信息，检查其存在性：对手账户信息为空时步骤业务失败并返回错误码 ER0081；对手账户信息非空时检查结果为「通过」，步骤正常完成。查询取得的对手账户信息以非必填输出字段 `internalKey`、`baseAcctNo`、`acctStatus` 返回。

范围限于本步骤需求「步骤描述」「输入」「输出」「相关枚举」「补充说明」声明的查询、存在性检查、失败与通过行为。查询目标实体与账号解析路径、「对手账户信息为空」判定口径、`baseAcctNo` 输出来源及必填缺失行为未确认，列入「待确认事项」，不补默认行为。

### 依赖核对

- **名称映射**：requirement-name-mapping 资产确认「账户信息」→ 实体「对公存款账户主表」；「对手账号」「账户状态」未收录属性域映射，本 Spec 按需求原文业务称谓表述，不展开未确认的属性域绑定。
- **实体字段**：对公存款账户主表实体 `RbBusAcctEO` 含 `internalKey`（Integer）、`acctStatus`（类型 `com.dcits.deposit.enums.AcctStatus`）、`clientNo`、`cardNo` 等字段，主键为（clientNo, internalKey）；实体及 DDL（RB_BUS_ACCT.sql）均无账号字段（无 baseAcctNo 列）。输出表声明的 `baseAcctNo`（账号）在该实体中不存在（见待确认事项 TBD-2）。
- **枚举**：`com.dcits.deposit.enums.AcctStatus` 存在于 `deposit-common`，取值/业务含义：A/活动、C/关闭、D/睡眠、H/待激活、I/预开户、N/新建、O/转营业外、P/逾期、R/预销户、S/久悬、U/手工解除；与需求「补充说明」「对应枚举类 com.dcits.deposit.enums.AcctStatus」一致。
- **错误码**：`deposit-application/src/main/resources/errorcodes.properties` 第 81 行已确认 `ER0081=对手账户不存在`。需求「步骤描述」第 2 条将该码绑定于「[对手账户信息]为空」的失败条件，码的业务说明与失败条件语义一致。
- **步骤结果契约**：`com.dcits.common.step.StepResult` 提供 succeed / errorCode / errorMessage。按 step-error-contract，正常完成时 succeed=true 且错误字段为空；业务失败时 succeed=false，errorCode 保存已确认码值 ER0081，errorMessage 采用「ER0081::对手账户不存在」（`错误码::业务说明` 格式）。需求中的检查结果「通过」不单独声明为业务输出字段，由步骤结果成功状态承载。
- **技术约束**：对公存款账户主表（RB_BUS_ACCT）主键为（客户号, 账户内部键值），`RbBusAcctEO` 无账号字段；「根据{对手账号}查询【账户信息】」的账号→账户记录解析路径需求未声明（见 TBD-1）。

## Requirements

### Requirement: REQ-001 按对手账号查询账户信息获取对手账户信息并输出
来源：需求「步骤描述」第 1 条、「输入」表、「输出」表、「相关枚举」及「补充说明」。

系统 SHALL 接收必填输入 `othBaseAcctNo`（`java.lang.String`，对手账号），据此查询账户信息（对公存款账户主表 RB_BUS_ACCT）获取对手账户信息，并将取得的对手账户信息作为非必填输出字段返回：`internalKey`（`java.lang.Integer`，账户内部键值）、`baseAcctNo`（`java.lang.String`，账号）、`acctStatus`（`com.dcits.deposit.enums.AcctStatus`，账户状态），来源实体均为对公存款账户主表（RB_BUS_ACCT）。

#### Scenario: REQ-001-S01 依据有效对手账号查询取得对手账户信息
- **GIVEN** 调用方提供必填输入对手账号 `othBaseAcctNo`（示例值「6228480012345678」），且该账号在对公存款账户主表存在对应账户记录
- **WHEN** 执行本步骤
- **THEN** 系统按该对手账号查询对公存款账户主表取得对手账户信息，并输出非必填字段 `internalKey`（账户内部键值）、`baseAcctNo`（账号）、`acctStatus`（账户状态，取值属于枚举 `com.dcits.deposit.enums.AcctStatus`），来源实体为对公存款账户主表（RB_BUS_ACCT）

### Requirement: REQ-002 对手账户信息为空时业务失败并返回 ER0081
来源：需求「步骤描述」第 2 条（原文：若[对手账户信息]为空，则返回[错误码]“ER0081”）。

当按对手账号查询未取得对手账户信息（对手账户信息为空）时，系统 SHALL 使步骤业务失败并返回错误码 ER0081（已确认错误码，业务说明「对手账户不存在」），errorMessage 采用「ER0081::对手账户不存在」格式，且不继续执行后续步骤。

#### Scenario: REQ-002-S01 对手账户信息为空时步骤失败返回 ER0081
- **GIVEN** 根据对手账号查询对公存款账户主表未取得对手账户信息（对手账户信息为空）
- **WHEN** 执行对手账户信息存在性检查
- **THEN** 步骤结果为失败：succeed=false，errorCode=「ER0081」，errorMessage=「ER0081::对手账户不存在」，且本步骤不继续执行后续步骤

### Requirement: REQ-003 对手账户信息非空时检查通过并正常完成
来源：需求「步骤描述」第 2 条（原文：…否则返回检查结果为“通过”）。

当对手账户信息非空时，系统 SHALL 判定检查结果为「通过」，正常完成本步骤：succeed=true，errorCode 与 errorMessage 为空。

#### Scenario: REQ-003-S01 对手账户信息存在时检查通过
- **GIVEN** 根据对手账号查询对公存款账户主表取得非空的对手账户信息
- **WHEN** 执行对手账户信息存在性检查
- **THEN** 检查结果为「通过」，步骤结果为成功：succeed=true，errorCode 与 errorMessage 为空

## 待确认事项

- **TBD-1（关联 REQ-001）查询目标实体与账号解析路径**：需求称“根据{对手账号}查询【账户信息】”，名称映射将「账户信息」映射为对公存款账户主表（RB_BUS_ACCT），但工程中该表主键为（客户号, 账户内部键值），`RbBusAcctEO` 与 DDL 均无账号字段；“对手账号 → 对公存款账户主表记录”的解析路径需求未声明（如经对公客户账户表 baseAcctNo 定位）。需确认本步骤实际查询目标实体及账号解析口径。
- **TBD-2（关联 REQ-001）输出 baseAcctNo 字段来源**：需求「输出」表声明 `baseAcctNo`（账号）来源实体为对公存款账户主表（RB_BUS_ACCT），但工程中该表实体 `RbBusAcctEO` 与 DDL 均无 `baseAcctNo` 字段；工程中 `baseAcctNo` 字段存在于对公客户账户表（`RbBusClientAcctEO`）及交易流水等实体。需确认 `baseAcctNo` 输出的实际来源实体与取值路径。
- **TBD-3（关联 REQ-001、REQ-002）「对手账户信息为空」判定口径**：需求未定义“对手账户信息为空”的判定标准——指按对手账号查询无匹配记录，还是记录存在但关键字段为空；输出表三个字段均标记非必填，字段空值与记录不存在的语义边界需确认。
- **TBD-4（关联 REQ-001）必填输入缺失行为**：`othBaseAcctNo` 标记为必填，需求未定义其缺失/为空时的行为（是否校验报错、错误码）；「输入」表「来源实体」列为空，对手账号的来源实体未声明。

## 验收范围

验收以 REQ-001~REQ-003 声明的行为为准：在对手账号有效且对公存款账户主表存在对应记录时，验证按对手账号查询取得对手账户信息并输出 `internalKey`、`baseAcctNo`、`acctStatus`（REQ-001-S01）；对手账户信息为空时步骤失败、errorCode=ER0081、errorMessage=「ER0081::对手账户不存在」且不继续执行后续步骤（REQ-002-S01）；对手账户信息非空时检查结果为「通过」、步骤成功（REQ-003-S01）。查询目标实体与账号解析路径（TBD-1）、`baseAcctNo` 输出来源（TBD-2）、「对手账户信息为空」判定口径（TBD-3）、必填缺失行为（TBD-4）不作本 Spec 已确认验收断言，待澄清后补充。
