# BR007 计算到期日期

## 目标与范围

本任务实现存款业务组件中计算类规则「计算到期日期」：以核心运行日期（`runDate`，即规则描述中的「系统日期」）为基准，按期限类型（`periodType`）与期限（`term`）推算到期日期（`maturityDate`）。

范围内：

- 覆盖 `periodType` 六种取值（日 / 月 / 年 / 周 / 季 / 半年）各自对应的到期日期计算方式（规则描述 a～f）。
- 覆盖月类期限（月、季、半年）在「基准日期为月末」或「加月后日期无效」时，将到期日期「日」调整为该月最后一天的调整行为。
- 覆盖年类期限在「基准日期为 2 月 29 日且到期年份不是闰年」时顺延为 2 月 28 日的调整行为。
- 本规则为纯计算规则，无外部实体读写，不涉及账务处理与状态变更。

不在范围内（源需求未定义，详见「验收范围与明确不覆盖的事项」）：

- `periodType` 取值合法性校验、`term` 的可解析性与取值范围校验；
- 日期时间口径（时、分、秒、毫秒及时区）的归一化；
- 到期日期计算之外的业务流程编排与后续处理。

- `BASE`：核心运行日期，即输入 `runDate`，规则描述中的「系统日期」。

- 输入表未声明 `来源实体`，`runDate` / `term` / `periodType` 均为本规则自身的入参，不来自外部实体查询。

## Requirements

### Requirement: REQ-001 按「日」类型计算到期日期

来源：docs/requirements/BR007.md「## 规则描述」a

当 `periodType` 为「日」（`TermType.D`）时，系统 SHALL 以 `runDate` 为基准加上 `term` 天，作为 `maturityDate`。

#### Scenario: REQ-001-S01 「日」类型同月内计算

- **GIVEN** `periodType` = `TermType.D`，`runDate` = 2026-01-05，`term` = "10"
- **WHEN** 执行计算到期日期
- **THEN** `maturityDate` = 2026-01-15

#### Scenario: REQ-001-S02 「日」类型跨月进位

- **GIVEN** `periodType` = `TermType.D`，`runDate` = 2026-01-15，`term` = "30"
- **WHEN** 执行计算到期日期
- **THEN** `maturityDate` = 2026-02-14

### Requirement: REQ-002 按「月」类型计算到期日期

来源：docs/requirements/BR007.md「## 规则描述」b

当 `periodType` 为「月」（`TermType.M`）时，系统 SHALL 以 `runDate` 为基准加上 `term` 个月，作为 `maturityDate` 的年月部分，日期部分默认取 `runDate` 的「日」。

在此基础上，若满足「`runDate` 是其所在月的最后一天（月末）」或「按 `runDate` 的『日』加月后的日期无效（例如 31 日加到只有 28/29 天的 2 月）」中任一条件，系统 SHALL 将 `maturityDate` 的「日」调整为加月后所在月的最后一天。

#### Scenario: REQ-002-S01 「月」类型普通计算

- **GIVEN** `periodType` = `TermType.M`，`runDate` = 2026-01-15，`term` = "3"
- **WHEN** 执行计算到期日期
- **THEN** `maturityDate` = 2026-04-15

#### Scenario: REQ-002-S02 「月」类型基准日期为月末且加月后日期有效

- **GIVEN** `periodType` = `TermType.M`，`runDate` = 2026-02-28（2026 年 2 月为 28 天的月末），`term` = "1"
- **WHEN** 执行计算到期日期
- **THEN** 加月后所在月为 2026 年 3 月，`runDate` 为月末，故 `maturityDate` = 2026-03-31

#### Scenario: REQ-002-S03 「月」类型加月后日期无效

- **GIVEN** `periodType` = `TermType.M`，`runDate` = 2026-08-31，`term` = "6"
- **WHEN** 执行计算到期日期
- **THEN** 加月后所在月为 2027 年 2 月，其「31 日」无效，故 `maturityDate` = 2027-02-28（2027 年非闰年）

#### Scenario: REQ-002-S04 「月」类型加月后落入闰年 2 月

- **GIVEN** `periodType` = `TermType.M`，`runDate` = 2024-01-31，`term` = "1"
- **WHEN** 执行计算到期日期
- **THEN** 加月后所在月为 2024 年 2 月，其「31 日」无效，故 `maturityDate` = 2024-02-29（2024 年为闰年）

### Requirement: REQ-003 按「年」类型计算到期日期

来源：docs/requirements/BR007.md「## 规则描述」c

当 `periodType` 为「年」（`TermType.Y`）时，系统 SHALL 以 `runDate` 为基准加上 `term` 年，保持月、日不变，作为 `maturityDate`。

在此基础上，若 `runDate` 为 2 月 29 日且加年后的到期年份不是闰年，系统 SHALL 将 `maturityDate` 调整为该年的 2 月 28 日。若到期年份是闰年，则不作此调整。

#### Scenario: REQ-003-S01 「年」类型普通计算

- **GIVEN** `periodType` = `TermType.Y`，`runDate` = 2026-03-15，`term` = "2"
- **WHEN** 执行计算到期日期
- **THEN** `maturityDate` = 2028-03-15

#### Scenario: REQ-003-S02 基准日期为 2 月 29 日且到期年份非闰年

- **GIVEN** `periodType` = `TermType.Y`，`runDate` = 2024-02-29，`term` = "1"
- **WHEN** 执行计算到期日期
- **THEN** 到期年份 2025 年不是闰年，2 月 29 日无效，故 `maturityDate` = 2025-02-28

#### Scenario: REQ-003-S03 基准日期为 2 月 29 日且到期年份为闰年

- **GIVEN** `periodType` = `TermType.Y`，`runDate` = 2024-02-29，`term` = "4"
- **WHEN** 执行计算到期日期
- **THEN** 到期年份 2028 年是闰年，不触发调整，`maturityDate` = 2028-02-29

### Requirement: REQ-004 按「周」类型计算到期日期

## 验收范围与明确不覆盖的事项

本 Spec 的验收范围为上表列出的 6 条需求、17 个场景，覆盖六种期限类型的计算分支，以及月类期限的月末/无效日调整、年类期限的 2 月 29 日调整等分支与边界。

明确不覆盖（源需求未定义，不作为本期验收依据）：

1. `term` 的字符串格式与非数字内容：源需求将 `term` 声明为 `java.lang.String`，但未规定其格式及非法值的处理，本 Spec 不对非法 `term` 的行为作断言。
2. `term` 为零或负数：规则描述只给出 `BASE + TERM×单位` 的计算式，未规定 0 或负期限的期望结果，本 Spec 不作断言。
3. `periodType` 为空或不在 `TermType` 取值集合内：源需求未规定该情形的行为，本 Spec 不作断言。
4. `periodType` 与 `term` 的取值组合约束（例如是否允许「日」配大额期限）：源需求未规定，本 Spec 不作断言。
5. 日期时间口径：`runDate` 与 `maturityDate` 均为 `java.util.Date`，源需求未规定时、分、秒、毫秒及时区在计算中的保留或归一化方式，本 Spec 不作断言。
6. 数值舍入与精度：本规则为日期计算，不涉及金额与比例，舍入与精度要求不适用。
7. `maturityDate` 在源需求中标记为「非必填」，本 Spec 按该标记记录其必填性，不据此推导新的业务规则。
8. 本规则之外的业务流程编排、账务处理、状态变更及外部实体读写：不在本任务范围内。
9. 关联 Spec：本任务无已合并的上游/下游 Spec 依赖，不涉及跨 Spec 编排与失败传播。
