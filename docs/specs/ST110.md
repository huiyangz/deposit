# ST110 更新累计限额

## 目标与范围

本任务为交易执行步骤类（条件触发的更新类步骤，单条编排、无业务失败分支）。源需求「## 步骤描述」给出唯一动作：在触发条件成立时，以 {账号} 作为限额检查对象值，连同 {限额场景编码} 定位【限额累计信息表】的记录，并写回累计限额与限额累计笔数两列；匹配不到记录时不更新本表且步骤正常结束。

**目标**：以 ST110 的已确认业务定义为依据，整理可验证的行为 Spec，使测试设计、实现与审核共用同一份触发条件、定位—写入契约与结束契约。

本次 Spec 覆盖：

- 输入契约：六个输入的字段名、类型、必填性与来源实体照录；占位符 {账号} 与 {限额场景编码} 的绑定。
- 触发条件：`限额检查结果` 等于「未超限」且（`limitSumAmt` 大于 0 或 `limitSumNum` 大于 0），含「或者」的两支与等于 0 的边界。
- 定位契约：以 {账号}（入参 `baseAcctNo`）作为限额检查对象值，连同 {限额场景编码}（入参 `limitSceneNo`）定位【限额累计信息表】的记录。
- 写入契约：把定位到记录的 $累计限额$ 更新为 `limitSumAmt`、$限额累计笔数$ 更新为 `limitSumNum`；写入字段范围仅此两列，不新增或删除记录。
- 未命中契约：匹配不到记录时不更新本表、步骤正常结束。
- 输出契约：`limitSumAmt`（`java.math.BigDecimal`，非必填，来源实体 限额累计信息表（RB_LIMIT_SUM_INFO））的声明与取值口径。
- 失败契约：本步骤无业务失败场景，失败仅由技术异常传播表达。

不在本次范围（源需求未涉及或未定义，本 Spec 不作要求）：

- `限额检查结果` 除字面值「未超限」以外的取值集合（该事项已按需求处理流程放行，见「## 验收范围与明确不覆盖的事项」第 1 项）。
- 任一必填输入取空（未上送、`null`）时的行为（源需求未定义，第 2 项）。
- 入参 `clientNo` 在本步骤中的用途（源需求「## 步骤描述」未使用该字段，第 3 项）。
- 【限额累计信息表】绑定到哪张表、哪个接口的技术口径，以及更新实现方式（是否先查后改、是否 selective、影响行数判定）、事务边界、并发与幂等（第 4 项）。
- 触发本步骤的上游编排与更新后的下游影响（登记流水、通知、额度控制等），源需求未描述（第 8 项）。
- 技术异常的传播形式、回滚口径与错误信息文本（源需求「## 失败处理」只声明由技术异常传播表达，第 7 项）。

- **GIVEN** 调用方按「## 输入」表提供六个输入：`限额检查结果` = `"未超限"`（示例值）、`baseAcctNo` = `"1100602112345678"`（示例账号值，非规范常量）、`limitSceneNo` = `"LSN0001"`（示例值）、`clientNo` = `"C0000001234"`（示例值）、`limitSumAmt` = `1000.00`（示例值）、`limitSumNum` = `5`（示例值），六者标记均为「必填」
- **WHEN** 调用本步骤
- **THEN** 步骤以该字段名、类型与「必填」标记接收六个输入：`限额检查结果` 按源需求原文的字段名接收，`baseAcctNo`／`limitSceneNo`／`clientNo` 的类型为 `java.lang.String`，`limitSumAmt` 为 `java.math.BigDecimal`，`limitSumNum` 为 `java.lang.Integer`
- **THEN** 各输入的「来源实体」列照录源需求：`baseAcctNo`＝对公存款账户限制表（RB_BUS_RESTRAINTS）；`limitSceneNo`／`clientNo`／`limitSumAmt`／`limitSumNum`＝限额累计信息表（RB_LIMIT_SUM_INFO）；`限额检查结果` 为空

#### Scenario: REQ-001-S02 {账号}／{限额场景编码} 的占位符绑定

- **GIVEN** 入参 `baseAcctNo` = `"1100602112345679"`（示例值）、`limitSceneNo` = `"LSN0002"`（示例值）
- **WHEN** 本步骤按源需求第 5 行执行「以{账号}作为限额检查对象值，连同{限额场景编码}定位…」
- **THEN** {账号} 取值为 `"1100602112345679"`、{限额场景编码} 取值为 `"LSN0002"`，二者分别绑定到 `baseAcctNo` 与 `limitSceneNo`；不引入其它字段作为该两个占位符的来源

#### Scenario: REQ-001-S03 不因来源实体列新增对限制表的读取

- **GIVEN** 源需求「## 输入」表把 `baseAcctNo` 的来源实体标为「对公存款账户限制表（RB_BUS_RESTRAINTS）」，而「## 步骤描述」只描述对【限额累计信息表】的定位与更新
- **WHEN** 调用本步骤执行
- **THEN** 本步骤只按 REQ-002 判定触发条件、按 REQ-003 定位并更新【限额累计信息表】；不查询、不校验「对公存款账户限制表（RB_BUS_RESTRAINTS）」，也不因该列示要求调用方补送其它入参

### Requirement: REQ-002 触发条件：限额检查结果为「未超限」且累计金额或累计笔数大于 0

来源：`docs/requirements/ST110.md`「## 步骤描述」1（第 5 行）前半 —— 原文：「若[限额检查结果]为“未超限”，且[限额累计金额]大于0或者[限额累计笔数]大于0」。

系统 SHALL 仅在同时满足下列两个条件时执行 REQ-003 的定位与更新，两个条件 MUST 同时成立：

- **(a) 检查结果条件**：`限额检查结果` 等于字面值「未超限」；
- **(b) 数值条件**：`limitSumAmt` 大于 0 **或者** `limitSumNum` 大于 0（两者满足其一即可）。

「大于 0」的比较 MUST 为严格大于：`limitSumAmt` 等于 0 不满足，`limitSumNum` 等于 0 不满足。条件不成立时，系统 MUST NOT 发起 REQ-003 的定位或写入（MUST NOT 修改【限额累计信息表】的数据，MUST NOT 新增或删除记录），本步骤 MUST 正常结束（按「### 承载口径」：`succeed = true` 且 `errorCode` 为空），MUST NOT 返回业务错误码。

#### Scenario: REQ-002-S01 检查结果为「未超限」且累计金额大于 0（累计笔数为 0）

- **GIVEN** `限额检查结果` = `"未超限"`，`limitSumAmt` = `1000.00`（大于 0）、`limitSumNum` = `0`
- **WHEN** 调用本步骤
- **THEN** 条件 (a) 成立、条件 (b) 因 `limitSumAmt` 大于 0 而成立，系统执行 REQ-003 的定位与更新（该情形覆盖「或者」的左支）

#### Scenario: REQ-002-S02 检查结果为「未超限」且累计笔数大于 0（累计金额为 0）

- **GIVEN** `限额检查结果` = `"未超限"`，`limitSumAmt` = `0.00`、`limitSumNum` = `3`（大于 0）
- **WHEN** 调用本步骤
- **THEN** 条件 (a) 成立、条件 (b) 因 `limitSumNum` 大于 0 而成立，系统执行 REQ-003 的定位与更新（该情形覆盖「或者」的右支）

#### Scenario: REQ-002-S03 检查结果为「未超限」且累计金额与累计笔数均大于 0

- **GIVEN** `限额检查结果` = `"未超限"`，`limitSumAmt` = `2500.50`、`limitSumNum` = `7`（两者均大于 0）
- **WHEN** 调用本步骤
- **THEN** 条件 (a)、(b) 均成立，系统执行 REQ-003 的定位与更新；两者同时大于 0 不改变触发结论，也不改变 REQ-003 的写入取值

#### Scenario: REQ-002-S04 检查结果不等于「未超限」时不触发更新

- **GIVEN** `限额检查结果` = `X`（X 为不等于 `"未超限"` 的任一取值，其具体取值形式源需求未定义，见不覆盖第 1 项），`limitSumAmt` = `1000.00`、`limitSumNum` = `5`（两者均大于 0）
- **WHEN** 调用本步骤
- **THEN** 条件 (a) 不成立，系统 MUST NOT 定位或更新【限额累计信息表】，MUST NOT 新增或删除记录
- **THEN** 本步骤正常结束（`succeed = true` 且 `errorCode` 为空），不返回业务错误码、不抛出业务异常

#### Scenario: REQ-002-S05 检查结果为「未超限」但两个数值均等于 0（边界）

- **GIVEN** `限额检查结果` = `"未超限"`，`limitSumAmt` = `0.00`、`limitSumNum` = `0`
- **WHEN** 调用本步骤
- **THEN** 条件 (a) 成立但条件 (b) 不成立（「大于 0」为严格大于，取值等于 0 不满足），系统 MUST NOT 定位或更新【限额累计信息表】
- **THEN** 本步骤正常结束（`succeed = true` 且 `errorCode` 为空），不返回业务错误码

### Requirement: REQ-003 以账号作为限额检查对象值连同限额场景编码定位并写回两列

来源：`docs/requirements/ST110.md`「## 步骤描述」1（第 5 行）后半 —— 原文：「则以{账号}作为限额检查对象值，连同{限额场景编码}定位【限额累计信息表】的记录，将该记录的$累计限额$更新为[限额累计金额]、$限额累计笔数$更新为[限额累计笔数]」。

在 REQ-002 触发条件成立时，系统 SHALL 以 {账号}（取自入参 `baseAcctNo`）作为限额检查对象值，连同 {限额场景编码}（取自入参 `limitSceneNo`）定位【限额累计信息表 `RB_LIMIT_SUM_INFO`】中同时满足「限额检查对象值 = `baseAcctNo`」与「限额场景编码 = `limitSceneNo`」的记录，并把该记录的 $累计限额$（限额累计金额）写入为入参 `limitSumAmt`、$限额累计笔数$ 写入为入参 `limitSumNum`。定位条件 MUST 为上述两键的合取；系统 MUST NOT 以 `clientNo` 或其它字段作为定位条件。两列的写入取值 MUST 分别等于本次入参 `limitSumAmt`、`limitSumNum`，MUST NOT 取自被更新记录的原值或其它来源。写入字段范围 MUST 仅为这两列：系统 MUST NOT 因本次更新修改定位到的记录中这两列以外的字段，MUST NOT 新增记录、MUST NOT 删除记录；两列 MUST 均被写回，MUST NOT 只写其中一列。

#### Scenario: REQ-003-S01 命中记录并写回两列

- **GIVEN** REQ-002 触发条件成立；入参 `baseAcctNo` = `"1100602112345678"`、`limitSceneNo` = `"LSN0001"`、`limitSumAmt` = `1000.00`、`limitSumNum` = `5`（示例值）；【限额累计信息表】中存在限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0001"` 的记录，其 $累计限额$ 原为 `300.00`、$限额累计笔数$ 原为 `2`（示例值），该记录其它字段为已给定值
- **WHEN** 执行本步骤
- **THEN** 该记录的 $累计限额$ 被写入为 `1000.00`、$限额累计笔数$ 被写入为 `5`，二者分别等于本次入参 `limitSumAmt`、`limitSumNum`
- **THEN** 该记录这两列以外的字段保持执行前的取值；不新增记录、不删除记录；不返回业务错误码（REQ-006）

#### Scenario: REQ-003-S02 定位条件为限额检查对象值与限额场景编码的合取

- **GIVEN** REQ-002 触发条件成立；入参 `baseAcctNo` = `"1100602112345678"`、`limitSceneNo` = `"LSN0001"`；【限额累计信息表】中同时存在：记录 α（限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0001"`）、记录 β（限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0009"`）、记录 γ（限额检查对象值 = `"1100602112345677"`、限额场景编码 = `"LSN0001"`）（均为示例值）
- **WHEN** 执行本步骤
- **THEN** 只有记录 α 被写入（$累计限额$ = `limitSumAmt`、$限额累计笔数$ = `limitSumNum`）；仅匹配限额检查对象值的记录 β 与仅匹配限额场景编码的记录 γ MUST NOT 被修改
- **THEN** 定位条件不含 `clientNo` 等其它字段，也不以 `baseAcctNo`、`limitSceneNo` 之外的字段扩大或缩小命中范围

#### Scenario: REQ-003-S03 写入取值等于本次入参而不依赖被更新记录的原值

- **GIVEN** 分别处于两种数据状态：**状态 A** 命中记录的 $累计限额$ 原为 `0.00`、$限额累计笔数$ 原为 `0`；**状态 B** 命中记录的 $累计限额$ 原为 `1000.00`、$限额累计笔数$ 原为 `5`（与本次入参同值）（均为示例值）
- **WHEN** 在两种状态下分别以相同的入参 `limitSumAmt` = `1000.00`、`limitSumNum` = `5` 执行本步骤
- **THEN** 两种状态下该记录的 $累计限额$ 均为 `1000.00`、$限额累计笔数$ 均为 `5`，与各自的执行前原值无关；写入取值不因原值等于目标值而改写为其它取值

### Requirement: REQ-004 匹配不到记录时不更新本表且步骤正常结束

来源：`docs/requirements/ST110.md`「## 步骤描述」1（第 5 行）末句 —— 原文：「匹配不到该记录时不更新本表，步骤正常结束」。

在 REQ-002 触发条件成立、但按「限额检查对象值 = `baseAcctNo` 且限额场景编码 = `limitSceneNo`」在【限额累计信息表】中匹配不到记录时，系统 MUST NOT 更新该表、MUST NOT 新增记录、MUST NOT 删除记录，本步骤 MUST 正常结束（按「### 承载口径」：`succeed = true` 且 `errorCode` 为空）。该情形 MUST NOT 被判定为业务失败，MUST NOT 返回业务错误码、MUST NOT 抛出业务异常，也 MUST NOT 改以其它条件重新定位。

#### Scenario: REQ-004-S01 无匹配记录时不更新且正常结束

- **GIVEN** REQ-002 触发条件成立（如 `限额检查结果` = `"未超限"`、`limitSumAmt` = `1000.00`）；入参 `baseAcctNo` = `"1100609999999999"`、`limitSceneNo` = `"LSN0001"`（示例值）；【限额累计信息表】中不存在限额检查对象值 = `"1100609999999999"` 且限额场景编码 = `"LSN0001"` 的记录
- **WHEN** 执行本步骤
- **THEN** 【限额累计信息表】不发生任何数据变更（不更新、不新增、不删除记录），其它记录的取值保持执行前状态
- **THEN** 本步骤正常结束（`succeed = true` 且 `errorCode` 为空）；不返回业务错误码、不抛出异常，也不因未匹配到记录而改以其它条件重新定位

#### Scenario: REQ-004-S02 触发条件不成立与匹配不到记录两种情形同样正常结束

- **GIVEN** **情形 1**：REQ-002 触发条件不成立（如 `限额检查结果` ≠ `"未超限"`）；**情形 2**：REQ-002 触发条件成立但按两键匹配不到记录
- **WHEN** 分别在两种情形下执行本步骤
- **THEN** 两种情形下本步骤均正常结束（`succeed = true` 且 `errorCode` 为空），均不修改【限额累计信息表】的数据
- **THEN** 两种情形的差别仅在于是否发起按两键的定位（情形 2 发起且未命中，情形 1 不发起），对步骤结果与数据状态的影响一致

### Requirement: REQ-005 输出 limitSumAmt 承载本次写入的限额累计金额

来源：`docs/requirements/ST110.md`「## 输出」表（第 21–23 行，`limitSumAmt` 第 23 行）。

系统 SHALL 以 `limitSumAmt`（类型 `java.math.BigDecimal`，非必填，限额累计金额，来源实体 限额累计信息表（RB_LIMIT_SUM_INFO））作为本步骤的输出，其字段名、类型与「非必填」标记 MUST 照录源需求「## 输出」表。在 REQ-003 的更新完成后，该输出的取值 SHALL 为本次写入的限额累计金额（与入参 `limitSumAmt` 同值），与【限额累计信息表】中该记录更新后的限额累计金额为同一取值；系统 MUST NOT 在该路径为该输出赋予本次写入值以外的取值。

#### Scenario: REQ-005-S01 更新成功后输出的限额累计金额等于本次写入值

- **GIVEN** REQ-002 触发条件成立；命中记录的 $累计限额$ 原为 `300.00`（示例值）；入参 `limitSumAmt` = `1000.00`
- **WHEN** 执行本步骤并完成更新，随后读取本步骤输出 `limitSumAmt`
- **THEN** 输出 `limitSumAmt` = `1000.00`，与库中该记录更新后的限额累计金额取值一致
- **THEN** 输出取值不是原值 `300.00`，也不是本次写入值以外的其它金额；输出字段名、类型 `java.math.BigDecimal` 与「非必填」标记按源需求照录

#### Scenario: REQ-005-S02 「非必填」标记照录，未定义路径取值不作断言

- **GIVEN** 源需求「## 输出」表把 `limitSumAmt` 标为「非必填」
- **WHEN** 分别处于「更新成功」（REQ-003）、「触发条件不成立」（REQ-002-S04／REQ-002-S05）、「匹配不到记录」（REQ-004）三种情形，读取本步骤输出 `limitSumAmt`
- **THEN** 更新成功情形下该输出取值为本次写入的限额累计金额（REQ-005-S01）
- **THEN** 「非必填」标记按源需求照录，本 Spec 不据此断言未触发更新或未命中记录情形下该输出是否出现及其取值（该取值源需求未定义，见不覆盖第 5 项）

### Requirement: REQ-006 无业务失败场景，失败仅由技术异常传播表达

来源：`docs/requirements/ST110.md`「## 失败处理」（第 27 行）—— 原文：「本步骤无业务失败场景，失败仅由技术异常传播表达。」

系统 SHALL 把本步骤的失败范围限定为技术异常：本步骤 MUST NOT 返回任何业务错误码，MUST NOT 把「触发条件不成立」（REQ-002-S04、REQ-002-S05）「匹配不到记录」（REQ-004）等业务情形判定为失败——二者均正常结束。除正常结束外，本步骤 MUST NOT 产生其它业务结论。定位或写入【限额累计信息表】的调用本身发生技术异常（抛出异常、超时、依赖不可用、数据访问失败）时，该失败 MUST NOT 被本步骤转换为业务错误码或业务失败结论，仅由技术异常按框架传播表达；本步骤 MUST NOT 为其设置捕获、重试或降级行为（源需求未要求）。

#### Scenario: REQ-006-S01 成功与正常结束路径均不返回业务错误码

- **GIVEN** 分别处于「触发条件成立且命中记录」（REQ-003-S01）、「触发条件不成立」（REQ-002-S04）、「匹配不到记录」（REQ-004-S01）三种情形
- **WHEN** 任一情形下执行本步骤并返回结论
- **THEN** 步骤结果均为 `succeed = true` 且 `errorCode` 为空（`null`），不存在业务错误码取值
- **THEN** 「未超限」以外的检查结果与「匹配不到记录」均不被表达为失败

#### Scenario: REQ-006-S02 数据访问技术异常不由本步骤转换为业务结果

- **GIVEN** 定位或写入【限额累计信息表】的数据访问调用发生技术异常（如依赖不可用、超时）
- **WHEN** 执行本步骤
- **THEN** 该失败由技术异常按框架传播表达，MUST NOT 被转换为业务错误码或业务失败结论，MUST NOT 被吞掉后以正常结束返回
- **THEN** 源需求未要求捕获、重试或降级，本步骤 MUST NOT 设置相应处理；`errorMessage` 的取值源需求未要求，不作断言
