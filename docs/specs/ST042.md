# ST042 获取累计限额

## 目标与范围

本任务将正式需求中「获取累计限额」交易执行步骤整理为可验证的 Spec。步骤以必填输入限额场景编码（limitSceneNo）与账号（baseAcctNo）为查询条件，查询限额累计信息表（RB_LIMIT_SUM_INFO），获取并输出该记录的限额累计金额（limitSumAmt）与限额累计笔数，同时输出客户号（clientNo）与限额场景编码（limitSceneNo）。

范围限于 ST042 需求文档「步骤描述」「输入」「输出」表声明的查询行为与输入输出契约。需求未定义的查询无匹配记录、必填输入缺失等行为记录为待确认事项，不补默认行为。

- 实体核对（deposit-infrastructure）：
  - `RbLimitSumInfoEO` / `RbLimitSumInfo` 字段与需求对应：`checkObjVal`（限额检查对象值）、`limitSceneNo`（限额场景编码）、`limitSumAmt`（限额累计金额，BigDecimal）、`否`（限额累计笔数，Integer）、`clientNo`（客户号）；其中 `checkObjVal`、`clientNo`、`limitSceneNo` 标有 `@NotNull`；
  - 物理表 RB_LIMIT_SUM_INFO 主键为（CHECK_OBJ_VAL, LIMIT_SCENE_NO）；LIMIT_SUM_AMT 为 DECIMAL(38,2)、`否` 为 INT，两列可空；CLIENT_NO 为 VARCHAR(22) 非空；

  - 业务输出与响应头（RespHeader）分离；需求未定义本步骤跳转或继续条件，本 Spec 不声明流转；
  - 需求未声明本步骤的业务失败条件及错误码，未确认前不新增失败场景、不编造错误码。

## Requirements

### Requirement: REQ-001 步骤输入契约

来源：需求文档「输入」表（原文：字段名 baseAcctNo、clientNo、limitSceneNo，标记均为必填，类型 java.lang.String）

系统 SHALL 以三个必填输入执行本步骤：`baseAcctNo`（账号，来源实体对公存款账户限制表（RB_BUS_RESTRAINTS））、`clientNo`（客户号，来源实体限额累计信息表（RB_LIMIT_SUM_INFO））、`limitSceneNo`（限额场景编码，来源实体限额累计信息表（RB_LIMIT_SUM_INFO）），三者类型均为 `java.lang.String`。

#### Scenario: REQ-001-S01 三个必填输入齐备时正常执行查询

- **GIVEN** 调用方提供 `baseAcctNo=「6001010001000001」`、`clientNo=「CL0000001」`、`limitSceneNo=「S001」`
- **WHEN** 执行获取累计限额步骤
- **THEN** 步骤以 `limitSceneNo` 与 `baseAcctNo` 为查询条件对限额累计信息表（RB_LIMIT_SUM_INFO）发起查询，并以成功状态结束（`succeed=true`，`errorCode`、`errorMessage` 为空），不因输入齐备产生额外业务错误

### Requirement: REQ-002 按限额场景编码及账号查询限额累计信息表，获取累计金额与笔数

来源：需求文档「步骤描述」（原文：根据[限额场景编码]以及{账号}查询【限额累计表】获取其对应的$限额累计金额$，$限额累计笔数$）

系统 SHALL 使用必填输入 `limitSceneNo`（限额场景编码）与 `baseAcctNo`（账号）作为查询条件查询限额累计信息表（RB_LIMIT_SUM_INFO）；当存在匹配记录时，获取该记录的限额累计金额（limitSumAmt）与限额累计笔数。

#### Scenario: REQ-002-S01 存在匹配记录时返回限额累计金额与限额累计笔数

- **GIVEN** 限额累计信息表（RB_LIMIT_SUM_INFO）存在与查询条件（`limitSceneNo=「S001」`、`baseAcctNo=「6001010001000001」`）匹配的记录，该记录的限额累计金额为 `1000.00`、限额累计笔数为 `5`
- **WHEN** 以 `limitSceneNo=「S001」`、`baseAcctNo=「6001010001000001」` 执行获取累计限额步骤
- **THEN** 步骤成功结束（`succeed=true`，`errorCode`、`errorMessage` 为空），输出限额累计金额 `limitSumAmt=1000.00`、限额累计笔数 `5`

### Requirement: REQ-003 输出契约

来源：需求文档「输出」表（原文：clientNo、limitSceneNo、limitSumAmt、否，标记均为非必填）

系统 SHALL 在查询命中记录时输出以下非必填字段，取值取自命中记录的对应列：`clientNo`（`java.lang.String`，客户号）、`limitSceneNo`（`java.lang.String`，限额场景编码）、`limitSumAmt`（`java.math.BigDecimal`，限额累计金额）、限额累计笔数（`java.lang.Integer`，字段名 `否`）；命中记录对应列为空时，相应输出为空。

#### Scenario: REQ-003-S01 命中记录时输出字段与记录对应列一致

- **GIVEN** 查询命中记录，其 `clientNo=「CL0000001」`、`limitSceneNo=「S001」`、`limitSumAmt=1000.00`、限额累计笔数 `5`
- **WHEN** 查询成功返回
- **THEN** 输出 `clientNo=「CL0000001」`、`limitSceneNo=「S001」`、`limitSumAmt=1000.00`、限额累计笔数 `5`

#### Scenario: REQ-003-S02 记录对应列为空时相应输出为空

- **GIVEN** 查询命中记录，其限额累计金额（`limitSumAmt`）为空、限额累计笔数（`否`）为空
- **WHEN** 查询成功返回
- **THEN** 输出 `limitSumAmt` 与限额累计笔数为空，`clientNo`、`limitSceneNo` 取命中记录对应值，步骤仍以成功状态结束

## 待确认事项

1. **「账号」的查询字段映射与客户号的作用**（关联 REQ-001、REQ-002）：需求以「{账号}」作为查询条件之一，未声明其对应限额累计信息表（RB_LIMIT_SUM_INFO）的哪个字段。工程上该表主键为（限额检查对象值 CHECK_OBJ_VAL, 限额场景编码 LIMIT_SCENE_NO），仅有「限额检查对象值」（checkObjVal）可承载账号；且限额场景定义（`RbLimitSceneDefEO`）含「检查对象类型」（`CheckObjType`：ACCT/CARD/CDGROUP/CUST），检查对象为客户级（CUST）时查询条件可能应为客户号而非账号。需确认：账号是否直接作为 checkObjVal 参与查询；必填输入 `clientNo` 在本步中是查询条件、校验依据还是仅透传输出；检查对象类型为 CUST 时是否改以 `clientNo` 查询。
2. **「限额累计笔数」字段名「否」**（关联 REQ-002、REQ-003）：需求输出表与工程实体/EO/DDL 中该字段名均为「否」（`java.lang.Integer`，业务说明「限额累计笔数」），疑为源文档录入或转换产生的非规范名称。需确认该字段的规范命名（如 limitSumCnt）；确认前沿用需求及工程现有名称「否」，业务含义为限额累计笔数。
3. **无匹配记录时的行为**（关联 REQ-002、REQ-003）：按 `limitSceneNo` 与 `baseAcctNo` 查询无匹配记录时，需求未定义行为（如按限额累计金额/笔数为 0 处理并继续，或返回业务错误及对应错误码）。需确认预期结果；确认前不写入已确认条款或验收断言，不生成临时错误码。
4. **必填输入缺失时的行为**（关联 REQ-001）：`baseAcctNo`、`clientNo`、`limitSceneNo` 标记为必填，需求未定义任一输入缺失或为空时的处理（是否校验报错、错误码及失败结果）。需确认。
