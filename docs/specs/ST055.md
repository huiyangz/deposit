# ST055 检查机构币种交易权限

## 目标与范围

**目标**：定义存款业务组件「检查机构币种交易权限」步骤（交易执行步骤）的行为契约：以交易机构与交易币种两个输入，按交易机构查询【机构币种信息】得到 [机构币种列表]，判断交易币种是否属于该列表；属于时返回检查结果“通过”，不属于时返回错误码“ER0047”。本 Spec 供测试设计、实现与审核共同使用。

**范围内**：

- 两个输入的字段契约：字段名、类型、必填性、取值域与枚举绑定。
- [机构币种列表] 的获取口径：以交易机构为查询条件查询【机构币种信息】，取匹配记录的币种构成列表。
- 成员判定口径：判断 {交易币种} 是否在 [机构币种列表] 范围内。
- 两条结果路径的可观察结果：属于 → 检查结果“通过”；不属于（含列表为空）→ 错误码“ER0047”。
- 结果的完备性与互斥：任一输入组合恰得两种结果之一。
- 「## 输出」表声明的输出字段 `ccy` 的字段契约（字段名、类型、必填性）照录。

**不在范围内**（源需求未要求，本 Spec 不定义、不验收）：

- 不定义【机构币种信息】的维护（新增、修改、删除、启停）及其配置业务规则：本步骤对该数据只读，不写入。
- 不定义交易机构、币种的主数据定义与枚举取值扩展。
- 不定义其他币种／权限类检查：账户币种是否在产品配置范围内、转账双方账户币种一致性、通兑机构是否支持该币种、账户属性与账户状态检查等均非本步骤内容。
- 不定义 `ccy` 输出的产生条件、取值与用途：源需求正文未给出该字段的产生规则（见「## 验收范围与明确不覆盖的事项」第 1 项）。
- 不定义输入为空（`null`）或缺失时的处理：源需求未规定。
- 不定义本步骤被交易或其他步骤调用时的编排、条件跳转、事务边界与回滚：源需求未涉及。
- 不定义结果的持久化、日志、监控、幂等、并发与性能要求。

## Requirements

### Requirement: REQ-001 输入契约与枚举绑定

来源：`docs/requirements/ST055.md`「## 输入」表（第 10–13 行）、「## 相关枚举」表（第 23–26 行）、「## 补充说明」（第 30–31 行）

系统 SHALL 以两个输入执行检查：`tranBranch`（类型 `com.dcits.depsit.enums.TranBranch`，必填，交易机构号）与 `tranCcy`（类型 `com.dcits.depsit.enums.Ccy`，必填，交易币种），并 MUST 按该顺序接收。`tranBranch` 的取值 MUST 为 `TranBranch` 的成员（内部机构编号代码），`tranCcy` 的取值 MUST 为 `Ccy` 的成员（AUD、CAD、CHF、CNY、EUR、GBP、HKD、JPY、KRW、RUB、SGD、USD）。系统 MUST NOT 使用这两个输入之外的输入，MUST NOT 因「来源实体」列为空而要求调用方额外提供机构币种数据，也 MUST NOT 因别名书写而从其他字段重复取数。

#### Scenario: REQ-001-S01 两个输入按契约传入并完成检查

- **GIVEN** 调用方按「## 输入」表准备 `tranBranch` = `TranBranch.VALUE_351155`（机构号 `"351155"`），`tranCcy` = `Ccy.CNY`
- **WHEN** 调用本步骤执行检查
- **THEN** 步骤以该组输入完成检查并给出结果（结果取决于该机构在【机构币种信息】中的币种配置），且除「### 依赖契约」声明的机构币种信息只读查询外，不读取其他数据、不调用其他业务组件

#### Scenario: REQ-001-S02 输入取值绑定到各自枚举类且别名不产生额外输入

- **GIVEN** 「## 相关枚举」将{交易机构号, 输入数据-交易机构号}绑定为 `com.dcits.depsit.enums.TranBranch`，将{交易币种, 输入数据-交易币种}绑定为 `com.dcits.depsit.enums.Ccy`
- **WHEN** 分别按两个枚举的成员传入（示例 `tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` = `Ccy.USD`）
- **THEN** 步骤按绑定类型接收这两个输入并参与判定；同一别名组内的写法（如「交易机构号」与「输入数据-交易机构号」）指向同一字段，不产生第三个输入，也不按别名到别处取值

### Requirement: REQ-002 按交易机构查询【机构币种信息】获取 [机构币种列表]

来源：`docs/requirements/ST055.md`「## 步骤描述」条目 1（第 5 行）—— 原文：「1.获取机构币种列表：根据{交易机构}查询【机构币种信息】获取[机构币种列表]」

系统 SHALL 以 `tranBranch`（{交易机构}）作为查询条件查询【机构币种信息】（实体表 `FM_BRANCH_CCY`，归属机构号 `branch`），并将匹配记录的币种（`ccy`）构成 [机构币种列表] 供后续成员判定使用。查询条件 MUST 为归属机构号 = `tranBranch`，MUST NOT 附加或替换为币种条件（否则会把待检查的币种当作查询条件，使成员判定失去意义）。该查询 MUST 为只读，MUST NOT 新增、修改或删除机构币种记录。同一交易机构存在多条机构币种记录时，[机构币种列表] MUST 含全部匹配记录的币种。

#### Scenario: REQ-002-S01 按交易机构取回其币种列表

- **GIVEN** 【机构币种信息】中归属机构号 `"351155"` 配有以下币种记录：CNY、USD、HKD（共 3 条）；输入 `tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` = `Ccy.USD`
- **WHEN** 调用本步骤执行检查
- **THEN** 步骤以归属机构号 = `"351155"` 查询【机构币种信息】，得到含 CNY、USD、HKD 三个币种的 [机构币种列表]；查询条件不含币种；除该只读查询外不写库、不修改机构币种记录

#### Scenario: REQ-002-S02 列表内容不随待检查的币种变化

- **GIVEN** 机构 `"351155"` 的机构币种记录为 CNY、USD 两条
- **WHEN** 分别以 `tranCcy` = `Ccy.CNY` 与 `tranCcy` = `Ccy.USD`（其余输入相同，`tranBranch` = `TranBranch.VALUE_351155`）调用本步骤执行检查
- **THEN** 两次检查取回的 [机构币种列表] 相同（均含 CNY、USD）；列表内容由查询条件 `tranBranch` 决定，不因 `tranCcy` 不同而被过滤或裁剪

### Requirement: REQ-003 交易币种在 [机构币种列表] 范围内时返回检查结果“通过”

来源：`docs/requirements/ST055.md`「## 步骤描述」条目 2（第 6 行）—— 原文：「2.检查账户币种：若{交易币种}在[机构币种列表]范围内，则返回检查结果为“通过”，否则返回[错误码]“ER0047”。」

系统 SHALL 在 `tranCcy` 在 [机构币种列表] 范围内（即【机构币种信息】中存在归属机构号 = `tranBranch` 且币种 = `tranCcy` 的记录）时返回检查结果“通过”。该路径 MUST 以成功状态表达（`succeed = true`，`errorCode`、`errorMessage` 为空），MUST NOT 返回错误码、MUST NOT 以抛出异常表达该结论、MUST NOT 返回“通过”以外的其他检查结果取值。

（条目 2 的标题为「检查账户币种」，但其正文的判定对象是 {交易币种} 与 [机构币种列表]；本步骤不涉及账户及其币种。本 Spec 按正文语义成文，标题名词差异不改变行为，见「## 验收范围与明确不覆盖的事项」第 3 项。）

#### Scenario: REQ-003-S01 交易币种在列表内时返回“通过”

- **GIVEN** 机构 `"351155"` 的机构币种记录含 USD；输入 `tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` = `Ccy.USD`
- **WHEN** 调用本步骤执行检查
- **THEN** 返回检查结果“通过”（`succeed = true`，`errorCode` 为空且不为 `"ER0047"`）

#### Scenario: REQ-003-S02 列表含多个币种时任一同配币种均返回“通过”

- **GIVEN** 机构 `"351155"` 的机构币种记录含 CNY、USD、HKD；输入 `tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` = `Ccy.HKD`
- **WHEN** 调用本步骤执行检查
- **THEN** 返回检查结果“通过”；结果不因 `tranCcy` 在列表中的位置、列表规模或列表内的记录条数而改变

#### Scenario: REQ-003-S03 该路径不引入账户数据依赖

- **GIVEN** 「## 步骤描述」条目 2 以「检查账户币种」为标题，其正文判定对象为 {交易币种} 与 [机构币种列表]
- **WHEN** 调用本步骤执行检查
- **THEN** 步骤不读取账户、账户币种或账户属性数据，判定仅依赖 `tranBranch`、`tranCcy` 与 [机构币种列表]；标题名词差异不改变本步骤的输入、判定与结果

### Requirement: REQ-004 交易币种不在 [机构币种列表] 范围内时返回错误码 ER0047

来源：`docs/requirements/ST055.md`「## 步骤描述」条目 2（第 6 行）—— 原文：「…否则返回[错误码]“ER0047”。」

系统 SHALL 在 `tranCcy` 不在 [机构币种列表] 范围内时返回错误码 `"ER0047"`，其文本为「当前交易机构不支持当前币种交易」（错误码注册表 `errorcodes.properties` 第 47 行既已登记，与源需求语义一致，本 Spec 不新增码值）。该路径 MUST 以业务失败状态表达（`succeed = false`，`errorCode = "ER0047"`），MUST NOT 返回检查结果“通过”，MUST NOT 以其他错误码表达本步骤的结论。

#### Scenario: REQ-004-S01 交易币种不在列表内时返回 ER0047

- **GIVEN** 机构 `"351155"` 的机构币种记录含 CNY、USD，不含 JPY；输入 `tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` = `Ccy.JPY`
- **WHEN** 调用本步骤执行检查
- **THEN** 返回错误码 `"ER0047"`（`succeed = false`，`errorCode = "ER0047"`），且不返回检查结果“通过”

#### Scenario: REQ-004-S02 错误码取值与注册表登记一致

- **GIVEN** 错误码注册表登记 `ER0047` =「当前交易机构不支持当前币种交易」
- **WHEN** 检查在不属于 [机构币种列表] 的路径返回错误码
- **THEN** `errorCode` 恰为 `"ER0047"`，与登记文本语义一致；步骤不使用注册表中的其他错误码，也不返回 `"ER0047"` 之外的码值

### Requirement: REQ-005 结果的完备性与互斥（含列表为空的边界）

来源：`docs/requirements/ST055.md`「## 步骤描述」条目 2（第 6 行）「若…则…，否则…」二分支结构；条目 1（第 5 行）的列表获取

系统 SHALL 对任一输入组合给出且仅给出两种结果之一：`tranCcy` 在 [机构币种列表] 范围内时“通过”、不在范围内时错误码 `"ER0047"`。两个条件互斥且完备：MUST NOT 出现无结果的组合，MUST NOT 同时给出两种结果，MUST NOT 在属于列表的组合上返回错误码。当查询【机构币种信息】无匹配记录时 [机构币种列表] 为空，此时任一 `tranCcy` 均不在该列表范围内，结果 MUST 为 `"ER0047"`。除结果状态与「## 输出」表声明的字段外，系统 MUST NOT 产生任何业务副作用（不写库、不改账户或交易状态、不发起机构币种信息查询之外的调用）。

#### Scenario: REQ-005-S01 同一机构下已配币种通过、未配币种返回 ER0047

- **GIVEN** 机构 `"351155"` 的机构币种记录为 CNY、USD 两条，`tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` 分别取 `Ccy` 的 12 个成员
- **WHEN** 逐一调用本步骤执行检查
- **THEN** 12 种组合中 CNY、USD 两种返回检查结果“通过”，其余 10 种返回错误码 `"ER0047"`；不存在未定义、无结果或两种结果并存的组合

#### Scenario: REQ-005-S02 机构无币种配置（空列表边界）

- **GIVEN** 【机构币种信息】中不存在归属机构号为 `"351156"` 的记录（查询无匹配记录）；输入 `tranBranch` = `TranBranch.VALUE_351156`，`tranCcy` = `Ccy.CNY`
- **WHEN** 调用本步骤执行检查
- **THEN** [机构币种列表] 为空，`tranCcy` 不在该列表范围内，返回错误码 `"ER0047"`（`succeed = false`）；步骤不抛出异常、不以“通过”兜底

#### Scenario: REQ-005-S03 判定不产生业务副作用

- **GIVEN** 属于列表的组合（机构 `"351155"` 配 CNY，`tranCcy` = `Ccy.CNY`）与不属于列表的组合（同一机构，`tranCcy` = `Ccy.JPY`）各一
- **WHEN** 分别调用本步骤执行检查
- **THEN** 除返回结果状态外不产生任何副作用：不新增、修改或删除机构币种记录，不改写账户或交易数据，不发起机构币种信息查询之外的 BCC、Mapper、数据库或外部接口调用

### Requirement: REQ-006 输出字段契约（照录，不推断产生条件）

来源：`docs/requirements/ST055.md`「## 输出」表（第 17–19 行，`ccy` 第 19 行）；「## 相关枚举」表第 26 行的「币种、输出数据-币种」别名

系统输出 MUST 包含源需求「## 输出」表声明的字段 `ccy`，其类型 MUST 为 `com.dcits.depsit.enums.Ccy`，标记为「非必填」（即可无值）。该字段的字段名、类型与标记由源需求直接给出，系统 MUST NOT 将其类型替换为其它枚举或基本类型。源需求正文未规定该字段的产生条件、取值与用途，本 Spec 不规定其何时有值、取何值，也不据此改变 REQ-003、REQ-004 的结果判定。

#### Scenario: REQ-006-S01 输出字段的名称、类型与标记与源需求输出表一致

- **GIVEN** 任一输入组合（示例 `tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` = `Ccy.USD`）
- **WHEN** 调用本步骤执行检查
- **THEN** 输出对象上存在名为 `ccy` 的字段，其声明类型为 `com.dcits.depsit.enums.Ccy`、标记为「非必填」（允许无值）；其是否产出与具体取值不被本 Spec 断言，REQ-003、REQ-004 的结果也不因该字段是否有值而改变

#### Scenario: REQ-006-S02 检查结果以结果状态表达，不以业务字段的有无表达

- **GIVEN** 属于列表的组合（机构 `"351155"` 配 CNY，`tranBranch` = `TranBranch.VALUE_351155`，`tranCcy` = `Ccy.CNY`）
- **WHEN** 调用本步骤执行检查
- **THEN** 检查结果“通过”以 `succeed = true` 且 `errorCode` 为空表达，不落成独立业务输出字段；通过／不通过的判定不以 `ccy` 字段是否有值表达，也不以该字段的取值表达
