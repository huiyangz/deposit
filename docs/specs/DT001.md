# DT001 检查账户是否能够出账

## 目标与范围

本任务将正式需求中「检查账户是否能够出账」决策规则整理为可验证的 Spec。规则依据账户状态及两个转账控制标志（账户转账止付标志、账户转账不收不付标志）判定账户是否允许出账，返回出账标志「允许」或「不允许」。

范围限于 DT001 需求文档「规则描述」条目 a–g 声明的判定逻辑及输入输出契约；对需求未覆盖的账户状态、标志组合及字段物理编码，仅记录待确认事项，不补默认行为。

## 正式需求来源

- `docs/requirements/DT001.md`（任务 DT001，规则类型：决策类）：
  - 「规则描述」条目 a–g；
  - 「输入」表（acctStatus、账户转账止付标志、账户转账不收不付标志）；
  - 「输出」表（出账标志）；
  - 「相关枚举」及「补充说明」（账户状态取值来源于代码[账户状态]，对应枚举类 `com.dcits.deposit.enums.AcctStatus`）。

## Requirements

### Requirement: REQ-001 账户状态为「新建」时返回「允许」

来源：规则描述条目 a（原文：若[账户状态]为“新建”，则返回[出账标志]为“允许”）

当账户状态为「新建」（`AcctStatus.N`）时，系统 SHALL 返回出账标志为「允许」。

#### Scenario: REQ-001-S01 新建账户返回允许

- **GIVEN** 账户状态为「新建」（`AcctStatus.N`），账户转账止付标志为「否」，账户转账不收不付标志为「否」
- **WHEN** 执行检查账户是否能够出账规则
- **THEN** 返回出账标志为「允许」

### Requirement: REQ-002 账户状态为「新建」且转账止付为「是」且不收不付为「否」时返回「不允许」

来源：规则描述条目 b（原文：若[账户状态]为“新建”且[账户转账止付标志]为“是”且[账户转账不收不付标志]为“否”，则返回[出账标志]为“不允许”）

> 注：该组合与 REQ-001 的「新建→允许」存在重叠，判定冲突见待确认事项。

#### Scenario: REQ-002-S01 新建且止付是、不收不付否返回不允许

- **GIVEN** 账户状态为「新建」（`AcctStatus.N`），账户转账止付标志为「是」，账户转账不收不付标志为「否」

## 待确认事项

1. **规则 a 与 b 的判定冲突**（关联 REQ-001、REQ-002）：当账户状态为「新建」且账户转账止付标志为「是」且账户转账不收不付标志为「否」时，规则 a（新建→允许）与规则 b（该组合→不允许）同时适用但结果相反，源需求未声明规则优先级或例外关系。需确认：该组合下预期结果为「允许」还是「不允许」，以及规则判定顺序/优先级。
2. **未覆盖输入**（关联 REQ-001~REQ-007）：以下情况源需求未定义返回结果，需确认默认返回（如一律「不允许」）或是否报错：
   - 账户状态为「睡眠」「预开户」「逾期」「预销户」「手工解除」（`AcctStatus.D/I/P/R/U`）；
   - 已列举状态下未列出的标志组合，例如「待激活」+止付「否」、「活动」+止付「是」或+不收不付「是」、「久悬」/「转营业外」+不收不付「否」、且规则 a/b 冲突组合之外的「新建」+其它标志组合。
3. **两个转账控制标志的来源与物理编码**（关联 REQ-002~REQ-006）：需求输入表将「账户转账止付标志」「账户转账不收不付标志」说明为「待定」，未确认来源实体/字段；类型为 `java.lang.String`，规则条件按「是」/「否」表述，需确认实际取值是否为字面量「是」/「否」或映射为其它编码（如「Y」/「N」）。
4. **输出「出账标志」的物理值**（关联全部 REQ）：需求输出表标记为非必填、类型为 `java.lang.String`，规则文本以「允许」/「不允许」表述，需确认实际返回值为字面量中文串还是映射编码。
5. **必填输入缺失**（关联全部 REQ）：`acctStatus` 标记为必填，但源需求未定义其为空/无效时的行为，需确认是否返回错误。

## 验收范围

验收以 REQ-001~REQ-007 声明的判定结果为准：覆盖「新建」「待激活」「活动」「久悬」「转营业外」「关闭」六种账户状态下需求明确列举的标志组合，验证返回的出账标志取值与需求原文一致。未覆盖输入、规则 a/b 冲突组合及字段物理编码不作为本 Spec 已确认验收断言，待待确认事项澄清后补充。
