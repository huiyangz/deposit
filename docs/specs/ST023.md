# ST023 登记代办人信息

## 目标与范围

本任务将正式需求中「登记代办人信息」交易执行步骤整理为可验证的 Spec。步骤行为：在存款交易执行过程中，若【代办人信息】数组不为空，则将代办人信息登记到代办人登记表（RB_COMMISSION_REGISTER），记录的字段与步骤输入一一对应；代办人信息数组为空时不登记，步骤正常结束。

范围限于 ST023 需求文档「步骤描述」条目1、「输入」表、「输出」表、「相关枚举」及「补充说明」声明的登记行为与输入输出契约。本任务属于存款交易执行流程中的步骤，底层业务资料为个人存款_存款_业需文档及其黑名单、检查限额、检查限制等流程组件文档（任务背景，不作为本步 Spec 的规则来源）。对需求未明确的代办人信息数组来源、数组与标量字段的处理粒度、必填校验失败行为及物理写入依赖，仅记录待确认事项，不补默认行为。

## 正式需求来源

- `docs/requirements/ST023.md`（任务 ST023，交易执行步骤）：
  - 「步骤描述」条目1（原文：若代办人信息数组不为空，则登记【代办人信息】，记录$代办人客户号$为{代办人客户号}…$代办核实员工号2$为{代办核实员工号2}）；
  - 「输入」表（16 个字段及必填性）；
  - 「输出」表（16 个字段，来源实体：代办人登记表（RB_COMMISSION_REGISTER））；
  - 「相关枚举」及「补充说明」（证件类型、国家和地区、代办人关系对应的枚举类）。

## Requirements

### Requirement: REQ-001 代办人信息数组非空时登记代办人信息

来源：步骤描述条目1（原文：若代办人信息数组不为空，则登记【代办人信息】，记录…）、「输入」表、「输出」表

当代办人信息数组不为空时，系统 SHALL 将代办人信息登记到代办人登记表（RB_COMMISSION_REGISTER），记录的代办人客户号、代办人名称、代办人证件类型、代办人证件号码、代办人证件开始日期、代办人证件到期日期、代办人电话、国家、代办人关系类型、代办人核实结果、核实电话号码、代办核实时间、代办核实员工号1、代办核实员工号2、交易参考号、代办原因与步骤对应输入赋值；登记完成后步骤 SHALL 成功结束（`succeed=true`、`errorCode` 与 `errorMessage` 为空），并按输出契约返回登记结果字段。

#### Scenario: REQ-001-S01 代办人信息数组非空时登记全部字段

- **GIVEN** 代办人信息数组非空，且本场景数组仅含一条代办人信息，步骤输入为：`reference`="REF20261031001"（示例）、`commissionClientName`="张三"（示例）、`commissionClientNo`="C0001"（示例）、`commissionDocumentId`="110101199001010011"（示例）、`commissionDocumentType`=`DocumentType.VALUE_110001`（居民身份证，规范常量）、`country`=`IssCountry.CHN`（中华人民共和国，规范常量）、`commissionStartDate`=2020-01-01（示例）、`commissionExpireDate`=2030-12-31（示例）、`commissionClientTel`="13800138000"（示例）、`commissionReason`="代亲属办理"（示例）、`commissionRelation`=`CommissionRelation.VALUE_1`（夫妻关系，规范常量）、`commissionConfirmUserIdKey1`="U1001"（示例）、`commissionConfirmUserIdKey2`="U1002"（示例）、`commissionConfirmTel`="13800138000"（示例）、`commissionConfirmTime`="20261031103000"（示例）、`commissionConfirmResult`="已核实"（示例）
- **WHEN** 执行登记代办人信息步骤
- **THEN** 在代办人登记表（RB_COMMISSION_REGISTER）新增一条登记记录，记录的参考号、代办人客户号、代办人名称、代办人证件类型、代办人证件号码、代办人证件开始日期、代办人证件到期日期、代办人电话、国家、代办人关系类型、代办人核实结果、核实电话号码、代办核实时间、代办核实员工号1、代办核实员工号2、代办原因与对应输入一一相等；步骤返回成功（`succeed=true`，`errorCode`、`errorMessage` 为空），返回的输出字段为登记后记录中的对应值。

### Requirement: REQ-002 代办人信息数组为空时不登记

来源：步骤描述条目1（原文：若代办人信息数组不为空，则登记【代办人信息】——条件分支的另一侧）

当代办人信息数组为空时，系统 SHALL 不登记代办人信息、不新增代办人登记表记录，步骤正常结束（`succeed=true`、`errorCode` 与 `errorMessage` 为空），不视为业务失败。

#### Scenario: REQ-002-S01 代办人信息数组为空不登记

- **GIVEN** 代办人信息数组为空
- **WHEN** 执行登记代办人信息步骤
- **THEN** 不新增代办人登记表（RB_COMMISSION_REGISTER）记录，步骤正常结束并返回成功（`succeed=true`，`errorCode`、`errorMessage` 为空），不视为业务失败。

## 待确认事项

1. **代办人信息数组来源与结构**：需求输入表未声明「代办人信息数组」字段，步骤描述中「若代办人信息数组不为空」所依据的数组在交易上下文中的来源、结构及元素字段未确认。需要确认：数组从何处取得、元素是否即输入表所列字段、数组非空但元素含空值时如何登记。影响：登记批次/循环行为无法唯一确定。（来源：步骤描述条目1、输入表；关联 REQ-001）
2. **数组与标量字段的处理粒度**：步骤描述使用单数「登记【代办人信息】」，输入/输出表均为标量字段，未明确由步骤对数组逐元素登记，还是由交易对每个元素分别调用本步骤。需要确认：本步骤一次调用登记的代办人数量与调用方式。（来源：步骤描述条目1、输入/输出表；关联 REQ-001）
3. **物理写入依赖字段来源**：代办人登记表数据对象 `RbCommissionRegisterEO` 标注 `@NotNull` 的 `createTimestamp`、`internalKey`、`channelSeqNo`、`clientNo`、`lastUpdTimestamp` 未在本需求输入表声明，其交易上下文来源未确认。需要确认：这些字段由交易上下文中哪些数据提供。（来源：输入表与 `RbCommissionRegisterEO`；关联 REQ-001）
4. **必填校验失败行为**：输入表标注 reference、commissionClientName、commissionDocumentId、commissionDocumentType、country、commissionStartDate、commissionExpireDate、commissionClientTel 为必填，但需求未声明缺失必填输入时的失败行为与错误码。需要确认：缺失必填输入时是否失败、使用哪个错误码及失败后的行为。（来源：输入表；关联 REQ-001）

## 验收范围

- 依据已确认需求可验证的行为：
  1. 代办人信息数组非空时，将代办人信息登记到代办人登记表（RB_COMMISSION_REGISTER），16 个字段与输入对应赋值，步骤成功返回并返回登记结果（REQ-001-S01）。
  2. 代办人信息数组为空时，不登记、不新增记录，步骤正常成功结束（REQ-002-S01）。
- 不在验收范围（需求未声明）：必填校验失败行为与错误码；除数组为空外的任何失败/异常分支（技术异常按项目约定传播，不作为本 Spec 断言）。
