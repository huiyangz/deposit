# ST109 检查限额场景配置是否有效

## 目标与范围

**目标**：以正式需求 `docs/requirements/ST109.md` 的已确认业务定义为依据，整理交易执行步骤「检查限额场景配置是否有效」的可验证行为 Spec。本步骤以 [限额场景编码]（`limitSceneNo`）、{交易日期}（入参 `tranDate`）、{交易时间}（入参 `tranTimestamp`）为输入，按 [限额场景编码] 查询【限额控制配置】，判断该限额场景编码在当前交易日期／交易时间下是否存在有效配置：有效时返回 [限额场景编码] 并回显配置的控制区间起止值，无效时返回 [限额场景编码] 为空。

**范围内**：

- 三个输入的字段契约：字段名、类型、必填性、与需求正文业务别名的对应关系。
- 【限额控制配置】的查询口径（按 [限额场景编码] 查询、可返回 0 条或多条）与查询字段来源。
- 多条配置与查无记录时的有效性判定口径（任一覆盖即有效、查无或全部未覆盖即无效）。
- 日期侧判定（{交易日期} 对 [限额控制开始日期]／[限额控制结束日期]）与时间侧判定（{交易时间} 对 [限额控制开始时间]／[限额控制结束时间]），含起止边界、单端未设置、两端未设置三类空值口径。
- 日期侧与时间侧的合取关系（须同时满足）。
- 有效时返回 [限额场景编码] 并回显控制区间值；无效时返回 [限额场景编码] 为空。
- 失败处理：本步骤无业务失败场景，失败仅由技术异常传播表达；本步骤为只读查询，不产生业务副作用。

**不在范围内**（源需求未涉及，本 Spec 不作要求）：

- 四类区间输出字段在「配置无效」时的取值（源需求仅规定 [限额场景编码] 为空，见「## 验收范围与明确不覆盖的事项」第 1 项）。
- 多条配置同时覆盖本次交易时，四条区间输出值具体取自哪一条配置（源需求采用「其中一条覆盖即有效」的宽容口径，见第 2 项）。
- 【限额控制配置】的启用标志 `validFlag`、限额机构编码 `limitBranchId`、限额机构范围 `limitBranchRange` 等字段的过滤与判定：源需求正文未引用（见第 3 项）。
- {交易时间}（`tranTimestamp`，`java.lang.String`）的字符串格式、解析与到区间时间字段的比较粒度（见第 4 项）。
- 本步骤的上游（谁调用、何时调用）、下游（返回结果的使用方）及跨步骤跳转：源需求未涉及。
- 非功能要求（性能、日志、监控、幂等、重试），源需求未定义。

## Requirements

### Requirement: REQ-001 输入契约

来源：`docs/requirements/ST109.md`「## 输入」表（第 11–15 行）

系统 SHALL 按顺序接收三个必填入参：`tranDate`（`java.util.Date`，交易日期）、`tranTimestamp`（`java.lang.String`，交易时间戳）、`limitSceneNo`（`java.lang.String`，限额场景编码）。系统 MUST NOT 使用这三项之外的输入，也 MUST NOT 因「来源实体」列为空而要求额外的数据获取。

#### Scenario: REQ-001-S01 三个必填入参按契约传入

- **GIVEN** 调用方已准备 `tranDate` = `2026-06-15`（`java.util.Date`）、`tranTimestamp` = `"2026-06-15 10:30:00"`（`java.lang.String`）、`limitSceneNo` = `"LS0001"`（`java.lang.String`）
- **WHEN** 以这三个入参执行本步骤
- **THEN** 系统按 `tranDate`、`tranTimestamp`、`limitSceneNo` 的顺序接收三项输入，`tranDate` 用于日期侧判定、`tranTimestamp` 用于时间侧判定、`limitSceneNo` 用于查询条件与有效时的原值返回；判定过程不读取其它输入

### Requirement: REQ-002 依限额场景编码查询限额控制配置

来源：`docs/requirements/ST109.md`「## 步骤描述」子步骤 1（第 5 行）

系统 SHALL 根据入参 [限额场景编码]（`limitSceneNo`）查询【限额控制配置】（`RB_LIMIT_CTRL_CONF`），并取得所查记录的 [限额控制开始日期]（`limitCtrlBgnDate`）、[限额控制结束日期]（`limitCtrlEndDate`）、[限额控制开始时间]（`limitCtrlBgnTime`）、[限额控制结束时间]（`limitCtrlEndTime`）。查询条件仅含 [限额场景编码]；因该表主键为（限额机构编码, 限额场景编码）而本步骤无限额机构编码输入，同一 [限额场景编码] MAY 查出 0 条或多条记录。

#### Scenario: REQ-002-S01 查出多条配置记录并取得四类控制区间值

- **GIVEN** 【限额控制配置】中同一 `limitSceneNo` = `"LS0001"` 存在 2 条记录：记录 A（`limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`、`limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`）与记录 B（`limitCtrlBgnDate` = `2026-07-01`、`limitCtrlEndDate` = `2026-07-31`、`limitCtrlBgnTime` = `08:00:00`、`limitCtrlEndTime` = `12:00:00`，限额机构编码与记录 A 不同）
- **WHEN** 以 `limitSceneNo` = `"LS0001"` 执行查询
- **THEN** 查询返回 2 条记录；每条记录的四类控制区间值均可读（含 `null` 情形），查询条件不包含限额机构编码

#### Scenario: REQ-002-S02 查无记录

- **GIVEN** 【限额控制配置】中不存在 `limitSceneNo` = `"LS9999"` 的任何记录
- **WHEN** 以 `limitSceneNo` = `"LS9999"` 执行查询
- **THEN** 查询返回 0 条记录，本步骤不因查无记录抛出业务异常

### Requirement: REQ-003 多条配置与查无记录的有效性判定口径

来源：`docs/requirements/ST109.md`「## 步骤描述」子步骤 1（第 5 行）

系统 SHALL 按以下口径判定 [限额场景编码] 的配置是否有效：查询结果为多条时，只要其中一条记录的控制区间覆盖本次交易（覆盖判定见 REQ-006），即认为该限额场景配置有效；查询无记录，或全部记录的控制区间都未覆盖本次交易时，即认为该限额场景配置无效（无效返回见 REQ-008）。

#### Scenario: REQ-003-S01 单条记录覆盖本次交易

- **GIVEN** 【限额控制配置】中 `limitSceneNo` = `"LS0001"` 仅 1 条记录，其日期侧与时间侧均覆盖本次交易（如 REQ-004-S01 与 REQ-005-S01 的取值）
- **WHEN** 以 `tranDate` = `2026-06-15`、`tranTimestamp` = `"2026-06-15 10:30:00"`、`limitSceneNo` = `"LS0001"` 执行本步骤
- **THEN** 该限额场景配置判定为**有效**

#### Scenario: REQ-003-S02 多条记录中恰有一条覆盖本次交易

- **GIVEN** 【限额控制配置】中 `limitSceneNo` = `"LS0001"` 存在 2 条记录：记录 A 的日期侧与时间侧均不覆盖本次交易（`limitCtrlBgnDate` = `2026-07-01`、`limitCtrlEndDate` = `2026-07-31`），记录 B 的两侧均覆盖本次交易（`limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`、`limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`）
- **WHEN** 以 `tranDate` = `2026-06-15`、`tranTimestamp` = `"2026-06-15 10:30:00"`、`limitSceneNo` = `"LS0001"` 执行本步骤
- **THEN** 该限额场景配置判定为**有效**（命中记录 B 即视为有效，不要求全部记录覆盖）

#### Scenario: REQ-003-S03 多条记录全部未覆盖本次交易

- **GIVEN** 【限额控制配置】中 `limitSceneNo` = `"LS0001"` 存在 2 条记录，两条记录的日期侧或时间侧均至少有一侧不覆盖本次交易（如记录 A 日期侧不覆盖、记录 B 时间侧不覆盖）
- **WHEN** 以 `tranDate` = `2026-06-15`、`tranTimestamp` = `"2026-06-15 10:30:00"`、`limitSceneNo` = `"LS0001"` 执行本步骤
- **THEN** 该限额场景配置判定为**无效**，且按 REQ-008 返回 [限额场景编码] 为空

### Requirement: REQ-004 日期侧判定

来源：`docs/requirements/ST109.md`「## 步骤描述」子步骤 2（第 7 行）

系统 SHALL 对每条候选配置记录按下述规则独立判定日期侧是否满足：{交易日期}（`tranDate`）不早于 [限额控制开始日期]（`limitCtrlBgnDate`）且不晚于 [限额控制结束日期]（`limitCtrlEndDate`）时，日期侧满足（含起止日期，即等于起止日期亦满足）；[限额控制开始日期]、[限额控制结束日期] 未设置的，日期侧不限制；只设置了其中一端的，按已设置的一端判断（仅设开始日期时要求不早于该日期，仅设结束日期时要求不晚于该日期）；两端都未设置的，日期侧视为满足（本次交易视为落在该配置的有效期内）。

#### Scenario: REQ-004-S01 起止日期均已设置且交易日期落在区间内

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`
- **WHEN** 以 `tranDate` = `2026-06-15` 进行日期侧判定
- **THEN** 日期侧判定结果为**满足**

#### Scenario: REQ-004-S02 交易日期等于起止日期边界（含起止）

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`
- **WHEN** 分别以 `tranDate` = `2026-01-01`、`tranDate` = `2026-12-31` 进行日期侧判定
- **THEN** 两次判定结果均为**满足**（起止日期本身包含在区间内）

#### Scenario: REQ-004-S03 交易日期早于开始日期

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`
- **WHEN** 以 `tranDate` = `2025-12-31` 进行日期侧判定
- **THEN** 日期侧判定结果为**不满足**

#### Scenario: REQ-004-S04 交易日期晚于结束日期

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`
- **WHEN** 以 `tranDate` = `2027-01-01` 进行日期侧判定
- **THEN** 日期侧判定结果为**不满足**

#### Scenario: REQ-004-S05 仅设置开始日期

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `null`（未设置）
- **WHEN** 分别以 `tranDate` = `2026-06-15`、`tranDate` = `2025-12-31` 进行日期侧判定
- **THEN** `tranDate` = `2026-06-15` 判定为**满足**（不早于已设置的开始日期）；`tranDate` = `2025-12-31` 判定为**不满足**；结束日期未设置一侧不构成限制

#### Scenario: REQ-004-S06 仅设置结束日期

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `null`（未设置）、`limitCtrlEndDate` = `2026-12-31`
- **WHEN** 分别以 `tranDate` = `2026-06-15`、`tranDate` = `2027-01-01` 进行日期侧判定
- **THEN** `tranDate` = `2026-06-15` 判定为**满足**（不晚于已设置的结束日期）；`tranDate` = `2027-01-01` 判定为**不满足**；开始日期未设置一侧不构成限制

#### Scenario: REQ-004-S07 起止日期均未设置

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `null`、`limitCtrlEndDate` = `null`
- **WHEN** 以任意 `tranDate`（如 `2026-06-15`）进行日期侧判定
- **THEN** 日期侧判定结果为**满足**（视为落在该配置的有效期内）

### Requirement: REQ-005 时间侧判定

来源：`docs/requirements/ST109.md`「## 步骤描述」子步骤 2（第 7 行）

系统 SHALL 对每条候选配置记录按下述规则独立判定时间侧是否满足：{交易时间}（`tranTimestamp`）不早于 [限额控制开始时间]（`limitCtrlBgnTime`）且不晚于 [限额控制结束时间]（`limitCtrlEndTime`）时，时间侧满足（含起止时间，即等于起止时间亦满足）；[限额控制开始时间]、[限额控制结束时间] 未设置的，时间侧不限制；只设置了其中一端的，按已设置的一端判断；两端都未设置的，时间侧视为满足（本次交易视为落在该配置的有效期内）。

#### Scenario: REQ-005-S01 起止时间均已设置且交易时间落在区间内

- **GIVEN** 候选配置记录 `limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`
- **WHEN** 以 `tranTimestamp` 表示的交易时间 = `10:30:00` 进行时间侧判定
- **THEN** 时间侧判定结果为**满足**

#### Scenario: REQ-005-S02 交易时间等于起止时间边界（含起止）

- **GIVEN** 候选配置记录 `limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`
- **WHEN** 分别以交易时间 = `09:00:00`、交易时间 = `17:00:00` 进行时间侧判定
- **THEN** 两次判定结果均为**满足**（起止时间本身包含在区间内）

#### Scenario: REQ-005-S03 交易时间早于开始时间

- **GIVEN** 候选配置记录 `limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`
- **WHEN** 以交易时间 = `08:59:59` 进行时间侧判定
- **THEN** 时间侧判定结果为**不满足**

#### Scenario: REQ-005-S04 交易时间晚于结束时间

- **GIVEN** 候选配置记录 `limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`
- **WHEN** 以交易时间 = `17:00:01` 进行时间侧判定
- **THEN** 时间侧判定结果为**不满足**

#### Scenario: REQ-005-S05 仅设置开始时间

- **GIVEN** 候选配置记录 `limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `null`（未设置）
- **WHEN** 分别以交易时间 = `10:30:00`、交易时间 = `08:59:59` 进行时间侧判定
- **THEN** 交易时间 = `10:30:00` 判定为**满足**（不早于已设置的开始时间）；交易时间 = `08:59:59` 判定为**不满足**；结束时间未设置一侧不构成限制

#### Scenario: REQ-005-S06 仅设置结束时间

- **GIVEN** 候选配置记录 `limitCtrlBgnTime` = `null`（未设置）、`limitCtrlEndTime` = `17:00:00`
- **WHEN** 分别以交易时间 = `10:30:00`、交易时间 = `17:00:01` 进行时间侧判定
- **THEN** 交易时间 = `10:30:00` 判定为**满足**（不晚于已设置的结束时间）；交易时间 = `17:00:01` 判定为**不满足**；开始时间未设置一侧不构成限制

#### Scenario: REQ-005-S07 起止时间均未设置

- **GIVEN** 候选配置记录 `limitCtrlBgnTime` = `null`、`limitCtrlEndTime` = `null`
- **WHEN** 以任意交易时间（如 `10:30:00`）进行时间侧判定
- **THEN** 时间侧判定结果为**满足**（视为落在该配置的有效期内）

### Requirement: REQ-006 日期侧与时间侧的合取

来源：`docs/requirements/ST109.md`「## 步骤描述」子步骤 2（第 7 行）

系统 SHALL 以「日期侧满足**且**时间侧满足」作为单条配置记录覆盖本次交易的充要条件：仅当同一条记录的日期侧（REQ-004）与时间侧（REQ-005）同时满足时，该记录才覆盖本次交易；任一侧不满足即该记录不覆盖。判定以记录为单位的合取进行，不将不同记录的各侧结果交叉组合。

#### Scenario: REQ-006-S01 两侧同时满足则该记录覆盖本次交易

- **GIVEN** 候选配置记录日期侧满足（`limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`，`tranDate` = `2026-06-15`）且时间侧满足（`limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`，交易时间 = `10:30:00`）
- **WHEN** 判定该记录是否覆盖本次交易
- **THEN** 该记录**覆盖**本次交易

#### Scenario: REQ-006-S02 日期侧满足但时间侧不满足

- **GIVEN** 候选配置记录日期侧满足（`tranDate` = `2026-06-15` 落在 `2026-01-01` 至 `2026-12-31` 内），时间侧不满足（`limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`，交易时间 = `18:00:00`）
- **WHEN** 判定该记录是否覆盖本次交易
- **THEN** 该记录**不覆盖**本次交易

#### Scenario: REQ-006-S03 日期侧不满足但时间侧满足

- **GIVEN** 候选配置记录日期侧不满足（`tranDate` = `2025-12-31` 早于 `limitCtrlBgnDate` = `2026-01-01`），时间侧满足（`limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`，交易时间 = `10:30:00`）
- **WHEN** 判定该记录是否覆盖本次交易
- **THEN** 该记录**不覆盖**本次交易

#### Scenario: REQ-006-S04 两侧均未设置

- **GIVEN** 候选配置记录 `limitCtrlBgnDate` = `null`、`limitCtrlEndDate` = `null`、`limitCtrlBgnTime` = `null`、`limitCtrlEndTime` = `null`
- **WHEN** 以任意 `tranDate` 与交易时间判定该记录是否覆盖本次交易
- **THEN** 该记录**覆盖**本次交易（日期侧与时间侧均视为满足），该 [限额场景编码] 的配置判定为有效

### Requirement: REQ-007 有效时返回限额场景编码并回显控制区间

来源：`docs/requirements/ST109.md`「## 步骤描述」子步骤 2（第 7 行）、「## 输出」表（第 19–25 行）

系统 SHALL 在判定 [限额场景编码] 的配置有效时（REQ-003）返回输出 `limitSceneNo`，其值为入参 [限额场景编码] 的原值（非空），并回显命中配置记录的控制区间 `limitCtrlBgnDate`、`limitCtrlEndDate`、`limitCtrlBgnTime`、`limitCtrlEndTime`。该结果 MUST NOT 以错误码或异常表达；四个区间字段按其来源列原值回显（可为 `null`，不得以默认值替代）。

#### Scenario: REQ-007-S01 配置有效时返回限额场景编码并回显区间值

- **GIVEN** 【限额控制配置】中 `limitSceneNo` = `"LS0001"` 存在记录 `limitCtrlBgnDate` = `2026-01-01`、`limitCtrlEndDate` = `2026-12-31`、`limitCtrlBgnTime` = `09:00:00`、`limitCtrlEndTime` = `17:00:00`
- **WHEN** 以 `tranDate` = `2026-06-15`、`tranTimestamp` = `"2026-06-15 10:30:00"`、`limitSceneNo` = `"LS0001"` 执行本步骤
- **THEN** 输出 `limitSceneNo` = `"LS0001"`（非空），四个区间输出字段回显该命中记录的 `limitCtrlBgnDate`、`limitCtrlEndDate`、`limitCtrlBgnTime`、`limitCtrlEndTime`；本步骤不产生业务失败

#### Scenario: REQ-007-S02 有效但命中记录的区间字段为空时按原值回显

- **GIVEN** 【限额控制配置】中 `limitSceneNo` = `"LS0002"` 存在记录 `limitCtrlBgnDate` = `null`、`limitCtrlEndDate` = `null`、`limitCtrlBgnTime` = `null`、`limitCtrlEndTime` = `null`（按 REQ-006-S04 覆盖本次交易）
- **WHEN** 以 `limitSceneNo` = `"LS0002"` 执行本步骤
- **THEN** 输出 `limitSceneNo` = `"LS0002"`（非空）；四个区间输出字段按来源列原值保持为空，MUST NOT 以默认日期或默认时间替代

### Requirement: REQ-008 无效时返回限额场景编码为空

来源：`docs/requirements/ST109.md`「## 步骤描述」子步骤 1（第 5 行）、子步骤 2（第 7 行）、「## 输出」表（第 21 行）

系统 SHALL 在判定 [限额场景编码] 的配置无效时（查询无记录，或全部记录的控制区间都未覆盖本次交易）返回输出 `limitSceneNo` 为空值，且 MUST NOT 返回业务失败、错误码或异常。

#### Scenario: REQ-008-S01 查无记录时返回为空

- **GIVEN** 【限额控制配置】中不存在 `limitSceneNo` = `"LS9999"` 的任何记录
- **WHEN** 以 `tranDate` = `2026-06-15`、`tranTimestamp` = `"2026-06-15 10:30:00"`、`limitSceneNo` = `"LS9999"` 执行本步骤
- **THEN** 输出 `limitSceneNo` 为空值；本步骤不产生业务失败，不以错误码或异常表达判定结果

#### Scenario: REQ-008-S02 有记录但全部未覆盖时返回为空

- **GIVEN** 【限额控制配置】中 `limitSceneNo` = `"LS0001"` 存在 2 条记录，两条记录的日期侧与时间侧均不同时满足（如记录 A 仅日期侧满足、记录 B 仅时间侧满足，另见 REQ-006-S02、REQ-006-S03）
- **WHEN** 以 `tranDate` = `2026-06-15`、`tranTimestamp` = `"2026-06-15 10:30:00"`、`limitSceneNo` = `"LS0001"` 执行本步骤
- **THEN** 输出 `limitSceneNo` 为空值（不因存在记录而返回编码，也不因两条记录各满足一侧而拼接为有效）

### Requirement: REQ-009 失败处理与副作用约束

来源：`docs/requirements/ST109.md`「## 失败处理」（第 29 行）

本步骤 SHALL NOT 产生业务失败场景：配置无效（REQ-008）为正常判定结果而非失败，判定结论 MUST NOT 以错误码、异常或业务提示表达；失败仅由技术异常传播表达。系统 MUST NOT 使用需求未声明的输入或数据服务，MUST NOT 写入或修改【限额控制配置】或任何其它数据（本步骤只读）。

#### Scenario: REQ-009-S01 技术异常按技术异常传播

- **GIVEN** 查询【限额控制配置】的数据服务调用发生技术异常（如数据访问异常）
- **WHEN** 执行本步骤
- **THEN** 该异常按技术异常向上传播，MUST NOT 被转换为「配置无效」的返回值、业务失败或错误码

#### Scenario: REQ-009-S02 判定过程无写入副作用

- **GIVEN** 一次正常执行（无论判定结果为有效或无效）
- **WHEN** 本步骤完成
- **THEN** 【限额控制配置】及任何其它表的数据均未被写入、修改或删除，本步骤不发起需求未声明的外部调用

## 验收范围与明确不覆盖的事项

1. **配置无效时四类区间输出字段的取值**：源需求仅规定无效时 [限额场景编码] 为空（第 5、7 行），未规定 `limitCtrlBgnDate`、`limitCtrlEndDate`、`limitCtrlBgnTime`、`limitCtrlEndTime` 在「查无记录」与「有记录但全部未覆盖」两种无效情形下的输出取值。本 Spec 不作要求，测试设计 MUST NOT 对该两情形下的四个字段构造断言。
2. **多条配置同时覆盖时四条区间值取自哪一条**：源需求采用「只要其中一条的控制区间覆盖本次交易，即认为该限额场景配置有效」的宽容口径（第 5 行），未指定唯一一条记录作为回显来源。回显命中配置中任一条的区间值均满足该表述，本 Spec 不要求业务指定唯一来源，测试设计 MUST NOT 断言具体的某一条记录值。
3. **`validFlag`（启用标志）等字段的过滤**：源需求正文未引用【限额控制配置】的启用标志，工程内该字段（`RbLimitCtrlConfEO.validFlag`，列 `VALID_FLAG`）亦无码值定义。本 Spec 不要求按启用标志过滤配置，也不据此报告「无生效配置」；同理，`limitBranchId`（限额机构编码）、`limitBranchRange`（限额机构范围）、`dealFlow`、`ctrlItemType`、`limitCtrlAmt`、`limitCtrlNum` 等本步骤未引用的字段均不参与判定。
4. **`tranTimestamp` 的格式与解析口径**：源需求以 {交易时间} 书写时间侧输入，其承载为 `java.lang.String` 的 `tranTimestamp`（交易时间戳），但未给出字符串格式、时区或到区间时间字段（`java.util.Date`）的比较粒度（是否按日／时／分／秒截断）。本 Spec 按「不早于／不晚于」的区间比较表述时间侧判定（REQ-005），具体格式与粒度不属本 Spec 覆盖范围；相应地，`tranDate` 与日期侧区间字段的比较粒度（是否按日历日截断）同样未由源需求定义，一并列入本项。
5. **步骤编排与上下游**：源需求未涉及本步骤的调用方、调用时机、返回结果的使用方及任何跨步骤跳转（正文无「组件内步骤调用」说明），本 Spec 不规定编排顺序与依赖传播。
6. **入参形态校验**：三个入参标为必填，但源需求未定义必填项缺失或取值非法时的行为，本 Spec 不生成相应条款。
7. **非功能要求**：性能、并发、日志、监控、幂等、重试与缓存，源需求未涉及。
