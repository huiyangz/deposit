# ST017 检查币种一致性

## 目标与范围

**目标**：定义存款业务组件「检查币种一致性」步骤（交易执行步骤）的行为契约：以交易币种与账户币种两个输入，按币种代码比较两者是否一致；一致时返回检查结果“通过”，不一致时返回错误码“ER0051”。本 Spec 供测试设计、实现与审核共同使用。

**范围内**：

- 两个输入的字段契约：字段名、类型、必填性、取值域与枚举绑定。
- 一致性判定口径：按币种代码比较，须跨 `Ccy` 与 `AcctCcy` 两个不同的枚举类型成立。
- 一致路径的可观察结果：检查结果“通过”。
- 不一致路径的可观察结果：错误码“ER0051”。
- 结果完备性与互斥：取值域内（12 × 12 = 144 种组合）任一组合恰得两种结果之一。

**不在范围内**（源需求未要求，本 Spec 不定义、不验收）：

- 不定义交易币种、账户币种的来源与获取方式：源需求「## 输入」表「来源实体」列均为空，两个值由调用方在同一次检查中直接提供；本步骤不查询账户、产品、机构或任何实体数据。
- 不定义金额、汇率、币种折算、精度与舍入、记账与账务处理。
- 不定义其他币种类检查：账户币种是否在产品配置范围内（ER0023）、交易机构是否支持该币种（ER0047）、转账双方账户币种一致性（ER0094）、通兑机构是否支持该币种（ER0020）等均非本步骤内容。
- 不定义本步骤被交易或其他步骤调用时的编排、条件跳转、事务边界与回滚：源需求未涉及。
- 不定义输入为空（null）或缺失时的处理：源需求未规定。
- 不定义结果的持久化、日志、监控、幂等、并发与性能要求。

## Requirements

### Requirement: REQ-001 输入契约与枚举绑定
来源：`docs/requirements/ST017.md`「## 输入」表（第 11–12 行）、「## 相关枚举」表（第 18–19 行）、「## 补充说明」（第 23–24 行）

系统 SHALL 以两个输入执行检查：`tranCcy`（类型 `com.dcits.depsit.enums.Ccy`，必填，交易币种）与 `acctCcy`（类型 `com.dcits.depsit.enums.AcctCcy`，必填，账户币种），并 MUST 按该顺序接收。`tranCcy` 的取值 MUST 为 `Ccy` 的成员（AUD、CAD、CHF、CNY、EUR、GBP、HKD、JPY、KRW、RUB、SGD、USD），`acctCcy` 的取值 MUST 为 `AcctCcy` 的成员（同一代码集合）。系统 MUST NOT 使用这两个输入之外的输入，MUST NOT 因「来源实体」列为空而要求额外的数据访问或引入第三个入参。

#### Scenario: REQ-001-S01 两个输入按契约传入并完成检查
- **GIVEN** 调用方按「## 输入」表准备 `tranCcy` = `Ccy.CNY`，`acctCcy` = `AcctCcy.CNY`
- **WHEN** 调用本步骤执行检查
- **THEN** 步骤以该组输入完成检查并给出结果（示例组合返回检查结果“通过”），且不读取输入表以外的数据、不调用 BCC、Mapper、数据库、账户实体或其他组件

#### Scenario: REQ-001-S02 输入取值绑定到各自枚举类
- **GIVEN** 「## 相关枚举」与「## 补充说明」将交易币种绑定为 `com.dcits.depsit.enums.Ccy`、将账户币种绑定为 `com.dcits.depsit.enums.AcctCcy`
- **WHEN** 分别按两个枚举的成员传入（示例 `tranCcy` = `Ccy.USD`，`acctCcy` = `AcctCcy.USD`）
- **THEN** 步骤按绑定类型接收这两个输入并参与一致性判定；两个别名（输入数据-交易币种、输入数据-账户币种）指向同一字段，不产生第三个输入，也不按别名去别处取值

### Requirement: REQ-002 一致性判定按币种代码比较
来源：`docs/requirements/ST017.md`「## 步骤描述」第 5 行（“{交易币种}与{账户币种}不一致”）；「## 输入」表第 11–12 行的类型绑定

系统 SHALL 以两个输入所表示的币种标识（枚举成员对应的币种代码，即 `Ccy.getValue()` 与 `AcctCcy.getValue()`）判定一致性：当 `tranCcy` 的币种代码与 `acctCcy` 的币种代码相同时判定为一致，不同时判定为不一致。因两侧类型分别为 `Ccy` 与 `AcctCcy`（不同的 Java 枚举类型），系统 MUST NOT 以 Java 枚举对象同一性或类型直接判等（否则任一合法组合都会被判为不一致）；MUST 按币种代码比较。两个枚举的代码集合逐项相同，故一致性判定对全部 144 种组合均有确定结论。

#### Scenario: REQ-002-S01 同一币种代码跨两个枚举类型判定为一致
- **GIVEN** `tranCcy` = `Ccy.CNY`，`acctCcy` = `AcctCcy.CNY`
- **WHEN** 执行一致性判定
- **THEN** 判定为一致（不得因两侧 Java 枚举类型不同、对象不相等而判为不一致），结果走「检查结果通过」路径

#### Scenario: REQ-002-S02 不同币种代码判定为不一致
- **GIVEN** `tranCcy` = `Ccy.CNY`，`acctCcy` = `AcctCcy.USD`
- **WHEN** 执行一致性判定
- **THEN** 判定为不一致，结果走错误码路径

#### Scenario: REQ-002-S03 非人民币代码同样按币种代码比较
- **GIVEN** `tranCcy` = `Ccy.HKD`，`acctCcy` = `AcctCcy.HKD`（或 USD/USD、JPY/JPY 等任一同代码组合）
- **WHEN** 执行一致性判定
- **THEN** 判定为一致；币种代码比较口径不限于人民币，也不受币种在 `Ccy`/`AcctCcy` 中声明顺序的影响

### Requirement: REQ-003 币种一致时返回检查结果“通过”
来源：`docs/requirements/ST017.md`「## 步骤描述」第 5 行（“否则返回检查结果为‘通过’”）

系统 SHALL 在 `tranCcy` 与 `acctCcy` 一致时返回检查结果为“通过”。该路径 MUST 以成功状态表达（`succeed = true`，且 `errorCode`、`errorMessage` 为空），MUST NOT 返回错误码、MUST NOT 以抛出异常表达该结论、MUST NOT 返回“通过”以外的其他检查结果取值。

#### Scenario: REQ-003-S01 一致时返回“通过”
- **GIVEN** `tranCcy` = `Ccy.CNY`，`acctCcy` = `AcctCcy.CNY`
- **WHEN** 调用本步骤执行检查
- **THEN** 返回检查结果“通过”（`succeed = true`，`errorCode` 为空）；`errorCode` 不为 `"ER0051"`

#### Scenario: REQ-003-S02 非人民币币种一致时同样返回“通过”
- **GIVEN** `tranCcy` = `Ccy.EUR`，`acctCcy` = `AcctCcy.EUR`
- **WHEN** 调用本步骤执行检查
- **THEN** 返回检查结果“通过”（`succeed = true`，`errorCode` 为空），不因币种非人民币而改变结果

### Requirement: REQ-004 币种不一致时返回错误码 ER0051
来源：`docs/requirements/ST017.md`「## 步骤描述」第 5 行（“则返回[错误码]‘ER0051’”）

系统 SHALL 在 `tranCcy` 与 `acctCcy` 不一致时返回错误码 `"ER0051"`，其文本为“交易币种与账户币种不一致”（错误码注册表 `errorcodes.properties` 第 51 行既已登记，与源需求语义一致，本 Spec 不新增码值）。该路径 MUST 以业务失败状态表达（`succeed = false`，`errorCode = "ER0051"`），MUST NOT 返回检查结果“通过”，MUST NOT 以其他错误码表达本步骤的币种不一致——`ER0094`（转账双方账户币种不一致）、`ER0023`（账户币种不在产品配置范围内）、`ER0047`（当前交易机构不支持当前币种交易）等均属其他场景，不在本步骤取值范围内。

#### Scenario: REQ-004-S01 不一致时返回 ER0051
- **GIVEN** `tranCcy` = `Ccy.CNY`，`acctCcy` = `AcctCcy.USD`
- **WHEN** 调用本步骤执行检查
- **THEN** 返回错误码 `"ER0051"`（`succeed = false`，`errorCode = "ER0051"`），且不返回检查结果“通过”

#### Scenario: REQ-004-S02 不一致的方向不影响结果
- **GIVEN** `tranCcy` = `Ccy.USD`，`acctCcy` = `AcctCcy.CNY`（与 S01 的币种组合互为反向）
- **WHEN** 调用本步骤执行检查
- **THEN** 同样返回错误码 `"ER0051"`；判定对两侧对称，不因哪一侧是交易币种而改变结果或码值

#### Scenario: REQ-004-S03 错误码取值与注册表登记一致
- **GIVEN** 错误码注册表登记 `ER0051` = “交易币种与账户币种不一致”
- **WHEN** 检查在不一致路径返回错误码
- **THEN** `errorCode` 恰为 `"ER0051"`，与登记文本语义一致；步骤不使用注册表中其他币种类错误码（如 ER0023、ER0047、ER0094）

### Requirement: REQ-005 结果完备性与互斥
来源：`docs/requirements/ST017.md`「## 步骤描述」第 5 行（“若…则…，否则…”的二分支结构）

系统 SHALL 对取值域内任一输入组合（`Ccy` 12 个成员 × `AcctCcy` 12 个成员，共 144 种）给出且仅给出两种结果之一：一致时“通过”、不一致时错误码 `"ER0051"`。两个条件互斥且完备：MUST NOT 出现无结果的组合，MUST NOT 同时给出两种结果，MUST NOT 在一致的组合上返回错误码或在多组合上返回“通过”。除该结果外，系统 MUST NOT 产生任何业务副作用（不写库、不改账户或交易状态、不发起外部调用）。

#### Scenario: REQ-005-S01 取值域内每个组合都有确定结果
- **GIVEN** 遍历 `Ccy` 的 12 个成员与 `AcctCcy` 的 12 个成员构成的全部 144 种组合
- **WHEN** 逐一调用本步骤执行检查
- **THEN** 每个组合都返回“通过”或错误码 `"ER0051"` 之一；其中币种代码相同的 12 种组合返回“通过”，其余 132 种组合返回 `"ER0051"`，无未定义、无结果或结果二义的情况

#### Scenario: REQ-005-S02 判定不产生副作用
- **GIVEN** `tranCcy` = `Ccy.GBP`，`acctCcy` = `AcctCcy.GBP`
- **WHEN** 调用本步骤执行检查
- **THEN** 除返回检查结果外不产生任何副作用：不改写账户或交易数据、不调用 BCC/Mapper/数据库/外部接口、不记录业务状态变更

## 验收范围与明确不覆盖的事项

本 Spec 为测试设计依据，不是已生成的测试用例，也不是测试执行结果。以下事项在源需求中未唯一确定或属范围之外，不作为本轮验收判定的对象；相关条款在测试设计中按源需求原文用词表述，不得据本 Spec 反推取值。

1. **输入为空或缺失时的行为未定义（来源：源需求未涉及）**：`tranCcy`、`acctCcy` 在「## 输入」表均标「必填」，源需求正文未规定二者为空（null）或缺失时是按“不一致”返回 ER0051、按“通过”处理还是以技术异常传播。REQ-001、REQ-003、REQ-004 及全部场景均以两个枚举的合法成员取值表述，不对空值/缺失路径作断言。
2. **结果的承载方式由工程基类约定，源需求未声明输出字段**：源需求无「## 输出」章节，“检查结果”与“错误码”未声明为业务字段。本 Spec 按工程基类 `StepResult` 的既有契约（`succeed` / `errorCode` / `errorMessage`，成功时错误码为空）将“通过”映射为 `succeed = true` 且错误码为空、将 `ER0051` 映射为 `succeed = false` 且 `errorCode = "ER0051"`。测试断言以该状态字段为准，不要求实现新增业务输出字段，也不得据“检查结果”一词新增输出结构；若后续需求方补充输出字段定义，需同步更新「### 输出」与 REQ-003、REQ-004。
3. **错误信息文本未规定**：源需求仅给出错误码 `"ER0051"`，未规定 `errorMessage` 文本。注册表登记文本「交易币种与账户币种不一致」可用作实现内容，但错误信息内容不在本轮断言范围内；断言对象为 `errorCode = "ER0051"`。`errorMessage` 的为空/非空亦不作断言。
4. **两个输入的来源与获取方式不在范围内**：「## 输入」表「来源实体」列均为空，源需求未声明从哪个实体/字段取数，本 Spec 不定义数据访问，也不断言任何取数调用。
5. **不在范围内的内容**：金额、汇率、币种折算、精度与舍入、记账与账务处理；ER0023、ER0047、ER0094 等其他币种类检查；本步骤被交易/其他步骤调用时的编排、跳转、事务与回滚；结果持久化、日志、监控、幂等、并发与性能要求——源需求均未定义，本 Spec 不作要求也不作断言。
