# ST017 检查币种一致性

## 目标与范围

本任务将正式需求「检查币种一致性」交易执行步骤整理为可验证的 Spec。步骤接收两个必填输入——交易币种（`tranCcy`，类型 `com.dcits.deposit.enums.Ccy`）与账户币种（`acctCcy`，类型 `com.dcits.deposit.enums.AcctCcy`）——判定两者是否一致：不一致时本步骤业务失败并返回错误码「ER0051」；一致时返回检查结果「通过」（步骤成功）。

范围限于 ST017 需求文档「步骤描述」「输入」「相关枚举」「补充说明」声明的判定逻辑与输入契约，以及工程中已确认的枚举取值、错误码定义与步骤结果公共机制。需求未声明的必填输入缺失行为、「通过」结果的业务输出表达等仅记录待确认事项，不补默认行为。

### 结果契约

本步骤结果由步骤公共机制 `com.dcits.common.step.StepResult` 表达，实际字段与访问器已核对：`succeed`（boolean，`isSucceed()`/`setSucceed()`）、`errorCode`（String，成功时为 null）、`errorMessage`（String，成功时为 null）。

- 检查通过：步骤成功（`succeed=true`），`errorCode` 与 `errorMessage` 为 null，对应检查结果「通过」。
- 币种不一致：步骤业务失败（`succeed=false`），`errorCode` 为「ER0051」，`errorMessage` 按已确认的 `错误码::业务说明` 格式为「ER0051::交易币种与账户币种不一致」。

### 依赖核对

- 枚举 `Ccy` 与 `AcctCcy` 均存在于 `deposit-common`，取值域一致，均为 ISO 货币代码：AUD、CAD、CHF、CNY、EUR、GBP、HKD、JPY、KRW、RUB、SGD、USD；两枚举均提供 `getValue()` 返回该代码。需求「补充说明」确认交易币种取值来源于 `Ccy`、账户币种取值来源于 `AcctCcy`。
- 两个输入为不同枚举类型，「一致」指两者的货币代码相同（如 `tranCcy=CNY` 与 `acctCcy=CNY` 一致，`tranCcy=CNY` 与 `acctCcy=USD` 不一致）。
- 错误码「ER0051」定义于 `deposit-application/src/main/resources/errorcodes.properties`（`ER0051=交易币种与账户币种不一致`），与需求失败条件一致。
- 名称映射资产（requirement-name-mapping）未收录「交易币种」「账户币种」「货币币种」的属性域或实体映射；需求原文已直接给出两个输入的枚举类名，本 Spec 按需求原文业务称谓与枚举类表述，不展开来源实体绑定。
- 需求「输入」表「来源实体」列为空，两个输入的来源实体/字段未在需求中指定，由调用方提供；本需求未提供流程图或场景上下文，不涉及前序步骤取值追溯。
- 本步骤为独立判断步骤，无组件内步骤调用；当前工程尚无本步骤实现（无继承 `StepResult` 的步骤类），属于本任务待生成的代码，不构成依赖缺失。

## Requirements

### Requirement: REQ-001 交易币种与账户币种一致时返回检查结果「通过」

来源：需求「步骤描述」第 1 条（原文：否则返回检查结果为"通过"）

当交易币种（`tranCcy`）与账户币种（`acctCcy`）一致时，系统 SHALL 将本步骤结果置为成功（`succeed=true`）、`errorCode` 为 null、`errorMessage` 为 null，并返回检查结果「通过」。

#### Scenario: REQ-001-S01 币种一致返回通过

- **GIVEN** 交易币种 `tranCcy` 为人民币元（`Ccy.CNY`），账户币种 `acctCcy` 为人民币元（`AcctCcy.CNY`），两者货币代码一致
- **WHEN** 执行检查币种一致性步骤
- **THEN** 步骤结果为成功（`succeed=true`）、`errorCode` 为 null、`errorMessage` 为 null，检查结果为「通过」

### Requirement: REQ-002 交易币种与账户币种不一致时返回错误码 ER0051

来源：需求「步骤描述」第 1 条（原文：若{交易币种}与{账户币种}不一致，则返回[错误码]"ER0051"）；工程 `errorcodes.properties`（`ER0051=交易币种与账户币种不一致`）

当交易币种（`tranCcy`）与账户币种（`acctCcy`）不一致时，系统 SHALL 将本步骤结果置为业务失败（`succeed=false`）、`errorCode` 为「ER0051」，`errorMessage` 按已确认的 `错误码::业务说明` 格式为「ER0051::交易币种与账户币种不一致」，且不返回检查结果「通过」。

#### Scenario: REQ-002-S01 币种不一致返回 ER0051

- **GIVEN** 交易币种 `tranCcy` 为人民币元（`Ccy.CNY`），账户币种 `acctCcy` 为美元（`AcctCcy.USD`），两者货币代码不一致
- **WHEN** 执行检查币种一致性步骤
- **THEN** 步骤结果为失败（`succeed=false`）、`errorCode` 为「ER0051」、`errorMessage` 为「ER0051::交易币种与账户币种不一致」，且不返回检查结果「通过」

## 待确认事项

1. **必填输入缺失的行为**（关联 REQ-001、REQ-002，来源：需求「输入」表必填标记）：`tranCcy`、`acctCcy` 均标记必填，但需求未定义任一输入缺失（null/未提供）时的行为——是否由步骤前必填校验拒绝、返回技术异常或使用其它错误码；本步骤代码尚未生成，校验边界未确认。需确认：任一输入为 null/缺失时的预期结果。
2. **「通过」结果的业务输出表达**（关联 REQ-001，来源：需求「步骤描述」第 1 条）：需求未声明业务输出字段（无「输出」表），本 Spec 将「检查结果为通过」落实为步骤成功状态（`succeed=true`、`errorCode`/`errorMessage` 为 null）。需确认：调用方是否还要求以字面业务值（如字符串「通过」）返回检查结果，及该值的既定承载字段。

## 验收范围

验收以 REQ-001、REQ-002 声明的判定结果为准：覆盖交易币种与账户币种一致（步骤成功、错误字段为空、检查结果为「通过」）与不一致（步骤失败、`errorCode=ER0051`、`errorMessage` 按已确认 `错误码::业务说明` 格式）两条路径；场景输入采用枚举内具体货币代码（CNY、USD）。必填输入缺失、「通过」结果的字面业务值表达不作为已确认验收断言，待待确认事项澄清后补充。
