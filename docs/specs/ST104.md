# ST104 检查限额

## 目标与范围

**目标**：以步骤 ST104「检查限额」的正式需求（`docs/requirements/ST104.md`）为唯一业务事实来源，整理可验证的行为 Spec。本步骤为交易执行步骤中的检查类步骤，正文只有 2 个平铺子步骤、无分支跳转、无循环、无「组件内步骤调用」说明、无规则编号引用：子步骤 1 按[限额场景编码]查询【限额控制配置（RB_LIMIT_CTRL_CONF）】取得$限额控制金额$与$限额控制笔数$；子步骤 2 以[限额累计金额]与$限额控制金额$、[限额累计笔数]与$限额控制笔数$作「大于」比较，任一维度超出即返回限额检查结果为「超限」，否则为「未超限」，并按两个控制值的可空性裁剪比较维度。本 Spec 供测试设计、实现与审核共同使用。

**范围内**：

- 「## 输入」表 3 个输入字段（`limitSceneNo`、`limitSumAmt`、`limitSumNum`）的字段名、类型、必填性与在本步骤中的用途。
- 子步骤 1 的取值行为：以[限额场景编码]（`limitSceneNo`）为查询条件查询【限额控制配置】，取得限额控制金额（`limitCtrlAmt`）与限额控制笔数（`limitCtrlNum`）；本步骤为只读，不写入任何数据。
- 子步骤 2 的判定规则：金额维度与笔数维度的严格「大于」比较、两维度之间的「或」组合、以及「否则」的未超限分支。
- 两个控制值（`limitCtrlAmt`、`limitCtrlNum`）为空时的比较裁剪口径，与两者都为空时返回「未超限」的口径（源需求第 7 行明文）。
- 「## 输出」表 5 个输出字段（`limitCtrlAmt`、`limitCtrlNum`、`limitSumAmt`、`否`、`limitCheckResult`）的字段名、类型、非必填标记、取值来源与 `limitCheckResult` 的字面取值。
- 失败表达方式：源需求「## 失败处理」明确本步骤无业务失败场景，失败仅由技术异常传播表达。

**不在范围内**（源需求未要求、未唯一确定，或已按需求处理流程放行，本 Spec 不定义、不验收）：

- 【限额控制配置】的定位口径：同一[限额场景编码]查出多条时的取值口径、查无记录时的处理，源需求「## 已接受的需求处理结论」已放行（见「## 验收范围与明确不覆盖的事项」第 1 项）。
- 必填输入（`limitSumAmt`、`limitSumNum`）取到空值（`null` 或空字符串）时的行为：源需求未定义（见第 3 项）。
- 「超限」「未超限」的枚举或码值承载：全工程无该结果的枚举定义，本 Spec 按源需求书写的字面值表述，不补码值（见第 4 项）。
- 输出表的标记口径与「否」字段名的书写：源需求「## 输出」表标记一律「非必填」、笔数字段名写作「否」，本 Spec 照录，不推断、不改名（见第 2、6 项）。
- 金额比较的精度、`scale` 与舍入口径：源需求只写「大于」，未定义精度处理（见第 7 项）。
- 本步骤在更大交易中的编排位置、条件跳转、事务边界与上下文传递，以及事务、幂等、并发、性能、日志、监控、重试、降级等非功能要求：源需求未涉及（见第 8 项）。

### 判定域与比较口径

- **比较维度**：金额维度＝`limitSumAmt` 与 `limitCtrlAmt`；笔数维度＝`limitSumNum` 与 `limitCtrlNum`。两维度为**并列的「或」关系**：任一维度满足「大于」即返回「超限」，不要求两个维度同时满足。
- **「大于」为严格比较**：左操作数大于右操作数才成立；两者相等不成立，须落入「否则」的「未超限」分支。
- **空值裁剪（源需求第 7 行明文）**：`limitCtrlAmt` 为空时**不比较金额维度**；`limitCtrlNum` 为空时**不比较笔数维度**；两者都为空时**不进行任何比较**，直接返回「未超限」。裁剪后的判定由剩余维度决定；四个可空组合的完整归属见 REQ-004-S05。
- **控制值的空值形态**：源需求以「为空」表述未提供控制值的情形。本 Spec 将两个控制值的「为空」统一理解为**无值**（`null`；查询结果对象上该属性未赋值），未区分空字符串（两个控制值类型分别为 `BigDecimal` 与 `Integer`，不承载空字符串）。该口径为解释项，见「## 验收范围与明确不覆盖的事项」第 7 项。
- **判定穷尽性**：在子步骤 1 取得控制值（含控制值为空）的前提下，判定域内任一组输入都由「超限」或「未超限」唯一确定，不存在两分支都不命中的组合。

## Requirements

### Requirement: REQ-001 按[限额场景编码]查询【限额控制配置】取得限额控制值

来源：`docs/requirements/ST104.md`「## 步骤描述」子步骤 1（第 5 行）—— 原文：「1.获取限额控制值：根据[限额场景编码]查询【限额控制配置】获取对应的$限额控制金额$和$限额控制笔数$」；「## 输出」表第 21–22 行

系统 SHALL 以本步骤输入的[限额场景编码]（`limitSceneNo`）为查询条件，查询【限额控制配置（RB_LIMIT_CTRL_CONF）】，取得该场景对应的**限额控制金额**（输出字段 `limitCtrlAmt`，类型 `java.math.BigDecimal`）与**限额控制笔数**（输出字段 `limitCtrlNum`，类型 `java.lang.Integer`）。取得的两个控制值 MUST 供子步骤 2 的判定使用（MUST NOT 由子步骤 2 重新取数）。本步骤 MUST NOT 使用 `limitSceneNo` 之外的查询条件，MUST NOT 查询或写入【限额累计信息表】或其它数据表，也 MUST NOT 产生任何数据变更。

#### Scenario: REQ-001-S01 按场景编码取得限额控制金额与限额控制笔数

- **GIVEN** 输入 `limitSceneNo = "LIMIT001"`（限额场景编码），且该场景在【限额控制配置】中提供限额控制金额 `100000.00`、限额控制笔数 `10`
- **WHEN** 执行本步骤的取值动作（子步骤 1）
- **THEN** 取得限额控制金额 `limitCtrlAmt = 100000.00`（`java.math.BigDecimal`）与限额控制笔数 `limitCtrlNum = 10`（`java.lang.Integer`），两者即子步骤 2 比较所用的控制值；本步骤不写入、不修改任何数据

#### Scenario: REQ-001-S02 查询条件仅为[限额场景编码]，不要求额外的限额机构编码输入

- **GIVEN** 源需求「## 输入」表只列 3 个输入（`limitSceneNo`、`limitSumAmt`、`limitSumNum`），无「限额机构编码」等其它入参；「## 已接受的需求处理结论」（第 31–41 行）已放行【限额控制配置】的定位口径
- **WHEN** 执行本步骤的取值动作（子步骤 1）
- **THEN** 查询条件为[限额场景编码] `limitSceneNo`；本步骤 MUST NOT 因缺少限额机构编码而要求补充输入或改判为业务失败；具体定位方法、查无记录与查到多条时的取值口径不在本 Spec 的验收范围（见「## 验收范围与明确不覆盖的事项」第 1 项）

### Requirement: REQ-002 「大于」比较触发超限（金额与笔数为「或」关系）

来源：`docs/requirements/ST104.md`「## 步骤描述」子步骤 2（第 7 行）前半段 —— 原文：「若[限额累计金额]大于[限额控制金额]或[限额累计笔数]大于[限额控制笔数]，则返回限额检查结果为“超限”」

系统 SHALL 在 `limitSumAmt` 大于 `limitCtrlAmt` **或** `limitSumNum` 大于 `limitCtrlNum` 时，返回限额检查结果 `limitCheckResult = "超限"`。两个维度为并列的「或」关系：任一维度满足「大于」即返回「超限」，MUST NOT 要求两个维度同时满足；MUST NOT 因未满足的那一维度而改变结论。比较 MUST 为**严格大于**（相等不成立）。

#### Scenario: REQ-002-S01 金额超限（金额大于控制金额）

- **GIVEN** 取得的限额控制金额 `limitCtrlAmt = 100000.00`、限额控制笔数 `limitCtrlNum = 10`；输入 `limitSumAmt = 120000.00`（大于 `100000.00`）、`limitSumNum = 8`（不大于 `10`）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "超限"`；判定命中金额维度，笔数维度不成立不影响结论

#### Scenario: REQ-002-S02 笔数超限（笔数大于控制笔数）

- **GIVEN** 取得的限额控制金额 `limitCtrlAmt = 100000.00`、限额控制笔数 `limitCtrlNum = 10`；输入 `limitSumAmt = 80000.00`（不大于 `100000.00`）、`limitSumNum = 12`（大于 `10`）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "超限"`；判定命中笔数维度，金额维度不成立不影响结论

#### Scenario: REQ-002-S03 两个维度同时超出（「或」关系的一次判定）

- **GIVEN** 取得的限额控制金额 `limitCtrlAmt = 100000.00`、限额控制笔数 `limitCtrlNum = 10`；输入 `limitSumAmt = 120000.00`（大于 `100000.00`）、`limitSumNum = 12`（大于 `10`）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "超限"`；结论与仅一个维度超出时一致，实现不要求区分「单维度超出」与「双维度超出」的返回差异

### Requirement: REQ-003 未超限判定与「大于」的相等边界

来源：`docs/requirements/ST104.md`「## 步骤描述」子步骤 2（第 7 行）—— 原文：「否则返回限额检查结果为“未超限”」

系统 SHALL 在两个维度**均不满足严格「大于」**时，返回限额检查结果 `limitCheckResult = "未超限"`。因「大于」为严格比较，`limitSumAmt` 等于 `limitCtrlAmt`、或 `limitSumNum` 等于 `limitCtrlNum` 时该维度不成立；两个维度都不成立即返回「未超限」。

#### Scenario: REQ-003-S01 两个维度均低于控制值

- **GIVEN** 取得的限额控制金额 `limitCtrlAmt = 100000.00`、限额控制笔数 `limitCtrlNum = 10`；输入 `limitSumAmt = 80000.00`（小于 `100000.00`）、`limitSumNum = 8`（小于 `10`）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "未超限"`

#### Scenario: REQ-003-S02 金额等于控制金额（严格大于的边界）

- **GIVEN** 取得的限额控制金额 `limitCtrlAmt = 100000.00`、限额控制笔数 `limitCtrlNum = 10`；输入 `limitSumAmt = 100000.00`（等于 `100000.00`，不满足「大于」）、`limitSumNum = 8`（不大于 `10`）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "未超限"`；金额维度因相等不成立，笔数维度亦不成立

#### Scenario: REQ-003-S03 笔数等于控制笔数（严格大于的边界）

- **GIVEN** 取得的限额控制金额 `limitCtrlAmt = 100000.00`、限额控制笔数 `limitCtrlNum = 10`；输入 `limitSumAmt = 80000.00`（不大于 `100000.00`）、`limitSumNum = 10`（等于 `10`，不满足「大于」）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "未超限"`

#### Scenario: REQ-003-S04 两个维度均等于控制值

- **GIVEN** 取得的限额控制金额 `limitCtrlAmt = 100000.00`、限额控制笔数 `limitCtrlNum = 10`；输入 `limitSumAmt = 100000.00`、`limitSumNum = 10`（两维度均相等）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "未超限"`；两个维度的「大于」均不成立

### Requirement: REQ-004 控制值为空时裁剪比较维度，两者都为空时返回「未超限」

来源：`docs/requirements/ST104.md`「## 步骤描述」子步骤 2（第 7 行）后半段 —— 原文：「[限额控制金额]为空时不比较金额、[限额控制笔数]为空时不比较笔数，两者都为空时返回限额检查结果为“未超限”」

系统 SHALL 按取得的限额控制值的可空性裁剪比较维度：`limitCtrlAmt` 为空（无值）时 MUST NOT 比较金额维度（该维度恒不成立，MUST NOT 视为「超限」、MUST NOT 抛出异常）；`limitCtrlNum` 为空（无值）时 MUST NOT 比较笔数维度；两者的判定只由**未被裁剪的剩余维度**决定。两者**都为空**时 MUST NOT 进行任何比较，直接返回 `limitCheckResult = "未超限"`（此时 MUST NOT 因累计金额或累计笔数的取值而返回「超限」）。

#### Scenario: REQ-004-S01 金额控制值为空、笔数维度超限

- **GIVEN** 取得的 `limitCtrlAmt = null`（限额控制金额为空）、`limitCtrlNum = 10`；输入 `limitSumAmt = 120000.00`、`limitSumNum = 12`（大于 `10`）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "超限"`；金额维度被裁剪不参与判定，笔数维度成立即返回「超限」

#### Scenario: REQ-004-S02 金额控制值为空时，金额大小不影响结论

- **GIVEN** 取得的 `limitCtrlAmt = null`、`limitCtrlNum = 10`；输入 `limitSumAmt = 120000.00`（绝对值大于任何已配置控制金额，但金额维度已裁剪）、`limitSumNum = 8`（不大于 `10`）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "未超限"`；MUST NOT 因 `limitSumAmt` 的取值而返回「超限」

#### Scenario: REQ-004-S03 笔数控制值为空、金额维度超限

- **GIVEN** 取得的 `limitCtrlAmt = 100000.00`、`limitCtrlNum = null`（限额控制笔数为空）；输入 `limitSumAmt = 120000.00`（大于 `100000.00`）、`limitSumNum = 12`
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "超限"`；笔数维度被裁剪不参与判定，金额维度成立即返回「超限」

#### Scenario: REQ-004-S04 笔数控制值为空时，笔数大小不影响结论

- **GIVEN** 取得的 `limitCtrlAmt = 100000.00`、`limitCtrlNum = null`；输入 `limitSumAmt = 80000.00`（不大于 `100000.00`）、`limitSumNum = 12`（笔数已裁剪、不参与判定）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "未超限"`；MUST NOT 因 `limitSumNum` 的取值而返回「超限」

#### Scenario: REQ-004-S05 两个控制值都为空时直接返回「未超限」（可空组合穷尽）

- **GIVEN** 取得的 `limitCtrlAmt = null` 且 `limitCtrlNum = null`；输入 `limitSumAmt = 120000.00`、`limitSumNum = 12`（累计值取值任意，示例取较大值）
- **WHEN** 执行本步骤的判定动作（子步骤 2）
- **THEN** 返回 `limitCheckResult = "未超限"`；不进行任何比较、不抛出异常。两个控制值的四种可空组合按下表确定判定：

| `limitCtrlAmt`（限额控制金额） | `limitCtrlNum`（限额控制笔数） | 参与的维度 | 判定 |
|--------------------------------|--------------------------------|------------|------|
| 有值 | 有值 | 金额维度与笔数维度 | 任一维度严格大于其控制值 → 「超限」；否则「未超限」（REQ-002、REQ-003） |
| 空 | 有值 | 仅笔数维度 | `limitSumNum` 大于 `limitCtrlNum` → 「超限」；否则「未超限」（REQ-004-S01、REQ-004-S02） |
| 有值 | 空 | 仅金额维度 | `limitSumAmt` 大于 `limitCtrlAmt` → 「超限」；否则「未超限」（REQ-004-S03、REQ-004-S04） |
| 空 | 空 | 无（不比较） | 「未超限」（REQ-004-S05） |

### Requirement: REQ-005 输出契约

来源：`docs/requirements/ST104.md`「## 输出」表（第 17–25 行，数据行第 21–25 行）

#### Scenario: REQ-005-S01 输出字段的字段名、类型与取值来源

#### Scenario: REQ-005-S02 累计金额与笔数按本次输入回显，不查询【限额累计信息表】

### Requirement: REQ-006 无业务失败场景，失败仅由技术异常传播表达

来源：`docs/requirements/ST104.md`「## 失败处理」（第 27–29 行，正文第 29 行）—— 原文：「本步骤无业务失败场景，失败仅由技术异常传播表达。」

系统 MUST NOT 因本步骤的业务判定产生业务失败：判定结论为「超限」时，本步骤 MUST 以 `limitCheckResult = "超限"` 表达结论，MUST NOT 返回错误码、MUST NOT 以步骤失败或抛出业务异常表达「超限」（源需求正文未引用 `ER0058=交易超出限额控制`，MUST NOT 据此把「超限」改判为业务失败）。本步骤不定义业务失败分支与错误码；执行过程中的技术异常（如查询【限额控制配置】时发生的技术异常）MUST 按技术异常向上传播，MUST NOT 被转换为「超限」或「未超限」的业务结论。

#### Scenario: REQ-006-S01 判定为「超限」不构成业务失败

- **GIVEN** 取得的限额控制金额 `100000.00`、限额控制笔数 `10`；输入 `limitSumAmt = 120000.00`、`limitSumNum = 12`
- **WHEN** 执行本步骤
- **THEN** 步骤正常完成（步骤结果 `succeed = true`、`errorCode = null`、`errorMessage = null`），仅返回 `limitCheckResult = "超限"`；不返回错误码、不抛出业务异常

#### Scenario: REQ-006-S02 技术异常按技术异常传播

- **GIVEN** 执行子步骤 1 的查询过程中发生技术异常（如数据访问异常）
- **WHEN** 执行本步骤
- **THEN** 该异常按技术异常向上传播，本步骤 MUST NOT 将其吞掉并改返回 `limitCheckResult = "超限"` 或 `"未超限"`，MUST NOT 新增业务失败分支或错误码
