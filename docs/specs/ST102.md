# ST102 检查账户机构是否可匹配到限额场景配置

- 步骤类型：交易执行步骤（检查类：账户查询 → 限额控制配置查询 → 机构上级链逐级遍历）

## 目标与范围

**目标**：以正式需求 `docs/requirements/ST102.md`（sha256 `88b1a71eb8f771330324dc2246d7bcb43db6054a919e02425321d0a060af8090`）的最终业务正文为依据，整理可验证的行为 Spec，供测试设计、实现与审核共用同一份取数、遍历与返回契约。

步骤以账号（`baseAcctNo`）为唯一入参：先由账号定位【账户信息】取得账户开立行行号；再按该机构号查【限额控制配置表】取「启用标志＝Y-启用」的配置所承载的限额场景编码；账户开立行未匹配到启用配置时，沿【机构信息表】的归属上级机构号逐级向上取得上级机构集合（不含账户开立行自身），按机构层级从高到低（总行、分行、支行）逐级查配置，返回首个匹配到的限额场景编码；账户开立行已匹配、或上级链全部未匹配时，分别返回已匹配的编码与空值。全步骤只读，除查询与结果返回外无业务副作用。

**本次 Spec 覆盖**：

- 输入契约：`baseAcctNo` 的字段名、类型、必填性、来源实体列与用途；占位符 {账号} 到 `baseAcctNo` 的绑定。
- 子步骤 1：按 {账号} 查询【账户信息】取账户开立行行号；`{账号}` 唯一确定一条账户记录，查不到记录或查到多条记录时返回错误码 `ER0048` 并结束本步骤。
- 子步骤 2：按账户开立行行号查询【限额控制配置表】取 `$启用标志$` 等于「Y-启用」的 `$限额场景编码$`；同一机构查出多条启用配置时按 [最后修改时间戳] 取最近维护的一条。
- 子步骤 3：限额场景编码非空 → 返回该编码并结束本步骤（不再执行子步骤 4、5）；为空 → 进入子步骤《获取上级机构集合》。
- 子步骤 4：按账户开立行行号查询【机构信息表】取得归属上级机构号，再按该归属上级机构号逐级向上，直到查不到归属上级机构号为止；所得全部上级机构构成 [上级机构集合]，不含账户开立行自身；查不到机构记录或没有取到任何上级机构时集合为空，子步骤 5 遍历零次并返回限额场景编码为空。
- 子步骤 5：按 [上级机构集合] 中元素的机构层级从高到低（总行、分行、支行）遍历；每元素按其机构号查询【限额控制配置表】取启用配置的限额场景编码（同一机构多条启用配置时按 [最后修改时间戳] 取最近维护的一条）；为空则继续下一条，非空则中断遍历并返回；遍历结束仍未命中则返回空值。
- 依赖调用映射（三张表的查询对象、条件与字段）、中间结果传递、子步骤执行顺序与短路行为。
- 输出契约：`limitSceneNo` 的取值口径，以及源需求「## 输出」表 8 个字段的名称、类型、标记照录。
- 失败契约：业务失败仅为子步骤 1 的查无/多条（`ER0048`）；其余失败仅由技术异常传播表达。

**不在本次范围**（源需求未涉及或未定义，本 Spec 不作要求，详见「## 验收范围与明确不覆盖的事项」）：

- 取得限额场景编码之后的上游编排（限额检查、授权、拒绝、提示、跳转等），以及本步骤在交易中的调用位置与调用方。
- 输入 `baseAcctNo` 取空（无值）时的行为：源需求标其「必填」，未定义空值处理。
- 三张表（【账户信息】【限额控制配置表】【机构信息表】）的新增、修改、删除与配置维护：本步骤只读。
- 归属上级机构号所指机构在【机构信息表】无记录（悬空引用）、归属链成环、上级机构层级码为「-1 虚拟机构层级」等异常链形态的处理（不覆盖项 1、2）。
- 同一机构层级上存在多个上级机构时的先后顺序（源需求只规定层级顺序，见不覆盖项 3）。
- 输出表中除 `limitSceneNo` 外其余 7 个字段是否对外回显、其取值与落库位置（不覆盖项 4）。
- 非功能要求（性能、并发、幂等、事务边界、日志、监控、重试、降级），源需求未定义。
- 组件内步骤调用 / 规则调用：**不适用**。源需求「## 补充说明」未含组件内步骤调用说明；子步骤 3 的「跳转至子步骤《获取上级机构集合》」指向本步骤内的子步骤 4，不是跨步骤调用，不存在需保留的最终目标编号、调用位置、参数来源与结果用途；源需求正文未引用任何其它任务编号。

- **技术可行性核对（非规范性）**：RB_LIMIT_CTRL_CONF 主键为「限额机构编码＋限额场景编码」，同一机构可存在多条不同场景编码的配置（含未启用者），故「同一机构多条启用配置」可达，REQ-003-S02、REQ-006-S04 的取用规则可判定；`lastUpdTimestamp` 为定长 26 位时间戳字符串（`LAST_UPD_TIMESTAMP VARCHAR(26) NOT NULL`），「最近维护」按该字段取值的时间先后判定。

### Requirement: REQ-002 子步骤 1：按账号查询【账户信息】取账户开立行行号

来源：`docs/requirements/ST102.md`「## 步骤描述」1（第 5 行）—— 原文：「1.获取账户开立行行号：根据{账号}查询【账户信息】获取$账户开立行行号$，{账号}唯一确定一条账户记录，查不到账户记录或查到多条账户记录时返回[错误码]"ER0048"（账户不存在）并结束本步骤」；「## 失败处理」（第 54 行）

系统 SHALL 以 {账号}（`baseAcctNo`）为条件查询【账户信息】（对公存款账户主表 RB_BUS_ACCT），{账号} 唯一确定一条账户记录：当且仅当恰好查到一条记录时，取该记录的账户开立行行号（`acctBranch`，`TranBranch`）作为本步骤的账户开立行行号、继续执行子步骤 2；当查不到记录或查到多条记录时，系统 SHALL 返回错误码 `ER0048`（账户不存在）并结束本步骤。该查询 MUST 只读，MUST NOT 新增、修改或删除任何记录。

#### Scenario: REQ-002-S01 唯一命中一条记录时取账户开立行行号并继续

- **GIVEN** 以 `baseAcctNo = "6201000000001234"`（示例数据）查询【账户信息】恰好返回 1 条记录，该记录的账户开立行行号为 `TranBranch.VALUE_352105`（`"352105"`，示例数据）
- **WHEN** 执行子步骤 1 的账号查询
- **THEN** 系统取该唯一记录的账户开立行行号 `"352105"` 作为后续子步骤的查询键，并进入子步骤 2
- **AND** 不使用其它任何记录的取值，查询只读、不产生写入

#### Scenario: REQ-002-S02 查不到记录时返回 ER0048 并结束本步骤

- **GIVEN** 以 `baseAcctNo = "6201000000001234"` 查询【账户信息】返回 0 条记录
- **WHEN** 执行子步骤 1 的账号查询
- **THEN** 步骤返回错误码 `ER0048`（账户不存在）并结束：`succeed = false`、`errorCode = "ER0048"`
- **AND** 不产出限额场景编码，不执行子步骤 2 的限额控制配置查询，不执行子步骤 3 的判定，不执行子步骤 4 的机构查询与子步骤 5 的遍历

#### Scenario: REQ-002-S03 查到多条记录时返回 ER0048 并结束本步骤

- **GIVEN** 以 `baseAcctNo = "6201000000001234"` 查询【账户信息】返回多于 1 条记录（如 2 条，账户开立行行号分别为 `TranBranch.VALUE_352105`、`TranBranch.VALUE_351155`，示例数据）
- **WHEN** 执行子步骤 1 的账号查询
- **THEN** 步骤返回错误码 `ER0048`（账户不存在）并结束：`succeed = false`、`errorCode = "ER0048"`

### Requirement: REQ-003 子步骤 2：按账户开立行行号查询【限额控制配置表】取启用的限额场景编码

来源：`docs/requirements/ST102.md`「## 步骤描述」2（第 7 行）—— 原文：「2.获取场景限额编码：根据[账户开立行行号]查询【限额控制配置表】获取$启用标志$等于"Y-启用"的$限额场景编码$；同一机构查出多条启用配置时，按[最后修改时间戳]取最近维护的一条配置的$限额场景编码$」

系统 SHALL 以子步骤 1 取得的账户开立行行号为条件查询【限额控制配置表】（RB_LIMIT_CTRL_CONF），取 `$启用标志$`（`validFlag`）等于「Y-启用」（按码值 `"Y"` 判定）的配置记录，并以该记录的 `$限额场景编码$`（`limitSceneNo`）作为本子步骤的限额场景编码。同一机构查出多条启用配置时，系统 MUST 按 [最后修改时间戳]（`lastUpdTimestamp`）取时间上最近维护的一条配置的限额场景编码；未启用的配置 MUST NOT 参与取用。零条启用配置命中时（该机构无任何配置记录，或全部记录的启用标志不为 `"Y"`），本子步骤未取到限额场景编码，该结果即子步骤 3 所判定的「限额场景编码为空」。定位条件 MUST 为「限额机构编码＝账户开立行行号」与「启用标志为启用」两项，MUST NOT 追加其它缩窄条件；查询 MUST 为只读。

#### Scenario: REQ-003-S01 账户开立行有唯一启用配置时取到限额场景编码

- **GIVEN** 子步骤 1 取得的账户开立行行号为 `"352105"`（示例数据）；【限额控制配置表】中 `limitBranchId = "352105"` 且 `validFlag = "Y"` 的配置恰有 1 条，其 `limitSceneNo = "LSN1001"`、`lastUpdTimestamp = "2026-09-20 10:00:00.000000"`（示例数据）
- **WHEN** 执行子步骤 2
- **THEN** 系统取该配置记录的限额场景编码 `"LSN1001"` 作为本子步骤的限额场景编码，供子步骤 3 判定与返回（REQ-004）
- **AND** 查询仅使用「限额机构编码＝`"352105"`」与「启用标志＝`"Y"`」两项条件，不追加其它字段参与定位，查询只读

#### Scenario: REQ-003-S02 同一机构多条启用配置时取最近维护的一条

- **GIVEN** 账户开立行行号为 `"352105"`（示例数据）；【限额控制配置表】中 `limitBranchId = "352105"` 的记录有 3 条：记录 α（`limitSceneNo = "LSN1001"`、`validFlag = "Y"`、`lastUpdTimestamp = "2026-09-20 10:00:00.000000"`）、记录 β（`limitSceneNo = "LSN1002"`、`validFlag = "Y"`、`lastUpdTimestamp = "2026-10-05 09:30:00.000000"`）、记录 γ（`limitSceneNo = "LSN1003"`、`validFlag = "N"`、`lastUpdTimestamp = "2026-10-08 08:00:00.000000"`）（均为示例数据）
- **WHEN** 执行子步骤 2
- **THEN** 系统在两条启用配置（α、β）中取 [最后修改时间戳] 最近维护的一条，即记录 β，取得限额场景编码 `"LSN1002"`
- **AND** 记录 α 的 `"LSN1001"` MUST NOT 被取用；未启用的记录 γ（`validFlag = "N"`）MUST NOT 参与取用，其较晚的时间戳 MUST NOT 影响选择结果

#### Scenario: REQ-003-S03 无启用配置时限额场景编码为空

- **GIVEN** 账户开立行行号为 `"352105"`（示例数据）；【限额控制配置表】中 `limitBranchId = "352105"` 的启用配置命中 0 条——包含两种来源：该机构无任何配置记录，或该机构的记录启用标志均不为 `"Y"`（如仅有一条 `limitSceneNo = "LSN1003"`、`validFlag = "N"`）
- **WHEN** 执行子步骤 2
- **THEN** 本子步骤未取到限额场景编码（未命中任何 `validFlag = "Y"` 的配置记录）
- **AND** 该结果在子步骤 3 中判定为「限额场景编码为空」，据此进入子步骤《获取上级机构集合》（REQ-004-S02）；本情形 MUST NOT 判为业务失败、MUST NOT 返回 `ER0048` 或其它错误码

### Requirement: REQ-004 子步骤 3：账户开立行匹配到限额场景时返回并结束本步骤

来源：`docs/requirements/ST102.md`「## 步骤描述」3（第 9 行）

系统 SHALL 在子步骤 2 之后判定限额场景编码是否为空：非空时返回该限额场景编码并结束本步骤，且 MUST NOT 执行子步骤《获取上级机构集合》（子步骤 4）与子步骤 5，MUST NOT 查询【机构信息表】；为空时转到子步骤《获取上级机构集合》，由子步骤 4、5 继续匹配。

#### Scenario: REQ-004-S01 账户开立行匹配到限额场景时直接返回

- **GIVEN** 子步骤 2 取得的限额场景编码为 `"LSN1002"`（示例数据，非空）
- **WHEN** 执行子步骤 3 的判定
- **THEN** 步骤返回限额场景编码 `"LSN1002"` 并结束本步骤（`succeed = true`、错误码为空）
- **AND** MUST NOT 按账户开立行行号查询【机构信息表】，MUST NOT 取得上级机构集合，MUST NOT 执行子步骤 5 的上级机构遍历与配置查询

#### Scenario: REQ-004-S02 账户开立行未匹配到限额场景时转入上级机构集合

- **GIVEN** 子步骤 2 未取得限额场景编码（子步骤 2 命中 0 条启用配置，REQ-003-S03）
- **WHEN** 执行子步骤 3 的判定
- **THEN** 系统判定 [限额场景编码] 为空，并转入子步骤 4《获取上级机构集合》
- **AND** 该转人不返回错误码、不结束本步骤，后续按 REQ-005 构建上级机构集合、按 REQ-006 遍历匹配

### Requirement: REQ-005 子步骤 4：沿归属上级机构号逐级向上构建上级机构集合

来源：`docs/requirements/ST102.md`「## 步骤描述」4（第 11 行）

系统 SHALL 按账户开立行行号查询【机构信息表】（FM_BRANCH）取得该机构的归属上级机构号（`attachedTo`），再按该归属上级机构号查询其归属上级机构号，如此沿归属上级机构号逐级向上，直到查不到归属上级机构号为止；逐级取得的全部上级机构构成 [上级机构集合]，该集合 MUST NOT 包含账户开立行自身。当按账户开立行行号查不到机构记录，或没有取到任何上级机构（账户开立行机构记录的归属上级机构号为空）时，[上级机构集合] MUST 为空，子步骤 5 遍历零次并返回限额场景编码为空；该情形 MUST NOT 判为业务失败、MUST NOT 返回错误码。逐级查询 MUST 只读，且每次查询的定位条件 MUST 为「归属机构号＝上一轮取得的归属上级机构号」。

#### Scenario: REQ-005-S01 沿归属上级机构号逐级取得全部上级机构

- **GIVEN** 账户开立行行号为 `"352105"`（示例数据）；【机构信息表】中 `branch = "352105"` 的机构记录归属上级机构号为 `"352001"`，`branch = "352001"` 的机构记录归属上级机构号为 `"351001"`，`branch = "351001"` 的机构记录归属上级机构号为空（均为示例数据）
- **WHEN** 执行子步骤 4
- **THEN** 系统沿归属上级机构号逐级向上，取得上级机构 `"352001"` 与 `"351001"`（各含其机构层级与机构号），构成 [上级机构集合]，遍历顺序为 `"351001"`（总行）在前、`"352001"`（分行）在后（REQ-006）
- **AND** [上级机构集合] MUST NOT 包含账户开立行 `"352105"` 自身；逐级查询只读、不产生写入

#### Scenario: REQ-005-S02 账户开立行在【机构信息表】查不到记录时集合为空

- **GIVEN** 账户开立行行号为 `"352105"`（示例数据）；【机构信息表】中不存在 `branch = "352105"` 的机构记录
- **WHEN** 执行子步骤 4
- **THEN** 系统查不到机构记录，[上级机构集合] 为空
- **AND** 子步骤 5 遍历零次，本步骤返回限额场景编码为空（`succeed = true`、错误码为空）；本情形 MUST NOT 判为业务失败，MUST NOT 返回 `ER0048` 或其它错误码，MUST NOT 访问【限额控制配置表】

#### Scenario: REQ-005-S03 机构记录存在但没有上级机构时集合为空

- **GIVEN** 账户开立行行号为 `"352105"`（示例数据）；【机构信息表】中存在 `branch = "352105"` 的机构记录，但其归属上级机构号为空（`null`）
- **WHEN** 执行子步骤 4
- **THEN** 系统没有取到任何上级机构，[上级机构集合] 为空
- **AND** 子步骤 5 遍历零次，本步骤返回限额场景编码为空；本情形同样不是业务失败、不返回错误码

### Requirement: REQ-006 子步骤 5：按机构层级从高到低遍历上级机构集合匹配限额场景

来源：`docs/requirements/ST102.md`「## 步骤描述」5（第 13 行）、5-1（第 15 行）、5-2（第 17 行）、5-3（第 18 行）

系统 SHALL 按 [上级机构集合] 中元素的机构层级从高到低——总行、分行、支行（对应 `HierarchyCode` 的 `0`、`1`、`2`）——逐个遍历：对当前元素，以其机构号（该元素的归属机构号 `branch`）为条件查询【限额控制配置表】取 `$启用标志$` 等于「Y-启用」（按码值 `"Y"` 判定）的配置的限额场景编码；同一机构查出多条启用配置时 MUST 按 [最后修改时间戳]（`lastUpdTimestamp`）取最近维护的一条。若所得限额场景编码为空，系统 SHALL 继续遍历下一条；若非空，系统 SHALL 中断本次遍历并返回该限额场景编码。遍历全部元素后仍未命中时，系统 SHALL 结束遍历并返回限额场景编码为空。全部查询 MUST 只读，且 MUST NOT 追加除「限额机构编码＝当前元素机构号」与「启用标志＝启用」之外的定位条件。

#### Scenario: REQ-006-S01 最高层级机构命中时中断遍历并返回

- **GIVEN** 子步骤 4 取得 [上级机构集合] 含两个元素：`"351001"`（机构层级＝总行，`HierarchyCode.VALUE_0`）与 `"352001"`（机构层级＝分行，`HierarchyCode.VALUE_1`）（示例数据）；【限额控制配置表】中 `limitBranchId = "351001"` 有启用配置 `limitSceneNo = "LSN2001"`，`limitBranchId = "352001"` 亦有启用配置 `limitSceneNo = "LSN3001"`（示例数据）
- **WHEN** 执行子步骤 5 的遍历
- **THEN** 系统先遍历总行 `"351001"`，命中启用配置取得限额场景编码 `"LSN2001"`，随即中断本次遍历并返回 `"LSN2001"`
- **AND** MUST NOT 再查询 `limitBranchId = "352001"` 的配置，MUST NOT 返回 `"LSN3001"`——遍历顺序为「总行 → 分行 → 支行」，不是由低到高

#### Scenario: REQ-006-S02 高层级未命中、低层级命中时继续遍历后返回

- **GIVEN** [上级机构集合] 含 `"351001"`（总行）与 `"352001"`（分行）（示例数据）；【限额控制配置表】中 `limitBranchId = "351001"` 无启用配置（无记录，或记录的启用标志均不为 `"Y"`），`limitBranchId = "352001"` 有启用配置 `limitSceneNo = "LSN3001"`（示例数据）
- **WHEN** 执行子步骤 5 的遍历
- **THEN** 系统对总行 `"351001"` 未取到限额场景编码，继续遍历下一条（分行 `"352001"`），命中后中断遍历并返回 `"LSN3001"`

#### Scenario: REQ-006-S03 全部上级机构均未命中时返回空值

- **GIVEN** [上级机构集合] 含 `"351001"`（总行）与 `"352001"`（分行）（示例数据）；【限额控制配置表】中这两个机构号均无 `validFlag = "Y"` 的配置记录
- **WHEN** 执行子步骤 5 的遍历
- **THEN** 系统逐个遍历两个元素均未取到限额场景编码，结束遍历并返回限额场景编码为空（未赋值，`null`）
- **AND** 本步骤以 `succeed = true`、错误码为空正常结束；本情形 MUST NOT 判为业务失败，MUST NOT 返回 `ER0048` 或其它错误码

#### Scenario: REQ-006-S04 某上级机构多条启用配置时取最近维护的一条

- **GIVEN** [上级机构集合] 含 `"351001"`（总行，无启用配置）与 `"352001"`（分行）（示例数据）；`limitBranchId = "352001"` 有两条启用配置：`limitSceneNo = "LSN3002"`（`lastUpdTimestamp = "2026-09-25 14:00:00.000000"`）与 `limitSceneNo = "LSN3001"`（`lastUpdTimestamp = "2026-10-06 11:20:00.000000"`），另有未启用记录 `limitSceneNo = "LSN3003"`（`validFlag = "N"`、`lastUpdTimestamp = "2026-10-09 09:00:00.000000"`）（均为示例数据）
- **WHEN** 执行子步骤 5 遍历到分行 `"352001"`
- **THEN** 系统在其两条启用配置中取 [最后修改时间戳] 最近维护的一条（`"LSN3001"`），中断遍历并返回 `"LSN3001"`
- **AND** `"LSN3002"` MUST NOT 被取用；未启用记录 `"LSN3003"` MUST NOT 参与取用

### Requirement: REQ-007 编排顺序、数据传递与短路行为

来源：`docs/requirements/ST102.md`「## 步骤描述」1～5（第 5、7、9、11、13、15、17、18 行）

系统 SHALL 按「子步骤 1 → 子步骤 2 → 子步骤 3 →（仅当限额场景编码为空时）子步骤 4 → 子步骤 5」的顺序执行，并把子步骤 1 取得的账户开立行行号作为子步骤 2、4 的查询键、把子步骤 4 取得的 [上级机构集合] 作为子步骤 5 的遍历对象、把命中的限额场景编码作为本步骤返回值。子步骤 1 触发 `ER0048` 业务失败、或子步骤 3 判定限额场景编码非空时，本步骤 MUST 短路结束，其余子步骤与查询 MUST NOT 执行。

#### Scenario: REQ-007-S01 正常路径按顺序执行并传递中间结果

- **GIVEN** `baseAcctNo = "6201000000001234"`（示例数据）查询【账户信息】唯一命中一条记录，其账户开立行行号为 `"352105"`；该机构无启用配置，其上级链为 `"352001"`（分行）→ `"351001"`（总行）（示例数据）
- **WHEN** 步骤正常执行
- **THEN** 系统依次执行：按账号查【账户信息】取账户开立行行号 `"352105"` → 按 `"352105"` 查【限额控制配置表】（未命中启用配置）→ 子步骤 3 判定为空 → 按 `"352105"` 查【机构信息表】并逐级向上取得 [上级机构集合] `{"351001" 总行, "352001" 分行} ` → 按层级从高到低遍历并返回首个命中的限额场景编码
- **AND** 每一步均以前一步的结果作为查询键或遍历对象；子步骤 2、4 使用的机构号同为账户开立行行号，子步骤 5 使用的机构号为当前遍历元素自身的机构号

#### Scenario: REQ-007-S02 子步骤 1 业务失败时短路，后续查询均不执行

- **GIVEN** `baseAcctNo = "6201000000001234"`（示例数据）查询【账户信息】返回 0 条或多于 1 条记录
- **WHEN** 步骤执行到子步骤 1 的账号查询
- **THEN** 步骤以 `ER0048` 结束
- **AND** MUST NOT 查询【限额控制配置表】，MUST NOT 查询【机构信息表】，MUST NOT 构建 [上级机构集合]，MUST NOT 执行子步骤 5 的遍历，不产出限额场景编码

#### Scenario: REQ-007-S03 子步骤 3 命中时短路，不进入上级机构遍历

- **GIVEN** 子步骤 2 在账户开立行 `"352105"` 命中启用配置，取得限额场景编码 `"LSN1001"`（示例数据）
- **WHEN** 步骤执行到子步骤 3
- **THEN** 步骤返回 `"LSN1001"` 并结束
- **AND** MUST NOT 查询【机构信息表】，MUST NOT 执行子步骤 4 与子步骤 5，MUST NOT 因存在上级机构而改写返回值

### Requirement: REQ-008 错误码与失败处理契约

来源：`docs/requirements/ST102.md`「## 失败处理」（第 54 行）；「## 步骤描述」1（第 5 行）

本步骤的业务失败场景仅为「按 {账号} 查询【账户信息】时查不到账户记录或查到多条账户记录」，此时系统 SHALL 返回错误码 `ER0048`（账户不存在）并结束本步骤，`succeed = false`、`errorCode = "ER0048"`、错误信息为「账户不存在」。除该情形外，本步骤 MUST NOT 定义其它业务失败分支：上级机构链未匹配、[上级机构集合] 为空、限额场景编码为空等均属正常返回；其余失败 MUST 仅由技术异常传播表达（不捕获、不转译为业务错误码）。

#### Scenario: REQ-008-S01 唯一业务失败以 ER0048 状态返回

- **GIVEN** 按 {账号} 查询【账户信息】查不到账户记录或查到多条账户记录（业务失败条件成立）
- **WHEN** 本步骤结束执行
- **THEN** 步骤结果为 `succeed = false`、`errorCode = "ER0048"`、错误信息「账户不存在」；不产出限额场景编码
- **AND** 不因该失败返回任何限额场景编码取值，也不把该情形转译为「未匹配到限额场景」的空值结论

#### Scenario: REQ-008-S02 技术异常不转译为业务错误码，向上传播

- **GIVEN** 步骤执行中的依赖数据查询或运行环境抛出技术异常（如数据访问异常、运行时异常），且不属于上述 `ER0048` 业务失败场景
- **WHEN** 该技术异常在步骤执行过程中发生
- **THEN** 步骤不捕获、不转译该异常为业务错误码或限额场景编码（不设置 `ER0048`、不返回空值冒充正常结果），异常向上传播给调用方
- **AND** 本步骤不据此新增重试、兜底默认值或吞异常后的默认返回

### Requirement: REQ-009 输出契约

来源：`docs/requirements/ST102.md`「## 输出」表（第 28–37 行，8 个数据行）；「## 步骤描述」2、3、5

系统 SHALL 按源需求「## 输出」表照录 `limitSceneNo`（`java.lang.String`，非必填）、`limitBranchId`（`com.dcits.depsit.enums.TranBranch`，非必填）、`limitBranchRange`（`com.dcits.depsit.enums.LimitBranchRange`，非必填）、`validFlag`（`java.lang.String`，非必填）、`baseAcctNo`（`java.lang.String`，非必填）、`acctBranch`（`com.dcits.depsit.enums.TranBranch`，非必填）、`branch`（`com.dcits.depsit.enums.TranBranch`，非必填）、`attachedTo`（`com.dcits.depsit.enums.TranBranch`，非必填）8 个字段的字段名、类型、标记与业务名称，MUST NOT 改名、改类型或收紧「非必填」标记。其中 `limitSceneNo` 承载本步骤的业务返回内容：匹配到启用配置时，其取值 MUST 为该配置记录的限额场景编码（子步骤 2 或子步骤 5 命中，REQ-003、REQ-006）；未匹配到任何启用配置（含上级链全部未命中、[上级机构集合] 为空）时，其取值 MUST 为空值。`limitBranchId` 按其来源实体含义表述为命中的配置记录的限额机构编码——在命中的配置记录上该值即本次查询所用的机构号（子步骤 2 为账户开立行行号，子步骤 5 为当前遍历元素的机构号），是否对外回显不作断言（不覆盖项 4）。其余字段照录字段契约，本 Spec 不为其补写回显或落库要求。

#### Scenario: REQ-009-S01 输出字段名、类型与标记照录

- **GIVEN** 源需求「## 输出」表（第 30–37 行）列出 8 个数据行，标记列一律为「非必填」，来源实体列分别为 限额控制配置（RB_LIMIT_CTRL_CONF）、对公存款账户主表（RB_BUS_ACCT）、机构信息表（FM_BRANCH）
- **WHEN** 解析本步骤的输出契约
- **THEN** 8 个字段以 `limitSceneNo`、`limitBranchId`、`limitBranchRange`、`validFlag`、`baseAcctNo`、`acctBranch`、`branch`、`attachedTo` 的字段名，及其在源需求声明的类型与「非必填」标记被照录
- **AND** 不新增源需求未声明的输出字段；不把「来源实体」列（取数来源表）当作落库位置；`limitBranchRange`、`validFlag`、`baseAcctNo`、`acctBranch`、`branch`、`attachedTo` 的对外回显口径不作断言（不覆盖项 4）

#### Scenario: REQ-009-S02 limitSceneNo 的取值来自命中的配置记录

- **GIVEN** 子步骤 2 在账户开立行 `"352105"` 命中启用配置 `limitSceneNo = "LSN1001"`（示例数据）
- **WHEN** 步骤返回限额场景编码
- **THEN** 输出 `limitSceneNo` 的取值 MUST 为 `"LSN1001"`；命中的配置记录自身的限额机构编码即本次查询键 `"352105"`
- **AND** 当子步骤 2 未命中、子步骤 5 在上级机构 `"352001"` 命中 `limitSceneNo = "LSN3001"`（示例数据）时，输出 `limitSceneNo` 的取值 MUST 为 `"LSN3001"`，该配置记录自身的限额机构编码即 `"352001"`；当子步骤 2 与子步骤 5 均未命中时，输出 `limitSceneNo` MUST 为空值

## 验收范围与明确不覆盖的事项

本 Spec 为测试设计依据，不是已生成的测试用例，也不是测试执行结果。**本 Spec 的验收以 REQ-001～REQ-009 的 24 个场景为准**：输入契约与占位符绑定、账号查询的三种结果（唯一命中、查无、多条）、限额控制配置查询的三种结果（唯一命中、多条取最近、无启用配置）、子步骤 3 的两条分支、上级机构集合的三种构建结果（逐级取得、查不到机构记录、无上级机构）、按层级从高到低遍历的四种结果（最高层级命中、低层级命中、全部未命中、同名多条取最近）、编排顺序与两处短路、唯一业务失败与技术异常两条失败路径、输出契约与 `limitSceneNo` 取值。

**明确不覆盖的事项**（源需求未要求或未定义，本 Spec 不作规定，验收时不断言）：

1. **归属上级机构号悬空引用**：当某轮取得的归属上级机构号在【机构信息表】查不到对应机构记录时，该机构是否计入 [上级机构集合]、逐级向上是否就此终止，源需求未定义（步骤描述 4 只规定「查不到机构记录或没有取到任何上级机构时 [上级机构集合] 为空」，未区分该情形与账户开立行自身查不到记录的情形）。本 Spec 不作规定，测试设计不据此构造断言。
2. **异常机构链形态**：归属上级机构号成环（逐级向上永不终止）、或上级机构的机构层级码为 `HierarchyCode.NEGATIVE_1`（`-1` 虚拟机构层级，源需求未列入「总行、分行、支行」的层级序列）时的处理与排序位置，源需求均未定义。
3. **同一机构层级存在多个上级机构时的先后顺序**：源需求只规定层级顺序「总行、分行、支行」，未规定同层内多个机构的遍历次序。
4. **输出表中除 `limitSceneNo` 外 7 个字段的回显与落库**：源需求「## 步骤描述」只把 [限额场景编码] 列为返回内容，未规定 `limitBranchId`、`limitBranchRange`、`validFlag`、`baseAcctNo`、`acctBranch`、`branch`、`attachedTo` 是否对外回显、回显时的取值口径与落库位置；输出表「来源实体」列记载的是取数来源表，不是落库位置。REQ-009 只照录字段契约并给出 `limitSceneNo` 与 `limitBranchId` 的取值口径。
5. **输入取空的行为**：`baseAcctNo` 标「必填」，源需求未定义其取到 `null` 或空字符串时的校验与行为，属合法输入域之外。
6. **「最近维护」的并列与空值口径**：源需求只写「按 [最后修改时间戳] 取最近维护的一条」；当同一机构的多条启用配置 [最后修改时间戳] 相同、或该字段取到空值时的取用口径源需求未定义（技术核对确认 `LAST_UPD_TIMESTAMP` 为 `NOT NULL` 的 26 位时间戳字符串，「最近维护」按该字段取值的时间先后判定）。
7. **【机构信息表】按机构号查询返回多条时的处理**：源需求未涉及；技术核对该表主键为归属机构号 `branch`，一次查询至多一条记录，本 Spec 不额外定义缺失/多条分支。
8. **「启用标志」的完整取值域**：源需求只书写「Y-启用」一个取值，本 Spec 只把码值 `"Y"` 作为命中条件，其余取值一律不构成命中，不枚举、不外推。
9. **错误信息文本与异常形式的非功能口径**：源需求只给出错误码 `ER0048`；「账户不存在」取自 `errorcodes.properties`（第 48 行），属技术约束核对；技术异常的传播形式、重试与降级、事务边界、并发、幂等、日志、监控等非功能要求源需求均未定义。
10. **「限额场景编码为空」的形态（解释项）**：本 Spec 将其解释为「未取得任何启用配置记录，因而未取到限额场景编码」，在承载对象上表现为空值（`null`）。技术核对确认 `RB_LIMIT_CTRL_CONF.LIMIT_SCENE_NO` 为 `NOT NULL`，故不存在「命中配置记录而其限额场景编码为空」的情形；该解释仅为测试设计提供可执行口径，不新增业务取值。
11. **上游编排与本步骤的调用位置**：取得限额场景编码后的限额检查、授权、拒绝、提示、跳转等，以及本步骤在交易中的调用位置、调用方与调用次数，源需求未定义；源需求无「组件内步骤调用」补充说明，本 Spec 不绑定任何前置或后续步骤编号。
