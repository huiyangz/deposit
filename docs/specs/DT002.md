# DT002 检查账户是否能够入账

## 目标与范围

本 Spec 定义决策规则「检查账户是否能够入账」（DT002）的输入输出契约与入账判定行为。规则根据账户状态（acctStatus，枚举 `com.dcits.deposit.enums.AcctStatus`）、账户转账止付标志、账户转账不收不付标志，输出入账标志（"允许"/"不允许"）。

范围仅覆盖需求文档「规则描述」条目 a–g 所列规则及其已确认的前提条件与结论。规则 a/b/g（均涉及"新建"状态）存在条件相同而结论相反的冲突，未确认前不作为已确认条款写入验收预期，详见「待确认事项」TBD-1。未列出的状态与标志组合、标志空值语义等缺口一并见「待确认事项」。

## Requirements

### Requirement: REQ-001 决策输入与输出契约
来源：需求文档「输入」「输出」表及「补充说明」；工程枚举 `com.dcits.deposit.enums.AcctStatus`。

系统 SHALL 依据必填输入 acctStatus（类型 `com.dcits.deposit.enums.AcctStatus`）以及非必填输入 账户转账止付标志、账户转账不收不付标志（类型 `java.lang.String`）执行入账判定，并输出 入账标志（类型 `java.lang.String`，取值"允许"或"不允许"）；acctStatus 的取值 SHALL 属于枚举 `com.dcits.deposit.enums.AcctStatus`。

#### Scenario: REQ-001-S01 输入输出契约可用性（待激活、止付是、不收不付否）
- **GIVEN** 调用方提供 acctStatus 为"待激活"（对应枚举值 H）、账户转账止付标志为"是"、账户转账不收不付标志为"否"
- **WHEN** 执行入账判定
- **THEN** 返回 入账标志 为"允许"，且输出仅含 入账标志 字段（需求输出表仅登记该输出字段）

### Requirement: REQ-002 允许入账的判定
来源：需求文档「规则描述」条目 c、d。

系统 SHALL 在满足以下任一条件时返回 入账标志 为"允许"：
- 账户状态为"待激活"且账户转账止付标志为"是"且账户转账不收不付标志为"否"（条目 c）
- 账户状态为"正常"且账户转账止付标志为"否"且账户转账不收不付标志为"否"（条目 d）

#### Scenario: REQ-002-S01 待激活账户允许入账
- **GIVEN** 账户状态为"待激活"（对应枚举值 H）、账户转账止付标志为"是"、账户转账不收不付标志为"否"
- **WHEN** 执行入账判定
- **THEN** 返回 入账标志 为"允许"

#### Scenario: REQ-002-S02 正常账户允许入账
- **GIVEN** 账户状态为"正常"、账户转账止付标志为"否"、账户转账不收不付标志为"否"
- **WHEN** 执行入账判定
- **THEN** 返回 入账标志 为"允许"

### Requirement: REQ-003 不允许入账的判定
来源：需求文档「规则描述」条目 e、f。

系统 SHALL 在满足以下任一条件时返回 入账标志 为"不允许"：
- 账户状态为"久悬"且账户转账不收不付标志为"否"（条目 e）
- 账户状态为"转营业外"且账户转账不收不付标志为"否"（条目 f）

#### Scenario: REQ-003-S01 久悬账户不允许入账
- **GIVEN** 账户状态为"久悬"（对应枚举值 S）、账户转账不收不付标志为"否"
- **WHEN** 执行入账判定
- **THEN** 返回 入账标志 为"不允许"

#### Scenario: REQ-003-S02 转营业外账户不允许入账
- **GIVEN** 账户状态为"转营业外"（对应枚举值 O）、账户转账不收不付标志为"否"
- **WHEN** 执行入账判定
- **THEN** 返回 入账标志 为"不允许"

## 待确认事项

- **TBD-1（关联 REQ-002/REQ-003 的覆盖边界，规则条目 a/b/g）**：规则 a（账户状态="新建"→入账标志"允许"）与规则 g（账户状态="新建"→入账标志"不允许"）条件相同而结论相反，规则 b（新建+止付=是+不收不付=否→"允许"）为 a/g 的子集。需确认原决策表的真实规则：g 是否实为"其余未列情况"的默认返回"不允许"（即其条件应为非 a–f 所列情况而非"新建"）；a/b 是否缺少止付/不收不付条件；以及"新建"状态下最终按哪条执行。未确认前，涉及"新建"的入账判定不作为已确认条款写入本 Spec，不产生验收场景。
- **TBD-2（关联 REQ-002-S02、规则条目 d）**：需求以"正常"作为账户状态值，但枚举 `com.dcits.deposit.enums.AcctStatus` 无"正常"取值（现有值含"活动"A 等）。需确认"正常"对应的枚举值（是否即"A"活动）。确认前规则 d 以业务称谓"正常"表述，场景 REQ-002-S02 不绑定枚举值。
- **TBD-3（关联 REQ-001）**：账户转账止付标志、账户转账不收不付标志在需求中标注"待定"，无字段名、无来源实体。需确认实际入参字段名及其对应 BO/DTO 字段。
- **TBD-4（关联 REQ-001、REQ-002/REQ-003）**：两标志类型为 String、业务取值"是"/"否"。实际存储/传输编码（如"Y"/"N"）及是否复用既有枚举未确认；取值既非"是"亦非"否"时的处理未定义。
- **TBD-5（关联 REQ-001、REQ-002/REQ-003）**：两标志标记"非必填"，但规则 c/d/e/f 均依赖其取值"是"/"否"。标志未提供（null 或空字符串）时各规则的判定结果未定义；需确认调用方是否保证提供，或对空值有既定处理。
- **TBD-6（关联 REQ-002/REQ-003）**：枚举 `AcctStatus` 中活动(A)、关闭(C)、睡眠(D)、预开户(I)、逾期(P)、预销户(R)、手工解除(U) 未出现在任何规则；已列状态的其他标志组合（如 待激活+止付=否、正常+止付=是、久悬+不收不付=是、转营业外+不收不付=是）未定义结果。需确认是否按"其余情况返回不允许"兜底、规则的匹配顺序与优先级。
- **TBD-7（关联 REQ-001 输出表）**：输出入账标志为 String，业务取值"允许"/"不允许"。实际输出编码（如"Y"/"N"或"1"/"0"）及是否存在对应枚举未确认。
