# DT002 检查账户是否能够入账

## 目标与范围

本任务定义决策类规则 DT002「检查账户是否能够入账」的行为契约：依据账户状态与两个账户标志，判定并返回入账标志。

范围内：

- 按「规则描述 a–f」给定的条件与优先级，对三个输入求值，返回唯一结果 `acctInFlag`。
- 三个输入的全部合法取值组合均有确定结果（分支 a–e 覆盖的组合按对应分支返回，其余组合按分支 f 返回）。

不在范围内（正式需求未要求，本 Spec 不定义、不验收）：

- 不校验账户是否存在，不查询、不加载账户数据，不修改账户状态或标志。
- 不定义账户状态与两个标志的赋值、维护规则（属其它任务）。
- 不调用其它组件（黑名单、检查限额、检查限制、维护限制）或任何外部服务。
- 不涉及金额计算、精度舍入、记账与账务处理。
- 不定义错误码、异常抛出或失败返回码；结果只通过返回值表达。

## Requirements

### Requirement: REQ-001 新建状态允许入账

来源：需求 `规则描述` 条目 a —— 原文：「若[账户状态]为"新建"，则返回[入账标志]为"允许"」；`补充说明`：账户状态取值来源枚举 `com.dcits.depsit.enums.AcctStatus`。

系统 SHALL 当 `acctStatus` 为「新建」（`AcctStatus.N`）时返回 `acctInFlag = "允许"`；该分支条件仅由账户状态决定，SHALL 不受 `acctTranStopPayFlag`、`acctTranNoRecvNoPayFlag` 取值影响。

#### Scenario: REQ-001-S01 新建状态、两个标志均为“否”时允许入账

- **GIVEN** `acctStatus = AcctStatus.N`（新建），`acctTranStopPayFlag = "N"`，`acctTranNoRecvNoPayFlag = "N"`
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "允许"`

#### Scenario: REQ-001-S02 新建状态、两个标志均为“是”时仍允许入账

- **GIVEN** `acctStatus = AcctStatus.N`（新建），`acctTranStopPayFlag = "Y"`，`acctTranNoRecvNoPayFlag = "Y"`
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "允许"`
- **AND** 分支 a 不含标志条件，此结果与两个标志取值无关

### Requirement: REQ-002 待激活状态在止付且非不收不付时允许入账

来源：需求 `规则描述` 条目 b —— 原文：「若[账户状态]为"待激活"且[账户转账止付标志]为"是"且[账户转账不收不付标志]为"否"，则返回[入账标志]为"允许"」。

#### Scenario: REQ-002-S01 待激活状态满足止付=是、不收不付=否时允许入账

- **GIVEN** `acctStatus = AcctStatus.H`（待激活），`acctTranStopPayFlag = "Y"`，`acctTranNoRecvNoPayFlag = "N"`
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "允许"`

### Requirement: REQ-003 活动状态在非止付且非不收不付时允许入账

### Requirement: REQ-006 未匹配上述任一分支时不允许入账

来源：需求 `规则描述` 条目 f —— 原文：「否则，返回[入账标志]为"不允许"」。

系统 SHALL 在输入组合不满足分支 a–e 中任一时返回 `acctInFlag = "不允许"`。该分支为默认分支，覆盖三个输入的全部其余合法取值组合。

#### Scenario: REQ-006-S01 待激活状态、止付=否时不允许入账

- **GIVEN** `acctStatus = AcctStatus.H`（待激活），`acctTranStopPayFlag = "N"`，`acctTranNoRecvNoPayFlag = "N"`
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "不允许"`
- **AND** 不匹配分支 b（要求止付=`"Y"`）

#### Scenario: REQ-006-S02 待激活状态、不收不付=是时不允许入账

- **GIVEN** `acctStatus = AcctStatus.H`（待激活），`acctTranStopPayFlag = "Y"`，`acctTranNoRecvNoPayFlag = "Y"`
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "不允许"`
- **AND** 不匹配分支 b（要求不收不付=`"N"`）

#### Scenario: REQ-006-S03 活动状态、止付=是时不允许入账

- **GIVEN** `acctStatus = AcctStatus.A`（活动），`acctTranStopPayFlag = "Y"`，`acctTranNoRecvNoPayFlag = "N"`
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "不允许"`
- **AND** 不匹配分支 c（要求止付=`"N"`）

#### Scenario: REQ-006-S04 活动状态、不收不付=是时不允许入账

- **GIVEN** `acctStatus = AcctStatus.A`（活动），`acctTranStopPayFlag = "N"`，`acctTranNoRecvNoPayFlag = "Y"`
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "不允许"`
- **AND** 不匹配分支 c（要求不收不付=`"N"`）

#### Scenario: REQ-006-S05 枚举内其它账户状态不允许入账

- **GIVEN** `acctStatus` 为 `AcctStatus.C`（关闭）、`AcctStatus.D`（睡眠）、`AcctStatus.I`（预开户）、`AcctStatus.P`（逾期）、`AcctStatus.R`（预销户）、`AcctStatus.U`（手工解除）中的任一取值，`acctTranStopPayFlag` 与 `acctTranNoRecvNoPayFlag` 取 `"Y"` 或 `"N"` 的任一组合
- **WHEN** 执行规则 DT002 求值
- **THEN** 返回 `acctInFlag = "不允许"`
- **AND** 这些状态未被分支 a–e 引用，逐项按分支 f 返回

### Requirement: REQ-007 入账标志取值域

来源：需求 `输出`表 —— 原文：「acctInFlag / java.lang.String / 必填 / 入账标志，取值："允许"、"不允许"」。

系统 SHALL 对任一合法输入组合返回 `acctInFlag`，其取值 SHALL 仅取自 `"允许"` 与 `"不允许"` 两个规范常量之一；SHALL NOT 返回空值、空字符串或其它文案。

#### Scenario: REQ-007-S01 任一合法输入组合返回值限定在取值域内

- **GIVEN** `acctStatus` 取 `AcctStatus` 枚举内任一常量，`acctTranStopPayFlag`、`acctTranNoRecvNoPayFlag` 各取 `"Y"` 或 `"N"`
- **WHEN** 执行规则 DT002 求值
- **THEN** `acctInFlag ∈ {"允许", "不允许"}`，且不为 `null`、不为空字符串

## 验收范围与明确不覆盖的事项

覆盖：

- 分支 a–f 的每一条决策行，含正例与不匹配该分支、由默认分支 f 兜底的反例。
- 分支 a 与 `acctTranStopPayFlag`、`acctTranNoRecvNoPayFlag` 取值无关的边界（REQ-001-S02）。
- 分支 d/e 在标志为「是」时不适用本分支、改由 f 返回同一结果（REQ-004-S02、REQ-005-S02）。
- 枚举内未被 a–e 引用的其它状态逐项落入 f（REQ-006-S05）。
- 输出取值域限定（REQ-007）。

明确不覆盖：

- 三个输入为空（`null`）、`acctStatus` 超出枚举常量集合、两个标志取 `"Y"`/`"N"` 之外的值：正式需求未定义，不作为验收输入（见「空值与非法取值语义」）。
- 账户状态与两个标志的来源、赋值与维护，账户查询与存在性校验。
- 其它组件与规则（黑名单、检查限额、检查限制、维护限制）的行为，及其与 DT002 的调用编排关系（本需求未声明调用方与调用时机）。
- 金额计算、精度舍入、记账处理、并发与事务语义、性能指标。
- 错误码、异常抛出等失败处理形式（本规则以返回值表达结果，需求未定义此类场景）。

需与业务确认的观察记录（不影响本 Spec 条款，仅提示原文事实）：

- 条目 d、e 的结果（均为「不允许」）与默认条目 f 一致，属行为冗余但原文明确列出，本 Spec 保留为独立条款 REQ-004、REQ-005，不改变行为、不合并删除。
