# ST125 检查是否存在属性限制

## 目标与范围

**目标**：以交易执行步骤（检查类）「检查是否存在属性限制」的已确认业务定义为依据，整理可验证的行为 Spec。步骤以入参 `baseAcctNo`（账号）查询【账户限制信息表】，取 `$限制状态$` 等于 `"A-生效"` **且** `$限制级别$` 等于 `"NATURE-账户属性限制"` 的 [账户限制信息]；未查到记录时限制编号、账户限制类型、限制状态、限制级别四项均为空值，查得多条记录时按 `$限制编号$` 升序取第一条并回显该条的四项；随后以取到的 [账户限制信息] 是否为空，返回 [属性限制标志]（`natureRestraintFlag`）为「否」或「是」。

**范围内**：

- 入参契约：`baseAcctNo` 的字段名、类型、必填性与业务名称，以及步骤描述中 `{账号}` 占位符的绑定。
- 查询契约：查询对象【账户限制信息表】、查询键、两个筛选条件（「且」）及其码值、必须包括的字段、查询的只读性。
- 步骤 1 的三条获取结果分支：未查到记录 → 四项回显为空值；查得记录 → 回显该记录的四项；查得多条记录 → 按 `$限制编号$` 升序取第一条后回显。
- 步骤 2 的两条判定分支：[账户限制信息] 为空 → 「否」；非空 → 「是」。
- 输出契约：`natureRestraintFlag`（取值域恰为「是」「否」）与四个回显字段 `resSeqNo`、`restraintType`、`restraintsStatus`、`restraintLevel` 的类型、标记与空值语义；结论的互斥性与唯一性。
- 「## 失败处理」所声明的无业务失败场景。

**不在范围内**（源需求未定义或属核对事项，详见「## 验收范围与明确不覆盖的事项」）：

- `baseAcctNo` 的上游取得方式与调用方（源需求「## 输入」表「来源实体」列为空）。
- 【账户限制信息表】之外的数据源、组件内步骤调用、外部服务调用与后续步骤（源需求无「组件内步骤调用」说明）。
- `natureRestraintFlag` 的落库位置与下游使用；四个回显字段的落库与报文形态。
- 输入合法性校验、枚举码值清单的完整性、`$限制编号$` 升序的比较口径。
- 非功能要求（性能、日志、监控、幂等、重试、并发）。

## Requirements

### Requirement: REQ-001 入参契约与占位符绑定

来源：`docs/requirements/ST125.md`「## 输入」表（第 11–13 行）、「## 步骤描述」1（第 5 行）、「## 相关枚举」表（第 28–32 行）、「## 补充说明」（第 36–38 行）

系统 SHALL 接收入参 `baseAcctNo`（类型 `java.lang.String`，必填，业务名称「账号」），并 MUST 将「## 步骤描述」1 中的 `{账号}` 绑定为该入参。系统 MUST NOT 使用 `baseAcctNo` 之外的输入。源需求「## 输入」表的「来源实体」列为空，系统 MUST NOT 据此推断或要求 `baseAcctNo` 由其它表／服务取得（其上游取得方式不在本步骤定义范围内），也 MUST NOT 因该列为空而免除本步骤依据步骤描述 1 发起的查询职责（REQ-002）。

#### Scenario: REQ-001-S01 入参契约与 {账号} 绑定

- **GIVEN** 源需求「## 输入」表仅一行：`baseAcctNo`，类型 `java.lang.String`，标记「必填」，说明「账号」，「来源实体」列为空
- **WHEN** 解析本步骤的输入与步骤描述 1 中的占位符
- **THEN** 本步骤接受 `baseAcctNo` 作为唯一外部入参，`{账号}`（第 5 行）绑定为 `baseAcctNo`，并作为查询【账户限制信息表】的查询键（REQ-002）
- **AND** 本步骤不接受限制状态、限制级别、限制编号、限制类型等作为入参；`baseAcctNo` 的上游取得方式与调用方不在本步骤范围内（不覆盖项 1）

#### Scenario: REQ-001-S02 三组别名与枚举类归属

- **GIVEN** 「## 相关枚举」表（第 30、31、32 行）将「限制类型」「账户限制类型」「输出数据-账户限制类型」列为同一枚举的别名，将「限制状态」「输出数据-限制状态」列为另一枚举的别名，将「限制级别」「输出数据-限制级别」列为第三个枚举的别名；「## 补充说明」（第 36–38 行）给出三者类名分别为 `com.dcits.depsit.enums.RestraintType`、`com.dcits.depsit.enums.RestraintsStatus`、`com.dcits.depsit.enums.RestraintLevel`
- **WHEN** 解析本步骤的字段与取值类型
- **THEN** 输出字段 `restraintType`、`restraintsStatus`、`restraintLevel` 的类型分别为 `RestraintType`、`RestraintsStatus`、`RestraintLevel`（输出表第 22–24 行），与补充说明的枚举类名一致
- **AND** 带「输出数据-」前缀的别名指向输出数据中的同名标志字段，与输入表仅 1 个输入字段的事实不冲突（三个枚举服务于输出字段的取值类型）；别名的不同表述不产生重复字段，也不改变枚举类归属

### Requirement: REQ-002 按 {账号} 查询【账户限制信息表】并按限制状态、限制级别筛选

来源：`docs/requirements/ST125.md`「## 步骤描述」1（第 5 行）—— 原文前半：「1.获取属性级限制：根据{账号}查询【账户限制信息表】获取$限制状态$等于"A-生效"且$限制级别$等于"NATURE-账户属性限制"的[账户限制信息]，必须包括$账户限制类型$、$限制编号$」

系统 SHALL 以 `baseAcctNo` 为查询键查询【账户限制信息表】，取回 `$限制状态$`（`restraintsStatus`）等于码值 `"A"` **且** `$限制级别$`（`restraintLevel`）等于码值 `"NATURE"` 的 [账户限制信息] 记录集合。两个筛选条件 MUST 同时满足，仅满足其中一个的记录 MUST NOT 入选。取回的记录 MUST 至少包括 `$账户限制类型$`（`restraintType`）与 `$限制编号$`（`resSeqNo`）两个字段。该查询 MUST 为只读操作，MUST NOT 新增、修改或删除【账户限制信息表】或其它数据源的记录。源需求未设置其它筛选条件（未按限制类型、限制编号、机构等筛选），本 Spec 不新增。

#### Scenario: REQ-002-S01 命中一条满足两个条件的记录

- **GIVEN** 【账户限制信息表】中存在账号 `baseAcctNo = "6217000012345678901"` 的记录：`resSeqNo = "RS20261009001"`、`restraintType = "13"`（挂失止付，示例数据）、`restraintsStatus = "A"`（生效）、`restraintLevel = "NATURE"`（账户属性限制）
- **WHEN** 执行步骤 1 的查询
- **THEN** 查询命中该记录，[账户限制信息] 即该记录，且已包括 `$账户限制类型$`（`restraintType`）与 `$限制编号$`（`resSeqNo`）
- **AND** 该查询不新增、修改或删除任何记录，不查询【账户限制信息表】之外的其它数据源

#### Scenario: REQ-002-S02 两个筛选条件为「且」

- **GIVEN** 账号 `baseAcctNo = "6217000012345678901"` 下有三条记录：`resSeqNo = "RS20261009003"`、`restraintsStatus = "E"`（已终止）、`restraintLevel = "NATURE"`；`resSeqNo = "RS20261009004"`、`restraintsStatus = "A"`（生效）、`restraintLevel = "ACCT"`（账户级别）；`resSeqNo = "RS20261009005"`、`restraintsStatus = "A"`、`restraintLevel = "NATURE"`（示例数据）
- **WHEN** 执行步骤 1 的查询
- **THEN** 仅第三条记录入选（两个条件同时满足），前两条均不入选
- **AND** [账户限制信息] 中不含状态非 `"A"` 或级别非 `"NATURE"` 的记录，即使其账号匹配

#### Scenario: REQ-002-S03 查询范围与只读性

- **GIVEN** 任一 `baseAcctNo`
- **WHEN** 执行步骤 1 的查询
- **THEN** 本步骤仅读取【账户限制信息表】的记录，不写入、不更新、不删除
- **AND** 不因「## 输入」表「来源实体」列为空而发起额外的数据访问，也不调用其它步骤、规则或外部服务

### Requirement: REQ-003 未查到记录时四项回显均为空值

来源：`docs/requirements/ST125.md`「## 步骤描述」1（第 5 行）—— 原文：「…未查到记录时限制编号、账户限制类型、限制状态、限制级别均为空值」

系统 SHALL 在查询未得到任何满足条件的记录时，将 `resSeqNo`（限制编号）、`restraintType`（账户限制类型）、`restraintsStatus`（限制状态）、`restraintLevel`（限制级别）四项均置为**空值（无值）**。此时 MUST NOT 产出错误码、MUST NOT 返回业务失败、MUST NOT 以空字符串或其它占位文案替代空值、MUST NOT 以未入选记录的数据回显。「未查到记录」指在 `baseAcctNo` 与两个筛选条件（REQ-002）下结果集为空，既包含表中不存在该账号的记录，也包含存在该账号的记录但无一条同时满足两个筛选条件。

#### Scenario: REQ-003-S01 账号在表中无任何限制记录

- **GIVEN** 【账户限制信息表】中不存在 `baseAcctNo = "6217000012345678901"` 的记录
- **WHEN** 执行步骤 1 的查询
- **THEN** [账户限制信息] 为空，`resSeqNo`、`restraintType`、`restraintsStatus`、`restraintLevel` 四项均为空值
- **AND** 不产出错误码、不返回业务失败、不抛出异常

#### Scenario: REQ-003-S02 账号有限制记录但均不满足两个筛选条件

- **GIVEN** 【账户限制信息表】中存在账号 `baseAcctNo = "6217000012345678901"` 的两条记录：`resSeqNo = "RS20261009006"`、`restraintsStatus = "F"`（未生效）、`restraintLevel = "NATURE"`；`resSeqNo = "RS20261009007"`、`restraintsStatus = "A"`（生效）、`restraintLevel = "CLIENT"`（客户级别）（示例数据）
- **WHEN** 执行步骤 1 的查询
- **THEN** 过滤后结果集为空，[账户限制信息] 为空，四项回显均为空值
- **AND** 与 REQ-003-S01 的处理一致：不产出错误码、不返回业务失败，且不以这两条记录中的任何一条回显

### Requirement: REQ-004 查得多条记录时按限制编号升序取第一条并回显

来源：`docs/requirements/ST125.md`「## 步骤描述」1（第 5 行）—— 原文：「…查得多条记录时按$限制编号$升序取第一条，回显该条的限制编号、账户限制类型、限制状态、限制级别」

系统 SHALL 在查询得到多条满足条件的记录时，按 `$限制编号$`（`resSeqNo`）**升序**排列并取第一条，将 [账户限制信息] 置为该条记录，并回显该条记录的 `resSeqNo`、`restraintType`、`restraintsStatus`、`restraintLevel` 四项。选中结果 MUST 由 `$限制编号$` 的升序唯一确定，MUST NOT 依赖数据源返回记录的物理顺序，MUST NOT 对多条结果做合并、拼接或任取。源需求未规定 `$限制编号$` 升序的比较口径（字符串序或数值序，字段类型为 `java.lang.String`），本 Spec 不补充该口径（不覆盖项 2）；对等长编号，两种口径的排序结果一致。

#### Scenario: REQ-004-S01 多条时取限制编号升序第一条并回显四项

- **GIVEN** 账号 `baseAcctNo = "6217000012345678901"` 下有三条满足两个筛选条件的记录：`resSeqNo = "RS20261009002"`、`restraintType = "13"`；`resSeqNo = "RS20261009001"`、`restraintType = "17"`；`resSeqNo = "RS20261009003"`、`restraintType = "22"`（示例数据）；三条的 `restraintsStatus` 均为 `"A"`、`restraintLevel` 均为 `"NATURE"`
- **WHEN** 执行步骤 1 的查询并按 `$限制编号$` 升序取第一条
- **THEN** [账户限制信息] 为 `resSeqNo = "RS20261009001"` 的记录，并回显该条的四项：`resSeqNo = "RS20261009001"`、`restraintType = "17"`（示例数据）、`restraintsStatus = "A"`、`restraintLevel = "NATURE"`
- **AND** 不回显其余两条记录的数据，也不产出多条结果的集合

#### Scenario: REQ-004-S02 选中结果由升序唯一确定，与返回顺序无关

- **GIVEN** 与 REQ-004-S01 相同的三条记录，但数据源返回的物理顺序为 `"RS20261009003"`、`"RS20261009001"`、`"RS20261009002"`
- **WHEN** 执行步骤 1 的查询并按 `$限制编号$` 升序取第一条
- **THEN** [账户限制信息] 仍为 `resSeqNo = "RS20261009001"` 的记录，回显的四项与 REQ-004-S01 相同
- **AND** 选中结果不随数据源返回顺序或处理顺序改变，任一次执行的结果唯一

### Requirement: REQ-005 以 [账户限制信息] 是否为空判定 [属性限制标志]

来源：`docs/requirements/ST125.md`「## 步骤描述」2（第 7 行）—— 原文：「2.检查是否存在属性限制：若{账户限制信息}等于空，则返回[属性限制标志]为"否"，否则返回[属性限制标志]为"是"。」

系统 SHALL 以步骤 1 取得的 [账户限制信息]（经筛选并按 `$限制编号$` 升序取第一条后的结果）为判据确定 `natureRestraintFlag`（[属性限制标志]）：[账户限制信息] 等于空（未查到记录，REQ-003）时返回 `natureRestraintFlag = "否"`；[账户限制信息] 非空（查得记录，单条命中 REQ-002 或多条取第一条 REQ-004）时返回 `natureRestraintFlag = "是"`。判定 MUST 只依赖 [账户限制信息] 是否为空这一个条件，MUST NOT 依赖 `restraintType`、`resSeqNo`、`restraintsStatus`、`restraintLevel` 的具体取值。两条分支 MUST 互斥且穷尽，`{账户限制信息}` 的「等于空」口径与 REQ-003 的「未查到记录」一致（同一结果集为空）。

#### Scenario: REQ-005-S01 [账户限制信息] 等于空时返回「否」

- **GIVEN** 步骤 1 的查询结果为空：账号在表中无记录，或记录均不满足两个筛选条件（REQ-003-S01、REQ-003-S02）
- **WHEN** 执行步骤 2 的判定
- **THEN** 返回 `natureRestraintFlag = "否"`（字符串字面「否」，源需求原文第 7 行）
- **AND** 不同时返回「是」；四个回显字段同时为空值（REQ-003、REQ-006-S03），不产出错误码

#### Scenario: REQ-005-S02 [账户限制信息] 非空时返回「是」

- **GIVEN** 步骤 1 的查询命中记录（示例一：账号 `baseAcctNo = "6217000012345678901"` 下一条 `restraintsStatus = "A"`、`restraintLevel = "NATURE"`、`resSeqNo = "RS20261009001"` 的记录；示例二：命中多条并已按 `$限制编号$` 升序取第一条）
- **WHEN** 执行步骤 2 的判定
- **THEN** 返回 `natureRestraintFlag = "是"`（字符串字面「是」，源需求原文第 7 行）
- **AND** 不同时返回「否」；判定结果不因命中的限制类型、限制编号、限制状态、限制级别的具体取值而改变（上述示例均返回「是」）

### Requirement: REQ-006 输出契约与结论唯一性

来源：`docs/requirements/ST125.md`「## 输出」表（第 17–24 行）、「## 步骤描述」1（第 5 行）与 2（第 7 行）

系统 SHALL 在每次执行中产出 `natureRestraintFlag`（`java.lang.String`，属性限制标志）与 `resSeqNo`（`java.lang.String`，限制编号）、`restraintType`（`com.dcits.depsit.enums.RestraintType`，账户限制类型）、`restraintsStatus`（`com.dcits.depsit.enums.RestraintsStatus`，限制状态）、`restraintLevel`（`com.dcits.depsit.enums.RestraintLevel`，限制级别）共 5 项。`natureRestraintFlag` 的取值 MUST 恰为「是」与「否」两个规范常量之一，两条判定路径均对其赋值（REQ-005），MUST NOT 为空值、空字符串或其它文案。四个回显字段在命中记录时 MUST 为选中记录（REQ-004）的对应字段值、在未查到记录时 MUST 为空值（REQ-003）。5 项输出的标记按源需求输出表照录为「非必填」（记的是实体字段可空性），本 Spec 不据此放宽产出要求，也不额外新增「输出不得为空」的校验条款。同一次执行 MUST NOT 同时产出「是」与「否」两项结论。

#### Scenario: REQ-006-S01 natureRestraintFlag 取值域限定为两个规范常量

- **GIVEN** 任一次本步骤的执行（查询命中或未命中）
- **WHEN** 读取输出
- **THEN** `natureRestraintFlag` 取值为「是」或「否」二者之一，不出现空值、空字符串、`true`／`false`、`"Y"`／`"N"` 或其它文案
- **AND** 源需求未给出「是」「否」的码值形式（第 7 行原文即为中文「是」「否」），本 Spec 不推断为 `"Y"`／`"N"` 等编码（不覆盖项 3）

#### Scenario: REQ-006-S02 四个回显字段的类型与空值语义

- **GIVEN** 任一次本步骤的执行
- **WHEN** 读取输出
- **THEN** `resSeqNo` 为 `java.lang.String`、`restraintType` 为 `com.dcits.depsit.enums.RestraintType`、`restraintsStatus` 为 `com.dcits.depsit.enums.RestraintsStatus`、`restraintLevel` 为 `com.dcits.depsit.enums.RestraintLevel`（输出表第 21–24 行）
- **AND** 命中记录时四项为该条记录的值（其中 `restraintsStatus`、`restraintLevel` 按筛选条件即码值 `"A"`、`"NATURE"`）；未查到记录时四项均为空值
- **AND** 两种情形均不抛出异常、不产出错误码、不返回业务失败

#### Scenario: REQ-006-S03 结论互斥且与执行路径一一对应

- **GIVEN** 任一次本步骤的执行，其路径为「[账户限制信息] 为空」（REQ-003）或「[账户限制信息] 非空」（REQ-002 单条命中／REQ-004 多条取第一条）之一
- **WHEN** 执行本步骤
- **THEN** [账户限制信息] 为空时恒为 `natureRestraintFlag = "否"` 且四项回显均为空值；非空时恒为 `natureRestraintFlag = "是"` 且四项回显为选中记录的值
- **AND** 两项结论不同时产出；判定只依赖 `baseAcctNo` 与【账户限制信息表】中满足筛选条件的记录，不依赖其它输入（REQ-005）

### Requirement: REQ-007 副作用与失败处理约束

来源：`docs/requirements/ST125.md`「## 失败处理」（第 42 行）、「## 步骤描述」1（第 5 行）

系统 SHALL 在全部路径上仅执行只读查询并返回输出：MUST NOT 新增、修改或删除【账户限制信息表】或任何其它数据源的数据，MUST NOT 产生账户、金额、状态类数据变更，MUST NOT 调用其它步骤、规则、外部服务或本表之外的其它数据源。本步骤 MUST NOT 以错误码或业务失败表达检查结论——源需求「## 失败处理」（第 42 行）声明本步骤无业务失败场景，失败仅由技术异常传播表达。

#### Scenario: REQ-007-S01 全路径无业务副作用、无错误码

- **GIVEN** 任一次本步骤的执行（覆盖未查到记录、单条命中、多条取第一条三条获取路径，以及返回「否」与返回「是」两条判定路径）
- **WHEN** 执行本步骤
- **THEN** 本步骤不新增、修改或删除任何数据，不产生业务数据变更，不调用其它步骤、规则、外部服务，也不查询【账户限制信息表】之外的其它数据源
- **AND** 不产出错误码、不返回业务失败；技术异常的传播形式（异常类型、文案、事务行为）不在本 Spec 范围内（不覆盖项 7）

## 验收范围与明确不覆盖的事项

本 Spec 的验收范围为上表列出的 7 条需求、15 个场景，覆盖从入参绑定、按账号与两个筛选条件查询，到未查到记录／单条命中／多条取第一条三条获取路径及两条判定路径产出 [属性限制标志] 的完整行为，含条件为「且」的过滤边界、回显字段的空值语义、结论的互斥性与唯一性，以及只读、无副作用约束。

明确不覆盖（源需求未定义或属非规范性核对，不作为本期验收依据）：

1. **`baseAcctNo` 的上游取得方式与调用方**：源需求「## 输入」表「来源实体」列为空，未说明账号由哪张表或哪个服务提供，也未描述本步骤在交易编排中的调用位置与调用方。本 Spec 只规定 `baseAcctNo` 为本步骤入参并作为查询键（REQ-001、REQ-002），不推断其取得方式、填充逻辑与上游依赖；验收不覆盖入参来源，只覆盖以给定 `baseAcctNo` 执行的查询与判定行为。
2. **`$限制编号$` 升序的比较口径**：源需求仅表述「按 `$限制编号$` 升序取第一条」，未规定按字符串序还是数值序比较，而字段类型为 `java.lang.String`。本 Spec 不补充该口径（REQ-004）；对等长编号两种口径结果一致，测试设计如需区分应以需求方确认为准，该口径差异不作为本轮验收判定的对象。
3. **`natureRestraintFlag` 的码值形式**：`natureRestraintFlag` 的规范常量按源需求第 7 行原文照录为中文字面「是」「否」（REQ-005、REQ-006-S01）；源需求未给出 `"Y"`／`"N"` 或其它编码形式，本 Spec 不推断、不新增映射。
4. **筛选取值的码值还原与枚举用词差异（表述口径，非源需求明文）**：源需求以「码值-含义」形式书写限制状态「"A-生效"」、限制级别「"NATURE-账户属性限制"」（第 5 行），本 Spec 按项目既有口径以码值 `"A"`、`"NATURE"` 表述（REQ-002）。工程枚举 `RestraintsStatus.A` 的注释为「已批准」、`RestraintLevel.NATURE` 的注释为「账户属性限制」（`deposit-common/src/main/java/com/dcits/depsit/enums/RestraintsStatus.java`、`RestraintLevel.java`）：两者的码值均与源需求书写一致，前者含义用词不同属书写差异，本 Spec 以码值 `"A"` 为筛选取值，不据此判定名称缺失、不新增业务规则或分支；`RestraintType` 的完整码值清单源需求未列举，本 Spec 不抄录。三者均不构成本步骤的业务规则，验收不覆盖枚举清单本身。
5. **查询对象的物理表名与 SQL**：【账户限制信息表】为源需求正文用语，其对应 `RB_BUS_RESTRAINTS` 系依据输出表「来源实体」列与工程实体 `RbBusRestraintsEO` 的同名字段得出的**非规范性核对**（见「### 依赖契约」）。本 Spec 不据此判定名称缺失，也不在验收中断言物理表名、列名或 SQL 语句。
