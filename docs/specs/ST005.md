# ST005 检查支取账户限额

## 目标与范围

本任务「检查支取账户限额」（ST005）为交易执行步骤。步骤以客户号、账号、限额因子、交易日期、交易时间戳、交易金额为输入，按《检查限额》流程检查支取交易是否受限额控制，并按检查结果返回业务结论或错误码。

已确认流程由「步骤描述」14 条组成，包含 10 次组件内步骤调用（补充说明确认按组件内步骤调用处理，调用参数和返回结果沿用原文描述）：

1. 匹配限额场景（ST043）→ 未匹配返回检查结果「通过」，匹配继续；
2. 检查机构匹配的限额场景配置（ST038）→ 限额场景编码为空返回「通过」；
3. 检查有效的限额场景配置（ST045）→ 限额场景编码为空返回「通过」；
4. 检查限额场景编码（ST037）→ 限额场景编码为空返回「通过」；
5. 获取累计限额（ST042）→ 计算限额累计金额（ST039）→ 检查限额（ST040）；
6. 未超限时按累计情况分支调用更新累计限额（ST046）或登记累计限额（ST044）；
7. 超限时获取超限处理方式（ST041），按「拒绝/授权/提示」分支返回错误码 ER0058、授权标志「需授权」或检查结果「超限，但可继续交易」。

范围限于 `docs/requirements/ST005.md`「步骤描述」「输入」「输出」「相关枚举」「补充说明」声明的内容。需求未定义的执行结果物理取值、检查结果与授权标志的承载方式、步骤12分支条件重叠、输出字段赋值来源等，逐项记录于「待确认事项」，不补默认行为。

## 待确认事项

- **TBD-1（关联 REQ-002）ST043 执行结果的物理取值与字段名**：步骤2 以「已匹配到限额场景」为继续条件；ST043 正式 Spec 以「已匹配/未匹配」为正常结论，其承载字段名与物理编码（中文串或映射编码）在 ST043 侧待确认。需确认「已匹配到限额场景」与「已匹配」的取值对应关系及[执行结果]字段名。
- **TBD-2（关联 REQ-002）步骤1 调用参数与 ST043 输入契约差异**：步骤描述原文列出{客户号}、{账号}、{限额因子}；ST043 已确认输入契约仅含因子名称。需确认客户号/账号是否实际传入 ST043、{限额因子}是否即输入字段因子名称。
- **TBD-3（关联 REQ-003、REQ-004、REQ-005）「[限额场景编码]为空」的物理语义**：空指 null 还是空字符串，需求未定义；三个判断点的空值语义需确认。
- **TBD-4（关联 REQ-006、REQ-007、REQ-008、REQ-010、REQ-011、REQ-012）步骤8/12 所用累计值的来源**：步骤6 从 ST042 取得既有累计值，步骤7 由 ST039 计算包含本次交易后的累计值；需求未明确步骤8 检查、步骤12 分支、步骤13/14 更新登记所使用的[限额累计金额][限额累计笔数]取自何者。本 Spec 按「ST042 取既有值→ST039 计算后值供步骤8 检查及后续步骤使用」整理，需确认。
- **TBD-5（关联 REQ-007）步骤7 调用参数与 ST039 输入契约差异**：步骤描述原文列出{账号}、{客户号}、{交易金额}、[限额场景编码]；ST039 已确认输入契约仅含 tranAmt、limitSceneNo。需确认{账号}{客户号}是否有对应调用参数。
- **TBD-6（关联 REQ-009）「提示」与「提醒」表述差异**：步骤11 分支为「拒绝/授权/提示」，ST041 正式 Spec 的检查结果分支为「拒绝/提醒/授权」（处理方式 DealFlow B/D/A，其中 D 为提醒处理）。需确认「提示」是否对应 ST041 的「提醒」（DealFlow.D）。
- **TBD-7（关联 REQ-002、REQ-003、REQ-004、REQ-005、REQ-009）检查结果与授权标志的承载方式**：检查结果「通过」「超限，但可继续交易」及授权标志「需授权」为步骤级业务结论，但需求输出表未登记相应字段（仅登记 限额检查结果、tranStatus 等）。需确认这些结论的物理字段名、类型与取值编码（是否复用 限额检查结果 字段或 tranStatus 等）。
- **TBD-8（关联 REQ-009）「授权」分支「等待授权」语义**：返回授权标志「需授权」后流程如何等待授权、授权结果如何回填到本步骤，需求未定义。
- **TBD-9（关联 REQ-010）步骤12 分支条件重叠**：当[限额累计金额]=0 且[限额累计笔数]>0（或金额>0 且笔数=0）时，分支a「(金额>0 或笔数>0) 继续执行」与分支b「(金额=0 或笔数=0) 跳转登记」同时成立，需求未定义优先分支。需确认重叠情形的走向。
- **TBD-10（关联 REQ-009、REQ-011、REQ-012）「提示」分支结束后的流转**：步骤11c 返回检查结果「超限，但可继续交易」后，是否继续执行步骤12-14（更新/登记累计限额），需求未定义。本 Spec 按步骤11c 返回检查结果即结束整理，需确认。
- **TBD-11（关联 REQ-001、REQ-006）输出字段赋值来源**：输出表重复登记 `limitSumAmt`、`否`（一组通用、一组来源 RB_LIMIT_SUM_INFO），且未声明 `tranStatus`（业务处理状态在何路径取何枚举值）、`limitSceneNo`、`checkObjVal`、`effectDate`、`expireDate` 等由哪个组件内步骤结果填充。需确认各输出字段与 ST042/ST039/ST044 产出的对应关系及是否重复输出。
