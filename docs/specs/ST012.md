# ST012 检查账户余额

## 目标与范围

本 Spec 将正式需求「检查账户余额」交易执行步骤整理为可验证的行为规范。步骤以账号（baseAcctNo）与交易金额（tranAmt）为输入，依次执行三个子步骤：根据账号查询【账户余额信息】（对公存款账户余额表）取得汇总金额、冻结金额、系统内理财余额、透支金额；按公式计算账户可用余额（汇总金额−冻结金额+系统内理财余额+透支金额）；将账户可用余额与交易金额比较，按比较结果将流程跳转至《检查法透标志》或《检查现金支取账户限制》，并返回需求输出表登记的五个输出字段。

范围限于 `docs/requirements/ST012.md` 的「步骤描述」第 1–3 条及「输入」「输出」表声明的行为与契约。需求未定义账号到余额记录的定位映射、查询无匹配记录、多条匹配记录、空输入等情形的行为，仅记录待确认事项，不补默认行为；需求未声明业务失败场景，本 Spec 不定义业务失败分支与错误码。

### 步骤结果契约

- 正常完成（含两个跳转分支的任一路径）时，步骤结果按 `com.dcits.common.step.StepResult` 表达为成功（succeed=true，errorCode、errorMessage 为空）。
- 需求未声明业务失败场景，本 Spec 不定义业务失败分支与错误码；账号对应的余额记录不存在、多条匹配记录、空输入等未决情形见「待确认事项」。
- 两个跳转（《检查法透标志》《检查现金支取账户限制》）是步骤对后续流程的指向，属流程路由：`com.dcits.common.step.GotoStepCondition` 通过 candidateSteps 声明本步骤可跳转的步骤，运行时按步骤返回的 gotoStepName 决定跳转目标。本 Spec 只约束跳转目标的业务名称（由需求原文确定），不定义路由值。

### 依赖核对

- 名称映射核对：`requirement-name-mapping` 资产确认「账户余额信息」→ 对公存款账户余额表（RB_BUS_ACCT_BALANCE），并收录「账户余额」→ 对公存款账户余额表；「汇总金额」「冻结金额」「系统内理财余额」「透支金额」「账户可用余额」等属性域未收录，按技能要求保留原业务称谓。源业务文档中「检查法透标志」「检查现金支取账户限制」为跳转目标步骤的业务名称，本 Spec 按需求原文表述，不展开其实现。
- 余额实体核对：`com.dcits.deposit.facade.eo.RbBusAcctBalanceEO` 字段与需求输出表一致——totalAmount（汇总金额，@NotNull）、pldAmount（冻结金额）、finregAmount（系统内理财余额）、odAmount（透支金额）、acctAvailBal（账户可用余额），均为 `java.math.BigDecimal`；实体另含 internalKey（@NotNull，账户内部键值）、oddAmount（透支总金额）、acctAvailBalPrev（上日账户可用余额）、dosAmount（久悬户账户余额），本步骤不涉及。
- 查询能力核对：`IRbBusAcctBalanceBcc.findByEo(RbBusAcctBalanceEO)` 返回 `List<RbBusAcctBalanceEO>`，`findByPrimaryKey(Integer internalKey)` 按主键查询；对公存款账户余额表主键为 INTERNAL_KEY，查询条件仅支持 internalKey 及金额字段组合，无账号（baseAcctNo）条件。需求「步骤描述」第 1 条表述为「根据{账号}查询」，「账号」如何定位到余额表记录（INTERNAL_KEY）的映射路径在本工程中未直接确认，见待确认事项 1。
- 金额精度：余额表金额列物理精度为 `DECIMAL(17,2)`，输入 tranAmt 与各金额输出均为 `java.math.BigDecimal`；需求未声明计算与比较的舍入规则，见待确认事项 6。

## Requirements

### Requirement: REQ-001 步骤输入与输出契约
来源：需求「输入」「输出」表。

系统 SHALL 接受必填输入 baseAcctNo（类型 `java.lang.String`，账号）与 tranAmt（类型 `java.math.BigDecimal`，交易金额），并按需求输出表返回以下字段（均为非必填）：totalAmount（`java.math.BigDecimal`，汇总金额）、pldAmount（`java.math.BigDecimal`，冻结金额）、finregAmount（`java.math.BigDecimal`，系统内理财余额）、odAmount（`java.math.BigDecimal`，透支金额）、acctAvailBal（`java.math.BigDecimal`，账户可用余额），来源实体均为对公存款账户余额表（RB_BUS_ACCT_BALANCE）。

#### Scenario: REQ-001-S01 正常流程返回完整输出
- **GIVEN** 输入 baseAcctNo=「622200001234」、tranAmt=1000.00；对公存款账户余额表存在该账号对应的余额记录（汇总金额 1000.00、冻结金额 100.00、系统内理财余额 50.00、透支金额 200.00）
- **WHEN** 执行检查账户余额步骤
- **THEN** 返回 totalAmount=1000.00、pldAmount=100.00、finregAmount=50.00、odAmount=200.00、acctAvailBal=1150.00，且步骤结果为成功（StepResult.succeed=true，errorCode、errorMessage 为空）

### Requirement: REQ-002 获取账户余额信息
来源：需求「步骤描述」第 1 条（原文：根据{账号}查询【账户余额信息】获取$汇总金额$、$冻结金额$、$系统内理财余额$、$透支金额$）。

系统 SHALL 以输入账号 baseAcctNo 查询【账户余额信息】（对公存款账户余额表），取得所查记录的汇总金额（totalAmount）、冻结金额（pldAmount）、系统内理财余额（finregAmount）、透支金额（odAmount），作为计算账户可用余额的输入。

#### Scenario: REQ-002-S01 账号对应余额记录存在时取得四项金额
- **GIVEN** 输入账号 baseAcctNo=「622200001234」；对公存款账户余额表存在该账号对应的余额记录（汇总金额 1000.00、冻结金额 100.00、系统内理财余额 50.00、透支金额 200.00）
- **WHEN** 执行获取账户余额信息
- **THEN** 步骤取得该记录的 totalAmount=1000.00、pldAmount=100.00、finregAmount=50.00、odAmount=200.00，作为账户可用余额计算的输入

### Requirement: REQ-003 计算账户可用余额
来源：需求「步骤描述」第 2 条（原文：[账户可用余额]=[汇总金额]-[冻结金额]+[系统内理财余额]+[透支金额]）。

系统 SHALL 按公式计算账户可用余额（acctAvailBal）= 汇总金额（totalAmount）− 冻结金额（pldAmount）+ 系统内理财余额（finregAmount）+ 透支金额（odAmount），计算结果作为可用余额判断的输入。

#### Scenario: REQ-003-S01 按公式计算账户可用余额
- **GIVEN** 已取得 totalAmount=1000.00、pldAmount=100.00、finregAmount=50.00、odAmount=200.00
- **WHEN** 执行计算账户可用余额
- **THEN** 计算得 acctAvailBal=1150.00（1000.00 − 100.00 + 50.00 + 200.00）

### Requirement: REQ-004 可用余额判断与流程跳转
来源：需求「步骤描述」第 3 条（原文：若[账户可用余额]小于{交易金额}，则跳转至步骤《检查法透标志》，否则跳转至步骤《检查现金支取账户限制》）。

系统 SHALL 比较账户可用余额（acctAvailBal）与输入交易金额（tranAmt）：若 acctAvailBal 小于 tranAmt，则将流程跳转至步骤《检查法透标志》；否则（acctAvailBal 不小于 tranAmt，含相等）将流程跳转至步骤《检查现金支取账户限制》。

#### Scenario: REQ-004-S01 可用余额小于交易金额时跳转《检查法透标志》
- **GIVEN** 计算得 acctAvailBal=1150.00，输入 tranAmt=1200.00
- **WHEN** 执行检查可用余额
- **THEN** 判定 1150.00 小于 1200.00，流程跳转至步骤《检查法透标志》，步骤结果保持成功

#### Scenario: REQ-004-S02 可用余额等于交易金额时跳转《检查现金支取账户限制》（边界）
- **GIVEN** 计算得 acctAvailBal=1150.00，输入 tranAmt=1150.00
- **WHEN** 执行检查可用余额
- **THEN** 判定 1150.00 不小于 1150.00，流程跳转至步骤《检查现金支取账户限制》，步骤结果保持成功

#### Scenario: REQ-004-S03 可用余额大于交易金额时跳转《检查现金支取账户限制》
- **GIVEN** 计算得 acctAvailBal=1150.00，输入 tranAmt=1000.00
- **WHEN** 执行检查可用余额
- **THEN** 判定 1150.00 不小于 1000.00，流程跳转至步骤《检查现金支取账户限制》，步骤结果保持成功

## 待确认事项

1. **账号到余额记录的定位映射**（关联 REQ-002）：需求「步骤描述」第 1 条表述为「根据{账号}查询【账户余额信息】」，但对公存款账户余额表（RB_BUS_ACCT_BALANCE）主键为 INTERNAL_KEY，表结构、EO 及查询接口（`IRbBusAcctBalanceBcc.findByEo`/`findByPrimaryKey`）均无账号（baseAcctNo）字段或查询条件；「账号」如何定位到对应的余额表记录（例如经 对公存款账户主表 RB_BUS_ACCT / 对公客户账户关系表 RB_BUS_CLIENT_ACCT 推导 internalKey）未确认。需确认账号定位到余额记录的具体映射路径与查询接口。
2. **查询无匹配记录的行为**（关联 REQ-002、REQ-004）：输入账号在余额表中无对应记录时，需求未定义步骤结果与流程走向。需确认：无记录时是否正常完成并返回空金额（若如此，账户可用余额计算与比较口径为何）、还是作为业务失败返回错误（若失败，需确认错误码与错误信息）。
3. **多条匹配记录的选择**（关联 REQ-002、REQ-003）：余额表按账号定位可能出现多条记录时，需求未声明选择哪条记录作为后续计算输入。需确认单记录选择规则。
4. **acctAvailBal 的计算值与存储值口径**（关联 REQ-001、REQ-003）：需求「步骤描述」第 2 条定义账户可用余额按公式计算，输出表将其来源登记为对公存款账户余额表；余额表实体 `RbBusAcctBalanceEO` 本身含 acctAvailBal 存储列。需确认输出 acctAvailBal 为公式计算值，还是取余额表存储列值（若取存储列，计算公式中[账户可用余额]的取值来源需一并确认）。
5. **必填输入缺失或无效时的行为**（关联 REQ-001）：baseAcctNo、tranAmt 均标记为必填，需求未定义其为空、缺失或无效时的处理。需确认是否返回校验错误及相应错误码。
6. **金额运算的舍入与精度规则**（关联 REQ-003、REQ-004）：金额字段物理精度为 `DECIMAL(17,2)`，输入输出为 `BigDecimal`；需求未声明减、加运算的舍入规则以及比较是否按舍入后取值。需确认是否要求舍入及舍入精度/模式，还是按 BigDecimal 原值运算比较。
7. **跳转目标步骤的最终编号与定义**（关联 REQ-004）：需求以业务名称《检查法透标志》《检查现金支取账户限制》表述跳转目标，未绑定最终步骤编号，目标步骤正式 Spec 亦不在本任务范围。本 Spec 按需求原文名称约束跳转目标；目标步骤编号与定义待对应任务确认后关联，本步骤不生成路由值。

## 验收范围

- 可验收：REQ-001-S01、REQ-002-S01、REQ-003-S01、REQ-004-S01、REQ-004-S02、REQ-004-S03 对应行为——账号对应余额记录存在时四项金额取得正确，账户可用余额按公式计算正确（1000.00−100.00+50.00+200.00=1150.00），可用余额小于交易金额跳转《检查法透标志》、不小于（含相等）跳转《检查现金支取账户限制》，步骤正常完成且 StepResult 为成功。
- 账号到余额记录的定位映射、查询无记录/多记录、baseAcctNo 或 tranAmt 空值、acctAvailBal 计算值与存储值口径、舍入规则及跳转目标步骤编号等未决事项（见「待确认事项」）不作为本 Spec 已确认验收断言，待澄清后补充。
- 待确认事项不阻塞本 Spec 已确认条款的整理与验收。
