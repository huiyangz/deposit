# ST022 检查对手账户限额

## 目标与范围

本任务将正式需求「检查对手账户限额」（ST022，存款业务组件 `com.dcits.deposit` / deposit-service，交易执行步骤）整理为可验证的 Spec。本步骤按「步骤描述」第 1–14 项编排执行：

1. 依次调用组件内步骤 ST043（匹配限额场景）、ST038（检查账户机构是否可匹配到限额场景配置）、ST045（检查限额场景配置是否有效）、ST037（获取限额场景编码），完成限额场景匹配、机构匹配、配置有效性检查与场景编码确认；ST043 执行结果非"已匹配到限额场景"、或 ST038/ST045/ST037 任一步骤返回的限额场景编码为空时，本步骤返回检查结果为"通过"并正常提前结束；
2. 调用 ST042（获取累计限额）取得限额累计金额与限额累计笔数，调用 ST039（计算限额累计金额）完成累计计算；
3. 调用 ST040（检查限额）取得限额检查结果；结果为"未超限"时跳转至步骤 12 按累计情况判断更新分支，否则调用 ST041（处理限额）按处理方式返回（拒绝→错误码 ER0058、授权→授权标志"需授权"并等待授权、提示→检查结果"超限，但可继续交易"）；
4. 未超限时按累计情况执行：限额累计金额大于 0 或限额累计笔数大于 0 则调用 ST046（更新累计限额），限额累计金额等于 0 或限额累计笔数等于 0 则跳转调用 ST044（登记累计限额）。

范围限于 ST022 需求文档「步骤描述」「输入」「输出」「相关枚举」「补充说明」声明的编排、短路与数据契约；对需求未覆盖的内容（交易金额来源、跨步骤参数传递、检查结果承载、"提示"/"提醒"命名、授权等待机制、tranStatus 取值等），仅记录待确认事项，不补默认行为、不新增业务参数。本 Spec 不展开十个组件内步骤的目标实现，调用位置、参数来源与结果用途按需求原文绑定。

- **组件内步骤调用参数映射**（需求「补充说明」确认按组件内步骤调用处理，参数/返回沿用原文）：

  - ST038「检查账户机构是否可匹配到限额场景配置」：`baseAcctNo` ← {对手账号}；输出 `limitSceneNo` 为空即未匹配。
  - ST045「检查限额场景配置是否有效」：`limitSceneNo` ← [限额场景编码]、`tranDate` ← {交易日期}、`tranTimestamp` ← {交易时间}（与输入 tranTimestamp 为同一值）；输出 `limitSceneNo` 非空即配置有效、为空即无效。
  - ST037「获取限额场景编码」：`limitSceneNo` ← [限额场景编码]、`baseAcctNo` ← {对手账号}、`clientNo` ← {对手客户号}；ST037InputBO 另有必填输入 `tranDate`，需求步骤 5 未列出（见 TBD-03）。
  - ST042「获取累计限额」：`limitSceneNo` ← [限额场景编码]、`baseAcctNo` ← {对手账号}、`clientNo` ← {对手客户号}；输出 `limitSumAmt`（限额累计金额）与 `否`（限额累计笔数，`java.lang.Integer`）。
  - ST039「计算限额累计金额」：`limitSceneNo` ← [限额场景编码]、`tranAmt` ← {交易金额}；{对手账号}/{对手客户号}未在 ST039InputBO 中登记（见 TBD-04）。
  - ST040「检查限额」：`limitSceneNo` ← [限额场景编码]、`limitSumAmt` ← [限额累计金额]、`limitSumNum` ← [限额累计笔数]；输出 `limitCheckResult`（限额检查结果，取值"超限"/"未超限"，严格"大于"判定、相等为"未超限"）。
  - ST041「处理限额」：`limitSceneNo` ← [限额场景编码]；输出 `dealFlow`（`com.dcits.deposit.enums.DealFlow`：A=授权处理、B=拒绝处理、D=提醒处理），ST022 按 dealFlow 推导检查结果（授权/拒绝/提醒）。
  - ST046「更新累计限额」：`limitSceneNo` ← [限额场景编码]、`clientNo` ← {对手客户号}、`baseAcctNo` ← {对手账号}，另需传入 限额检查结果、limitSumAmt、否（限额累计笔数）；触发条件为 未超限 且（金额>0 或 笔数>0）。
  - ST044「登记累计限额」：`limitSceneNo` ← [限额场景编码]、`clientNo` ← {对手客户号}、`baseAcctNo` ← {对手账号}，另需传入 限额检查结果、limitSumAmt、否、tranAmt（交易金额）、runDate（系统日期，来源系统日期表 FM_DATE）；触发条件为 未超限 且（金额==0 或 笔数==0）。
- **错误码**：`errorcodes.properties:58` 已确认 `ER0058=交易超出限额控制`，与需求步骤 11a「拒绝 → 返回[错误码]'ER0058'」对应，是已确认的业务失败码值。
- **枚举**：`com.dcits.deposit.enums.DealFlow`（A/B/D）、`com.dcits.deposit.enums.TranStatus`（需求「相关枚举」确认业务处理状态取值来源）。
- **步骤结果契约**：`com.dcits.common.step.StepResult` 提供 succeed/errorCode/errorMessage；正常完成以及"返回检查结果为'通过'"的正常提前结束均按成功处理（succeed=true、错误字段为空），"拒绝"分支按业务失败返回已确认错误码 ER0058。
- **差异记录**：需求步骤 4 的{交易时间}与输入 tranTimestamp（交易时间戳）按同一值处理；{交易金额}未列入 ST022 输入表；输出表"否"/limitSumAmt 各登记两次（一次无来源实体、一次来源 RB_LIMIT_SUM_INFO）。上述差异以需求为准记录，见待确认事项。

#### Scenario: REQ-005-S01 限额检查结果为未超限时跳转至更新分支判断

- **GIVEN** 按[限额场景编码]、[限额累计金额]、[限额累计笔数]调用 ST040 返回[限额检查结果]="未超限"

### Requirement: REQ-006 超限处理方式与返回结果

来源：ST022「步骤描述」第 10–11 项（原文：根据[限额场景编码]访问…《处理限额》获取[检查结果]；a.若[检查结果]为"拒绝"，则返回[错误码]"ER0058"；b.若[检查结果]为"授权"，则返回[授权标志]为"需授权"并等待授权；c.若[检查结果]为"提示"，则返回检查结果为"超限，但可继续交易"）

在[限额检查结果]不为"未超限"时，系统 SHALL 按 [限额场景编码] 调用组件内步骤 ST041「处理限额」，按其处理方式分别处理，三个分支互斥：

- 处理方式为"提示"（DealFlow.D 提醒）时，本步骤返回检查结果为"超限，但可继续交易"并正常结束（"提示"与 ST041 正式 Spec 的"提醒"命名差异见待确认事项 TBD-08）。

ST041 仅输出 dealFlow，检查结果（授权/拒绝/提醒）由本步骤按 dealFlow 推导；"拒绝""授权""提示"对应处理方式的比较取值与检查结果承载见待确认事项 TBD-07、TBD-08。

#### Scenario: REQ-006-S01 处理方式为拒绝时返回错误码 ER0058

- **GIVEN** [限额检查结果]="超限"，按[限额场景编码]调用 ST041 返回的处理方式为"拒绝"（对应 `DealFlow.B`）
- **WHEN** 执行「步骤描述」第 11a 项
- **THEN** 本步骤返回[错误码]"ER0058"并以业务失败结束，errorMessage 使用已确认格式"ER0058::交易超出限额控制"

#### Scenario: REQ-006-S02 处理方式为授权时返回授权标志需授权

- **GIVEN** [限额检查结果]="超限"，按[限额场景编码]调用 ST041 返回的处理方式为"授权"（对应 `DealFlow.A`）
- **WHEN** 执行「步骤描述」第 11b 项
- **THEN** 本步骤返回[授权标志]"需授权"并等待授权；授权标志输出字段为输出表中已登记的 `授权标志`（`java.lang.String`）

#### Scenario: REQ-006-S03 处理方式为提示时返回超限但可继续交易

- **GIVEN** [限额检查结果]="超限"，按[限额场景编码]调用 ST041 返回的处理方式为"提示"（对应 `DealFlow.D` 提醒）

- **THEN** 本步骤返回检查结果为"超限，但可继续交易"并以成功状态正常结束

### Requirement: REQ-007 根据累计情况判断限额更新分支

## 待确认事项

- **TBD-01（关联 REQ-004、REQ-009）{交易金额}的来源**：步骤 7 调 ST039 与步骤 14 调 ST044 均需{交易金额}（分别对应 ST039InputBO.tranAmt、ST044InputBO.tranAmt），但 ST022「输入」表未声明交易金额字段。需确认 ST022 从何处取得交易金额（交易上下文、调用方其它输入或既有参数）。
- **TBD-02（关联 REQ-002）ST043 调用参数与执行结果承载**：步骤 1 按{对手客户号}、{对手账号}、{限额因子}调用 ST043，但 ST043InputBO 仅含 `factorName`（对手客户号/对手账号未在其 BO 中登记）；且 ST043OutputBO 未暴露检查结果（"已匹配到限额场景"/"未匹配到限额场景"），ST043 正式 Spec 的 TBD-5 亦待确认。需确认 ST043 的完整调用参数，以及本步骤如何取得并判断[执行结果]。
- **TBD-03（关联 REQ-003）ST037 调用缺交易日期参数**：步骤 5 按[限额场景编码]、{对手账号}、{对手客户号}调用 ST037，而 ST037InputBO 必填输入含 `tranDate`（交易日期）。需确认本步骤是否向 ST037 补传 tranDate={交易日期}（tranDate 输入值）。
- **TBD-04（关联 REQ-004）ST039 调用参数契约**：步骤 7 按{对手账号}、{对手客户号}、{交易金额}、[限额场景编码]调用 ST039，但 ST039InputBO 仅含 `tranAmt`、`limitSceneNo`，无对手账号/客户号字段（ST039 正式 Spec 的 TBD-2 亦在确认检查对象值来源）。需确认{对手账号}/{对手客户号}在 ST039 调用中的用途与传递方式。
- **TBD-05（关联 REQ-004、REQ-005、REQ-008）累计值数据流向与无记录空值**：步骤 8 调 ST040、步骤 12 判断所用[限额累计金额]/[限额累计笔数]按原文承接自步骤 6（ST042 输出）；步骤 7（ST039）计算结果的用途（是否覆盖[限额累计金额]/[限额累计笔数]用于 ST040 检查、步骤 12 判断及 ST046 更新）需求未明确。另 ST042 无匹配记录时累计值取值（ST042 正式 Spec TBD-3）及 null 值参与比较的口径亦未定义。需确认各环节实际使用的累计值来源及空值口径。
- **TBD-06（关联 REQ-007）步骤 12 分支条件重叠**：第 12a 项（未超限且金额>0 或 笔数>0 → 继续更新）与第 12b 项（未超限且金额==0 或 笔数==0 → 跳转登记）在"金额>0 且笔数==0""金额==0 且笔数>0"区间同时成立，需求未定义重叠区间的取舍（是否应为"金额>0 且笔数>0 → 更新、金额==0 且笔数==0 → 登记"，或以 ST046/ST044 各自触发条件为准）。需确认重叠区间走哪条分支。
- **TBD-07（关联 REQ-002、REQ-003、REQ-006、REQ-010）检查结果的承载**：本步骤返回的检查结果"通过"/"超限，但可继续交易"未在输出表登记承载字段（输出表仅有"限额检查结果"与"授权标志"）；ST041 的检查结果（拒绝/提醒/授权）在 ST041OutputBO 中仅以 `dealFlow` 承载；"限额检查结果"输出字段的填充时机与取值亦未声明。需确认检查结果的承载字段/方式、ST041 检查结果的推导映射及"限额检查结果"字段的填充。

## 验收范围

验收以 REQ-001~REQ-010 声明的行为为准：

- REQ-001：五个必填输入契约。
- REQ-002：ST043 执行结果为"已匹配到限额场景"继续执行、否则返回检查结果"通过"并成功提前结束。
- REQ-003：ST038/ST045/ST037 依次调用、任一步骤返回限额场景编码为空即返回"通过"并提前结束、三次均非空继续执行。
