# ST030 检查对手账户是否能够入账

## 目标与范围

本 Spec 定义交易执行步骤「检查对手账户是否能够入账」（ST030）的输入输出契约与检查行为。步骤以对手账号（othBaseAcctNo）为输入，依次取得对手账户状态、对手账户转账止付标志、对手账户转账不收不付标志，执行规则《检查账户是否能够入账》（DT002）取得入账标志；当入账标志为"允许"时返回检查结果"通过"，否则返回错误码"ER0077"。

范围仅覆盖需求「步骤描述」第 1–5 条、「输入」「输出」「相关枚举」「补充说明」「执行规则」已确认的契约，以及「补充说明」明确的两处组件内步骤调用（ST052「检查是否存在转账止付限制」、ST056「检查是否存在转账不收不付限制」，按组件内步骤调用处理，调用参数和返回结果沿用原文描述）。需求未定义的查询方式、命名口径、查询无记录与必填缺失处理、输出物理编码等缺口记录于「待确认事项」，不作为已确认验收断言，不补默认行为。

### 依赖核对（已核实的工程约束）

- **名称映射**（`requirement-name-mapping` 资产）：业务称谓「账户信息」→ 实体「对公存款账户主表」（RB_BUS_ACCT），与「输出」表 acctStatus 的来源实体一致。「账户状态」「输出数据-账户状态」未收录属性域映射，需求「补充说明」确认取值来源于枚举类 `com.dcits.deposit.enums.AcctStatus`，按枚举处理。「对手账号」（othBaseAcctNo）、「入账标志」「转账止付标志」「转账不收不付标志」未收录，保留原业务称谓。
- **枚举核对**（`deposit-common`）：`AcctStatus` 存在，取值（代码值/业务名称）为 N/新建、H/待激活、S/久悬、O/转营业外、A/活动、C/关闭、D/睡眠、I/预开户、P/逾期、R/预销户、U/手工解除，含 `getValue()`/`byValue()`。需求「补充说明」确认账户状态取值来源于该类。
- **组件内步骤调用**（关联 Spec ST052、ST056）：ST052「检查是否存在转账止付限制」输入 baseAcctNo（`java.lang.String`，必填，账号），输出转账止付标志（`java.lang.String`，业务取值"是"/"否"）及其余 resSeqNo 等字段；ST056「检查是否存在转账不收不付限制」输入 baseAcctNo（`java.lang.String`，必填，账号），输出转账不收不付标志（`java.lang.String`，业务取值"是"/"否"）及其余 resSeqNo 等字段。本步骤以对手账号 othBaseAcctNo 作为调用账号（ST052/ST056 输入 baseAcctNo），调用参数与返回结果沿用原文描述；原文第 2、3 条以[现金止收标志]表述所取得的标志，与 ST052/ST056 输出名称及本步骤第 4 条/「输出」表的命名差异见 TBD-1；参数映射（othBaseAcctNo→baseAcctNo）确认见 TBD-5。
- **规则调用**（关联 Spec DT002）：规则《检查账户是否能够入账》为决策类规则，DT002 Spec 确认契约：输入 acctStatus（`com.dcits.deposit.enums.AcctStatus`，必填）、账户转账止付标志（`java.lang.String`，非必填）、账户转账不收不付标志（`java.lang.String`，非必填），输出入账标志（`java.lang.String`，取值"允许"/"不允许"）。工程实现 `com.dcits.deposit.rule.DT002.execute(AcctStatus acctStatus, String transferStopFlag, String transferNoCreditNoDebitFlag)` 为静态方法，返回"允许"/"不允许"；参数顺序与需求步骤第 4 条（[对手账户状态]、[对手账户转账止付标志]、[对手账户转账不收不付标志]）一致。DT002 对"新建""正常"状态、未列组合及标志空值的判定存在其 Spec 待确认事项（TBD-1/TBD-2/TBD-6），本步骤的[入账标志]结果继承该规则的已确认与未确认部分，不重定义规则（见 TBD-2）。
- **查询接口核对（步骤 1）**：对公存款账户主表 EO `RbBusAcctEO`（deposit-infrastructure-api）含 acctStatus（`AcctStatus`）字段，主键为 clientNo+internalKey；EO 未暴露账号（baseAcctNo）字段。数据服务 `IRbBusAcctBcc.findByEo(RbBusAcctEO)` 按 EO 非空字段组合查询并返回 `List<RbBusAcctEO>`，无法直接按对手账号过滤。需求要求"根据{对手账号}查询【账户信息】获取账户状态"，按对手账号定位账户记录并取得 acctStatus 的查询方式/关联字段未确认，见 TBD-4（工程 `ST051Pbc` 存在同类缺口记录）。
- **步骤结果机制与错误码**：`StepResult`（`com.dcits.common.step`）含 succeed/errorCode/errorMessage，成功时 errorCode 为 null；交易级 `RespHeader` 同构，正常业务输出与响应头分离。需求步骤第 5 条声明业务失败分支：入账标志非"允许"时返回错误码"ER0077"。错误码核对：`deposit-application` 的 errorcodes.properties 第 77 行 `ER0077=转入账户不允许入账，交易失败`，与需求步骤第 5 条声明的码值一致，按 `错误码::业务说明` 格式用于 errorMessage（"ER0077::转入账户不允许入账，交易失败"）。"检查结果为'通过'"对应步骤正常完成，承载方式见 TBD-7。

## Requirements

### Requirement: REQ-001 依据对手账号获取对手账户状态

来源：需求「步骤描述」第 1 条（原文：1.获取对手账户状态：根据{对手账号}查询【账户信息】获取$账户状态$）；「输入」表 othBaseAcctNo；「输出」表 acctStatus；「相关枚举」「补充说明」（账户状态→`com.dcits.deposit.enums.AcctStatus`）；名称映射（账户信息→对公存款账户主表）。

系统 SHALL 依据输入对手账号 othBaseAcctNo（`java.lang.String`，必填）查询【账户信息】（对公存款账户主表 RB_BUS_ACCT），取得该对手账户的账户状态；账户状态取值 SHALL 属于枚举 `com.dcits.deposit.enums.AcctStatus`，作为 REQ-004 执行入账判定规则的输入，并按「输出」表作为 acctStatus（非必填）输出。

#### Scenario: REQ-001-S01 对手账号存在账户记录时取得账户状态
- **GIVEN** 输入对手账号 othBaseAcctNo 为"622800000001"（示例值，账号格式约束需求未定义）；对公存款账户主表（RB_BUS_ACCT）存在该对手账号对应的账户记录，其账户状态为"活动"（枚举 `AcctStatus.A`，示例值）
- **WHEN** 依据对手账号查询【账户信息】获取账户状态
- **THEN** 取得该对手账户的账户状态 `AcctStatus.A`，作为 REQ-004 执行入账判定规则的输入，并按「输出」表输出 acctStatus

### Requirement: REQ-004 执行入账判定规则获取入账标志

来源：需求「步骤描述」第 4 条（原文：4.检查对手账户是否能够交易：根据[对手账户状态]，[对手账户转账止付标志]，[对手账户转账不收不付标志]执行规则《检查账户是否能够入账》,获取[入账标志]）；「执行规则」；关联 Spec DT002。

系统 SHALL 以 REQ-001 取得的[对手账户状态]、REQ-002 取得的[对手账户转账止付标志]、REQ-003 取得的[对手账户转账不收不付标志]为输入（按 [账户状态]、[转账止付标志]、[转账不收不付标志] 顺序），执行规则《检查账户是否能够入账》（DT002），取得[入账标志]（`java.lang.String`，业务取值"允许"/"不允许"），作为 REQ-005 检查的依据并按「输出」表作为入账标志（非必填）输出；入账标志的判定结果继承 DT002 Spec 已确认规则（如 待激活+止付=是+不收不付=否→"允许"；久悬/转营业外+不收不付=否→"不允许"）及其未确认事项（见 TBD-2），本步骤不重定义规则。

#### Scenario: REQ-004-S01 待激活且止付为是且不收不付为否时规则返回"允许"
- **GIVEN** [对手账户状态]="待激活"（`AcctStatus.H`，示例值）、[对手账户转账止付标志]="是"、[对手账户转账不收不付标志]="否"（按 DT002 Spec 规则条目 c）
- **WHEN** 以[对手账户状态]、[对手账户转账止付标志]、[对手账户转账不收不付标志]执行规则《检查账户是否能够入账》
- **THEN** 取得[入账标志]="允许"，作为 REQ-005 检查的依据并按「输出」表输出入账标志

#### Scenario: REQ-004-S02 久悬且不收不付为否时规则返回"不允许"
- **GIVEN** [对手账户状态]="久悬"（`AcctStatus.S`，示例值）、[对手账户转账不收不付标志]="否"（按 DT002 Spec 规则条目 e）
- **WHEN** 以[对手账户状态]、[对手账户转账止付标志]、[对手账户转账不收不付标志]执行规则《检查账户是否能够入账》
- **THEN** 取得[入账标志]="不允许"，作为 REQ-005 检查的依据并按「输出」表输出入账标志

### Requirement: REQ-005 依据入账标志返回检查结果

来源：需求「步骤描述」第 5 条（原文：5.检查入账标志：若[入账标志]为"允许"，则返回检查结果为"通过"，否则返回[错误码]"ER0077"）；errorcodes.properties（第 77 行 `ER0077=转入账户不允许入账，交易失败`）。

系统 SHALL 在[入账标志]为"允许"时返回检查结果为"通过"，按步骤正常完成处理（成功状态，errorCode 为 null、errorMessage 为空），不产生错误码；系统 SHALL 在[入账标志]非"允许"时返回错误码"ER0077"（含义"转入账户不允许入账，交易失败"），按业务失败处理，errorMessage 使用"ER0077::转入账户不允许入账，交易失败"格式。规则输出取值域为"允许"/"不允许"（DT002 REQ-001），"不允许"为已确认落入"否则"分支的取值；其它取值（如空值）的归属未区分，见 TBD-2。

#### Scenario: REQ-005-S01 入账标志为"允许"时返回通过
- **GIVEN** 规则《检查账户是否能够入账》执行返回[入账标志]="允许"
- **WHEN** 检查入账标志
- **THEN** 返回检查结果为"通过"：步骤正常完成（成功状态，errorCode 为 null、errorMessage 为空），不产生错误码"ER0077"

#### Scenario: REQ-005-S02 入账标志为"不允许"时返回错误码 ER0077
- **GIVEN** 规则《检查账户是否能够入账》执行返回[入账标志]="不允许"
- **WHEN** 检查入账标志
- **THEN** 步骤按业务失败结束，返回错误码"ER0077"（含义"转入账户不允许入账，交易失败"），errorMessage 为"ER0077::转入账户不允许入账，交易失败"，不返回检查结果"通过"

### Requirement: REQ-006 输出契约

来源：需求「输出」表。

系统 SHALL 按「输出」表输出以下字段（类型与必填性按表）：
- 入账标志（`java.lang.String`，非必填，规则《检查账户是否能够入账》执行结果）；
- 转账止付标志（`java.lang.String`，非必填，组件内步骤 ST052 返回结果）；

## 待确认事项

- **TBD-1（关联 REQ-002、REQ-003）[现金止收标志] 与 [转账止付标志]/[转账不收不付标志] 命名冲突**：需求「步骤描述」第 2、3 条均表述"获取[现金止收标志]"，而第 4 条与「输出」表分别以[对手账户转账止付标志]、[对手账户转账不收不付标志]使用与登记；组件内步骤 ST052 的判定结论名称为转账止付标志（stopFlag）、ST056 的为转账不收不付标志（transferNoCreditNoDebitFlag）。"现金止收标志"是另一组件内步骤 ST054「检查是否存在现金止收限制」的判定结论名称，与转账止付/转账不收不付为不同业务结论。需确认：步骤 2/3 实际从 ST052/ST056 取得的字段与命名口径（疑为原文笔误），以及[对手账户转账止付标志]/[对手账户转账不收不付标志] 与 ST052/ST056 返回值的对应关系。
- **TBD-2（关联 REQ-004、REQ-005）入账标志判定结果的继承与"否则"分支覆盖范围**：规则《检查账户是否能够入账》（DT002）对"新建""正常"状态、未列状态（活动/关闭/睡眠/预开户/逾期/预销户/手工解除）与标志组合、标志空值/非"是"非"否"取值的判定存在 DT002 Spec 待确认事项（TBD-1/TBD-2/TBD-6），本步骤的[入账标志]结果继承该规则未确认部分，对手账户状态或标志落到未确认组合时的[入账标志]取值未确认；入账标志取值域之外（如空值）落入需求"否则"分支时是否返回 ER0077、与"不允许"是否区分未确认。
- **TBD-3（关联 REQ-002、REQ-003）组件内步骤查询无记录/多条记录时的返回口径**：ST052/ST056 按账号与限制状态"A-生效"查询无生效限制记录时返回的标志取值、多条生效限制记录时的取数规则未确认（ST052 TBD-1/TBD-2、ST056 待确认 1/2）。该未决返回进入本步骤作为[对手账户转账止付标志]/[对手账户转账不收不付标志]参与入账判定的结果取决于其行为。
- **TBD-4（关联 REQ-001）按对手账号查询账户信息的查询方式**：对公存款账户主表 EO `RbBusAcctEO` 未暴露账号（baseAcctNo）字段，主键为 clientNo+internalKey；现有 `IRbBusAcctBcc.findByEo` 按 EO 非空字段组合查询、无法直接按对手账号过滤。需求步骤 1 要求"根据{对手账号}查询【账户信息】获取账户状态"，按对手账号定位账户记录并取得 acctStatus 的查询方式/关联字段未确认（工程 `ST051Pbc` 存在同类缺口记录）。
