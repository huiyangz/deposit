# ST033 检查账户余额类型一致性

## 目标与范围

本 Spec 将正式需求「检查账户余额类型一致性」交易执行步骤整理为可验证的行为规范。步骤依次获取转出账户与转入账户的余额类型（第 1、2 步），并检查两者一致性：不一致时步骤失败并返回错误码 `ER0075`，一致时检查结果返回「通过」（第 3 步）；步骤另声明非必填输出字段 `rbAcctType`（存款账户类型，枚举 `com.dcits.deposit.enums.RbAcctType`）。

范围限于需求「步骤描述」第 1–3 步、「输入」「输出」表、「相关枚举」及「补充说明」声明的行为。步骤描述以「余额类型」作为比较对象，而「输出」表及「补充说明」声明输出为「存款账户类型」（`rbAcctType`）；两者在工程中为对公存款账户主表上两个不同字段（`balType`/`rbAcctType`），其对应关系、输出字段归属账户及账号查询路径未由需求确认，详见「待确认事项」，本 Spec 不补默认行为。

## 输入、输出及依赖契约

### 输入

| 字段名 | 类型 | 标记 | 来源实体 | 说明 |
|--------|------|------|----------|------|
| `baseAcctNo` | `java.lang.String` | 必填 | 未在需求中指定（由调用方提供） | 账号（转出账户） |
| `othBaseAcctNo` | `java.lang.String` | 必填 | 未在需求中指定（由调用方提供） | 对手账号（转入账户） |

### 输出

| 字段名 | 类型 | 标记 | 来源实体 | 说明 |
|--------|------|------|----------|------|
| `rbAcctType` | `com.dcits.deposit.enums.RbAcctType` | 非必填 | 对公存款账户主表（RB_BUS_ACCT） | 存款账户类型 |

### 步骤结果契约

- 步骤成功：`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 均为 `null`，对应检查结果「通过」。
- 步骤业务失败：`StepResult.succeed = false`，`errorCode = "ER0075"`，`errorMessage` 按 `错误码::业务说明` 格式为 `"ER0075::转账双方账户余额类型不一致"`。
- 错误码来源：`deposit-application/src/main/resources/errorcodes.properties` 第 75 行 `ER0075=转账双方账户余额类型不一致`。

### 依赖核对

- 名称映射（requirement-name-mapping）：「账户信息」→ 对公存款账户主表（RB_BUS_ACCT），已收录；「余额类型」「存款账户类型」未收录于属性域映射，本 Spec 按需求原文业务称谓表述。
- 枚举 `com.dcits.deposit.enums.RbAcctType` 存在于 `deposit-common`，取值与中文含义：`A`=AIO账户、`C`=结算账户、`S`=储蓄账户、`T`=定期账户，对应需求「存款账户类型」（输出 `rbAcctType`）。
- 枚举 `com.dcits.deposit.enums.BalType` 存在于 `deposit-common`，取值与中文含义：`CA`=钞余额、`TT`=汇余额；工程中 `RbBusAcctEO` 的 `balType` 字段即为「余额类型」。需求步骤所比较的「余额类型」是否即该字段，见待确认事项 TBD-1。
- `RbBusAcctEO`（对公存款账户主表）同时含 `rbAcctType`（存款账户类型，`RbAcctType`）与 `balType`（余额类型，`BalType`）两个不同字段；主键为客户号 `clientNo` + 账户内部键值 `internalKey`。
- 账号 `baseAcctNo` 位于对公客户账户表（RB_BUS_CLIENT_ACCT，主键 `baseAcctNo`+`clientNo`），不在对公存款账户主表上；`IRbBusAcctBcc` 公开方法含 `findByEo`、`findByPrimaryKey(clientNo, internalKey)` 等，无按账号查询方法。按账号定位对公存款账户主表记录的实际查询/关联路径未确认，见 TBD-3。

## Requirements

### Requirement: REQ-001 获取转出账户余额类型

来源：需求「步骤描述」第 1 步（原文：根据{账号}查询【账户信息】获取$余额类型$）

系统 SHALL 根据输入 账号（`baseAcctNo`）查询【账户信息】（对公存款账户主表，RB_BUS_ACCT）获取转出账户的余额类型，作为第 3 步一致性比较的转出侧取值。

#### Scenario: REQ-001-S01 按账号查询转出账户余额类型

- **GIVEN** 输入 `baseAcctNo` 为账号（示例值："1000000001"），对公存款账户主表中存在对应转出账户记录且其余额类型为钞余额（`BalType.CA`）
- **WHEN** 执行第 1 步，按账号查询【账户信息】
- **THEN** 取得转出账户余额类型为钞余额（`BalType.CA`），并作为第 3 步转出侧取值用于一致性比较

### Requirement: REQ-002 获取转入账户余额类型

来源：需求「步骤描述」第 2 步（原文：根据{对手账号}查询【账户信息】获取$余额类型$）

系统 SHALL 根据输入 对手账号（`othBaseAcctNo`）查询【账户信息】（对公存款账户主表，RB_BUS_ACCT）获取转入账户的余额类型，作为第 3 步一致性比较的转入侧取值。

#### Scenario: REQ-002-S01 按对手账号查询转入账户余额类型

- **GIVEN** 输入 `othBaseAcctNo` 为对手账号（示例值："1000000002"），对公存款账户主表中存在对应转入账户记录且其余额类型为汇余额（`BalType.TT`）
- **WHEN** 执行第 2 步，按对手账号查询【账户信息】
- **THEN** 取得转入账户余额类型为汇余额（`BalType.TT`），并作为第 3 步转入侧取值用于一致性比较

### Requirement: REQ-003 检查账户余额类型一致性

来源：需求「步骤描述」第 3 步（原文：若转出账户的[余额类型]与转入账户的[余额类型]不一致，则返回[错误码]"ER0075"，否则返回检查结果为"通过"）

当转出账户余额类型与转入账户余额类型不一致时，系统 SHALL 使本步骤失败：`StepResult.succeed = false`，`errorCode = "ER0075"`，`errorMessage = "ER0075::转账双方账户余额类型不一致"`。当两者一致时，系统 SHALL 使本步骤成功：`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 均为 `null`，检查结果为「通过」。

#### Scenario: REQ-003-S01 余额类型一致返回通过

- **GIVEN** 转出账户余额类型与转入账户余额类型一致（示例值：两者均为钞余额 `BalType.CA`）
- **WHEN** 执行第 3 步，比较转出账户与转入账户的余额类型
- **THEN** 本步骤成功（`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 为 `null`），检查结果为「通过」

#### Scenario: REQ-003-S02 余额类型不一致返回 ER0075

- **GIVEN** 转出账户余额类型为钞余额（`BalType.CA`）、转入账户余额类型为汇余额（`BalType.TT`），两者不一致
- **WHEN** 执行第 3 步，比较转出账户与转入账户的余额类型
- **THEN** 本步骤失败（`StepResult.succeed = false`），`errorCode` 为 `ER0075`，`errorMessage` 为 `"ER0075::转账双方账户余额类型不一致"`

### Requirement: REQ-004 输出 rbAcctType 契约

来源：需求「输出」表、「相关枚举」及「补充说明」（存款账户类型取值来源于代码，对应枚举类 `com.dcits.deposit.enums.RbAcctType`）

系统 SHALL 按输出表声明提供非必填输出字段 `rbAcctType`，类型为 `com.dcits.deposit.enums.RbAcctType`，取值来源于【账户信息】（对公存款账户主表，RB_BUS_ACCT）的存款账户类型，取值 SHALL 属于枚举 `RbAcctType` 的 `A`=AIO账户、`C`=结算账户、`S`=储蓄账户、`T`=定期账户。该输出字段与第 1–3 步所比较「余额类型」字段的关系及归属账户见待确认事项 TBD-1、TBD-2。

#### Scenario: REQ-004-S01 输出字段类型与枚举取值

- **GIVEN** 本步骤执行完成且输出 `rbAcctType` 字段被赋值
- **WHEN** 检查本步骤输出字段 `rbAcctType`
- **THEN** `rbAcctType` 类型为 `com.dcits.deposit.enums.RbAcctType`，取值属于 `{A, C, S, T}` 之一，且字段标记为非必填

## 待确认事项

- **TBD-1（关联 REQ-001~REQ-003、REQ-004）：比较字段与输出字段的概念关系未确认。** 需求步骤描述及错误码 `ER0075`（转账双方**账户余额类型**不一致）均针对「余额类型」，工程中 `RbBusAcctEO.balType`（`BalType` 枚举：CA=钞余额、TT=汇余额）即「余额类型」字段；而需求「输出」表及「补充说明」声明输出 `rbAcctType` 为「存款账户类型」（`RbAcctType` 枚举：A/C/S/T）。两字段在同一实体上且概念不同，需求未声明两者关系。需确认：第 3 步比较所取的「余额类型」是否即 `balType`；输出 `rbAcctType` 是否即为比较所用字段，还是独立于比较的另一个字段及其取值来源。
- **TBD-2（关联 REQ-004）：输出 `rbAcctType` 的归属账户未确认。** 需求输出表未说明该字段取自转出账户还是转入账户（步骤 1、2 分别查询两个账户的余额类型）。需确认输出 `rbAcctType` 来源于哪个账户及在哪一步取得。
- **TBD-3（关联 REQ-001、REQ-002）：按账号查询对公存款账户主表的路径未确认。** 需求按{账号}/{对手账号}查询【账户信息】获取余额类型；工程中对公存款账户主表主键为客户号+账户内部键值且 `IRbBusAcctBcc` 无按账号查询方法，账号 `baseAcctNo` 位于对公客户账户表（RB_BUS_CLIENT_ACCT）。需确认实际定位路径（如经对公客户账户表关联客户号后再查询对公存款账户主表，或经其他组件），不因接口暂缺而补造客户端方法。
- **TBD-4（关联 REQ-001、REQ-002）：按账号/对手账号查询无记录时的行为未定义。** 需求未声明查询不到对公存款账户主表记录时应返回何种结果（是否作为业务失败、错误码为何）。需确认。
- **TBD-5（关联 REQ-001、REQ-002）：必填输入缺失行为未定义。** `baseAcctNo`、`othBaseAcctNo` 标记为必填，但需求未定义输入为空/缺失时的行为（是否校验失败及错误码）。需确认。
