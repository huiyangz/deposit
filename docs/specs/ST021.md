# ST021 检查支取账户类型

## 目标与范围

本 Spec 定义交易执行步骤「检查支取账户类型」（ST021）的输入输出契约与账户类型检查行为。步骤按必填输入 baseAcctNo（账号）查询【账户信息】（对公存款账户主表）取得存款账户类型，再按账户类型判定检查结果：账户类型既非「T-定期账户」也非「A-AIO账户」时检查通过；账户类型为 T 或 A 时返回错误码「ER0052」。

范围仅覆盖需求文档「步骤描述」第 1、2 步，「输入」「输出」「相关枚举」「补充说明」所声明的内容。原文条件「若[账户类型]不等于"T-定期账户"或"A-AIO账户"」存在「或/且」字面歧义，本 Spec 结合错误码业务说明整理为「既非 T 且非 A」，歧义详情见「待确认事项」TBD-1。查询无记录、账户类型为空等需求未定义情形见 TBD-2、TBD-3，不补默认行为。

## 输入、输出及依赖契约

### 输入

| 字段名 | 类型 | 必填性 | 说明 |
|---|---|---|---|
| `baseAcctNo` | `java.lang.String` | 必填 | 账号，用于查询账户信息 |

### 输出

| 字段名 | 类型 | 必填性 | 来源实体 | 说明 |

| `rbAcctType` | `com.dcits.deposit.enums.RbAcctType` | 非必填 | 对公存款账户主表（RB_BUS_ACCT） | 存款账户类型 |

### 相关枚举（已核对工程）

枚举 `com.dcits.deposit.enums.RbAcctType`（deposit-common）取值与业务名称：

| 代码值 | 业务名称 |
|---|---|
| A | AIO账户 |
| C | 结算账户 |
| S | 储蓄账户 |
| T | 定期账户 |

需求判定条件中的「T-定期账户」「A-AIO账户」对应代码值 T、A。

### 错误码（已核对工程）

| 错误码 | 业务说明 | 来源 |
|---|---|---|

### 依赖核对

- 名称映射（`requirement-name-mapping` 资产）：业务称谓「账户信息」→ 对公存款账户主表（RB_BUS_ACCT），与需求输出表来源实体一致；属性域「存款账户类型」未收录于映射资产，需求「补充说明」已明确其取值来源于代码[存款账户类型]、对应枚举类 `com.dcits.deposit.enums.RbAcctType`，本 Spec 保留原业务称谓并沿用该枚举绑定，不改写业务事实。
- 对公存款账户主表实体 `RbBusAcct`（对应表 RB_BUS_ACCT）存在字段 `rbAcctType`（`java.lang.String`，注释「存款账户类型」），与需求输出字段同名；输出 `rbAcctType` 以该字段代码值（"A"/"C"/"S"/"T"）映射为对应枚举值（枚举类提供 `byValue(String)` 转换）。
- 错误码 ER0052 已存在于项目错误码定义，业务说明「当前账户不为活期账户」，与需求将 T（定期账户）、A（AIO账户）判定失败（非活期类）的语义一致，无冲突。
- 步骤结果契约：`com.dcits.common.step.StepResult` 含 `succeed` / `errorCode` / `errorMessage`；正常完成时 `succeed=true` 且错误码、错误信息为空，业务失败时 `succeed=false` 且 `errorCode` 携带确认码值、`errorMessage` 采用「错误码::业务说明」格式（`ER0052::当前账户不为活期账户`）。
- 需求输出表仅声明 `rbAcctType` 一个业务输出字段，未声明「检查结果」字段；检查结论「通过 / 返回错误码 ER0052」以步骤成功状态与错误码承载。
- 需求未指定按账号查询账户信息的具体服务方法或定位字段，步骤实现所需查询接口尚未生成，不构成需求缺失，实现阶段按「对公存款账户主表」数据服务（如 `IRbBusAcctBcc`）核对。

## Requirements

### Requirement: REQ-001 获取存款账户类型
来源：需求「步骤描述」第1步（原文：获取账户类型：根据{账号}查询【账户信息】获取$账户类型$）；「输入」表、「输出」表、「相关枚举」「补充说明」。

系统 SHALL 以必填输入 baseAcctNo（`java.lang.String`，账号）为查询条件，从【账户信息】（对公存款账户主表 RB_BUS_ACCT）取得该账户的存款账户类型，并以输出 rbAcctType（类型 `com.dcits.deposit.enums.RbAcctType`）返回；rbAcctType 的取值 SHALL 为对公存款账户主表存款账户类型字段（`rbAcctType`）代码值对应的枚举值，代码值与枚举对应关系见「输入、输出及依赖契约」。

#### Scenario: REQ-001-S01 按账号查询并返回存款账户类型
- **GIVEN** 输入 baseAcctNo 必填（样例值 `1234567890123`），且该账号对应账户存在于对公存款账户主表，其存款账户类型字段代码值为 "C"
- **WHEN** 执行步骤第1步，按 baseAcctNo 查询账户信息
- **THEN** 输出 rbAcctType 为 `RbAcctType.C`（结算账户），与账户主表存款账户类型字段代码值 "C" 对应

### Requirement: REQ-002 账户类型既非定期账户也非 AIO 账户时检查通过
来源：需求「步骤描述」第2步通过分支（原文：若[账户类型]不等于"T-定期账户"或"A-AIO账户"，则返回检查结果为"通过"）；「或/且」字面歧义见 TBD-1，本条按业务语义整理为「既非 T 且非 A」。

当存款账户类型既不是 T（定期账户）也不是 A（AIO账户）时，系统 SHALL 返回检查结果为「通过」：步骤正常完成（`StepResult.succeed` 为 true，`errorCode` 与 `errorMessage` 均为空），并输出 rbAcctType；不返回任何错误码。

#### Scenario: REQ-002-S01 账户类型为结算账户时检查通过
- **GIVEN** 存款账户类型为 C（结算账户）
- **WHEN** 执行步骤第2步检查账户类型
- **THEN** 返回检查结果为「通过」：步骤正常完成（`succeed=true`，`errorCode` 与 `errorMessage` 均为空），输出 rbAcctType 为 `RbAcctType.C`

#### Scenario: REQ-002-S02 账户类型为储蓄账户时检查通过
- **GIVEN** 存款账户类型为 S（储蓄账户）
- **WHEN** 执行步骤第2步检查账户类型
- **THEN** 返回检查结果为「通过」：步骤正常完成（`succeed=true`，`errorCode` 与 `errorMessage` 均为空），输出 rbAcctType 为 `RbAcctType.S`

### Requirement: REQ-003 账户类型为定期账户或 AIO 账户时返回错误码 ER0052
来源：需求「步骤描述」第2步失败分支（原文：否则返回[错误码]"ER0052"）；错误码业务说明来自项目错误码定义（`errorcodes.properties`）。

当存款账户类型为 T（定期账户）或 A（AIO账户）时，系统 SHALL 返回错误码「ER0052」，即步骤业务失败：`StepResult.succeed` 为 false，`errorCode` 为 "ER0052"，`errorMessage` 为 "ER0052::当前账户不为活期账户"。

#### Scenario: REQ-003-S01 账户类型为定期账户时返回 ER0052
- **GIVEN** 存款账户类型为 T（定期账户）
- **WHEN** 执行步骤第2步检查账户类型
- **THEN** 步骤业务失败（`succeed=false`），`errorCode` 为 "ER0052"，`errorMessage` 为 "ER0052::当前账户不为活期账户"

#### Scenario: REQ-003-S02 账户类型为 AIO 账户时返回 ER0052
- **GIVEN** 存款账户类型为 A（AIO账户）
- **WHEN** 执行步骤第2步检查账户类型
- **THEN** 步骤业务失败（`succeed=false`），`errorCode` 为 "ER0052"，`errorMessage` 为 "ER0052::当前账户不为活期账户"

## 待确认事项

- **TBD-1（关联 REQ-002、REQ-003；「或/且」歧义）**：原文「若[账户类型]不等于"T-定期账户"或"A-AIO账户"，则返回检查结果为"通过"，否则返回[错误码]"ER0052"」。按字面「或」（不等于 T **或** 不等于 A）理解时，条件恒为真，else 分支（返回 ER0052）不可达，与需求明确给出两分支结果的意图不符。本 Spec 依据错误码 ER0052 业务说明「当前账户不为活期账户」（T 定期账户、A AIO 账户均为非活期类）整理为「既非 T **且** 非 A → 通过；T 或 A → ER0052」。需确认原文意图是否为「不等于 T 且不等于 A → 通过」；若确认为字面「或」语义，判定条件与 REQ-002/REQ-003 需重排。
- **TBD-2（关联 REQ-001）**：baseAcctNo 标记为必填，但需求未定义其缺失/为空时的行为（是否校验失败、返回哪个错误码或如何处理）。
- **TBD-3（关联 REQ-001、REQ-002、REQ-003）**：按 baseAcctNo 查询账户信息无记录，或账户的存款账户类型字段为空/不在枚举代码值（A/C/S/T）范围内时，需求未定义行为（是否视为检查不通过、返回哪个错误码或按其它规则处理）。
