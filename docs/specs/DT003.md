# DT003 根据核准类型设置账户状态

## 目标与范围

本任务为决策类规则（源需求标注：规则类型＝决策类）。规则在开户建档场景下，依据账户属性、对公存款账户用途、境内境外标志、企业标志，决定对公存款账户的账户状态（acctStatus），结果归属对公存款账户主表（RB_BUS_ACCT）。

本次 Spec 覆盖：

- 判定入参：acctNatureNo（账户属性，必填）、rbBusAcctPurpose（对公存款账户用途，非必填）、corporationFlag（企业标志，必填）、inlandOffshore（境内境外标志，必填）。
- 判定输出：acctStatus（账户状态，非必填，来源实体：对公存款账户主表 RB_BUS_ACCT）。
- 分支结构：按账户属性分为五组（基本户、一般户、专用户、临时户、验资户），组间按账户属性互斥、不存在执行先后或优先级关系；账户属性为这五类之外的取值时走兜底分支（REQ-007）。
- 账户属性为“专用户”时，先按对公存款账户用途是否为“预算单位专用存款户”分流为两种处理（REQ-003 / REQ-004）。

不在本次范围（源需求未涉及，本 Spec 不作要求）：

- 账户状态字段的历史取值、前置校验、状态流转及后续业务处理。
- 入参形态校验（必填项为空、取值不在合法枚举内）时的规则行为。
- 组件内步骤调用、外部服务/领域服务调用、超时与重试、失败传播（本规则为纯决策计算，源需求未涉及）。
- 规则名称中“核准类型”的业务口径（见“验收范围与明确不覆盖的事项”第 1 项）。

|--------|--------------------|--------|------|--------------------|
| acctStatus | java.lang.String | 非必填 | 账户状态 | 对公存款账户主表（RB_BUS_ACCT），字段 RB_BUS_ACCT.ACCT_STATUS |

说明：

- 承载口径：`RbBusAcct` 实体中 `acctStatus` 为 java.lang.String（落库字段），查询层 EO 中为枚举 `AcctStatus`；源需求声明输出类型为 java.lang.String。该差异属技术承载口径，不改变业务取值语义。

### 枚举绑定（用于给出可执行的取值）

- 账户属性描述词与 `AcctNatureNo` 成员按枚举注释一对一绑定：基本户＝VALUE_11001（代码 11001，基本存款账户）；一般户＝VALUE_11002（11002，一般存款账户）；专用户＝VALUE_11004（11004，专用存款账户）；临时户＝VALUE_11003（11003，临时存款账户）；验资户＝VALUE_17（17，验资户）。源需求正文以描述词表述，未给出代码。
- 账户用途“预算单位专用存款户”＝`RbBusAcctPurpose.VALUE_4`（代码 4，预算单位专用）；源需求正文以描述词表述，未给出代码。
- 账户状态描述词与 `AcctStatus` 成员一对一绑定：新建＝`AcctStatus.N`（代码 N）；预开户＝`AcctStatus.I`（代码 I）。`AcctStatus` 的合法成员为 A 活动、C 关闭、D 睡眠、H 待激活、I 预开户、N 新建、O 转营业外、P 逾期、R 预销户、S 久悬、U 手工解除。

## Requirements

### Requirement: REQ-001 账户属性为“基本户”时的账户状态判定
来源：`docs/requirements/DT003.md` 规则描述 1a、1b、1c、1d。

系统 SHALL 在账户属性为“基本户”（AcctNatureNo.VALUE_11001，代码 11001）时，按下述境内境外标志与企业标志的组合确定账户状态，且该分支结果不受对公存款账户用途取值影响：

- 境内 且 企业标志＝是：账户状态为“新建”。
- 境内 且 企业标志＝否：账户状态为“预开户”。
- 境外 且 企业标志＝是：账户状态为“预开户”。
- 境外 且 企业标志＝否：账户状态为“新建”。

#### Scenario: REQ-001-S01 基本户、境内、企业标志为是
- **GIVEN** acctNatureNo＝基本户（11001），inlandOffshore＝“境内”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N），作为 RB_BUS_ACCT.ACCT_STATUS 的取值返回

#### Scenario: REQ-001-S02 基本户、境内、企业标志为否
- **GIVEN** acctNatureNo＝基本户（11001），inlandOffshore＝“境内”，corporationFlag＝“否”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“预开户”（AcctStatus.I，代码 I）

#### Scenario: REQ-001-S03 基本户、境外、企业标志为是
- **GIVEN** acctNatureNo＝基本户（11001），inlandOffshore＝“境外”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“预开户”（AcctStatus.I，代码 I）

#### Scenario: REQ-001-S04 基本户、境外、企业标志为否
- **GIVEN** acctNatureNo＝基本户（11001），inlandOffshore＝“境外”，corporationFlag＝“否”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N）

### Requirement: REQ-002 账户属性为“一般户”时的账户状态判定
来源：`docs/requirements/DT003.md` 规则描述 2。

系统 SHALL 在账户属性为“一般户”（AcctNatureNo.VALUE_11002，代码 11002）时，无条件将账户状态取值为“新建”，即境内境外标志、企业标志、对公存款账户用途的取值均不改变该结果。

#### Scenario: REQ-002-S01 一般户、境内、企业标志为是
- **GIVEN** acctNatureNo＝一般户（11002），inlandOffshore＝“境内”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N）

#### Scenario: REQ-002-S02 一般户、境外、企业标志为否
- **GIVEN** acctNatureNo＝一般户（11002），inlandOffshore＝“境外”，corporationFlag＝“否”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N），与 REQ-002-S01 结果一致，表明该分支不依赖境内境外标志与企业标志

### Requirement: REQ-003 账户属性为“专用户”且账户用途为“预算单位专用存款户”时的账户状态判定
来源：`docs/requirements/DT003.md` 规则描述 3.1a、3.1b、3.1c、3.1d。

系统 SHALL 在账户属性为“专用户”（AcctNatureNo.VALUE_11004，代码 11004）且对公存款账户用途为“预算单位专用存款户”（RbBusAcctPurpose.VALUE_4，代码 4）时，按下述组合确定账户状态：

- 境内 且 企业标志＝是：不设置账户状态，账户状态留空。
- 境内 且 企业标志＝否：账户状态为“预开户”。
- 境外 且 企业标志＝是：不设置账户状态，账户状态留空。
- 境外 且 企业标志＝否：账户状态为“新建”。

#### Scenario: REQ-003-S01 专用户、预算单位专用存款户、境内、企业标志为是
- **GIVEN** acctNatureNo＝专用户（11004），rbBusAcctPurpose＝“预算单位专用存款户”（代码 4），inlandOffshore＝“境内”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 本情形不设置账户状态，账户状态留空（不返回、不写入任何 AcctStatus 取值）
- **AND** 不因此回落到 REQ-007 兜底分支，不得返回“新建”或“预开户”

#### Scenario: REQ-003-S02 专用户、预算单位专用存款户、境内、企业标志为否
- **GIVEN** acctNatureNo＝专用户（11004），rbBusAcctPurpose＝“预算单位专用存款户”（代码 4），inlandOffshore＝“境内”，corporationFlag＝“否”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“预开户”（AcctStatus.I，代码 I）

#### Scenario: REQ-003-S03 专用户、预算单位专用存款户、境外、企业标志为是
- **GIVEN** acctNatureNo＝专用户（11004），rbBusAcctPurpose＝“预算单位专用存款户”（代码 4），inlandOffshore＝“境外”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 本情形不设置账户状态，账户状态留空（不返回、不写入任何 AcctStatus 取值）
- **AND** 不因此回落到 REQ-007 兜底分支，不得返回“新建”或“预开户”

#### Scenario: REQ-003-S04 专用户、预算单位专用存款户、境外、企业标志为否
- **GIVEN** acctNatureNo＝专用户（11004），rbBusAcctPurpose＝“预算单位专用存款户”（代码 4），inlandOffshore＝“境外”，corporationFlag＝“否”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N）

### Requirement: REQ-004 账户属性为“专用户”且账户用途不为“预算单位专用存款户”时的账户状态判定
来源：`docs/requirements/DT003.md` 规则描述 3.2。

系统 SHALL 在账户属性为“专用户”（AcctNatureNo.VALUE_11004，代码 11004）且对公存款账户用途不为“预算单位专用存款户”（含取其它枚举取值以及为空）时，将账户状态取值为“新建”，且该结果不依赖境内境外标志与企业标志的取值。

#### Scenario: REQ-004-S01 专用户、账户用途为其它取值
- **GIVEN** acctNatureNo＝专用户（11004），rbBusAcctPurpose＝“非预算单位专用”（代码 3），inlandOffshore＝“境内”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N），不适用 REQ-003 的留空分支

#### Scenario: REQ-004-S02 专用户、账户用途为空
- **GIVEN** acctNatureNo＝专用户（11004），rbBusAcctPurpose＝空（未上送或为空值），inlandOffshore＝“境外”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N），即空用途不进入 REQ-003 分支

### Requirement: REQ-005 账户属性为“临时户”时的账户状态判定

- 境外 且 企业标志＝否：账户状态为“新建”。

- **AND** 该分支的存在与判定条件（临时户、境外、企业标志为是）本身确定，不因此并入 REQ-005 其它分支或 REQ-007 兜底分支

#### Scenario: REQ-005-S04 临时户、境外、企业标志为否

系统 SHALL 在账户属性既不为“基本户”“一般户”“专用户”“临时户”，也不为“验资户”（即 REQ-001 至 REQ-006 的条件均不成立）时，将账户状态取值为“新建”，且该结果不依赖对公存款账户用途、境内境外标志与企业标志的取值。

#### Scenario: REQ-007-S01 账户属性为未列举取值
- **GIVEN** acctNatureNo＝对公人民币定期存款账户（11005，不属于基本户/一般户/专用户/临时户/验资户），rbBusAcctPurpose＝空，inlandOffshore＝“境外”，corporationFlag＝“是”
- **WHEN** 执行本规则
- **THEN** 账户状态取值为“新建”（AcctStatus.N，代码 N）

## 验收范围与明确不覆盖的事项

以下事项为源需求「已接受的需求处理结论」中已按需求处理流程放行、不得重复阻断的事项，逐条挂账如下，本 Spec 不据此补出源需求未写明的业务取值。

1. **规则名称中的“核准类型”**：规则名称为“根据核准类型设置账户状态”，但规则描述的判定字段为账户属性与账户用途，输入表中没有“核准类型”；本组件另有独立的账户核准类型（`RbCorpNatureDef.natureProperty`、枚举 `ApprType` 核准件类型 11/12/13）。本 Spec 按规则描述正文生成，不引入“核准类型”入参，也不以账户核准类型替代账户属性判定；名称口径待业务确认，不影响本 Spec 条款的执行。

2. **账户状态取值“无”（REQ-005-S03、REQ-006-S03）**：源需求两处要求账户状态为“无”，而“无”不是 `AcctStatus` 的合法成员；放行记录明确“处理记录不等同于补充了未写明的业务取值”，并给出候选方案 A（不设置账户状态、留空）与 B（应为“新建”）。本 Spec 保留该分支的判定条件，但不写入两候选中的任一取值：确认前该分支不可执行、不作为可断言的验收结果。取值口径确认后需同步修订 REQ-005、REQ-006 及其场景。

3. **账户属性/账户用途描述词与枚举代码的绑定**：源需求正文以描述词表述，未给出代码。本 Spec 按枚举注释唯一匹配给出绑定（基本户＝11001、一般户＝11002、专用户＝11004、临时户＝11003、验资户＝17；预算单位专用存款户＝4）。若业务口径与此不同，以需求正文描述词为准并在确认后修订本 Spec。

4. **必填入参为空或取值不在合法枚举内的行为**：源需求未定义（acctNatureNo、corporationFlag、inlandOffshore 标为必填但无异常分支；corporationFlag 与 inlandOffshore 无取值枚举）。本 Spec 不生成默认值、校验、异常或兜底处理条款；这两项描述词之外的取值不纳入验收。

5. **非决策性行为**：本规则不含组件内步骤调用、外部依赖调用、数据查询、重试与失败传播，源需求亦未要求；相关顺序、调用次数与失败处理不在验收范围。

6. **不覆盖的字段**：账户状态历史值（acctStatusPrev）及账户状态的后续流转、账户状态之外的其它账户要素，均不在本 Spec 范围。

7. **本 Spec 的验收场景是测试设计依据**，不是已生成的测试用例，也不是测试执行结果。
