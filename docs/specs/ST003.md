# ST003 检查对手账户属性

## 目标与范围

本 Spec 定义交易执行步骤「检查对手账户属性」（ST003）的输入输出契约与账户属性检查流转行为。步骤根据必填输入 othBaseAcctNo（对手账号）获取对公存款账户主表（RB_BUS_ACCT）记录的账户属性 acctNatureNo（枚举 `com.dcits.deposit.enums.AcctNatureNo`），并据该属性决定跳转至步骤《检查账户到期日》或返回检查结果为"通过"。

范围仅覆盖需求文档「步骤描述」两条步骤及其输入、输出与相关枚举约定。需求未定义任何业务失败场景，本 Spec 不新增失败条款与错误码。账户属性取值"验资户"（对应 `AcctNatureNo.VALUE_17`）为已确认对应；"临时户"与枚举取值的对应关系待确认，见 TBD-1；其余缺口见「待确认事项」。

- 枚举 `com.dcits.deposit.enums.AcctNatureNo` 存在于 `deposit-common`，取值（代码值/业务名称）含：17/验资户、11003/临时存款账户、11001/基本存款账户、11002/一般存款账户、11004/专用存款账户 等。需求「补充说明」确认账户属性取值来源于该枚举类。枚举中无业务名称"临时户"，见 TBD-1。
- 名称映射核对：需求「步骤描述」中的【账户信息】经 `requirement-name-mapping` 资产映射为实体「对公存款账户主表」；「账户属性」未收录于属性域资产（未收录不改变含义），需求「相关枚举」「补充说明」已将其绑定枚举 `AcctNatureNo`。
- 对公存款账户主表（RB_BUS_ACCT）EO `RbBusAcctEO` 的 `acctNatureNo` 字段类型为 `AcctNatureNo`；其主键为（clientNo, internalKey），无账号（baseAcctNo）字段，`othBaseAcctNo` 到主表记录的定位路径需求未定义，见 TBD-2。
- 步骤结果契约：`com.dcits.common.step.StepResult` 含 succeed、errorCode、errorMessage（成功时 errorCode/errorMessage 为 null）；需求未定义业务失败场景，正常结束按成功表达。
- 步骤跳转机制：`com.dcits.common.step.GotoStepCondition` 注解通过 candidateSteps 声明本步骤可能跳转的其它步骤名称，运行时根据步骤结果的 gotoStepName 决定是否跳转及跳转目标。本步骤候选跳转目标按需求为《检查账户到期日》。

## Requirements

### Requirement: REQ-001 获取账户属性
来源：需求文档「步骤描述」第 1 条、输入/输出表及「补充说明」。

系统 SHALL 根据必填输入 othBaseAcctNo（类型 `java.lang.String`，对手账号）获取对公存款账户主表（RB_BUS_ACCT）记录的账户属性，并输出 acctNatureNo（类型 `com.dcits.deposit.enums.AcctNatureNo`，账户属性）；acctNatureNo 的取值 SHALL 属于枚举 `com.dcits.deposit.enums.AcctNatureNo`。

#### Scenario: REQ-001-S01 根据对手账号取得并输出账户属性
- **GIVEN** 输入 othBaseAcctNo 为待检查的对手账号，且存在对应的对公存款账户主表记录
- **WHEN** 执行本步骤
- **THEN** 本步骤输出该账户记录的账户属性 acctNatureNo，取值属于枚举 `com.dcits.deposit.enums.AcctNatureNo`

### Requirement: REQ-002 账户属性检查与流转
来源：需求文档「步骤描述」第 2 条。

系统 SHALL 检查取得的账户属性：若账户属性为"验资户"或"临时户"，则跳转至步骤《检查账户到期日》；否则返回检查结果为"通过"，步骤正常成功结束，不跳转。

#### Scenario: REQ-002-S01 账户属性为验资户时跳转
- **GIVEN** 取得的账户属性为"验资户"（对应枚举值 `AcctNatureNo.VALUE_17`）
- **WHEN** 执行账户属性检查
- **THEN** 本步骤的跳转指示指向步骤《检查账户到期日》（gotoStepName=检查账户到期日），返回检查结果为"通过"的行为不发生

#### Scenario: REQ-002-S02 账户属性为临时户时跳转
- **GIVEN** 取得的账户属性为"临时户"
- **WHEN** 执行账户属性检查
- **THEN** 本步骤的跳转指示指向步骤《检查账户到期日》（gotoStepName=检查账户到期日），返回检查结果为"通过"的行为不发生

#### Scenario: REQ-002-S03 其它账户属性返回通过
- **GIVEN** 取得的账户属性既非"验资户"亦非"临时户"（如"基本存款账户"）
- **WHEN** 执行账户属性检查
- **THEN** 本步骤返回检查结果为"通过"，步骤正常成功结束（succeed=true，errorCode/errorMessage 为 null），不产生跳转指示

## 待确认事项

- **TBD-1（关联 REQ-002，枚举取值对应）**：需求条件为"验资户"或"临时户"。`AcctNatureNo` 中"验资户"对应 VALUE_17（已确认）；"临时户"在该枚举中无同名取值，最接近取值为"临时存款账户"（VALUE_11003）。工程另有枚举 `NatureClass`（账户属性分类）含"临时户"（VALUE_7），但需求「输出」「补充说明」已将账户属性绑定至 `AcctNatureNo`。需确认"临时户"实际对应的枚举与取值（是否即 `AcctNatureNo.VALUE_11003` 临时存款账户），确认前场景 REQ-002-S02 按业务称谓"临时户"表述、不绑定具体枚举值。
- **TBD-2（关联 REQ-001，账号定位路径）**：需求要求根据{账号}（othBaseAcctNo）获取账户信息，但对公存款账户主表（RB_BUS_ACCT）主键为（clientNo, internalKey），EO 无账号（baseAcctNo）字段；需求未定义 othBaseAcctNo 到主表记录的具体定位方式（如经对公客户账户表 baseAcctNo 关联、内部键映射等）。需确认实际查询路径。
- **TBD-3（关联 REQ-001，无记录/缺失行为）**：按 othBaseAcctNo 查询无对应主表记录时，以及 othBaseAcctNo 缺失（必填输入未提供）时的行为未定义；需求未定义该失败场景，按工程约定不作为业务失败假定。需确认是否有既定处理。
- **TBD-4（关联 REQ-002，"通过"输出表达）**：需求要求"返回检查结果为'通过'"，但输出表仅声明 acctNatureNo，未声明独立"检查结果"字段；本 Spec 将"通过"按步骤成功（succeed=true、错误字段为 null）且不跳转表达。若业务上需要独立的检查结果输出字段或特定返回值，需确认。
