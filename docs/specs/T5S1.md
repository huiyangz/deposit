# T5S1 检查客户限制

## 目标与范围

本任务将正式需求「检查客户限制」交易接口整理为可验证的 Spec。交易接口以必填输入客户号（clientNo）按执行步骤顺序调用组件内步骤 ST047（检查客户是否存在限制），并将步骤返回的客户限制信息（限制编号、账户限制类型、限制状态）作为交易输出返回；正常业务输出与响应头分开表达。

范围限于 T5S1 需求文档「输入」「输出」「执行步骤」声明的对外契约与单步骤编排行为。步骤内部查询行为以已完成并合并的正式 Spec ST047 为准，本 Spec 只按需核对 ST047 的输入输出契约、步骤接口与结果约定，不展开其查询实现或间接依赖。对 ST047 无命中、多条命中、clientNo 缺失及步骤失败触发条件等需求未覆盖的情形，仅记录待确认事项，不补默认行为。

## 输入、输出及依赖契约

### 对外输入

| 字段名 | 类型 | 必填性 | 说明 |
|---|---|---|---|
| `clientNo` | `java.lang.String` | 必填 | 客户号 |

### 对外输出

| 字段名 | 类型 | 必填性 | 来源实体 | 说明 |
|---|---|---|---|---|
| `resSeqNo` | `java.lang.String` | 非必填 | 客户限制表（RB_CLIENT_RESTRAINTS） | 限制编号 |
| `restraintType` | `java.lang.String` | 非必填 | 客户限制表（RB_CLIENT_RESTRAINTS） | 账户限制类型 |
| `restraintsStatus` | `java.lang.String` | 非必填 | 客户限制表（RB_CLIENT_RESTRAINTS） | 限制状态 |

### 步骤调用与结果契约

- **组件内步骤 ST047（检查客户是否存在限制）**：接口 `com.dcits.deposit.step.IST047`，`ST047OutputBO execute(ST047InputBO input)`。输入 BO `com.dcits.deposit.facade.bo.ST047InputBO` 含 `clientNo`（String，客户号，必填）；输出 BO `com.dcits.deposit.facade.bo.ST047OutputBO extends com.dcits.common.step.StepResult`，业务字段 `resSeqNo`（String，限制编号）、`restraintType`（枚举 `com.dcits.deposit.enums.RestraintType`，账户限制类型）、`restraintsStatus`（枚举 `com.dcits.deposit.enums.RestraintsStatus`，限制状态）。
- **枚举编码 API（deposit-common）**：`RestraintType.getValue()`、`RestraintsStatus.getValue()` 返回标准代码值字符串（如 `"70"`=黑名单控制专用-停止所有业务、`"A"`=已批准）；`byValue(String)` 反向转换，未匹配返回 null。交易输出 restraintType、restraintsStatus 类型为 String，按代码值口径映射（ST047 输出枚举 → 代码值 String），不采用 `valueOf`、`name()` 或 `toString()` 作为编码转换。
- **步骤结果与响应头（deposit-common）**：`StepResult` 含 `succeed`、`errorCode`（成功时为 null）、`errorMessage`（成功时为 null）；`RespHeader` 含相同成功/错误字段及 `isSucceed()/setSucceed(boolean)/getErrorCode()/setErrorCode(String)/getErrorMessage()/setErrorMessage(String)` 访问器。交易接口入口按工程交易接口契约为 `T5S1OutputDTO execute(RespHeader header, T5S1InputDTO input)`；DTO 按工程约定位于 `deposit-contract` 的 `com.dcits.deposit.task.dto` 包，本轮尚未生成，不构成依赖缺失。正常业务输出与响应头分开表达，不把响应头字段并入输出 DTO。
- **名称映射核对**：`requirement-name-mapping` 资产未收录「客户限制表」「客户限制信息」「限制状态」「账户限制类型」「限制编号」「客户号」；需求「输出」表已直接标注来源实体 RB_CLIENT_RESTRAINTS，ST047 正式 Spec 已确认实体与字段对应关系，本 Spec 按需求原文业务称谓表述，不展开额外绑定。

## Requirements

### Requirement: REQ-001 对外输入输出契约
来源：需求「输入」表、「输出」表

系统 SHALL 以必填输入 clientNo（类型 `java.lang.String`，客户号）作为本交易接口的入参，并返回三个非必填输出字段 resSeqNo（限制编号）、restraintType（账户限制类型）、restraintsStatus（限制状态），类型均为 `java.lang.String`，业务值来源为客户限制表（RB_CLIENT_RESTRAINTS）的对应属性。

#### Scenario: REQ-001-S01 输入输出契约可用
- **GIVEN** 调用方上送交易输入 clientNo = "C001234"
- **WHEN** 执行检查客户限制交易接口
- **THEN** 交易输出 DTO 包含 resSeqNo、restraintType、restraintsStatus 三个字段，均为 `java.lang.String` 且标记非必填，值来源为客户限制表（RB_CLIENT_RESTRAINTS）

### Requirement: REQ-002 按执行步骤顺序以客户号调用 ST047
来源：需求「执行步骤」表（步骤 1：ST047 检查客户是否存在限制）；ST047 正式 Spec 输入契约；工程步骤接口 `IST047`

系统 SHALL 以必填输入 clientNo 构造 ST047 输入 BO（`ST047InputBO.clientNo`），按执行步骤顺序调用组件内步骤 ST047（检查客户是否存在限制，接口 `IST047.execute(ST047InputBO)`）一次；该调用 SHALL 在最终输出组装与返回之前完成，且不调用需求未声明的其它步骤。

#### Scenario: REQ-002-S01 以客户号调用 ST047
- **GIVEN** 交易输入 clientNo = "C001234"
- **WHEN** 执行检查客户限制交易接口
- **THEN** 交易接口以 `ST047InputBO.clientNo` = "C001234" 调用 `IST047.execute(ST047InputBO)` 一次，该调用先于最终输出组装完成，且仅调用 ST047 一个步骤

### Requirement: REQ-003 ST047 成功时按代码值映射输出并置响应头成功
来源：需求「输出」表；ST047 正式 Spec 输出契约（resSeqNo、restraintType、restraintsStatus 及枚举类型）；工程交易接口契约（RespHeader 成功状态约定）

系统 SHALL 在 ST047 返回成功（`isSucceed` 为 true）时，将 ST047 输出 resSeqNo 原样映射为交易输出 resSeqNo，将 ST047 输出 restraintType、restraintsStatus 的标准代码值（分别经 `RestraintType.getValue()`、`RestraintsStatus.getValue()`）映射为交易输出 restraintType、restraintsStatus（String），并设置传入响应头成功状态（`succeed` 为 true，`errorCode`、`errorMessage` 为 null）后返回交易输出 DTO。

#### Scenario: REQ-003-S01 ST047 成功并返回客户限制信息时输出映射
- **GIVEN** ST047 返回成功（`succeed` 为 true，`errorCode`、`errorMessage` 为 null），其业务输出 resSeqNo = "RS000001"、restraintType = `RestraintType.VALUE_70`（代码值 "70"，黑名单控制专用-停止所有业务）、restraintsStatus = `RestraintsStatus.A`（代码值 "A"）
- **WHEN** 交易接口依据 ST047 成功结果组装最终输出
- **THEN** 交易输出 resSeqNo = "RS000001"、restraintType = "70"、restraintsStatus = "A"，传入的 RespHeader `succeed` 为 true、`errorCode` 与 `errorMessage` 为 null

### Requirement: REQ-004 ST047 返回失败时短路返回并透传错误
来源：工程交易接口契约（`RespHeader`/`StepResult` 失败短路与错误传播约定）

系统 SHALL 在 ST047 返回失败（`isSucceed` 为 false）时，将传入响应头设置为失败（`succeed` 为 false），将该次步骤结果的 errorCode、errorMessage 原样写入响应头，并立即返回，不继续组装最终业务输出。

#### Scenario: REQ-004-S01 ST047 返回失败时短路并透传错误
- **GIVEN** ST047 返回失败（`isSucceed` 为 false），其 errorCode 与 errorMessage 已设置为该次步骤返回的错误码与错误信息（码值与描述由 ST047 返回值决定，本需求未定义，见待确认事项 TBD-4）
- **WHEN** 交易接口检查到 ST047 结果失败
- **THEN** 传入的 RespHeader `succeed` 为 false，其 errorCode、errorMessage 与 ST047 该次返回的 errorCode、errorMessage 一致，交易接口立即返回且最终输出业务字段不填充

## 待确认事项

- **TBD-1（关联 REQ-003）**：ST047 正式 Spec 的 TBD-1（同一客户存在多条限制状态="A"记录时返回单条还是全部、单条选取/排序口径未定义）与 TBD-2（客户不存在限制状态="A"记录时，ST047 返回成功且业务字段为空的成功/失败语义未定义）。本交易接口的输出为单值字段，ST047 无命中返回空业务字段（枚举为 null）时，交易输出 resSeqNo、restraintType、restraintsStatus 是否为空、枚举 null 在代码值映射下的处理，以及无生效限制时本交易接口的成功/失败语义，随 ST047 对应待确认事项澄清后补充。
- **TBD-2（关联 REQ-002）**：clientNo 标记必填，需求未定义其为空或无效值时的行为（是否要求入参前置校验及校验不通过时的语义）；ST047 正式 Spec TBD-3 同源，本交易接口的入参校验行为待确认。
- **TBD-3（关联 REQ-003 类型口径）**：ST047 正式 Spec TBD-4 关于需求表述「限制状态等于 A-生效」与枚举标准业务名称「A-已批准」的差异；本交易接口输出 restraintType、restraintsStatus 为 String 代码值（经枚举 `getValue()`），需求未另行定义输出业务表述口径，随 ST047 TBD-4 确认。
- **TBD-4（关联 REQ-004）**：ST047 正式 Spec 未声明业务失败场景与错误码（步骤按成功结束），本交易接口的失败短路与错误透传为已确认交易接口契约，但 ST047 返回失败（`isSucceed` 为 false）的实际业务触发条件及错误码值未定义；需确认 ST047 失败结果的出现条件与码值。

## 验收范围

- 可验收：REQ-001-S01（对外输入输出契约）、REQ-002-S01（以必填输入 clientNo 调用 ST047 一次且先于输出组装）、REQ-003-S01（ST047 成功后 resSeqNo 原样映射、restraintType 与 restraintsStatus 按代码值映射为 String，响应头成功且错误字段为 null）、REQ-004-S01（步骤返回失败时响应头置失败、错误字段透传一致、立即返回且不组装业务输出）。
- 查询无命中、多条命中及空业务字段处理（TBD-1）、clientNo 缺失行为（TBD-2）、「A-生效」与「A-已批准」口径（TBD-3）、ST047 失败触发条件与错误码（TBD-4）不作为本 Spec 已确认验收断言，待待确认事项澄清后补充。
- 待确认事项不阻塞本 Spec 已确认条款的整理与验收。
