# ST026 检查对手账户通存标志

## 目标与范围

本 Spec 定义交易执行步骤「检查对手账户通存标志」（ST026）的输入输出契约与通存标志检查行为。步骤接收必填输入对手账号（`othBaseAcctNo`），按对手账号查询账户信息（对公存款账户主表 RB_BUS_ACCT）获取通存标志（通存标识，输出字段 `allDepInd`），并检查通存标志：等于「Y-是」时正常完成并继续执行；不等于「Y-是」时步骤业务失败并返回错误码 ER0055。

范围限于本步骤需求「步骤描述」「输入」「输出」「相关枚举」「补充说明」声明的查询、检查、失败与继续行为。检查条件「Y-是」与输出枚举 `AllDepInd` 取值的对应、步骤描述标题歧义、查询无记录行为及账号解析路径未确认，列入「待确认事项」，不补默认行为。

### 依赖核对

- **名称映射**：requirement-name-mapping 资产确认「账户信息」→ 实体「对公存款账户主表」；「通存标志」「通存标识」未收录属性域映射，本 Spec 按需求原文业务称谓表述，不展开未确认的属性域绑定。
- **实体字段**：`RbBusAcct`（对公存款账户主表实体，`deposit-infrastructure`）含字段 `allDepInd`（通存标识）；`RbBusAcctEO` 中 `allDepInd` 类型为 `com.dcits.deposit.enums.AllDepInd`，与需求输出表来源一致。
- **枚举**：`com.dcits.deposit.enums.AllDepInd` 存在于 `deposit-common`，取值/业务含义：N001/允许全行存入、N002/允许分行存入、N003/允许同城跨行存入、N004/不允许跨行存入。枚举无「Y」取值；需求检查条件「Y-是」与枚举取值的对应关系未确认（见待确认事项 TBD-2）。
- **错误码**：`deposit-application/src/main/resources/errorcodes.properties` 已确认 `ER0055=当前交易机构不是账户的通存机构`。需求「步骤描述」第 2 条将该码绑定于「通存标志不等于 Y-是」的失败条件；码的业务说明与本失败条件的语义对应关系待确认（见 TBD-1）。
- **步骤结果契约**：`com.dcits.common.step.StepResult` 提供 succeed / errorCode / errorMessage。按 step-error-contract，正常完成时 succeed=true 且错误字段为空；业务失败时 succeed=false，errorCode 保存已确认码值 ER0055，errorMessage 采用「ER0055::当前交易机构不是账户的通存机构」（`错误码::业务说明` 格式）。
- **技术约束**：对公存款账户主表（RB_BUS_ACCT）主键为（clientNo, internalKey），`RbBusAcct` 无账号字段；「根据{对手账号}查询【账户信息】」的账号→账户记录解析路径需求未声明（见 TBD-4）。

## Requirements

### Requirement: REQ-001 按对手账号查询账户信息获取通存标志
来源：需求「步骤描述」第 1 条、「输入」表、「输出」表、「相关枚举」及「补充说明」。

系统 SHALL 接收必填输入 `othBaseAcctNo`（`java.lang.String`，对手账号），据此查询账户信息（对公存款账户主表 RB_BUS_ACCT）获取通存标志（通存标识），并将该通存标志作为非必填输出字段 `allDepInd`（类型 `com.dcits.deposit.enums.AllDepInd`）返回。

#### Scenario: REQ-001-S01 依据有效对手账号查询取得通存标识
- **GIVEN** 调用方提供对手账号 `othBaseAcctNo`（示例值「6228480012345678」），且该账号在对公存款账户主表存在对应账户记录
- **WHEN** 执行本步骤
- **THEN** 系统按该对手账号查询对公存款账户主表取得通存标志，输出字段 `allDepInd`（通存标识，非必填，来源对公存款账户主表）返回查询获取的通存标志，取值对应枚举 `AllDepInd`（具体枚举取值映射见待确认事项 TBD-2）

### Requirement: REQ-002 通存标志不等于「Y-是」时业务失败并返回 ER0055
来源：需求「步骤描述」第 2 条（原文：若[通存标志]不等于“Y-是”，则返回[错误码]“ER0055”）。

当通存标志不等于「Y-是」（业务取值“是”）时，系统 SHALL 使步骤业务失败并返回错误码 ER0055（已确认错误码，业务说明「当前交易机构不是账户的通存机构」），且不继续执行后续步骤。

#### Scenario: REQ-002-S01 通存标志为「否」时步骤失败返回 ER0055
- **GIVEN** 根据对手账号查询对公存款账户主表得到的通存标志取值不等于「Y-是」（示例取值为「N」，业务含义“否”）
- **WHEN** 执行通存标志检查
- **THEN** 步骤结果为失败：succeed=false，errorCode=「ER0055」，errorMessage=「ER0055::当前交易机构不是账户的通存机构」，且本步骤不继续执行后续步骤

### Requirement: REQ-003 通存标志为「Y-是」时正常完成并继续
来源：需求「步骤描述」第 2 条（原文：…否则继续执行）。

当通存标志等于「Y-是」（业务取值“是”）时，系统 SHALL 正常完成本步骤（succeed=true，errorCode 与 errorMessage 为空）并继续执行后续步骤。

#### Scenario: REQ-003-S01 通存标志为「是」时步骤成功继续
- **GIVEN** 根据对手账号查询对公存款账户主表得到的通存标志取值为「Y-是」（示例取值为「Y」，业务含义“是”）
- **WHEN** 执行通存标志检查
- **THEN** 步骤结果为成功：succeed=true，errorCode 与 errorMessage 为空，本步骤正常完成并继续执行后续步骤

## 待确认事项

- **TBD-1（关联 REQ-001、REQ-002）**：需求「步骤描述」第 1 条标题为「获取账户开立行行号」，但该条获取并检查的值是 $通存标志$，与任务名「检查对手账户通存标志」不一致；同时已确认错误码 ER0055 的业务说明为「当前交易机构不是账户的通存机构」，暗示失败判定可能涉及当前交易机构与账户通存机构的比较。需确认：本步骤是否只获取并检查通存标志，还是亦需取得/比较账户开立行行号或当前交易机构；失败条件的真实判定口径。
- **TBD-2（关联 REQ-001、REQ-002、REQ-003）**：检查条件以「通存标志不等于 Y-是」表述，但输出字段 `allDepInd`（通存标识）已确认绑定枚举 `AllDepInd`，该枚举取值为 N001（允许全行存入）、N002（允许分行存入）、N003（允许同城跨行存入）、N004（不允许跨行存入），无「Y」取值。需确认：「通存标志」与「通存标识」（allDepInd）是否为同一属性；「Y-是」对应的实际编码及与 `AllDepInd` 取值的映射关系。
- **TBD-3（关联 REQ-001）**：需求未定义按对手账号查询【账户信息】无匹配记录时的行为（是否业务失败、失败错误码与信息）。
- **TBD-4（关联 REQ-001）**：对公存款账户主表（RB_BUS_ACCT）主键为（客户号, 账户内部键值），实体无账号字段；「根据{对手账号}查询【账户信息】」的账号→账户记录解析路径（如经对公客户账户表 baseAcctNo 定位）需求未声明，需确认查询口径。
- **TBD-5（关联 REQ-001）**：othBaseAcctNo 标记为必填，需求未定义其缺失/为空时的行为（是否校验报错、错误码）；输入表「来源实体」列为空，对手账号的来源实体未声明。

## 验收范围

验收以 REQ-001~REQ-003 声明的行为为准：在对手账号有效且对公存款账户主表存在对应记录时，验证按对手账号查询取得通存标志并输出 `allDepInd`（REQ-001-S01）；通存标志不等于「Y-是」时步骤失败、errorCode=ER0055、errorMessage=「ER0055::当前交易机构不是账户的通存机构」且不继续执行（REQ-002-S01）；通存标志为「Y-是」时步骤成功并继续执行（REQ-003-S01）。「Y-是」与 `AllDepInd` 的取值映射（TBD-2）、步骤标题歧义与失败条件口径（TBD-1）、查询无记录行为（TBD-3）、账号解析路径（TBD-4）、必填缺失行为（TBD-5）不作本 Spec 已确认验收断言，待澄清后补充。
