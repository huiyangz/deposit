# ST040 检查限额

## 目标与范围

本任务将正式需求「检查限额」（ST040，交易执行步骤）整理为可验证的 Spec。步骤包含两项已确认行为：

1. **获取限额控制值**：根据限额场景编码（limitSceneNo）查询【限额控制配置】（RB_LIMIT_CTRL_CONF），取得限额控制金额（limitCtrlAmt）与限额控制笔数（limitCtrlNum）；
2. **检查限额**：比较限额累计金额、限额累计笔数与对应的限额控制金额、限额控制笔数，返回限额检查结果「超限」或「未超限」。

范围限于 `docs/requirements/ST040.md` 的「步骤描述」「输入」「输出」所声明内容。需求未定义的查询唯一性与附加条件、无配置记录时的行为、限额检查结果输出字段、限额累计笔数字段名及空值/缺失输入行为，逐项记录于「待确认事项」，不补默认行为。

## Requirements

### Requirement: REQ-001 步骤输入与输出契约

来源：需求文档「输入」「输出」表。

系统 SHALL 接收必填输入 `limitSceneNo`（`java.lang.String`，限额场景编码）、`limitSumAmt`（`java.math.BigDecimal`，限额累计金额）、限额累计笔数（`java.lang.Integer`），并输出 `limitCtrlAmt`（限额控制金额）、`limitCtrlNum`（限额控制笔数）、`limitSumAmt`（限额累计金额）、限额累计笔数四类字段；其中限额控制值来源为限额控制配置（RB_LIMIT_CTRL_CONF），累计金额与累计笔数来源标注为限额累计信息表（RB_LIMIT_SUM_INFO）。

#### Scenario: REQ-001-S01 接收必填输入并输出声明字段

- **GIVEN** 调用方提供 `limitSceneNo` 为「S001」、`limitSumAmt` 为 `1000.00`、限额累计笔数为 `10`
- **WHEN** 执行检查限额步骤
- **THEN** 步骤按输出契约返回，输出包含 `limitCtrlAmt`、`limitCtrlNum`、`limitSumAmt`、限额累计笔数四类字段，且输出的 `limitSumAmt` 为 `1000.00`、限额累计笔数为 `10`（按输入承接）

### Requirement: REQ-002 获取限额控制值

来源：需求「步骤描述」第 1 条（原文：根据[限额场景编码]查询【限额控制配置】获取对应的$限额控制金额$和$限额控制笔数$）。

系统 SHALL 根据输入 `limitSceneNo` 查询【限额控制配置】（RB_LIMIT_CTRL_CONF），并将对应记录的限额控制金额（`limitCtrlAmt`）与限额控制笔数（`limitCtrlNum`）作为本步的限额控制值，供检查限额判定使用。

#### Scenario: REQ-002-S01 命中限额控制配置取得控制值

- **GIVEN** 限额控制配置（RB_LIMIT_CTRL_CONF）中存在 `limitSceneNo` 为「S001」的记录，其限额控制金额为 `800.00`、限额控制笔数为 `5`
- **WHEN** 执行检查限额步骤
- **THEN** 步骤按「S001」查询限额控制配置并取得限额控制金额 `800.00`、限额控制笔数 `5`，输出 `limitCtrlAmt=800.00`、`limitCtrlNum=5`

### Requirement: REQ-003 超限判定与检查结果

来源：需求「步骤描述」第 2 条（原文：若[限额累计金额]大于[限额控制金额]或[限额累计笔数]大于[限额控制笔数]，则返回限额检查结果为“超限”，否则返回限额检查结果为“未超限”）。

系统 SHALL 在限额累计金额大于限额控制金额，或限额累计笔数大于限额控制笔数时，返回限额检查结果为「超限」；在两个条件均不成立（小于或等于）时，返回限额检查结果为「未超限」。两条件为「或」关系，「大于」为严格大于（相等不超限）。

#### Scenario: REQ-003-S01 限额累计金额超限返回超限

- **GIVEN** 限额控制金额为 `800.00`、限额控制笔数为 `5`，限额累计金额为 `1000.00`、限额累计笔数为 `5`
- **WHEN** 执行检查限额步骤
- **THEN** 返回限额检查结果为「超限」

#### Scenario: REQ-003-S02 限额累计笔数超限返回超限

- **GIVEN** 限额控制金额为 `800.00`、限额控制笔数为 `5`，限额累计金额为 `500.00`、限额累计笔数为 `10`
- **WHEN** 执行检查限额步骤
- **THEN** 返回限额检查结果为「超限」

#### Scenario: REQ-003-S03 金额与笔数均超限返回超限

- **GIVEN** 限额控制金额为 `800.00`、限额控制笔数为 `5`，限额累计金额为 `1000.00`、限额累计笔数为 `10`
- **WHEN** 执行检查限额步骤
- **THEN** 返回限额检查结果为「超限」

#### Scenario: REQ-003-S04 均未超限返回未超限

- **GIVEN** 限额控制金额为 `800.00`、限额控制笔数为 `5`，限额累计金额为 `500.00`、限额累计笔数为 `5`
- **WHEN** 执行检查限额步骤
- **THEN** 返回限额检查结果为「未超限」

#### Scenario: REQ-003-S05 相等边界返回未超限

- **GIVEN** 限额控制金额为 `800.00`、限额控制笔数为 `5`，限额累计金额为 `800.00`、限额累计笔数为 `5`
- **WHEN** 执行检查限额步骤
- **THEN** 返回限额检查结果为「未超限」（严格「大于」判定，相等不超限）

## 待确认事项

- **TBD-1（关联 REQ-001、REQ-003）限额累计笔数字段名「否」**：需求「输入」「输出」表的字段名列原文均为「否」；工程侧 `RB_LIMIT_SUM_INFO` 的 DDL 列与实体 `RbLimitSumInfo`/`RbLimitSumInfoEO` 字段名同样为「否」（getter `get否()`）。该名称与业务语义「限额累计笔数」不符，疑似为如 `limitSumNum` 的编码名在需求与建表两处同时被破坏。需确认实际字段名；确认前本 Spec 以业务称谓「限额累计笔数」表述。
- **TBD-2（关联 REQ-003）限额检查结果输出字段缺失**：步骤描述返回「限额检查结果」为「超限」/「未超限」，但需求输出表未登记该字段，未给出字段名、类型及物理取值（中文串还是映射编码）。需确认检查结果字段名/类型/取值编码。
- **TBD-3（关联 REQ-002）限额控制配置查询的唯一性、附加条件与无记录行为**：RB_LIMIT_CTRL_CONF 主键为（限额机构编码 `LIMIT_BRANCH_ID`，限额场景编码 `LIMIT_SCENE_NO`），需求仅提供 `limitSceneNo` 作为查询入参，未提供机构维度，也未声明是否过滤启用标志（`validFlag`）或生效期间。同一限额场景编码跨机构存在多条记录时如何取对应配置需确认（是否补传机构，或按既定规则选取）；查询无命中记录时限额控制金额/笔数无值，比较行为未定义（报错或视为无限额控制），需确认。
- **TBD-4（关联 REQ-001、REQ-002、REQ-003）限额累计金额/笔数的来源**：输入表将两者标记为必填输入，输出表来源标注为限额累计信息表（RB_LIMIT_SUM_INFO），而步骤描述未声明本步对 RB_LIMIT_SUM_INFO 的查询。需确认本步是仅承接调用方传入的累计值（本 Spec 当前按此整理），还是需自行查询 RB_LIMIT_SUM_INFO 取数。
- **TBD-5（关联 REQ-001~REQ-003）必填输入缺失行为**：`limitSceneNo`、`limitSumAmt`、限额累计笔数标记为必填，但需求未定义其为空/缺失时的行为（是否校验并报业务失败及错误码）。需求未声明失败场景，本 Spec 未虚构失败结果。
- **TBD-6（关联 REQ-003）空值比较语义**：限额控制金额/笔数或限额累计金额/笔数为 null 时比较结果未定义（如控制值空是否视为无限额、累计值空是否视为 0 或报错）。需确认空值语义。
