# ST106 获取累计限额

## 目标与范围

本任务为交易执行步骤类（读取类步骤，单条定位、无业务失败分支）。源需求「## 步骤描述」给出唯一动作：以 {账号} 作为限额检查对象值，连同 [限额场景编码] 查询【限额累计表】的记录，取得该记录的 $限额累计金额$ 与 $限额累计笔数$；查无记录时两值均为 0。

**目标**：以 ST106 的已确认业务定义为依据，整理可验证的行为 Spec，使测试设计、实现与审核共用同一份输入契约、定位—取值契约、输出契约与结束契约。

本次 Spec 覆盖：

- 输入契约：三个输入的字段名、类型、必填性与来源实体照录；占位符 {账号} 与 [限额场景编码] 的绑定。
- 定位契约：以 {账号}（入参 `baseAcctNo`）作为限额检查对象值，连同 [限额场景编码]（入参 `limitSceneNo`）查询【限额累计信息表 `RB_LIMIT_SUM_INFO`】，定位条件为两键的合取，不使用 `clientNo` 参与定位。
- 取值契约：命中记录时取得该记录的 $限额累计金额$ 与 $限额累计笔数$；查无记录时两值均为 0。
- 输出契约：`clientNo`／`limitSceneNo`／`limitSumAmt`／`limitSumNum` 四个输出的字段名、类型、「非必填」标记与来源实体照录，其中 `limitSumAmt`／`limitSumNum` 的取值映射由定位结果确定。
- 失败契约：本步骤无业务失败场景，失败仅由技术异常传播表达。

不在本次范围（源需求未涉及或未定义，本 Spec 不作要求）：

- 输出回显字段 `clientNo`、`limitSceneNo` 的取值口径（源需求「## 步骤描述」未赋予其取值来源，第 1 项）。
- 命中记录但 $限额累计金额$／$限额累计笔数$ 列为空（`null`）时的取值口径（源需求未定义，第 2 项）。
- 任一必填输入取空（未上送、`null`）时的行为（源需求未定义，第 3 项）。
- 入参 `clientNo` 在本步骤中的用途（源需求「## 步骤描述」未使用该字段，第 4 项）。
- 【限额累计信息表】绑定到哪张表、哪个接口的技术口径，以及查询实现方式（按主键查询还是条件查询、是否按场景配置的检查对象类型分流）、事务边界与缓存（第 5 项）。
- 触发本步骤的上游编排与取得累计限额后的下游用途（如限额比较、登记流水、超限判定）（第 9 项）。
- 技术异常的传播形式、回滚口径与错误信息文本（源需求「## 失败处理」只声明由技术异常传播表达，第 8 项）。

#### Scenario: REQ-001-S01 三个输入的字段名、类型与必填性照录

- **GIVEN** 调用方按「## 输入」表提供三个输入：`baseAcctNo` = `"1100602112345678"`（示例账号值，非规范常量）、`clientNo` = `"C0000001234"`（示例值）、`limitSceneNo` = `"LSN0001"`（示例值），三者标记均为「必填」
- **WHEN** 调用本步骤
- **THEN** 步骤以该字段名、类型与「必填」标记接收三个输入：三者类型均为 `java.lang.String`，均为必填
- **THEN** 各输入的「来源实体」列照录源需求：`baseAcctNo`＝对公存款账户限制表（RB_BUS_RESTRAINTS）；`clientNo`／`limitSceneNo`＝限额累计信息表（RB_LIMIT_SUM_INFO）

#### Scenario: REQ-001-S02 {账号}／[限额场景编码] 的占位符绑定

- **GIVEN** 入参 `baseAcctNo` = `"1100602112345679"`（示例值）、`limitSceneNo` = `"LSN0002"`（示例值）
- **WHEN** 本步骤按源需求第 5 行执行「以{账号}作为限额检查对象值，连同[限额场景编码]查询…」
- **THEN** {账号} 取值为 `"1100602112345679"`、[限额场景编码] 取值为 `"LSN0002"`，二者分别绑定到 `baseAcctNo` 与 `limitSceneNo`；不引入其它字段作为该两个占位符的来源
- **THEN** 两个占位符在源需求中分别以花括号 `{}` 与方括号 `[]` 书写，本步骤不据此区分语义，一律按上述绑定处理

#### Scenario: REQ-001-S03 不因来源实体列新增对限制表的读取

- **GIVEN** 源需求「## 输入」表把 `baseAcctNo` 的来源实体标为「对公存款账户限制表（RB_BUS_RESTRAINTS）」，而「## 步骤描述」只描述对【限额累计表】的查询与取值
- **WHEN** 调用本步骤执行
- **THEN** 本步骤只按 REQ-002 查询【限额累计信息表】并取值；不查询、不校验「对公存款账户限制表（RB_BUS_RESTRAINTS）」，也不因该列示要求调用方补送其它入参

### Requirement: REQ-002 以账号作为限额检查对象值连同限额场景编码查询并取值

来源：`docs/requirements/ST106.md`「## 步骤描述」1（第 5 行）前半 —— 原文：「以{账号}作为限额检查对象值，连同[限额场景编码]查询【限额累计表】获取该记录的$限额累计金额$，$限额累计笔数$」。

系统 SHALL 以 {账号}（取自入参 `baseAcctNo`）作为限额检查对象值，连同 [限额场景编码]（取自入参 `limitSceneNo`）查询【限额累计信息表 `RB_LIMIT_SUM_INFO`】中同时满足「限额检查对象值 = `baseAcctNo`」与「限额场景编码 = `limitSceneNo`」的记录。定位条件 MUST 为上述两键的合取；系统 MUST NOT 以 `clientNo` 或其它字段作为定位条件，也 MUST NOT 以单键（仅限额检查对象值或仅限额场景编码）扩大命中范围。命中记录时，系统 SHALL 取得该记录的 $限额累计金额$（限额累计金额）作为输出 `limitSumAmt`、$限额累计笔数$（限额累计笔数）作为输出 `limitSumNum`；取值 MUST 为该记录该两列的取值本身，MUST NOT 被改写为其它的值（如代入参值、置 0 或做运算）。本步骤为纯读取动作：查询与取值 MUST NOT 修改、新增或删除【限额累计信息表】的记录。

#### Scenario: REQ-002-S01 命中记录并取得两值

- **GIVEN** 入参 `baseAcctNo` = `"1100602112345678"`、`limitSceneNo` = `"LSN0001"`（示例值）；【限额累计信息表】中存在限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0001"` 的记录，其 $限额累计金额$ = `1000.00`、$限额累计笔数$ = `5`（示例值），该记录其它字段为已给定值
- **WHEN** 执行本步骤
- **THEN** 系统取得该记录的 $限额累计金额$ = `1000.00` 作为输出 `limitSumAmt`、$限额累计笔数$ = `5` 作为输出 `limitSumNum`，二者与库中该记录该两列的取值一致
- **THEN** 【限额累计信息表】不发生任何数据变更（不更新、不新增、不删除记录）；不返回业务错误码（REQ-005）

#### Scenario: REQ-002-S02 定位条件为限额检查对象值与限额场景编码的合取

- **GIVEN** 入参 `baseAcctNo` = `"1100602112345678"`、`limitSceneNo` = `"LSN0001"`（示例值）；【限额累计信息表】中同时存在：记录 α（限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0001"`，$限额累计金额$ = `1000.00`、$限额累计笔数$ = `5`）、记录 β（限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0009"`，$限额累计金额$ = `777.00`、$限额累计笔数$ = `7`）、记录 γ（限额检查对象值 = `"1100602112345677"`、限额场景编码 = `"LSN0001"`，$限额累计金额$ = `888.00`、$限额累计笔数$ = `8`）（均为示例值）
- **WHEN** 执行本步骤
- **THEN** 输出 `limitSumAmt` = `1000.00`、`limitSumNum` = `5`，取自记录 α
- **THEN** 仅匹配限额检查对象值的记录 β 与仅匹配限额场景编码的记录 γ MUST NOT 被取用；本步骤不写入任何记录

#### Scenario: REQ-002-S03 定位不使用 clientNo

- **GIVEN** 入参 `baseAcctNo` = `"1100602112345678"`、`limitSceneNo` = `"LSN0001"`、`clientNo` = `"C0000001234"`（示例值）；【限额累计信息表】中存在限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0001"` 的记录，其客户号为 `"C0000009999"`（与入参 `clientNo` 不同，示例值），其 $限额累计金额$ = `1200.00`、$限额累计笔数$ = `6`
- **WHEN** 执行本步骤
- **THEN** 该记录仍被命中，输出 `limitSumAmt` = `1200.00`、`limitSumNum` = `6`
- **THEN** 定位条件不含 `clientNo`，命中与否不取决于入参 `clientNo` 与记录客户号是否一致，也不以该字段扩大或缩小命中范围

### Requirement: REQ-003 查无记录时限额累计金额与限额累计笔数均为 0

来源：`docs/requirements/ST106.md`「## 步骤描述」1（第 5 行）末句 —— 原文：「查无记录时，$限额累计金额$与$限额累计笔数$均为0」。

系统 SHALL 在按「限额检查对象值 = `baseAcctNo` 且限额场景编码 = `limitSceneNo`」查询【限额累计信息表】而查无记录时，使输出 `limitSumAmt` 与 `limitSumNum` 均为数值 0（`limitSumAmt` 为零金额、`limitSumNum` 为整数 0）。该情形 MUST NOT 被判定为业务失败，MUST NOT 返回业务错误码、MUST NOT 抛出业务异常，MUST NOT 因查无记录而改以其它条件重新查询或以其它取值（如空值、默认限额）替代 0。查无记录时本步骤 MUST NOT 在前述表中新增记录、MUST NOT 修改或删除任何记录。

#### Scenario: REQ-003-S01 查无记录时两值均为 0

- **GIVEN** 入参 `baseAcctNo` = `"1100609999999999"`、`limitSceneNo` = `"LSN0001"`（示例值）；【限额累计信息表】中不存在限额检查对象值 = `"1100609999999999"` 且限额场景编码 = `"LSN0001"` 的记录
- **WHEN** 执行本步骤
- **THEN** 输出 `limitSumAmt` = `0`（零金额）、`limitSumNum` = `0`（整数零），均不为空值、不为其它数值
- **THEN** 本步骤正常结束（按「### 承载口径」：`succeed = true` 且 `errorCode` 为空）；不返回业务错误码、不抛出异常

#### Scenario: REQ-003-S02 查无记录不改变表数据、也不改以其它条件重新查询

- **GIVEN** 入参 `baseAcctNo` = `"1100609999999999"`、`limitSceneNo` = `"LSN0001"`（示例值）；【限额累计信息表】存在其它记录（如限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0001"` 的记录），但不含该两键对应的记录
- **WHEN** 执行本步骤
- **THEN** 【限额累计信息表】不发生任何数据变更（不新增、不修改、不删除记录），其它记录的取值保持执行前状态
- **THEN** 系统不以仅匹配其中一键的记录替代命中结果，也不以空值或其它默认值替代 0

### Requirement: REQ-004 输出契约与取值映射

来源：`docs/requirements/ST106.md`「## 输出」表（第 17–22 行）、「## 步骤描述」1（第 5 行）。

系统 SHALL 以「## 输出」表声明的四个字段作为本步骤的输出，其字段名、类型、业务名称与「非必填」标记 MUST 照录源需求：`clientNo`（`java.lang.String`，客户号）、`limitSceneNo`（`java.lang.String`，限额场景编码）、`limitSumAmt`（`java.math.BigDecimal`，限额累计金额）、`limitSumNum`（`java.lang.Integer`，限额累计笔数），四者来源实体均为 限额累计信息表（RB_LIMIT_SUM_INFO）。输出取值 MUST 按定位结果确定：命中记录时 `limitSumAmt`／`limitSumNum` 等于该记录的 $限额累计金额$／$限额累计笔数$（REQ-002）；查无记录时均为 0（REQ-003）。本步骤 MUST NOT 新增「## 输出」表以外的业务输出字段。「非必填」标记 MUST 照录、MUST NOT 升格为必填，也不得据该标记断言该字段无需返回。`clientNo`／`limitSceneNo` 两个回显字段的取值口径（回显入参、取命中记录对应列或其它）源需求未定义，本 Spec 只照录其字段契约，不对其取值作断言。

#### Scenario: REQ-004-S01 命中记录路径的输出字段契约与取值

- **GIVEN** 入参 `baseAcctNo` = `"1100602112345678"`、`clientNo` = `"C0000001234"`、`limitSceneNo` = `"LSN0001"`（示例值）；【限额累计信息表】中存在限额检查对象值 = `"1100602112345678"`、限额场景编码 = `"LSN0001"` 的记录，其 $限额累计金额$ = `1000.00`、$限额累计笔数$ = `5`（示例值）
- **WHEN** 执行本步骤并读取本步骤输出
- **THEN** 输出的字段名为 `clientNo`、`limitSceneNo`、`limitSumAmt`、`limitSumNum`；`limitSumAmt` 的类型为 `java.math.BigDecimal`、取值为 `1000.00`，`limitSumNum` 的类型为 `java.lang.Integer`、取值为 `5`，二者与库中该记录该两列的取值一致
- **THEN** `clientNo`（`java.lang.String`）与 `limitSceneNo`（`java.lang.String`）按输出表照录其字段名与类型；其取值不作断言（源需求未定义该两字段的取值口径，见不覆盖第 1 项）

#### Scenario: REQ-004-S02 查无记录路径的取值

- **GIVEN** 入参 `baseAcctNo` = `"1100609999999999"`、`limitSceneNo` = `"LSN0001"`（示例值）；【限额累计信息表】中不存在该两键对应的记录
- **WHEN** 执行本步骤并读取本步骤输出
- **THEN** 输出 `limitSumAmt` = `0`、`limitSumNum` = `0`（REQ-003-S01），二者均不为空值
- **THEN** `clientNo`／`limitSceneNo` 仍按输出表照录其字段名与类型；其取值不作断言（源需求未定义该两字段的取值口径，见不覆盖第 1 项）

#### Scenario: REQ-004-S03 「非必填」标记照录且不据此推定无需返回

- **GIVEN** 源需求「## 输出」表把四个输出字段均标为「非必填」
- **WHEN** 分别处于「命中记录」（REQ-002-S01）与「查无记录」（REQ-003-S01）两种情形，读取本步骤输出
- **THEN** 四个字段的「非必填」标记按源需求照录，本 Spec 不将其升格为必填
- **THEN** 该标记按本项目 ST 步骤稿的既有口径记录的是承载实体的可空性，不构成「命中或查无路径下可以不返回 `limitSumAmt`／`limitSumNum`」的依据；两种情形下 `limitSumAmt` 与 `limitSumNum` 均有确定取值（分别为记录值与 0）

### Requirement: REQ-005 无业务失败场景，失败仅由技术异常传播表达

来源：`docs/requirements/ST106.md`「## 失败处理」（第 24–26 行，正文第 26 行）—— 原文：「本步骤无业务失败场景，失败仅由技术异常传播表达。」

系统 SHALL 把本步骤的失败范围限定为技术异常：本步骤 MUST NOT 返回任何业务错误码，MUST NOT 把「查无记录」（REQ-003）判定为失败——该情形正常结束并给出 0 值结果。查询或取值调用本身发生技术异常（抛出异常、超时、依赖不可用、数据访问失败）时，该失败 MUST NOT 被本步骤转换为业务错误码或业务失败结论，仅由技术异常按框架传播表达；本步骤 MUST NOT 为其设置捕获、重试或降级行为（源需求未要求）。

#### Scenario: REQ-005-S01 命中与查无两条路径均不返回业务错误码

- **GIVEN** 分别处于「命中记录」（REQ-002-S01）与「查无记录」（REQ-003-S01）两种情形
- **WHEN** 任一情形下执行本步骤并返回结论
- **THEN** 步骤结果均为 `succeed = true` 且 `errorCode` 为空（`null`），不存在业务错误码取值
- **THEN** 「查无记录」不被表达为失败，其结论由 `limitSumAmt = 0`、`limitSumNum = 0` 承载

#### Scenario: REQ-005-S02 数据访问技术异常不由本步骤转换为业务结果

- **GIVEN** 查询【限额累计信息表】的数据访问调用发生技术异常（如依赖不可用、超时）
- **WHEN** 执行本步骤
- **THEN** 该失败由技术异常按框架传播表达，MUST NOT 被转换为业务错误码或业务失败结论，MUST NOT 被吞掉后以「两值均为 0」或其它正常结束结果返回
- **THEN** 源需求未要求捕获、重试或降级，本步骤 MUST NOT 设置相应处理；`errorMessage` 的取值源需求未要求，不作断言
