# ST028 检查支取账户属性

## 目标与范围

本 Spec 将正式需求「检查支取账户属性」交易执行步骤整理为可验证的行为规范。步骤依据必填输入 `baseAcctNo`（账号）从【账户信息】（对公存款账户主表 RB_BUS_ACCT）获取账户属性 `acctNatureNo`，并按账户属性决定流程走向：账户属性为「验资户」或「临时户」时跳转至步骤《检查账户到期日》，否则返回检查结果为「通过」。

范围限于 ST028 需求文档「步骤描述」「输入」「输出」「相关枚举」「补充说明」声明的行为及输入输出契约；对需求未定义的必填输入缺失、账号查无记录、账户属性为空等行为仅记录待确认事项，不补默认行为。跳转目标步骤《检查账户到期日》未提供任务编号且无已完成正式 Spec，本 Spec 仅保留目标名称，不展开目标实现或间接依赖。

### 依赖核对

- 名称映射（requirement-name-mapping 资产）：「账户信息」→ 对公存款账户主表，与输出表来源实体「对公存款账户主表（RB_BUS_ACCT）」一致；「账户属性」未收录属性域映射，需求「补充说明」将其绑定至枚举 `com.dcits.deposit.enums.AcctNatureNo`，本 Spec 按该绑定整理，保留需求原文业务称谓。
- 枚举 `com.dcits.deposit.enums.AcctNatureNo`（deposit-common）：存在 VALUE_17="17"（验资户）；无「临时户」同名取值，业务名最接近 VALUE_11003="11003"（临时存款账户），对应关系待确认（见待确认事项 TBD-1）。
- 账户信息字段：对公存款账户主表 EO `RbBusAcctEO.acctNatureNo` 类型为 `AcctNatureNo`（字段注释「账户属性」），与需求输出类型一致；实体层 `RbBusAcct.acctNatureNo` 为 String 物理编码，EO 侧经 `AcctNatureNo.byValue(String)` 转换（`RbBusAcctValueUtil.entityToEo` 确认）。
- 按账号获取账户信息：`IRbBusAcctBcc`（对公存款账户主表数据服务）提供 findByPrimaryKey(clientNo, internalKey)、findByEo(RbBusAcctEO) 等方法，未提供按账号 baseAcctNo 查询账户主表的方法；需求「根据{账号}获取【账户信息】」的实际定位路径未在可用工程资料中确认（见 TBD-2）。
- 步骤框架：`com.dcits.common.step.StepResult`（succeed/errorCode/errorMessage）承载步骤结果；`@GotoStepCondition(candidateSteps)` 声明本步骤执行过程中可能跳转到的其它步骤名称，运行时依据步骤返回结果的 gotoStepName 决定是否跳转及跳转目标。跳转属正常提前结束（显式成功、清空错误字段），不属业务失败。
- 错误结果：需求未声明本步骤的业务失败场景及错误码；按步骤错误结果约定，不补写失败处理或编造错误码。需求未定义的缺失输入、查无记录、属性为空情形见 TBD-3、TBD-4。

## Requirements

### Requirement: REQ-001 根据账号获取账户属性

来源：需求「步骤描述」第 1 条、「输入」表 baseAcctNo、「输出」表 acctNatureNo、「补充说明」。

系统 SHALL 根据必填输入 `baseAcctNo`（java.lang.String，账号）获取【账户信息】（对公存款账户主表 RB_BUS_ACCT），取得账户属性 `acctNatureNo`（类型 `com.dcits.deposit.enums.AcctNatureNo`），并将取得的账户属性作为本步骤输出返回。

#### Scenario: REQ-001-S01 按账号获取账户属性并输出

- **GIVEN** 步骤输入 `baseAcctNo` 为已登记账户的账号（示例值 "6000100000012345"，测试推导用示例数据，非规范常量），该账号在对公存款账户主表（RB_BUS_ACCT）中对应记录的账户属性为「基本存款账户」（`AcctNatureNo.VALUE_11001`）
- **WHEN** 执行「检查支取账户属性」步骤，按 `baseAcctNo` 获取账户信息
- **THEN** 步骤取得账户属性并输出 `acctNatureNo` 为「基本存款账户」（`AcctNatureNo.VALUE_11001`）

### Requirement: REQ-002 账户属性为验资户或临时户时跳转至检查账户到期日，否则返回通过

来源：需求「步骤描述」第 2 条。

当 `acctNatureNo` 为「验资户」或「临时户」时，本步骤 SHALL 以跳转至步骤《检查账户到期日》结束（正常提前结束，非业务失败），且不返回「通过」；当 `acctNatureNo` 为其它取值时，本步骤 SHALL 返回检查结果为「通过」，不触发跳转，正常完成。

#### Scenario: REQ-002-S01 账户属性为验资户时跳转至检查账户到期日

- **GIVEN** 本步骤取得的账户属性 `acctNatureNo` 为「验资户」（`AcctNatureNo.VALUE_17`，取值 "17"）
- **WHEN** 执行账户属性检查
- **THEN** 本步骤跳转至步骤《检查账户到期日》，不返回「通过」，步骤正常提前结束（非业务失败）

#### Scenario: REQ-002-S02 账户属性为临时户时跳转至检查账户到期日

- **GIVEN** 本步骤取得的账户属性 `acctNatureNo` 为「临时户」（需求原文称谓；枚举对应取值待确认，业务名最接近「临时存款账户」`AcctNatureNo.VALUE_11003`，取值 "11003"，见待确认事项 TBD-1）
- **WHEN** 执行账户属性检查
- **THEN** 本步骤跳转至步骤《检查账户到期日》，不返回「通过」，步骤正常提前结束（非业务失败）

#### Scenario: REQ-002-S03 账户属性非验资户且非临时户时返回通过

- **GIVEN** 本步骤取得的账户属性 `acctNatureNo` 为「验资户」「临时户」之外的取值（如「基本存款账户」`AcctNatureNo.VALUE_11001`）
- **WHEN** 执行账户属性检查
- **THEN** 本步骤返回检查结果为「通过」，不触发跳转，步骤正常完成

## 待确认事项

- **TBD-1（关联 REQ-002-S02）**：「临时户」与枚举取值对应。需求以「临时户」表述跳转条件，枚举 `AcctNatureNo` 无「临时户」同名取值，业务名最接近 VALUE_11003="11003"（临时存款账户）。需确认「临时户」是否即 `AcctNatureNo.VALUE_11003`（临时存款账户），以及「验资户」对应 `AcctNatureNo.VALUE_17`（"17"）是否唯一。确认前条件保留需求原文称谓，场景不绑定未确认枚举常量。
- **TBD-2（关联 REQ-001）**：按账号获取账户信息的路径。可用接口 `IRbBusAcctBcc`（对公存款账户主表数据服务）未提供按账号 baseAcctNo 查询账户主表的方法（仅有按主键 clientNo+internalKey 的 findByPrimaryKey 及按 EO 属性组合的 findByEo）。需确认本步骤「根据{账号}获取【账户信息】」的实际调用方式：平台通用账户查询客户端、经对公客户账户表（RB_BUS_CLIENT_ACCT）由账号定位客户号后查询账户主表、或交易上下文中已有账户信息等。
- **TBD-3（关联 REQ-001）**：`baseAcctNo` 标记必填，但需求未定义其为空、非规范值或按该账号查无账户记录时的步骤行为（是否业务失败、错误码及返回）。需确认。
- **TBD-4（关联 REQ-002）**：`acctNatureNo` 输出标记非必填，需求未定义账户属性为空（null，账户主表无属性取值）时「检查账户属性」的结果（按「通过」处理还是业务失败）。需确认。
- **TBD-5（关联 REQ-002-S03）**：「检查结果为『通过』」的承载方式。需求输出表仅声明 acctNatureNo，未声明「检查结果」字段；「通过」以步骤正常完成状态表达还是需显式业务输出字段未确认。需确认。
