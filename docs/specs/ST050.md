# ST050 设置贷记交易的借贷标志

## 目标与范围

**目标**：定义存款业务组件「设置贷记交易的借贷标志」步骤（交易执行步骤）的可验证行为契约。本步骤为单一原子步骤，无输入、无子步骤、无分支与循环：将 [借贷标志] 赋值为常量“贷方”，并以输出字段 `crDrInd`（类型 `com.dcits.depsit.enums.CrDrInd`）返回。本 Spec 供测试设计、实现与审核共同使用。

任务名称「设置贷记交易的借贷标志」中的“贷记”与本步骤描述赋值为“贷方”为同一方向，源需求正文与输出表无冲突。

**范围内**：

- 赋值行为的唯一取值：`CrDrInd.C`（码值 `"C"`，业务含义「贷方」）。
- 输出字段 `crDrInd` 的字段契约：字段名、类型、标记（非必填）、业务含义「借贷标志」，以及别名 {借贷标志, 输出数据-借贷标志} 与 `CrDrInd` 的绑定。
- 无输入依赖与无副作用：取值仅来自代码常量，不引用交易外部取值，不查询实体、不发起外部调用。
- 步骤结果的表达方式：正常完成时为成功状态，无业务失败结果。
- 失败表达方式：本步骤无业务失败场景，失败仅由技术异常传播表达。

**不在范围内**（源需求未要求，本 Spec 不定义、不验收）：

- 不定义 [借贷标志] 之外字段的赋值，以及借贷标志在交易日志、账户、凭证等处的落库写入、持久化时机与后续使用。
- 不定义本步骤的输入：源需求无「## 输入」章节，本步骤为纯常量赋值，无交易外部取值可引用；输入为空、缺失或非法取值的处理不在本 Spec 范围。
- 不定义“借”方向的赋值：源需求只要求赋值为“贷方”，`CrDrInd.D`（借）不在本步骤取值域内（见「## 验收范围与明确不覆盖的事项」第 3 项）。
- 不定义组件内步骤调用、外部依赖调用、数据查询、事务边界、重试与降级：源需求无相应描述。
- 不定义本步骤在更大交易中的步骤编排、条件跳转与上下文传递：源需求未涉及。
- 不定义非功能要求（性能、日志、监控、幂等、并发）：源需求未涉及。

## Requirements

### Requirement: REQ-001 将 [借贷标志] 赋值为“贷方”并作为输出 crDrInd 返回

来源：`docs/requirements/ST050.md`「## 步骤描述」第 1 条（第 5 行）；「## 输出」表（第 9–11 行，`crDrInd` 第 11 行）；「## 相关枚举」表（第 15–17 行）；「## 补充说明」（第 21 行）

系统 SHALL 将 [借贷标志] 赋值为常量“贷方”，即枚举 `com.dcits.depsit.enums.CrDrInd` 的成员 `C`（码值 `"C"`），并以字段名 `crDrInd`（类型 `com.dcits.depsit.enums.CrDrInd`，业务含义「借贷标志」）作为本步骤输出返回。该取值 MUST 唯一且确定：系统 MUST NOT 赋为 `CrDrInd.D`（借），MUST NOT 依据任何入参、账户/产品/机构/交易数据或运行环境决定取值，MUST NOT 以空值或其它取值替代。

#### Scenario: REQ-001-S01 赋值为贷方，即 CrDrInd.C（码值 "C"）

- **GIVEN** 本步骤为纯常量赋值，调用方无需提供任何输入
- **WHEN** 调用本步骤
- **THEN** [借贷标志] 被赋值为“贷方”，规范化后等于枚举常量 `CrDrInd.C`，其 `getValue()` 为 `"C"`
- **AND** 该取值不等于 `CrDrInd.D`（借，码值 `"D"`），不因任何外部因素变化

#### Scenario: REQ-001-S02 输出字段契约与成功路径上的必赋值

- **GIVEN** 本步骤为纯常量赋值，调用方无需提供任何输入
- **WHEN** 调用本步骤并正常完成
- **THEN** 输出以字段名 `crDrInd`、类型 `com.dcits.depsit.enums.CrDrInd`、业务含义「借贷标志」给出，取值为贷方（`CrDrInd.C`）
- **AND** 源需求「## 输出」表标记的「非必填」为该字段的可空性声明；本步骤唯一执行路径上该字段总被赋值，成功路径不得返回空值，也不得新增其它输出字段
- **AND** 源需求第 21 行声明的别名「输出数据-借贷标志」与「借贷标志」指称同一字段，不产生第二个输出字段

### Requirement: REQ-002 无输入依赖、无数据访问且无副作用

来源：`docs/requirements/ST050.md`「## 步骤描述」第 1 条（第 5 行，单条赋值动作）；「## 补充说明」（第 21 行，「取值来源于代码[借贷标志]」）；源需求未设「## 输入」章节

系统 SHALL NOT 要求或读取任何业务输入：[借贷标志] 的取值 MUST 仅来自代码常量。系统 MUST NOT 为确定该取值而查询账户、产品、机构、交易定义或其它实体，MUST NOT 调用 BCC、Mapper、数据库、外部接口或其它业务组件步骤，MUST NOT 产生除返回 `crDrInd` 之外的任何业务副作用（不写库、不改写账户或交易数据）。单次调用中该赋值 MUST 执行恰好一次，无分支、无循环、无重试。

#### Scenario: REQ-002-S01 无输入也能完成赋值与返回

- **GIVEN** 调用方未提供任何输入（源需求无「## 输入」章节）
- **WHEN** 调用本步骤
- **THEN** 步骤正常完成赋值并返回 `crDrInd = CrDrInd.C`（贷方）
- **AND** 不因缺少输入而取默认业务入参、不因缺少输入而失败，也不要求调用方额外上送任何字段

#### Scenario: REQ-002-S02 执行不产生副作用与数据访问

- **GIVEN** 调用方未提供任何输入
- **WHEN** 调用本步骤并正常完成
- **THEN** 除返回值 `crDrInd` 外无可观察副作用：不写库、不改写账户或交易数据、不查询任何实体、不调用 BCC/Mapper/数据库/外部接口/其它组件步骤
- **AND** 该赋值在单次调用中执行恰好一次，无分支、无循环、无重试

### Requirement: REQ-003 无业务失败场景，失败仅由技术异常传播表达

来源：`docs/requirements/ST050.md`「## 失败处理」（第 23–25 行，正文第 25 行）——原文：「本步骤无业务失败场景，失败仅由技术异常传播表达。」

系统 SHALL NOT 产生业务失败结果：本步骤 MUST NOT 返回业务错误码、MUST NOT 以失败状态表示业务结论、MUST NOT 定义业务校验、拒件或降级分支。执行正常完成时，步骤结果 MUST 为成功状态（`succeed = true`，`errorCode` 与 `errorMessage` 均为 `null`）。执行过程中出现失败时，其表现 MUST 仅为技术异常按工程既有方式向上传播，系统 MUST NOT 将技术异常吞掉或转换为业务失败结果、默认取值或其它兜底值。

#### Scenario: REQ-003-S01 正常执行的结果状态

- **GIVEN** 调用方未提供任何输入
- **WHEN** 调用本步骤并正常完成
- **THEN** 步骤结果 `succeed = true`，`errorCode` 与 `errorMessage` 均为 `null`
- **AND** 不返回任何业务错误码，也不返回业务失败标识

#### Scenario: REQ-003-S02 失败不以业务失败结果表达

- **GIVEN** 调用方未提供任何输入，且执行过程中出现技术性失败
- **WHEN** 调用本步骤
- **THEN** 该失败按工程既有方式以技术异常向上传播；不返回业务失败状态、不返回业务错误码
- **AND** 不以 `CrDrInd.D`、空值或其它默认取值作为兜底结果返回

## 验收范围与明确不覆盖的事项

1. **取值“C-贷方”的书写口径**：源需求正文以「码值-含义」形式书写（「C-贷方」），本 Spec 按码值 `"C"` 判定并绑定 `CrDrInd.C`；枚举注释写作「贷」，与「贷方」为同一业务含义的同义表达，不改变判定与断言对象。源需求未给出该取值之外的其它枚举绑定方式，本 Spec 不引入。

2. **输出字段 `crDrInd` 的标记与「来源实体」列**：标记「非必填」为源需求对输出字段可空性的声明，本步骤唯一执行路径上恒产出贷方，本 Spec 不据此新增空值分支或条件赋值。「来源实体」列为空，本 Spec 不假定其落库位置、持久化时机与后续使用；技术核对所见的 `RbBusTranJnlEO.crDrInd`（类型 `CrDrInd`）仅为类型承载核对，不构成本步骤对交易日志的查询或写入要求。

3. **“借”方向（`CrDrInd.D`）**：本步骤只要求赋值为“贷方”，`CrDrInd.D` 不在本步骤取值域内；设置借记交易的借贷标志属另一任务的职责，不在本 Spec 范围。本 Spec 只在反向断言中要求结果不等于 `D`，不定义任何取 `D` 的路径。

4. **本步骤无输入**：源需求无「## 输入」章节、无输入表。纯常量赋值步骤无交易外部取值可引用，属正常形态；本 Spec 不据此新增输入字段、默认值、校验、异常或兜底处理，也不验收输入为空/缺失/非法取值的情形。

5. **非业务性行为**：本步骤不含组件内步骤调用、跨步骤数据传递、外部依赖调用、数据查询、事务与失败传播，源需求亦未要求；相关调用顺序、调用次数与失败处理不在验收范围。失败仅以技术异常传播表达，不作业务断言对象之外的约定。

6. **取值边界**：`CrDrInd` 仅含 `C`、`D` 两个成员，本步骤取值恒为 `C`，不存在其它合法取值、精度、舍入或时间口径问题；源需求未涉及金额、币种、日期等字段。
