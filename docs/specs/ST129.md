# ST129 检查增加限制起始日期

## 目标与范围

本任务为交易执行步骤类（源需求以「步骤描述」给出单条检查动作）。步骤依据上送的开始日期（startDate）与系统日期（runDate）、结束日期（endDate）的先后关系，判定增加限制的起始日期是否可接受，并返回检查结果「不通过」或「通过」。

本次 Spec 覆盖：

- 判定入参：startDate（开始日期，必填，`java.util.Date`）、runDate（核心运行日期，必填，`java.util.Date`，源自系统日期表 FM_DATE）、endDate（结束日期，必填，`java.util.Date`）。
- 判定逻辑：`startDate < runDate` 或 `startDate > endDate` 二者之一成立即「不通过」；二者均不成立（即 `runDate <= startDate <= endDate`）则「通过」。
- 占位符绑定：源需求步骤描述中的 {开始日期}→startDate、{系统日期}→runDate、{结束日期}→endDate。
- 产出：检查结果「不通过」或「通过」，二者互斥，由同一分支判定产出。

不在本次范围（源需求未涉及，本 Spec 不作要求）：

- 三个入参为空值（未提供）时的步骤行为（源需求仅将其标记为必填，未定义为空时的分支）。
- 检查结果的承载字段、类型、落库位置与对外展示形式（源需求无「输出」章节）。
- 错误码（源需求步骤描述未给出任何错误码）。
- 「增加限制」业务场景的识别、进入条件与前置校验，以及检查结果被上层如何使用。
- 组件内步骤调用、规则调用、外部服务/领域服务调用、数据查询、超时与重试（源需求未描述任何依赖调用）。
- 日期比较的时间粒度（是否截断时间部分）与相等时的分支（源需求只给出「小于」「大于」两种关系）。

## Requirements

### Requirement: REQ-001 开始日期早于系统日期时返回检查结果为「不通过」

来源：`docs/requirements/ST129.md` 步骤描述第 1 条（原文：「若上送的{开始日期}小于{系统日期}…则返回检查结果为"不通过"」的「{开始日期}小于{系统日期}」分支）、输入表 runDate 行与 startDate 行。

系统 SHALL 在本步骤执行时，当 startDate 早于（小于）runDate 时返回检查结果为「不通过」，且该结果不因 startDate 与 endDate 的关系而改变（即 startDate 与 endDate 的关系同时成立时仍为「不通过」）。

#### Scenario: REQ-001-S01 开始日期早于系统日期且不晚于结束日期时返回不通过
- **GIVEN** startDate = 2026-09-01，runDate = 2026-10-09（系统日期），endDate = 2026-12-31
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「不通过」
- **THEN** 不产出检查结果「通过」

#### Scenario: REQ-001-S02 开始日期早于系统日期且同时晚于结束日期时仍返回不通过
- **GIVEN** startDate = 2026-09-01，runDate = 2026-10-09，endDate = 2026-08-20（两个不通过条件同时成立）
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「不通过」（两个条件为「或者」关系，任一成立即不通过，结果唯一）
- **THEN** 不产出检查结果「通过」

### Requirement: REQ-002 开始日期晚于结束日期时返回检查结果为「不通过」

来源：`docs/requirements/ST129.md` 步骤描述第 1 条（原文：「…或者大于{结束日期}，则返回检查结果为"不通过"」的「{开始日期}大于{结束日期}」分支）、输入表 endDate 行与 startDate 行。

系统 SHALL 在本步骤执行时，当 startDate 晚于（大于）endDate 时返回检查结果为「不通过」，无论 startDate 与 runDate 的关系如何（包括 startDate 不早于 runDate 或与其相等的情形）。

#### Scenario: REQ-002-S01 开始日期晚于系统日期且晚于结束日期时返回不通过
- **GIVEN** startDate = 2026-11-01，runDate = 2026-10-09，endDate = 2026-10-20
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「不通过」
- **THEN** 不产出检查结果「通过」

#### Scenario: REQ-002-S02 开始日期等于系统日期但晚于结束日期时返回不通过
- **GIVEN** startDate = 2026-10-09，runDate = 2026-10-09（与 startDate 相等，即不小于系统日期），endDate = 2026-09-30
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「不通过」（「小于」为严格关系，相等不构成第一个不通过条件，但「大于结束日期」成立）

### Requirement: REQ-003 两个不通过条件均不成立时返回检查结果为「通过」

来源：`docs/requirements/ST129.md` 步骤描述第 1 条（原文：「…否则放回检查结果为"通过"」的「否则」分支）、输入表 runDate、startDate、endDate 三行。

系统 SHALL 在本步骤执行时，当 startDate 不早于 runDate（`startDate >= runDate`）且 startDate 不晚于 endDate（`startDate <= endDate`）时返回检查结果为「通过」，包括 startDate 与 runDate 相等、startDate 与 endDate 相等两种边界情形。

#### Scenario: REQ-003-S01 开始日期介于系统日期与结束日期之间时返回通过
- **GIVEN** startDate = 2026-11-01，runDate = 2026-10-09，endDate = 2026-12-31
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「通过」
- **THEN** 不产出检查结果「不通过」

#### Scenario: REQ-003-S02 开始日期等于系统日期时返回通过（下界边界）
- **GIVEN** startDate = 2026-10-09，runDate = 2026-10-09，endDate = 2026-12-31
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「通过」（相等不满足「小于」，故第一个不通过条件不成立）

#### Scenario: REQ-003-S03 开始日期等于结束日期时返回通过（上界边界）
- **GIVEN** startDate = 2026-12-31，runDate = 2026-10-09，endDate = 2026-12-31
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「通过」（相等不满足「大于」，故第二个不通过条件不成立）

#### Scenario: REQ-003-S04 三个日期取同一值时返回通过
- **GIVEN** startDate = runDate = endDate = 2026-10-09
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 步骤产出的检查结果为「通过」（两个不通过条件均不成立）

### Requirement: REQ-004 判定输入绑定与日期先后比较口径

来源：`docs/requirements/ST129.md` 步骤描述第 1 条中的三个占位符（{开始日期}、{系统日期}、{结束日期}）与输入表 runDate、startDate、endDate 三行。

系统 SHALL 将步骤描述中的 {开始日期} 绑定为入参 startDate、{系统日期} 绑定为入参 runDate、{结束日期} 绑定为入参 endDate，并仅依据这三个入参的时点先后（早于即小于、晚于即大于）完成 REQ-001～REQ-003 的判定。

#### Scenario: REQ-004-S01 三个占位符与三个入参一一绑定
- **GIVEN** 本步骤收到入参 startDate、runDate、endDate，其中 {系统日期} 取 runDate 的取值（核心运行日期，源自系统日期表 FM_DATE）
- **WHEN** 执行本步骤的增加限制起始日期检查
- **THEN** 判定所用的「开始日期」「系统日期」「结束日期」分别等于 startDate、runDate、endDate 三个入参的取值，不使用其它日期字段（如 FM_DATE 的 nextRunDate、lastRunDate）参与判定
