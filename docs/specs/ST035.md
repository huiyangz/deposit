# ST035 检查支取账户黑名单

## 目标与范围

本 Spec 将正式需求「检查支取账户黑名单」交易执行步骤整理为可验证的行为规范。步骤依次：第 1 步按{凭证类型}查询【凭证信息】（凭证类型定义表，TB_VOUCHER_DEF）获取$凭证种类$；第 2 步赋值[事件类型]为「DEBT」；第 3 步按{账号}、{交易机构}、{交易类型}、[事件类型]、{服务代码}、{接口服务代码}、{接口服务类型}、{渠道类型}、[凭证种类]九个参数调用组件内步骤 ST036「检查黑名单」，取得[执行结果]；第 4 步按[执行结果]分支：通过/提醒→继续执行、授权→返回授权标志为「是」、拒绝→返回错误码 `ER0057`。

范围限于需求「步骤描述」第 1–4 步、「输入」「输出」表、「相关枚举」及「补充说明」声明的行为。第 3 步调用目标按「补充说明」确认为组件内步骤 ST036「检查黑名单」（原文《黑名单组件》→任务《检查黑名单》→步骤《检查黑名单》已合并为本组件内步骤），本 Spec 按组件内步骤调用整理，不按规则调用或跨组件远程调用处理；调用参数和返回结果沿用原文描述。授权分支「等待授权结果后再执行后续步骤」的编排机制需求未定义，见「待确认事项」TBD-3。

### 步骤结果契约

- 步骤成功（含「通过」「提醒」「授权」三个正常结论）：`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 均为 `null`。
- 步骤业务失败（[执行结果]为「拒绝」）：`StepResult.succeed = false`，`errorCode = "ER0057"`，`errorMessage = "ER0057::黑名单账户，拒绝交易"`。
- 错误码来源：`deposit-application/src/main/resources/errorcodes.properties` 第 57 行 `ER0057=黑名单账户，拒绝交易`。
- `StepResult`（`com.dcits.common.step.StepResult`）为抽象基类，字段：`succeed`（boolean）、`errorCode`（String，成功时为 `null`）、`errorMessage`（String，成功时为 `null`），访问器 `isSucceed()/getErrorCode()/getErrorMessage()`。

### 依赖核对

- 名称映射（requirement-name-mapping）：「凭证信息」→ 凭证类型定义表（TB_VOUCHER_DEF）；本步骤需求文本不涉及「账户信息」等其它已映射实体。

## Requirements

### Requirement: REQ-001 获取凭证种类

来源：需求「步骤描述」第 1 步（原文：根据{凭证类型}查询【凭证信息】获取其对应的$凭证种类$）

系统 SHALL 根据输入 凭证类型（`docType`）查询【凭证信息】（凭证类型定义表，TB_VOUCHER_DEF）获取对应的凭证种类，并作为输出 `docClass`（`com.dcits.deposit.enums.DocClass`）及第 3 步调用 ST036 的[凭证种类]取值。`docType` 非必填时凭证种类的取得、查询无记录时的行为见待确认事项 TBD-4、TBD-5。

#### Scenario: REQ-001-S01 按凭证类型查询获取凭证种类

- **GIVEN** 输入 `docType` 为凭证类型（示例值：`DocType.VALUE_778`，取值 "778"）；【凭证类型定义表】存在对应记录且其凭证种类为 `DocClass.DCT`（银行承兑汇票）
- **WHEN** 执行第 1 步，根据{凭证类型}查询【凭证信息】
- **THEN** 取得凭证种类为 `DocClass.DCT`，作为输出 `docClass`（非必填）及第 3 步调用 ST036 的[凭证种类]取值

### Requirement: REQ-002 赋值事件类型

来源：需求「步骤描述」第 2 步（原文：赋值[事件类型]为"DEBT"）

系统 SHALL 将[事件类型]赋值为「DEBT」，作为输出 `eventType`（`java.lang.String`，非必填）及第 3 步调用 ST036 的[事件类型]取值。

#### Scenario: REQ-002-S01 赋值事件类型为 DEBT

- **GIVEN** 第 1 步已执行完成
- **WHEN** 执行第 2 步，赋值[事件类型]
- **THEN** [事件类型]为「DEBT」，输出 `eventType` 为 "DEBT"（`java.lang.String`），并作为第 3 步调用 ST036 的[事件类型]取值

### Requirement: REQ-003 调用组件内步骤 ST036 执行黑名单检查

来源：需求「步骤描述」第 3 步（原文：根据{账号}、{交易机构}、{交易类型}、[事件类型]、{服务代码}、{接口服务代码}、{接口服务类型}、{渠道类型}、[凭证种类]访问业务组件《黑名单组件》的任务《检查黑名单》的步骤《检查黑名单》，获取[执行结果]）及「补充说明」（组件内步骤调用：原文《黑名单组件》→任务《检查黑名单》→步骤《检查黑名单》已合并为本组件内步骤 ST036「检查黑名单」，按组件内步骤调用处理，调用参数和返回结果沿用原文描述）

系统 SHALL 在第 3 步以组件内步骤调用方式调用 ST036「检查黑名单」，以{账号}（`baseAcctNo`）、{交易机构}（`tranBranch`）、{交易类型}（`tranType`）、[事件类型]（第 2 步赋值「DEBT」）、{服务代码}（`serviceCode`）、{接口服务代码}（`messageCode`）、{接口服务类型}（`messageType`）、{渠道类型}（`sourceType`）、[凭证种类]（第 1 步取得 `docClass`）传入，并取得 ST036 步骤结果作为[执行结果]。[执行结果]语义按 ST036 已确认契约：「通过」= ST036 正常结束且不设置 `dealFlow`；「拒绝」= `dealFlow` 为 `DealFlow.B`；「授权」= `DealFlow.A`；「提醒」= `DealFlow.D`。

#### Scenario: REQ-003-S01 按九参数调用组件内步骤并取得执行结果

- **GIVEN** 输入 `baseAcctNo`="1000000001"、`tranBranch`=`TranBranch.VALUE_351155`（"351155"）、`tranType`=`TranType.VALUE_1003`（"1003"）、`serviceCode`="SVC0001"、`messageCode`="CIFDP0001"、`messageType`="TRD"、`sourceType`=`SourceType.CIP`（"CIP"）；第 1 步已取得 `docClass`=`DocClass.DCT`、第 2 步已赋值[事件类型]="DEBT"
- **WHEN** 执行第 3 步，调用组件内步骤 ST036「检查黑名单」
- **THEN** 按上述九个参数调用 ST036，ST036 返回步骤正常结束且不设置 `dealFlow`（检查结果「通过」），本步骤取得[执行结果]="通过"（供第 4 步分支）

### Requirement: REQ-004 检查执行结果并返回

来源：需求「步骤描述」第 4 步（原文：a.若[执行结果]为"通过"或"提醒"，则继续执行。b.若[执行结果]为"授权"，则返回授权标志为"是"并等待授权结果后再执行后续步骤。c.若[执行结果]为"拒绝"，否则返回[错误码]"ER0057"）

当[执行结果]为「通过」或「提醒」时，系统 SHALL 使本步骤正常结束并继续执行后续步骤：`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 均为 `null`。当[执行结果]为「授权」时，系统 SHALL 使本步骤正常结束（`StepResult.succeed = true`）并返回授权标志为「是」（输出 授权标志="是"）；「等待授权结果后再执行后续步骤」的编排机制见待确认事项 TBD-3。当[执行结果]为「拒绝」时，系统 SHALL 使本步骤失败：`StepResult.succeed = false`，`errorCode = "ER0057"`，`errorMessage = "ER0057::黑名单账户，拒绝交易"`。

#### Scenario: REQ-004-S01 执行结果为通过时继续执行

- **GIVEN** 第 3 步取得[执行结果]="通过"（ST036 正常结束且未设置 `dealFlow`）
- **WHEN** 执行第 4 步，检查[执行结果]
- **THEN** 本步骤正常结束（`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 为 `null`），继续执行后续步骤

#### Scenario: REQ-004-S02 执行结果为提醒时继续执行

- **GIVEN** 第 3 步取得[执行结果]="提醒"（`dealFlow = DealFlow.D`）
- **WHEN** 执行第 4 步，检查[执行结果]
- **THEN** 本步骤正常结束（`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 为 `null`），继续执行后续步骤

#### Scenario: REQ-004-S03 执行结果为授权时返回授权标志

- **GIVEN** 第 3 步取得[执行结果]="授权"（`dealFlow = DealFlow.A`）
- **WHEN** 执行第 4 步，检查[执行结果]
- **THEN** 本步骤正常结束（`StepResult.succeed = true`，`errorCode` 与 `errorMessage` 为 `null`），输出 授权标志="是"；「等待授权结果后再执行后续步骤」的编排按待确认事项 TBD-3 处理

#### Scenario: REQ-004-S04 执行结果为拒绝时返回错误码 ER0057

- **GIVEN** 第 3 步取得[执行结果]="拒绝"（`dealFlow = DealFlow.B`）
- **WHEN** 执行第 4 步，检查[执行结果]
- **THEN** 本步骤失败：`StepResult.succeed = false`，`errorCode` 为 `ER0057`，`errorMessage` 为 `"ER0057::黑名单账户，拒绝交易"`

## 待确认事项

- **TBD-1（关联 REQ-003）：{交易机构}（`tranBranch`）映射到 ST036 哪个输入字段未确认。** 需求第 3 步将{交易机构}作为 ST036 调用参数；ST036「输入」表无「交易机构」字段，其 `acctBranch` 为「账户开立行行号」（`TranBranch`），与「交易机构号」（`TranBranch`）业务概念不同（ST036 自身 Spec 的 TBD-5 亦未确认{交易机构}的来源）。需确认{交易机构}是否映射到 ST036 的 `acctBranch`，还是 ST036 另有交易机构输入。
- **TBD-2（关联 REQ-003）：ST036 其余输入字段的组装来源未确认。** ST036 输入除本步骤 9 个调用参数外，另有必填输入 `acctBranch`、`programId`、`blacklistCheckFlag`、`serviceStatus`、`documentId`、`documentType` 及非必填输入 `clientNo`（ST035「输入」表含 `clientNo`，但需求第 3 步未将其列入调用参数）。需求未声明这些字段在组件内步骤调用中如何取值。需确认取值来源，不得以默认值或占位值填充。
- **TBD-3（关联 REQ-004）：「等待授权结果后再执行后续步骤」的编排机制未定义。** 需求仅要求授权分支返回授权标志为「是」；由谁等待授权结果、授权结果如何获取、授权结束后是否重复执行本检查或直接继续后续步骤，需求未声明。本步骤可确认的可观察行为仅为正常结束并输出 授权标志="是"。
- **TBD-4（关联 REQ-001）：`docType` 非必填时凭证种类的取得未定义。** `docType` 标记为非必填，需求未定义未上送 `docType` 时第 1 步是否执行、输出 `docClass` 是否为空。需确认。
- **TBD-5（关联 REQ-001）：按凭证类型查询凭证类型定义表无记录时的行为未定义。** 需求未声明查询无记录时的处理（`docClass` 是否为空、是否报错及错误码）。需确认。
- **TBD-6（关联 REQ-001~REQ-004）：必填输入缺失行为未定义。** 需求「输入」表 8 个字段标记为必填，需求未定义输入为空/缺失时的校验行为及错误码。需确认。
