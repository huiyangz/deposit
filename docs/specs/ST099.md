# ST099 检查利息资本化标志

## 目标与范围

本任务为交易执行步骤类（源需求以「步骤描述」两条子步骤给出，无跳转）。步骤依据入参中的利息资本化标志与结算账户类型，先在子步骤 1 判定利息资本化标志是否为「N-否」，再按判定结果决定是否执行子步骤 2 的结算账户类型检查，最终返回检查结果「通过」或错误码 `ER0034`。

本次 Spec 覆盖：

- 输入两项：intCapFlag（利息资本化标志，必填，`java.lang.String`）、settleAcctClass（结算账户类型，必填，`com.dcits.depsit.enums.SettleAcctClass`）。
- 子步骤 1：{利息资本化标志} 是否等于「N-否」的判定，以及两种分支的走向——等于则继续执行子步骤 2；不等于则返回检查结果为「通过」（不执行子步骤 2）。
- 子步骤 2：{结算账户类型} 是否等于「INT-利息入账账户」的判定，以及两种分支的产出——不等于则返回错误码 `ER0034`；等于则返回检查结果为「通过」。
- 两条子步骤的执行顺序与短路：子步骤 1 判定为「不等于」时，本步骤在子步骤 1 即结束，子步骤 2 不执行。
- 两项入参取值与枚举类 `com.dcits.depsit.enums.SettleAcctClass` 的绑定，以及「N-否」「INT-利息入账账户」的「码值-含义」记法在判定中的字面口径。

不在本次范围（源需求未涉及，本 Spec 不作要求）：

- 检查结果与错误码作为返回值的业务字段名、类型、必填性与落库位置（源需求无「## 输出」章节，见「验收范围与明确不覆盖的事项」第 1 项）。
- 两项入参的取数出处（源需求输入表「来源实体」列为空，步骤正文亦未描述任何查询或调用，本 Spec 不假定数据来源）。
- 两项入参为空值、或取值超出其合法取值域时的行为（源需求仅标记为必填，未定义相应分支）。
- 结算账户实体/账户是否实际存在的查询与校验（源需求子步骤 2 的条件只写 {结算账户类型} 与「INT-利息入账账户」的比较，未描述任何查询）。
- 返回 `ER0034` 之后交易的终止、回滚与向上层传播方式。
- 组件内步骤调用、规则调用、外部服务/领域服务调用、数据查询、超时与重试（源需求未描述任何依赖调用）。
- 「通过」以外的检查结果取值（源需求在本步骤只出现「通过」；失败以错误码 `ER0034` 表达）。
- 本步骤产出结果的下游使用与持久化。

## Requirements

### Requirement: REQ-001 利息资本化标志不等于「N-否」时返回检查结果为「通过」并跳过子步骤 2

来源：`docs/requirements/ST099.md` 步骤描述第 1 条（原文：「若{利息资本化标志}等于"N-否"，则继续执行，否则返回检查结果为"通过"」的「否则」分支）、输入表 intCapFlag 行。

系统 SHALL 在入参 intCapFlag 不等于「N-否」（判定字面为码值 `"N"`）时，返回检查结果为「通过」，且 MUST NOT 执行子步骤 2 的结算账户类型判定、MUST NOT 返回错误码 `ER0034`。该判定条件仅为 intCapFlag 与 `"N"` 的比较，源需求未给出其它条件。

#### Scenario: REQ-001-S01 标志不等于「N-否」且结算账户类型非「利息入账账户」时仍返回「通过」

- **GIVEN** intCapFlag = `"Y"`（不等于码值 `"N"`），settleAcctClass = `SettleAcctClass.PAY`（码值 `"PAY"`，付款账户，非「INT-利息入账账户」）
- **WHEN** 执行本步骤的利息资本化标志检查（子步骤 1）
- **THEN** 返回检查结果为「通过」（步骤结果 `succeed = true`，`errorCode` 为空）
- **THEN** 不返回错误码 `ER0034`，不执行子步骤 2 的结算账户类型判定（本步骤在子步骤 1 即结束）

#### Scenario: REQ-001-S02 标志不等于「N-否」且结算账户类型为「利息入账账户」时同样返回「通过」

- **GIVEN** intCapFlag = `"Y"`，settleAcctClass = `SettleAcctClass.INT`（码值 `"INT"`，利息入账账户）
- **WHEN** 执行子步骤 1
- **THEN** 返回检查结果为「通过」（步骤结果 `succeed = true`，`errorCode` 为空）
- **THEN** 不返回错误码 `ER0034`；该结果与 REQ-001-S01 在 settleAcctClass 取值不同的情形下一致，表明子步骤 1 的判定不依赖 settleAcctClass

### Requirement: REQ-002 利息资本化标志等于「N-否」时继续执行子步骤 2，结算账户类型不为「INT-利息入账账户」时返回错误码 ER0034

来源：`docs/requirements/ST099.md` 步骤描述第 1 条（原文：「…等于"N-否"，则继续执行…」的「若」分支）、步骤描述第 2 条（原文：「检查利息入账结算账户存在性：若{结算账户类型}不为"INT-利息入账账户"，则返回[错误码]"ER0034"」的「若」分支）、输入表 settleAcctClass 行。

系统 SHALL 在 intCapFlag 等于「N-否」（判定字面为码值 `"N"`）时继续执行子步骤 2，并判断 settleAcctClass 是否为「INT-利息入账账户」：不为「INT-利息入账账户」时返回错误码 `ER0034`，且 MUST NOT 返回检查结果「通过」、MUST NOT 返回 `ER0034` 以外的错误码。子步骤 2 的判定条件仅为 settleAcctClass 与「INT-利息入账账户」的比较，源需求未给出其它条件。

#### Scenario: REQ-002-S01 标志为「N-否」且结算账户类型为「付款账户」时返回 ER0034

- **GIVEN** intCapFlag = `"N"`（「N-否」），settleAcctClass = `SettleAcctClass.PAY`（码值 `"PAY"`，付款账户）
- **WHEN** 依次执行子步骤 1、子步骤 2
- **THEN** 子步骤 1 判定为等于「N-否」，继续执行子步骤 2
- **THEN** 返回错误码 `ER0034`（「非利息资本化账户必须上送利息入账账户」，步骤结果 `succeed = false`、`errorCode = "ER0034"`）
- **THEN** 不返回检查结果「通过」（`succeed` 不为 `true`）

#### Scenario: REQ-002-S02 结算账户类型为注释含「利息入账账户」字样的其它成员时仍返回 ER0034

- **GIVEN** intCapFlag = `"N"`（「N-否」），settleAcctClass = `SettleAcctClass.CON`（码值 `"CON"`，注释「全部本金转存利息入账账户」）
- **WHEN** 执行子步骤 2 的结算账户类型判定
- **THEN** 判定为不为「INT-利息入账账户」，返回错误码 `ER0034`
- **THEN** 不返回检查结果「通过」；判定不因该成员的中文注释中含「利息入账账户」字样而改变（其码值 `"CON"` 不等于 `"INT"`）

### Requirement: REQ-003 利息资本化标志等于「N-否」且结算账户类型为「INT-利息入账账户」时返回检查结果为「通过」

来源：`docs/requirements/ST099.md` 步骤描述第 2 条（原文：「…否则返回检查结果为"通过"」的「否则」分支）、步骤描述第 1 条的「继续执行」。

系统 SHALL 在 intCapFlag 等于「N-否」且 settleAcctClass 为「INT-利息入账账户」（`SettleAcctClass.INT`，码值 `"INT"`）时，返回检查结果为「通过」，且 MUST NOT 返回错误码 `ER0034`。

#### Scenario: REQ-003-S01 标志为「N-否」且结算账户类型为「利息入账账户」时检查通过

- **GIVEN** intCapFlag = `"N"`（「N-否」），settleAcctClass = `SettleAcctClass.INT`（码值 `"INT"`，利息入账账户）
- **WHEN** 依次执行子步骤 1、子步骤 2
- **THEN** 返回检查结果为「通过」（步骤结果 `succeed = true`，`errorCode` 为空）
- **THEN** 不返回错误码 `ER0034`

### Requirement: REQ-004 结算账户类型按枚举类 SettleAcctClass 的 INT 成员判定

来源：`docs/requirements/ST099.md` 步骤描述第 2 条（「不为"INT-利息入账账户"」）、相关枚举表（结算账户分类／结算账户类型／输入数据-结算账户类型）、补充说明（原文：「{结算账户类型,输入数据-结算账户类型}取值来源于代码[结算账户分类]，对应枚举类-类名：com.dcits.depsit.enums.SettleAcctClass」）。

系统 SHALL 以 `com.dcits.depsit.enums.SettleAcctClass` 的成员判定「是否为"INT-利息入账账户"」，判定依据为成员的码值：码值等于 `"INT"` 的成员（`SettleAcctClass.INT`，注释「利息入账账户」）即「INT-利息入账账户」；该枚举中码值为 `"INT"` 的成员唯一，其余成员的码值均不等于 `"INT"`，一律判定为不为「INT-利息入账账户」。

#### Scenario: REQ-004-S01 码值为 INT 的成员判定为「INT-利息入账账户」

- **GIVEN** settleAcctClass 由枚举类 `com.dcits.depsit.enums.SettleAcctClass` 的成员构成，取该枚举中码值为 `"INT"` 的成员（`SettleAcctClass.INT`，注释「利息入账账户」）
- **WHEN** 执行子步骤 2 的结算账户类型判定
- **THEN** 判定为等于「INT-利息入账账户」，按 REQ-003 返回检查结果为「通过」
- **THEN** 判定依据为该成员的码值 `"INT"`，MUST NOT 要求 settleAcctClass 的取值为字符串 `"INT-利息入账账户"`

#### Scenario: REQ-004-S02 码值不等于 INT 的成员一律判定为不为「INT-利息入账账户」

- **GIVEN** intCapFlag = `"N"`，settleAcctClass = `SettleAcctClass.PRI`（码值 `"PRI"`，本金入账账户）
- **WHEN** 执行子步骤 2 的结算账户类型判定
- **THEN** 判定为不为「INT-利息入账账户」，按 REQ-002 返回错误码 `ER0034`
- **THEN** 枚举类 `SettleAcctClass` 的 21 个成员中只有 `SettleAcctClass.INT` 的码值为 `"INT"`，其余成员（如码值 `"PRI"`、`"PAY"`、`"CON"`、`"SSI"` 等）均不满足「等于"INT-利息入账账户"」

### Requirement: REQ-005 利息资本化标志按码值 "N" 等值判定

来源：`docs/requirements/ST099.md` 步骤描述第 1 条（原文：「若{利息资本化标志}等于"N-否"」）、输入表 intCapFlag 行（类型 `java.lang.String`，说明「利息资本化标志」）。

系统 SHALL 以 intCapFlag 与码值 `"N"` 的等值比较实现「等于"N-否"」的判定：源需求以「N-否」的「码值-含义」形式给出取值，`N` 为码值、「否」为其含义，判定字面为 `"N"`；系统 MUST NOT 要求 intCapFlag 恰为字符串 `"N-否"`。

#### Scenario: REQ-005-S01 标志取码值 N 时判定为等于「N-否」

- **GIVEN** intCapFlag = `"N"`（源需求以「N-否」记法给出的取值，码值 `"N"`、含义「否」）
- **WHEN** 执行子步骤 1 的利息资本化标志判定
- **THEN** 判定为等于「N-否」，继续执行子步骤 2（最终结果按 REQ-002 或 REQ-003 产出）
- **THEN** 判定字面为码值 `"N"`，不因 intCapFlag 的取值未携带「-否」后缀而判定为不等
