# ST054 检查是否存在现金止收限制

## 目标与范围

本 Spec 将正式需求「检查是否存在现金止收限制」交易执行步骤整理为可验证的行为描述。步骤以账号（baseAcctNo）为输入，通过两次查询（账户限制信息、限制类型信息）判断该账号是否命中现金止收限制，并返回现金止收标志「是」/「否」，同时按「输出」表输出两次查询取得的字段。

范围限于需求「步骤描述」步骤 1–3 声明的查询与判定逻辑、「输入」「输出」表契约及「相关枚举」「补充说明」确认的枚举来源。需求未声明业务失败场景与错误码，本 Spec 不新增失败分支、错误码或技术异常处理；多条生效限制的聚合判定、现金止收标志的输出字段去向、限制类型记录缺失等缺口见「待确认事项」，不补默认行为。

### 依赖核对

- 枚举核对（`deposit-common`）：`RestraintType`（限制类型，取值如"6"=不允许现金存入、"13"=挂失止付等）、`RestraintsStatus`（A="已批准"、E="已终止"、F="未生效"）、`Status`（A="有效"、C="非活动状态"、D="删除"、F="无效"、N="新增"、O="未过账"、P="已过账"、U="修改"）、`DrCrCtlFlag`（A="禁止借贷方"、C="禁止贷方"、D="禁止借方"）均存在，需求「补充说明」确认取值来源对应枚举类。`cashFlag`、`stopFlag` 在实体与 EO 中为 `java.lang.String` 字段，工程中无「现金标志」枚举（`CashItem` 为现金项目枚举，非现金标志）。
- 实体字段核对：`RbBusRestraints`（RB_BUS_RESTRAINTS）含 baseAcctNo、restraintType、restraintsStatus、resSeqNo（String）；`RbRestraintType`（RB_RESTRAINT_TYPE）含 restraintType（主键）、status、drCrCtlFlag、cashFlag、stopFlag（String）。对应 EO（`RbBusRestraintsEO`、`RbRestraintTypeEO`）将 restraintType、restraintsStatus、status、drCrCtlFlag 分别以 `RestraintType`、`RestraintsStatus`、`Status`、`DrCrCtlFlag` 枚举承载，baseAcctNo、resSeqNo、cashFlag、stopFlag 为 String。
- 查询接口核对：`IRbBusRestraintsBcc.findByEo` 可按 EO 非空属性组合查询并返回 `List<RbBusRestraintsEO>`；`IRbRestraintTypeBcc.findByEo` / `findByRestraintType` 可依据账户限制类型查询限制类型信息。本步骤实现尚未生成，不构成依赖缺失。
- 名称映射核对（requirement-name-mapping）：已确认「账户限制信息」→「对公存款账户限制表」、「限制类型表」→「存款限制类型表」；「限制状态」「账户限制类型」「借贷方控制标志」「现金标志」「状态」「限制编号」「止付标志」未收录属性域映射，按需求业务称谓保留。
- 步骤结果与错误（step-error-contract / step-return-contract）：需求未声明业务失败场景与错误码，本 Spec 不新增失败分支或错误码；正常完成按步骤成功表达（`StepResult` succeed=true，errorCode/errorMessage 为空）。查询无记录不构成业务失败。必填缺失等未定义行为见 TBD-6。

## Requirements

### Requirement: REQ-001 依据账号查询生效账户限制信息
来源：需求「步骤描述」步骤 1、「输入」表。

系统 SHALL 以输入 baseAcctNo（类型 java.lang.String，必填，业务含义"账号"）与$限制状态$="A-生效"（编码"A"，对应枚举 `RestraintsStatus.A`，见 TBD-3）作为查询条件，在【账户限制信息】（对公存款账户限制表，RB_BUS_RESTRAINTS）中取得该账号处于生效状态的[账户限制信息]；取得的账户限制信息 SHALL 至少包含$账户限制类型$（restraintType）与$限制编号$（resSeqNo）。同一账号可能存在多条生效限制记录，其纳入后续判定的方式见待确认事项 TBD-1。

#### Scenario: REQ-001-S01 账号存在生效限制
- **GIVEN** 账号 baseAcctNo="6222020000000000001"，对公存款账户限制表（RB_BUS_RESTRAINTS）中存在限制状态="A-生效"（编码"A"）的记录：限制编号 resSeqNo="R10001"、账户限制类型="6"（不允许现金存入）
- **WHEN** 依据 baseAcctNo 与限制状态="A-生效"查询账户限制信息
- **THEN** 取得该条账户限制信息，其账户限制类型="6"、限制编号="R10001"；后续以该账户限制信息的账户限制类型作为限制类型表查询条件

#### Scenario: REQ-001-S02 账号无生效限制
- **GIVEN** 账号 baseAcctNo="6222020000000000001" 在对公存款账户限制表（RB_BUS_RESTRAINTS）中无限制状态="A-生效"（编码"A"）的记录（或无任何记录）
- **WHEN** 依据 baseAcctNo 与限制状态="A-生效"查询账户限制信息
- **THEN** 未取得账户限制信息，本步骤返回现金止收标志="否"（无生效限制即不满足步骤 3 的"是"条件，落入"否则"分支）

### Requirement: REQ-002 依据账户限制类型查询生效限制类型信息
来源：需求「步骤描述」步骤 2、「输出」表。

系统 SHALL 以[账户限制信息]中的$账户限制类型$为查询条件，在【限制类型表】（存款限制类型表，RB_RESTRAINT_TYPE）中取得$状态$="A-生效"（编码"A"，对应枚举 `Status.A`，见 TBD-3）的限制类型记录，并按「输出」表取得该记录的账户限制类型（restraintType）、状态（status）、借贷方控制标志（drCrCtlFlag）、现金标志（cashFlag）、止付标志（stopFlag）。

#### Scenario: REQ-002-S01 限制类型记录存在且生效
- **GIVEN** [账户限制信息]的账户限制类型="6"，存款限制类型表（RB_RESTRAINT_TYPE）中存在账户限制类型="6"且状态="A-生效"（编码"A"）的记录
- **WHEN** 依据账户限制类型="6"查询限制类型信息
- **THEN** 取得该限制类型记录，其账户限制类型、状态="A-生效"（`Status.A`）、借贷方控制标志、现金标志、止付标志按该记录取值

### Requirement: REQ-003 现金止收限制判定
来源：需求「步骤描述」步骤 3。

系统 SHALL 按以下规则返回现金止收标志：当限制类型对应的$借贷方控制标志$="C-禁止贷方"（编码"C"，对应枚举 `DrCrCtlFlag.C`）且$现金标志$="N-不允许现金"（编码"N"）时，返回现金止收标志="是"；否则（含借贷方控制标志≠"C-禁止贷方"、现金标志≠"N-不允许现金"、无生效限制记录等情形）返回现金止收标志="否"。

#### Scenario: REQ-003-S01 命中现金止收限制返回"是"
- **GIVEN** 限制类型记录（账户限制类型="6"）的借贷方控制标志="C-禁止贷方"（`DrCrCtlFlag.C`）、现金标志="N-不允许现金"
- **WHEN** 执行现金止收限制判定
- **THEN** 返回现金止收标志="是"

#### Scenario: REQ-003-S02 借贷方控制标志不满足返回"否"
- **GIVEN** 限制类型记录的借贷方控制标志="D-禁止借方"（`DrCrCtlFlag.D`，不等于"C-禁止贷方"）、现金标志="N-不允许现金"
- **WHEN** 执行现金止收限制判定
- **THEN** 返回现金止收标志="否"

#### Scenario: REQ-003-S03 现金标志不满足返回"否"
- **GIVEN** 限制类型记录的借贷方控制标志="C-禁止贷方"（`DrCrCtlFlag.C`）、现金标志不为"N-不允许现金"（示例值"Y"；除"N-不允许现金"外现金标志取值未确认，见 TBD-4）
- **WHEN** 执行现金止收限制判定
- **THEN** 返回现金止收标志="否"

### Requirement: REQ-004 步骤输出契约
来源：需求「输出」表、「相关枚举」、「补充说明」。

系统 SHALL 按「输出」表输出以下字段（类型与必填性按表）：
- 来源 对公存款账户限制表（RB_BUS_RESTRAINTS）：resSeqNo（java.lang.String，非必填）、restraintType（com.dcits.deposit.enums.RestraintType，非必填）、restraintsStatus（com.dcits.deposit.enums.RestraintsStatus，非必填）；
- 来源 存款限制类型表（RB_RESTRAINT_TYPE）：restraintType（com.dcits.deposit.enums.RestraintType，非必填）、status（com.dcits.deposit.enums.Status，非必填）、drCrCtlFlag（com.dcits.deposit.enums.DrCrCtlFlag，非必填）、cashFlag（java.lang.String，非必填）、stopFlag（java.lang.String，非必填）。

两个来源表均输出 restraintType 的命名/映射见待确认事项 TBD-7；现金止收标志未登记于「输出」表，去向见 TBD-2。

#### Scenario: REQ-004-S01 输出字段按来源实体可获取
- **GIVEN** 查询命中一条生效账户限制信息及其对应生效限制类型记录
- **WHEN** 执行本步骤并完成现金止收判定
- **THEN** 输出包含 resSeqNo、restraintType、restraintsStatus（来源：对公存款账户限制表）与 restraintType、status、drCrCtlFlag、cashFlag、stopFlag（来源：存款限制类型表），字段类型与必填性符合「输出」表

## 待确认事项

- **TBD-1（关联 REQ-001、REQ-003）**：多条生效限制的聚合判定。需求步骤 1 未声明账号生效限制的唯一性；工程查询接口返回 `List`，同一账号可能命中多条生效限制记录，而步骤 3 返回单一现金止收标志。需确认：多条生效限制时是否"任一命中即'是'"，判定顺序/优先级，以及「输出」表来自对公存款账户限制表的字段（resSeqNo/restraintType/restraintsStatus）在多条记录时输出哪条。
- **TBD-2（关联 REQ-003、REQ-004）**：现金止收标志的输出去向。需求步骤 3 明确"返回现金止收标志为'是'/'否'"，但「输出」表未登记该字段。需确认承载该结论的输出字段名/类型，业务取值"是"/"否"的物理编码，以及「输出」表字段是否为步骤完整输出。
- **TBD-3（关联 REQ-001、REQ-002）**："A-生效"语义。需求以"A-生效"表述限制状态与状态的条件取值；编码"A"在枚举 `RestraintsStatus`（业务名"已批准"）与 `Status`（业务名"有效"）中均存在，但业务标签"生效"与两枚举业务名表述不一致。需确认"A-生效"分别对应 `RestraintsStatus.A` 与 `Status.A`，及"生效"与"已批准"/"有效"的语义对应关系。
- **TBD-4（关联 REQ-003）**：现金标志取值。需求仅确认现金标志="N-不允许现金"；cashFlag 为 String 字段，工程无对应枚举，除"N"外取值及含义未定义，影响"现金标志≠N"分支的测试预期（场景 REQ-003-S03 中"Y"为示例数据，非规范常量）。
- **TBD-5（关联 REQ-002、REQ-003）**：限制类型记录不存在或状态非生效。[账户限制信息]中的账户限制类型在限制类型表无状态="A-生效"的记录（或无任何记录）时，步骤 2/3 的取值与结论未定义。
- **TBD-6（关联 REQ-001）**：必填输入缺失。baseAcctNo 标记必填，但需求未定义其为空/缺失时的处理（是否业务失败及错误码）；需求未声明任何业务失败场景，本 Spec 不新增失败分支。
- **TBD-7（关联 REQ-004）**：输出字段命名。需求「输出」表登记两个"restraintType"（分别来源对公存款账户限制表、存款限制类型表），输出载体中两字段的命名与映射需确认。
