# ST057 检查支取交易类型

## 目标与范围

**目标**：以交易执行步骤 ST057「检查支取交易类型」的已确认业务定义为依据，整理可验证的行为 Spec。步骤以 {交易类型}（`tranType`）为唯一输入，按该交易类型查询【交易类型定义】取得 $借贷标志$、$现金交易标志$、$冲正交易标志$，并以「借贷标志为「D-借方」且 现金交易标志为「Y是」且 冲正交易标志为「N否」」为判据：成立则继续执行，否则返回错误码「ER0067」。

**范围内**：

- 输入 `tranType` 的字段契约：字段名、类型、必填性、取值来源与枚举类归属。
- 步骤1 的取数契约：查询对象、查询键、取出的三个字段及其与输出的对应。
- 步骤2 的判定契约：三个条件（且关系）成立与不成立的判定、通过分支、返回 `ER0067` 的失败分支、判定组合的穷尽性。
- 输出 `crDrInd`、`cashTranFlag`、`reversal` 的字段名、类型、标记、取值语义与来源。
- 失败时的错误码取值与短路约束，以及检查步骤的副作用约束。

**不在范围内**：

- 输入 `tranType` 在调用方侧的产生方式与上游填充逻辑（源需求「## 输入」表「来源实体」列为空，见「## 验收范围与明确不覆盖的事项」第 5 项）。
- 【交易类型定义】查询无匹配记录、三个字段取到无值时的处理：源需求未定义（见第 1 项）。
- 失败后的业务动作：错误提示文案、流程回退、调用方（上游步骤）的处理（源需求仅给出错误码）。
- 输入合法性校验（`tranType` 是否为合法枚举取值，见第 4 项）、日志/监控/性能/幂等等非功能要求。
- 后续步骤的内容与编号（步骤描述止于「继续执行」，源需求无「组件内步骤调用」补充说明）。

### 取值书写口径（码值与含义）

源需求「## 步骤描述」2（第 6 行）以「码值+含义」形式书写判定取值：借贷标志写作「"D-借方"」，现金交易标志写作「"Y是"」、冲正交易标志写作「"N否"」。按本项目已合并规格对同一书写形式的既有口径（`docs/specs/DT002.md` 对「"Y-是"」按码值 `"Y"` 表述判定），本 Spec 以**码值**作为判定取值：

- **借贷标志**：`D` 含义「借方」（源需求「"D-借方"」）、`C` 含义「贷方」（`com.dcits.depsit.enums.CrDrInd` 的全部两个取值）。
- **现金交易标志**：`Y` 含义「是」（源需求「"Y是"」）；`N` 含义「否」。
- **冲正交易标志**：`Y` 含义「是」；`N` 含义「否」（源需求「"N否"」）。

该口径为表述约定，不改变判定条件；「Y是」「N否」未带分隔符属源需求书写差异（源需求「## 补充说明」未给出这两个标志的取值清单），已登记为解释项（见「## 验收范围与明确不覆盖的事项」第 3 项）。

## Requirements

### Requirement: REQ-001 步骤输入与命名契约

来源：`docs/requirements/ST057.md`「## 输入」表（第 10–12 行）、「## 相关枚举」表（第 24–27 行）、「## 补充说明」（第 29–32 行）

系统 SHALL 以 `tranType`（类型 `com.dcits.depsit.enums.TranType`，必填，业务名称「交易类型」）作为本步骤的唯一输入，其取值 MUST 为 `com.dcits.depsit.enums.TranType` 的码值。源需求正文中的「{交易类型}」与「[输入数据-交易类型]」MUST 指向同一输入 `tranType`；「[借贷标志]」与「[输出数据-借贷标志]」MUST 指向同一输出 `crDrInd`，MUST NOT 因别名的不同表述引入重复的输入或输出。系统 MUST NOT 使用 `tranType` 以外的输入，也 MUST NOT 因「来源实体」列为空而自行增加取数动作。

#### Scenario: REQ-001-S01 以合法交易类型作为唯一输入执行

- **GIVEN** 调用方按「## 输入」表传入示例输入 `tranType = "1003"`（`TranType` 中 1003 对应「现金支取」，示例数据），未传入其它任何输入
- **WHEN** 调用本步骤执行
- **THEN** 本步骤仅以 `tranType = "1003"` 驱动执行：先按该值查询【交易类型定义】（REQ-002），再对查询所得三字段作判定（REQ-003、REQ-004）；不要求、不读取 `tranType` 之外的入参

#### Scenario: REQ-001-S02 别名与枚举类对应关系

- **GIVEN** 源需求「## 相关枚举」表将「交易类型、输入数据-交易类型」列为同一枚举的别名，将「借贷标志、输出数据-借贷标志」列为另一枚举的别名；「## 补充说明」（第 31–32 行）给出 {交易类型,输入数据-交易类型} → `com.dcits.depsit.enums.TranType`、{借贷标志,输出数据-借贷标志} → `com.dcits.depsit.enums.CrDrInd`
- **WHEN** 解析本步骤的输入与输出清单
- **THEN** 输入仍为 1 个（`tranType`，类型 `TranType`）、输出仍为 3 个（`crDrInd` 类型 `CrDrInd`，`cashTranFlag`、`reversal` 类型 `java.lang.String`）；别名的不同表述不产生重复字段，也不改变各字段的枚举类归属

### Requirement: REQ-002 步骤1：按交易类型查询【交易类型定义】取得三个字段

来源：`docs/requirements/ST057.md`「## 步骤描述」1（第 5 行）—— 原文：「1.获取现金支取交易类型：根据{交易类型}查询【交易类型定义】获取对应的$借贷标志$、$现金交易标志$、$冲正交易标志$」

系统 SHALL 以 `tranType` 为查询键查询【交易类型定义】，并取得该交易类型对应记录的「借贷标志」「现金交易标志」「冲正交易标志」，分别作为 `crDrInd`、`cashTranFlag`、`reversal` 三个输出的取值。三个字段 MUST 取自同一次按交易类型的查询的同一记录，MUST NOT 通过多次查询或跨记录拼接取值。本步骤 MUST NOT 修改【交易类型定义】的数据。

#### Scenario: REQ-002-S01 命中记录并取得三个字段

- **GIVEN** `tranType = "1003"`（现金支取），且【交易类型定义】中该交易类型的记录为「借贷标志＝D（借方）、现金交易标志＝Y（是）、冲正交易标志＝N（否）」（示例数据）
- **WHEN** 执行步骤1
- **THEN** 取得 `crDrInd = D`（`CrDrInd.D`）、`cashTranFlag = "Y"`、`reversal = "N"` 三个值，并交由步骤2 判定；查询按交易类型（主键）进行，不新增、修改或删除任何数据

#### Scenario: REQ-002-S02 三个字段同源于一次查询

- **GIVEN** `tranType` 为任一合法交易类型码值
- **WHEN** 执行步骤1
- **THEN** `crDrInd`、`cashTranFlag`、`reversal` 三者均取自该次查询所得记录的同一记录，字段名与实体业务字段一一对应（借贷标志→`crDrInd`、现金交易标志→`cashTranFlag`、冲正交易标志→`reversal`）；不存在将不同记录或不同交易的字段组合使用的路径，也不存在查询【交易类型定义】之外的数据来源

### Requirement: REQ-003 步骤2：三个判定条件同时成立则继续执行

来源：`docs/requirements/ST057.md`「## 步骤描述」2（第 6 行）—— 原文：「2.检查交易类型：若[借贷标志]为“D-借方”，且[现金交易标志]为“Y是”，且[冲正交易标志]为“N否”，则继续执行，否则返回[错误码]“ER0067”」的前半句

系统 SHALL 在 `crDrInd` 等于 `D`（借方）且 `cashTranFlag` 等于 `Y`（是）且 `reversal` 等于 `N`（否）时判定通过并继续执行。三个条件为**且（AND）**关系，MUST 同时成立；任一条件不成立即不进入本分支。判定通过时 MUST NOT 返回错误码 `ER0067`，本步骤以通过状态结束，且不产生数据写入或其它业务副作用。

#### Scenario: REQ-003-S01 三条件均成立（正常路径）

- **GIVEN** 步骤1 取得 `crDrInd = D`（借方）、`cashTranFlag = "Y"`（是）、`reversal = "N"`（否）
- **WHEN** 执行步骤2 判定
- **THEN** 判定通过并继续执行：不返回错误码 `ER0067`，本步骤以通过状态结束，且不产生数据写入或其它业务副作用

#### Scenario: REQ-003-S02 判定使用步骤1 取得的三个字段值

- **GIVEN** 步骤1 已按 `tranType` 取得 `crDrInd`、`cashTranFlag`、`reversal`
- **WHEN** 执行步骤2 判定
- **THEN** 判定直接使用这三个已取得的值，不重新查询【交易类型定义】、不引入其它数据来源；判定对象为步骤1 查得的三个字段值，而非输入参数 `tranType` 本身

### Requirement: REQ-004 步骤2：任一条件不成立则返回错误码 ER0067

来源：`docs/requirements/ST057.md`「## 步骤描述」2（第 6 行）—— 原文后半句：「…否则返回[错误码]“ER0067”」

系统 SHALL 在 `crDrInd` 不等于 `D`（借方），或 `cashTranFlag` 不等于 `Y`（是），或 `reversal` 不等于 `N`（否）时返回错误码 `ER0067`，并 MUST NOT 继续执行。「否则」为穷尽分支：凡未同时满足三个条件的取值组合，均返回 `ER0067`，不存在既不继续执行也不返回 `ER0067` 的组合。

#### Scenario: REQ-004-S01 借贷标志非「借方」

- **GIVEN** 步骤1 取得 `crDrInd = C`（贷方）、`cashTranFlag = "Y"`（是）、`reversal = "N"`（否）
- **WHEN** 执行步骤2 判定
- **THEN** 返回错误码 `ER0067`；因 `crDrInd` 不满足「D-借方」，判定不通过，不继续执行

#### Scenario: REQ-004-S02 现金交易标志非「是」

- **GIVEN** 步骤1 取得 `crDrInd = D`（借方）、`cashTranFlag = "N"`（否）、`reversal = "N"`（否）
- **WHEN** 执行步骤2 判定
- **THEN** 返回错误码 `ER0067`；因 `cashTranFlag` 不满足「Y是」，判定不通过，不继续执行

#### Scenario: REQ-004-S03 冲正交易标志非「否」

- **GIVEN** 步骤1 取得 `crDrInd = D`（借方）、`cashTranFlag = "Y"`（是）、`reversal = "Y"`（是，即冲正交易）
- **WHEN** 执行步骤2 判定
- **THEN** 返回错误码 `ER0067`；因 `reversal` 不满足「N否」，判定不通过，不继续执行

#### Scenario: REQ-004-S04 多个条件同时不成立

- **GIVEN** 步骤1 取得 `crDrInd = C`（贷方）、`cashTranFlag = "N"`（否）、`reversal = "Y"`（是）
- **WHEN** 执行步骤2 判定
- **THEN** 返回错误码 `ER0067`；三个条件均不成立，判定不通过，不继续执行，且返回值仍为同一错误码 `ER0067`（不因不成立的条件个数不同而返回不同结果）

#### Scenario: REQ-004-S05 不成立组合穷尽返回 ER0067（贯通判定表）

- **GIVEN** 判定域为 `crDrInd` ∈ {`D`、`C`}、`cashTranFlag` ∈ {`Y`、`N`}、`reversal` ∈ {`Y`、`N`} 的全部 8 种组合
- **WHEN** 逐一执行步骤2 判定
- **THEN** 每个组合均给出下表确定的结果，仅 `(D, Y, N)` 继续执行，其余 7 个组合均返回 `ER0067`，不存在未定义或无结果的组合：

| `crDrInd`（借贷标志） | `cashTranFlag`（现金交易标志） | `reversal`（冲正交易标志） | 结果 |
|------------------------|--------------------------------|----------------------------|------|
| `D`（借方） | `Y`（是） | `N`（否） | 继续执行（不返回 `ER0067`） |
| `D`（借方） | `Y`（是） | `Y`（是） | 返回 `ER0067` |
| `D`（借方） | `N`（否） | `N`（否） | 返回 `ER0067` |
| `D`（借方） | `N`（否） | `Y`（是） | 返回 `ER0067` |
| `C`（贷方） | `Y`（是） | `N`（否） | 返回 `ER0067` |
| `C`（贷方） | `Y`（是） | `Y`（是） | 返回 `ER0067` |
| `C`（贷方） | `N`（否） | `N`（否） | 返回 `ER0067` |
| `C`（贷方） | `N`（否） | `Y`（是） | 返回 `ER0067` |

#### Scenario: REQ-004-S06 取值不属于所列码值（「否则」的兜底覆盖）

- **GIVEN** 步骤1 取得的 `cashTranFlag` 为所列码值之外的其它字面取值（示例：`cashTranFlag = "X"`，同时 `crDrInd = D`、`reversal = "N"`）
- **WHEN** 执行步骤2 判定
- **THEN** 返回错误码 `ER0067`；源需求以「否则返回 ER0067」表述穷尽分支，该组合不满足「现金交易标志为 Y是」，落入「否则」；本步骤不校验字段取值的合法性，也不抛出异常

### Requirement: REQ-005 步骤输出契约

来源：`docs/requirements/ST057.md`「## 输出」表（第 16–20 行）、「## 相关枚举」表（第 24–27 行）、「## 补充说明」（第 29–32 行）

系统 SHALL 以 `crDrInd`（类型 `com.dcits.depsit.enums.CrDrInd`，非必填，借贷标志）、`cashTranFlag`（类型 `java.lang.String`，非必填，现金交易标志）、`reversal`（类型 `java.lang.String`，非必填，冲正交易标志）三个字段承载步骤1 按 `tranType` 查询【交易类型定义】所得的同名业务字段值。`crDrInd` 的取值 MUST 为该枚举的码值（`D`／`C`）；`cashTranFlag`、`reversal` 为字符串取值（判定取值 `Y`／`N`）。三个输出的字段名、类型与「非必填」标记 MUST 照录源需求，MUST NOT 被别名或枚举类名替换，MUST NOT 因「来源实体」列为空而改变来源或类型。

#### Scenario: REQ-005-S01 通过路径下输出三个字段

- **GIVEN** `tranType = "1003"`（现金支取），步骤1 查得记录字段「借贷标志＝D、现金交易标志＝Y、冲正交易标志＝N」（示例数据），步骤2 判定通过
- **WHEN** 本步骤结束
- **THEN** 输出 `crDrInd = D`（`CrDrInd.D`，借方的码值）、`cashTranFlag = "Y"`、`reversal = "N"`，三者与步骤1 查询所得字段值一致；不以含义后缀（如「-借方」「是」「否」）或枚举类名替代码值输出

#### Scenario: REQ-005-S02 输出的类型与标记照录

- **GIVEN** 源需求「## 输出」表给出三个输出的字段名、类型与「非必填」标记，「## 相关枚举」与「## 补充说明」给出 `TranType`、`CrDrInd` 两个枚举类的对应
- **WHEN** 核对本步骤的输出契约
- **THEN** 输出为 3 个字段：`crDrInd`（`com.dcits.depsit.enums.CrDrInd`）、`cashTranFlag`（`java.lang.String`）、`reversal`（`java.lang.String`），标记均为「非必填」；枚举对应关系只用于确定 `crDrInd` 的取值类型，MUST NOT 作为第 4 个输出，也 MUST NOT 将 `cashTranFlag`、`reversal` 改为枚举类型

### Requirement: REQ-006 失败返回与执行约束

来源：`docs/requirements/ST057.md`「## 步骤描述」2（第 6 行）

系统 SHALL 在判定不通过时返回错误码 `ER0067`，MUST NOT 返回其它错误码、MUST NOT 返回空值、MUST NOT 以异常代替错误码，并 MUST NOT 在返回该错误码后继续执行。本步骤为检查步骤，MUST NOT 产生数据写入、数据修改或外部调用等业务副作用。

#### Scenario: REQ-006-S01 错误码唯一且短路

- **GIVEN** 步骤1 取得任一不满足三条件的字段组合（示例：`crDrInd = C`、`cashTranFlag = "N"`、`reversal = "N"`）
- **WHEN** 执行步骤2 判定
- **THEN** 返回错误码 `ER0067`（工程内 `errorcodes.properties` 第 67 行记为「交易类型错误」，非规范性核对），不返回其它错误码、不返回 `null`、不抛出异常；本步骤在返回该错误码后即结束，不执行后续动作

#### Scenario: REQ-006-S02 检查步骤不产生副作用

- **GIVEN** `tranType` 为任一合法交易类型码值
- **WHEN** 本步骤执行完毕（无论判定通过或返回 `ER0067`）
- **THEN** 除既定的一次【交易类型定义】查询外，不发起其它 BCC、Mapper、数据库、外部接口或业务 Service 调用；不新增、修改或删除任何数据；输出与返回值仅由该次查询与判定决定

## 验收范围与明确不覆盖的事项

本 Spec 为测试设计依据，不是已生成的测试用例，也不是测试执行结果。以下事项在源需求中未唯一确定或属范围之外，不作为本轮验收判定的对象；相关条款按源需求原文用词表述，不得据本 Spec 反推取值。

1. **查询无匹配记录或三字段取到无值时的处理未定义（源需求未定义，不阻断本轮）**：源需求「## 步骤描述」1 只规定「根据{交易类型}查询【交易类型定义】获取对应的$借贷标志$、$现金交易标志$、$冲正交易标志$」，未规定查询不到该交易类型记录时的处理，也未规定三个字段本身取到无值（空）时的处理，「## 步骤描述」2 的「否则」是否覆盖上述情形亦未说明。REQ-002 只成文「按交易类型查询并取三字段」的契约（本步骤以交易类型为主键查询，单条记录语义），REQ-004 的判定表只覆盖三字段取到所列码值的组合；上述无记录/无值情形不作断言，测试设计不得据本 Spec 对其作断言，如需覆盖应先行明确需求。
2. **失败路径下输出字段的取值未定义**：源需求未说明返回错误码 `ER0067` 时 `crDrInd`、`cashTranFlag`、`reversal` 是否仍承载步骤1 查询所得值。本 Spec 仅对通过路径的输出取值成文（REQ-005-S01），失败路径的输出取值不作要求；三个输出标的「非必填」标记照录源需求，不据此推断其在失败路径下有值或无值。
3. **判定取值的书写形式（解释项，非源需求明文）**：源需求以「"D-借方"」「"Y是"」「"N否"」书写判定取值，其中「Y是」「N否」未带分隔符。本 Spec 按项目已合并规格对「码值-含义」书写形式的既有口径（`docs/specs/DT002.md`）以**码值** `D`／`Y`／`N` 表述判定与输出（见「### 取值书写口径」、REQ-004-S05、REQ-005-S01）。如需求方明确实际取值为含含义后缀的整体字面（如 `"Y是"`），需同步更新 REQ-003、REQ-004、REQ-005 及判定表；该口径不改变三个判定条件的组合关系。
4. **输入取值的合法性未要求校验**：源需求未要求校验 `tranType` 是否为 `TranType` 中的合法枚举值，也未定义非法取值时的处理。REQ-001 只成文类型与必填性，该情形的处理不在本轮验收范围内。
5. **输入在调用方侧的来源未规定**：源需求「## 输入」表「来源实体」列为空，`tranType` 由调用方（上游步骤）提供，本 Spec 不规定其取得方式、上游填充逻辑与在调用链中的位置。
6. **工程载体核对不作为断言**：`IRbTranDefBcc`／`RbTranDefEO`（【交易类型定义表(RB_TRAN_DEF)】）、`TranType`／`CrDrInd` 枚举类、`errorcodes.properties` 第 67 行 `ER0067=交易类型错误`，均为「### 依赖契约」中的**非规范性观察**，仅用于确认字段与错误码的技术可行性，不构成依赖契约、不进入测试断言；若工程实现与源需求冲突，以源需求为准。
7. **不在范围内的内容**：错误提示文案与错误码之外的信息；失败后调用方的处理与流程回退；后续步骤的内容与编号（源需求止于「继续执行」，无「组件内步骤调用」说明）；日志、监控、性能、幂等、重试等非功能要求——源需求均未定义，本 Spec 不作要求也不作断言。
