# ST120 检查是否存在转账不收不付限制

## 目标与范围

本步骤（交易执行步骤，存款业务组件）用于判断一个存款账户上是否存在「转账不收不付」限制：按账号取出该账户全部处于生效状态的账户限制信息，逐条对照【限制类型表】的配置判定，任一条限制的配置同时满足「禁止借贷方」与「禁止转账」时，判定该账户存在转账不收不付限制并回显命中的那条限制信息。

范围内：

- 按输入账号与限制状态查询【账户限制信息】；
- 按账户限制类型查询【限制类型表】并校验配置状态是否生效；
- 通过借贷方控制标志与转账标志判定单条限制是否构成转账不收不付限制；
- 多条限制的逐条判断与最终结果聚合、命中记录回显；
- 输出字段与失败处理口径。

不在范围内：本步骤只做判定与回显，不新增、修改或解除任何限制记录，不执行冻结/解限等账务动作；不包含跳转其他步骤（正式需求正文与补充说明均未声明组件内步骤调用或跳转目标）。

## Requirements

### Requirement: REQ-001 按账号与生效限制状态查询账户限制信息

来源：需求「## 步骤描述」子步骤 1；「## 输入」`baseAcctNo`

系统 SHALL 以输入账号 `baseAcctNo` 与限制状态等于 `RestraintsStatus.A`（需求写作「A-生效」）为条件查询【账户限制信息】，取回该账户全部处于生效状态的限制记录；取回记录 SHALL 包含「限制编号」`resSeqNo` 与「账户限制类型」`restraintType` 字段，用于后续逐条判定与命中回显。未取回任何生效限制记录时，系统 SHALL 直接得出转账不收不付标志为 `"否"`。

#### Scenario: REQ-001-S01 账号下无生效的账户限制信息

- **GIVEN** 输入 `baseAcctNo = "6222020000000001"`，该账号在【账户限制信息】中不存在 `restraintsStatus = A` 的记录（查询返回 0 条）
- **WHEN** 执行本步骤
- **THEN** 输出 `acctTranNoRecvNoPayFlag = "否"`
- **AND** 该分支不存在可用的 `restraintType` 取值，不触发【限制类型表】的查询

#### Scenario: REQ-001-S02 账号下存在一条或多条生效的账户限制信息

- **GIVEN** 输入 `baseAcctNo = "6222020000000001"`，该账号在【账户限制信息】中存在 1 条及以上 `restraintsStatus = A` 的记录，且每条记录均带有 `resSeqNo` 与 `restraintType`
- **WHEN** 执行本步骤
- **THEN** 对每条取回的限制记录分别执行 REQ-002、REQ-003 判定
- **AND** 本步骤最终输出由 REQ-004 的聚合规则决定

### Requirement: REQ-002 按账户限制类型查询限制类型配置并校验生效状态

来源：需求「## 步骤描述」子步骤 2

系统 SHALL 以当前限制记录的账户限制类型 `restraintType` 查询【限制类型表】，取回对应的配置记录；仅当取回记录的 `status` 等于 `Status.A`（需求写作「A-生效」）时，系统 SHALL 将该配置记录的 `drCrCtlFlag`、`transferFlag` 作为 REQ-003 的判定输入。若查不到该 `restraintType` 对应的配置记录，或取回记录的 `status` 不等于 `Status.A`，系统 SHALL 判定该条账户限制信息不构成转账不收不付限制，该条不参与命中判定；全部限制信息均不构成时，转账不收不付标志为 `"否"`。

#### Scenario: REQ-002-S01 限制类型存在生效配置

- **GIVEN** 当前限制记录的 `restraintType = "TRF01"`，【限制类型表】存在 `restraintType = "TRF01"` 且 `status = A` 的配置记录，其 `drCrCtlFlag = A`、`transferFlag = "N"`
- **WHEN** 查询该限制类型的配置
- **THEN** 该配置记录的 `drCrCtlFlag`、`transferFlag` 作为 REQ-003 的判定输入，该条限制记录进入构成条件判定

#### Scenario: REQ-002-S02 限制类型查不到配置记录

- **GIVEN** 当前限制记录的 `restraintType = "TRF99"`，【限制类型表】不存在 `restraintType = "TRF99"` 的配置记录
- **WHEN** 查询该限制类型的配置
- **THEN** 该条账户限制信息不构成转账不收不付限制，不产生命中结果
- **AND** 判定流程按 REQ-004 处理其余限制记录；若全部限制信息均不构成，则 `acctTranNoRecvNoPayFlag = "否"`

#### Scenario: REQ-002-S03 限制类型存在配置但状态非生效

- **GIVEN** 当前限制记录的 `restraintType = "TRF01"`，【限制类型表】存在 `restraintType = "TRF01"` 的配置记录，但其 `status = F`（无效），且 `drCrCtlFlag = A`、`transferFlag = "N"`
- **WHEN** 查询该限制类型的配置并校验状态
- **THEN** 该配置记录视为不生效，该条账户限制信息不构成转账不收不付限制，不产生命中结果
- **AND** 判定流程按 REQ-004 处理其余限制记录；若全部限制信息均不构成，则 `acctTranNoRecvNoPayFlag = "否"`

### Requirement: REQ-003 判定单条限制是否构成转账不收不付限制

来源：需求「## 步骤描述」子步骤 3

对已取到生效配置的限制记录，系统 SHALL 仅当该配置的借贷方控制标志 `drCrCtlFlag` 等于 `DrCrCtlFlag.A`（需求写作「A-禁止借贷方」）且转账标志 `transferFlag` 等于 `"N"`（需求写作「N-禁止转账」）时，判定该条限制构成转账不收不付限制；`drCrCtlFlag` 与 `transferFlag` 中任一不满足时，系统 SHALL 判定该条限制不构成转账不收不付限制。

#### Scenario: REQ-003-S01 借贷方控制标志为禁止借贷方且转账标志为禁止转账

- **GIVEN** 当前限制记录的生效配置为 `drCrCtlFlag = A`（禁止借贷方）、`transferFlag = "N"`（禁止转账）
- **WHEN** 判定该条限制是否构成转账不收不付限制
- **THEN** 判定结果为构成，该条限制命中转账不收不付限制，结果按 REQ-004 处理

#### Scenario: REQ-003-S02 借贷方控制标志为禁止借贷方但转账标志不是禁止转账

- **GIVEN** 当前限制记录的生效配置为 `drCrCtlFlag = A`（禁止借贷方）、`transferFlag = "Y"`（示例值，需求未枚举 `"N"` 以外的转账标志取值，仅用于表达「不等于 N」的分支）
- **WHEN** 判定该条限制是否构成转账不收不付限制
- **THEN** 判定结果为不构成，该条限制不命中转账不收不付限制

#### Scenario: REQ-003-S03 借贷方控制标志不是禁止借贷方但转账标志为禁止转账

- **GIVEN** 当前限制记录的生效配置为 `drCrCtlFlag = C`（禁止贷方）、`transferFlag = "N"`（禁止转账）
- **WHEN** 判定该条限制是否构成转账不收不付限制
- **THEN** 判定结果为不构成，该条限制不命中转账不收不付限制

#### Scenario: REQ-003-S04 借贷方控制标志与转账标志均不满足构成条件

- **GIVEN** 当前限制记录的生效配置为 `drCrCtlFlag = D`（禁止借方）、`transferFlag = "Y"`（示例值，表达「不等于 N」）
- **WHEN** 判定该条限制是否构成转账不收不付限制
- **THEN** 判定结果为不构成，该条限制不命中转账不收不付限制

### Requirement: REQ-004 逐条判定结果的聚合与命中回显

来源：需求「## 步骤描述」子步骤 1（逐条判断与聚合、回显）；子步骤 2（「全部限制信息都不构成时返回否」）；「## 输出」

系统 SHALL 对取回的全部生效限制记录逐条执行 REQ-002、REQ-003 判定，并按以下规则聚合本步骤结果：

- 任意一条限制记录构成转账不收不付限制时，`acctTranNoRecvNoPayFlag` 为 `"是"`，并回显该条命中记录的 `resSeqNo`、`restraintType`、`restraintsStatus`；
- 全部限制记录均不构成转账不收不付限制时，`acctTranNoRecvNoPayFlag` 为 `"否"`。

单条限制未命中不构成本步骤的最终结果，仅为逐条判断中的一个中间结论，其余限制记录继续按 REQ-002、REQ-003 判定。

#### Scenario: REQ-004-S01 唯一一条限制记录命中

- **GIVEN** 账号下只有 1 条 `restraintsStatus = A` 的限制记录 `resSeqNo = "R0001"`、`restraintType = "TRF01"`、`restraintsStatus = A`，其【限制类型表】配置为 `status = A`、`drCrCtlFlag = A`、`transferFlag = "N"`
- **WHEN** 执行本步骤
- **THEN** 输出 `acctTranNoRecvNoPayFlag = "是"`
- **AND** 输出回显 `resSeqNo = "R0001"`、`restraintType = "TRF01"`、`restraintsStatus = A`
- **AND** 配置侧输出字段取值与命中配置记录一致：`drCrCtlFlag = A`、`status = A`、`transferFlag = "N"`

#### Scenario: REQ-004-S02 多条限制记录中仅某一条命中

- **GIVEN** 账号下有 2 条 `restraintsStatus = A` 的限制记录：第 1 条 `resSeqNo = "R0001"`、`restraintType = "TRF01"`（配置 `drCrCtlFlag = A`、`transferFlag = "Y"`，不构成），第 2 条 `resSeqNo = "R0002"`、`restraintType = "TRF02"`（配置 `status = A`、`drCrCtlFlag = A`、`transferFlag = "N"`，构成）
- **WHEN** 执行本步骤
- **THEN** 输出 `acctTranNoRecvNoPayFlag = "是"`
- **AND** 输出回显第 2 条命中记录的 `resSeqNo = "R0002"`、`restraintType = "TRF02"`、`restraintsStatus = A`
- **AND** 配置侧输出字段取值与第 2 条命中记录对应的配置一致：`drCrCtlFlag = A`、`status = A`、`transferFlag = "N"`

#### Scenario: REQ-004-S03 多条限制记录全部不构成

- **GIVEN** 账号下有 2 条 `restraintsStatus = A` 的限制记录：第 1 条 `restraintType = "TRF01"`（配置 `drCrCtlFlag = C`、`transferFlag = "N"`，不构成），第 2 条 `restraintType = "TRF02"`（配置 `drCrCtlFlag = A`、`transferFlag = "Y"`，不构成）
- **WHEN** 执行本步骤
- **THEN** 输出 `acctTranNoRecvNoPayFlag = "否"`

#### Scenario: REQ-004-S04 前序记录不构成、后续记录命中

- **GIVEN** 账号下有 3 条 `restraintsStatus = A` 的限制记录：第 1 条 `restraintType = "TRF98"` 在【限制类型表】无配置记录（不构成），第 2 条 `restraintType = "TRF01"` 的配置 `status = F`（不生效，不构成），第 3 条 `resSeqNo = "R0003"`、`restraintType = "TRF02"` 的配置 `status = A`、`drCrCtlFlag = A`、`transferFlag = "N"`（构成）
- **WHEN** 执行本步骤
- **THEN** 输出 `acctTranNoRecvNoPayFlag = "是"`
- **AND** 输出回显第 3 条命中记录的 `resSeqNo = "R0003"`、`restraintType = "TRF02"`、`restraintsStatus = A`

### Requirement: REQ-005 失败处理

来源：需求「## 失败处理」

本步骤无业务失败场景，系统 SHALL NOT 产生业务失败结果或业务错误码；依赖查询等技术异常 SHALL 按技术异常传播表达，不映射为业务标志 `"否"`。

#### Scenario: REQ-005-S01 依赖查询发生技术异常

- **GIVEN** 输入 `baseAcctNo = "6222020000000001"`，且【账户限制信息】或【限制类型表】的查询在执行中发生技术异常
- **WHEN** 执行本步骤
- **THEN** 技术异常按技术异常传播表达
- **AND** 不以 `acctTranNoRecvNoPayFlag = "否"` 作为对技术异常的业务结果

## 验收范围与明确不覆盖的事项
