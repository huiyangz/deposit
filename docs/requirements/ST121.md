# ST121 检查限制优先级

## 步骤描述

1.获取交易的冻结级别：根据{交易类型}查询【交易定义信息】获取交易的$冻结级别$

2.获取限制的冻结级别：根据{账户限制类型}查询【限制类型定义信息】获取限制的$冻结级别$
3.检查限制优先级：若交易的[冻结级别]高于账户限制类型对应的[冻结级别]，则返回检查结果“不检查限制”，否则返回检查结果为“继续检查”；交易的[冻结级别]或限制类型的[冻结级别]取不到值时，返回检查结果为“继续检查”。

> 3.检查限制优先级：若交易的[冻结级别]高于账户限制类型对应的[冻结级别]，则返回检查结果“不检查限制”，否则返回检查结果为“继续检查”；交易的[冻结级别]或限制类型的[冻结级别]取不到值时，返回检查结果为“继续检查”。

问题：子步骤3 的判定条件「交易的[冻结级别]高于账户限制类型对应的[冻结级别]」没有定义「冻结级别」的可取取值与高低顺序，「高于」无法唯一判定。

交易的冻结级别取自【交易定义信息】、限制的冻结级别取自【限制类型定义信息】，两处的「冻结级别」都是业务维护的两位编码、允许为空，来源文档的数据字典也只给出它的类型（两位编码类），没有列出有哪些取值、哪个取值高于哪个取值；本工程内也没有对应的枚举或码值定义。因此实现只能自行假定比较方式：按编码顺序、按数值大小或按另一套业务顺序比较会得到不同的结论，同一笔交易可能得出相反的「不检查限制」／「继续检查」，直接影响限制检查是否放行。

修正要求：请业务方给出「冻结级别」的取值清单及高低顺序（哪个取值高于哪个取值），或指明该顺序由哪份可查的业务规定确定。
